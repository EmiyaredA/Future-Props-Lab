# Agent Note: 远程窗口采集留边

Status: implemented

## Problem

ScreenCaptureKit 有时按应用的底层绘制面进行缩放，输出的可见窗口只占编码帧的一部分。Chrome 主窗口复现上方约 78 像素、右侧约 123 像素的留边。浏览器按完整视频帧居中，因此可见窗口偏向左下，视频坐标也与目标窗口不一致。

## Decision

采集保留透明度。编码前用帧的像素比例换算目标窗口的预期尺寸。仅当存在明显留边且可见像素范围与该尺寸吻合时，裁掉透明留边，将有效画面缩放到编码帧尺寸。几何信息缺失、可见范围不吻合或帧已填满时，沿用原始画面。裁剪输出复用像素缓冲池。

## Alternatives considered

- 在 Web 调整视频对齐只能移动整个编码帧，留边仍在帧内，键鼠坐标也不会自动修正。
- 切换采集的屏幕裁切、等比或原尺寸选项，实测同一个 Chrome 窗口仍有留边。
- 仅使用系统报告的内容矩形会留下窗口上方的透明区域，实测该矩形比实际可见区域高约 78 像素。

## Consequences

同一逻辑适用于所有远程应用。浏览器继续按已编码画面与目标窗口的统一比例映射键鼠坐标。可见范围与窗口几何明显不符的辅助窗口仍使用原始帧。

## Verification

在真实 Chrome 问题窗口复现 1146×720 帧中约 1023×643 的可见区域。校正后有效画面覆盖完整宽度，纵向仅有约一像素的边缘过渡。另一个正常 Chrome 窗口及文本编辑没有可见偏移。实际 Chrome 和文本编辑均通过 H.264 硬件编码。合成回归覆盖左下留边、微弱透明边缘、黑色内容、比例不匹配及无比例元数据。
