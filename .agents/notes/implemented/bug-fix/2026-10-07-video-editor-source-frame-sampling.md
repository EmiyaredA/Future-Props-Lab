# Agent Note: 精确停帧与导出按源帧展示区间采样

Status: implemented

## Problem

24 FPS 素材映射到 30 FPS 时间线的非源帧网格时刻时，精确停帧直接用 FFmpeg 输入 `-ss`，会丢弃仍应展示的当前帧并返回下一帧。素材自身切镜恰好落在剪辑接缝附近时，监视器提前出现另一场景。导出解码器的 `trim=start=请求时刻` 与默认 FPS 舍入存在同类问题；素材尾帧展示区间内取帧还可能得到空输出。

只读诊断中，APTMV-冈牧-V2 revision 1151 的时间线 17.100 秒映射到第三段素材的 4.591572 秒。有效源 PTS 为 4.583333… 秒，旧取帧返回 4.625 秒的下一场景。该处没有转场，也不是两段片段同时生效。

## Decision

共享媒体渲染能力中的 `video_sampling.py` 根据源视频整数 PTS 和 time base，选取不晚于请求时刻的最后一帧，使用精确有理数比较，并归一化非零流起始时间。探测从请求时刻之前的关键帧开始，只读取局部时间区间；不使用平均帧率推算 VFR 帧号。

精确停帧 seek 到所选源帧；导出保留该帧与请求起点的时间相位，在细时间基下计算变速后的 PTS，再向上对齐输出 FPS 网格，使下一源帧只在其真实展示时刻到达后出现。解码尾部补一秒克隆帧，以保证接近 EOF 的首个样本可输出；后续仍沿用流式解码器持有末帧与取消规则。

持久帧缓存增加采样版本，浏览器精确停帧 URL 更新渲染版本。旧缓存不修改也不删除，但新请求不再命中它。时间线文档、片段、素材与数据库保持原值。

## Alternatives considered

- 自动缩短片段或移动接缝：掩盖采样错误并改变用户工程，不能保证其他切镜正确。
- 减去固定一帧或按平均 FPS 向下取整：对 VFR、非零流起点和不同输入帧率不成立。
- 只修精确停帧：导出仍可能提前显示下一场景，节目监视器无法作为导出依据。

## Consequences

每次独立 seek 需要额外一次局部 PTS 探测，流时钟元数据按不可变素材路径缓存。导出连续播放仍复用原来的管道解码器，不逐帧启动探测。FFmpeg 粗定位、细裁切与 B-frame 预解码继续保留。

没有公共 HTTP/SSE schema 变更、数据库迁移或真实工程写入。修复生效需要运行中的后端应用源码更新。
