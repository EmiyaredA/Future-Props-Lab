# Agent Note: 桌宠窄窗口中的走路动画与档位反馈

Status: implemented

## Problem

220px 高的角色容器只有 165px 宽，分层动画引擎按身体半径计算的 minX 大于 maxX，走路目标与当前位置重合，第一次帧更新即结束。运行悬停按钮只有“走动”标题，切换档位后没有当前值反馈，且需要等待下一次定时器。编辑器未保存的默认值与已经打开的桌宠会话不同。

## Decision

分层角色渲染器明确启用 walkInPlace，使用独立的剩余路程推进步幅并固定角色锚点；屏幕位置仍由 PetRuntime 经受限 Electron movePet IPC 请求，宿主工作区校验仍负责边界。普通舞台保持原有位移行为，窄舞台的左右边界收敛到中心而非反转。

走动按钮提示当前档位，启用走动时立即请求一次移动；随后沿用 7 秒和 17 秒频率。成功回执成为下一次位置输入；遇到完全被钳制的位移时尝试反向。拖动与聊天期间暂停自动走动，移动失败有可见反馈。项目默认配置仍需保存后关闭重开，不自动覆盖用户当前会话或未保存编辑。

## Alternatives considered

- 扩大角色容器：改变角色尺寸与命中区域，仍受屏幕工作区约束。
- 仅增加定时器频率：不能解决动画范围为零和当前档位不可见的问题。

## Consequences

角色动作与屏幕移动有明确的职责边界；分层人物和鲸鱼共享修复。Live2D 来源仍使用自身绑定动作。编辑器模拟桌面继续只由事件试玩驱动，不自动运行真实桌面移动。

## Verification

Web 回归覆盖窄容器 walk/run 的持续迈腿、固定锚点、resize 与自然结束，以及普通宽舞台保留位移。运行测试覆盖频率、即时切档、关闭走动、工作区边缘反向、聊天暂停、失败恢复和卸载清理。
