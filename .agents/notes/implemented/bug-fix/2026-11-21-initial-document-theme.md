# Agent Note: 跨应用新文档的首屏主题

Status: implemented

## Problem

工坊内部已采用 History 导航，但应用目录与独立工坊之间仍需要加载目标 HTML。
独立入口仅设置主题属性，实际底色依赖外部 CSS；暗色用户在新文档初始化期间仍会看到白底。
现有服务已加载当前源码，因此重新启动后端不能补上首屏样式缺口。

## Decision

按 Studio 框架的独立应用边界继续保留跨应用文档跳转。公共 Vite 插件 `themeBootstrap.ts`
为全部入口注入同步内联主题脚本和最小底色样式，开发、兼容网站、管理与独立构建共用。
`shared/ui/themePreference.ts` 提供无 React 依赖的自包含偏好解析；插件序列化同一函数，运行时直接调用。
有效的已存偏好优先，否则跟随系统；存储被拒绝时仍使用系统偏好，不在启动阶段写入偏好。
底色采用运行时色板变量及相同的加载前回退值，保留用户后续切换主题的能力。
删除各 HTML 重复的旧解析逻辑，并将插件源码纳入独立服务构建摘要，避免复用过时程序。

真实跨文档验收同时发现门户将 `/apps` 声明为递归根路径，错误接管其他工坊。
导航上下文明确区分 `roots` 的子树与 `exactPaths` 的单页归属；门户仅接管自己的四个单页及其尾斜线，
工坊继续使用已有子树声明。验收必须观察目标文档请求，不能仅凭 URL 已改变认定跨工坊成功。

## Alternatives considered

- 仅重启服务或清浏览器缓存：当前服务源码已更新，不能解决 CSS 加载前的默认画布底色。
- 将所有工坊合并到同一 React 路由：破坏独立应用装配，且不能覆盖首次访问和刷新。
- 每个 HTML 复制主题脚本与底色：会再次造成遗漏和偏好规则漂移，表格等入口已暴露这种差异。

## Consequences

跨应用仍有目标应用加载过程，加载期间的画布遵守当前主题；不以常驻其他工坊来掩盖加载时间。
初始化不发请求，不读取账号数据，不修改数据库或正式配置。内联样式使用 CSS 媒体查询为无脚本场景提供系统偏好回退。
没有新增用户路由或修改各工坊的编辑、权限与保存协议。

## Verification

- 偏好解析及实际序列化脚本覆盖已存明暗色、系统明暗色、无效值和存储拒绝，并与 React 运行时规则对照。
- Chrome 遍历全部 20 个 HTML，阻断外部脚本与样式，验证首屏底色、color-scheme 和偏好不被覆写。
- 应用目录的真实按钮触发跨应用导航，以 Chrome 渲染帧检查暗色切换过程，并保留目标文档首屏截图。
- 类型检查、变更文件静态检查、Studio 构建及工程文档门禁验证公共插件与入口兼容。
- 24 项聚焦单元测试、14 条 Chrome 旅程与 102 项相关架构测试通过；20 个 HTML 的三组首屏偏好逐一验证。
  渲染帧包含源应用与目标暗色画布，并显式确认目标文档请求。Studio、独立 Portal 和 Visual 构建通过；
  生成 HTML 的同步脚本在模块前执行且遵守系统暗色，Agent Note 与产品文档保护门禁通过。
- 当前本机 3000 的门户、视觉和剪辑入口均返回新初始化脚本，剪辑服务 `/ready` 返回 200；未重启后端。
- 验收账号、隔离数据库、日志与截图保存在 `.local/dark-navigation-20261121/`；正式本机服务保持运行。
