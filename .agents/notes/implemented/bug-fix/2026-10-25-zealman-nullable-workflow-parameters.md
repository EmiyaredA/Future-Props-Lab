# Agent Note: ZEALMAN 可空工作流参数回读

Status: implemented

## Problem

共享 WorkflowVideoParameters 同时描述 U17 与 U06。画布和 SDK 序列化会将未选工作流的字段也保存为 null，例如 U17 带 width/height/seed=null。原先按键是否存在检查工作流参数，导致回读后的有效草稿被拒绝；通用视频选项的显式 null 也可能被误判为不支持。

真实执行同时遇到旧版 ZEALMAN 服务拒绝已公开的 ref_image_0 固定键，以及 U17 已有 prompt 映射未开放。这是部署契约问题，与可空参数校验问题分别记录，不能通过猜测节点数字或替换参考顺序绕过。

## Decision

在共享 ZEALMAN 适配边界将已知参数的 null 归一化为未提供，继续使用当前工作流默认值；seed=0、False 等实际值不因真值判断丢失。不支持的非空参数、未知键、范围、整数与步长约束继续拒绝。通用字段中的隐式 schema 默认值不视为调用者请求。

参考输入继续遵守原有零起始 ref_image/ref_audio/ref_video 契约，提示词经 prompt 传入。公共 HTTP/SSE 形状、SDK 生成物、数据库和任务状态机保持现有契约，提交异常不自动重试。

本次制作运行器通过正式 SDK 提交任务，同时检查应用任务与上游真实队列；空闲时在两次 U 系列提交之间按上游文档释放缓存显存。它是本地单卡制作流程，不把工作流编排或其他入口的并发控制塞进供应商适配器。

## Alternatives considered

- 仅在一次性脚本删除 null：可恢复本轮任务，但其他入口回读同样草稿仍会失败。
- 放宽全部参数校验：会让其他工作流的有效数值或拼错字段流向供应商，继续严格拒绝。
- 将固定参考键改为节点数字：偏离公开契约，并有输入错位风险，维持现有正确编号。

## Consequences

可空 schema 的合法回读请求得到一致归一化，不改变真实参数的含义。部署工作流需启用实际需要的 prompt 输入；备份、修复和回读证明模型图与参考顺序未变。真实视频的身份、动作、音色仍须逐段验收，接口受理和技术校验不表示质量通过。


上游运行恢复补充：S002 在批量加载 303 帧 7680×4320 参考时 ComfyUI 进程退出，随后接口连接拒绝。没有 kernel OOM 证据，不将内存耗尽写成已确认根因。恢复同一服务后，仅将参考解码宽高限制为 1280×720，保持源文件、帧率、时序、模型及输出参数。服务恢复后观察到 API 别名元数据和 prompt 开关缺失，按已验证备份恢复这些字段；S003 真实执行图证明固定输入及解码尺寸正确，上游恰有一个任务执行。所有中断、未受理和成功版本均保留，实际中断镜头留到整轮检查后针对性返修。
