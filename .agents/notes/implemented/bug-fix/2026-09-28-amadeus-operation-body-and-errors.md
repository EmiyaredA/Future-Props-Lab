# Agent Note: Amadeus 业务操作正文与校验反馈

Status: implemented

## Problem

模型可能把 `fpl_operation_write` 的 `body` 作为 JSON 字符串提交。审批后的内部业务 API 收到 JSON 字符串而非对象，返回 422；Amadeus 又只保留 HTTP 状态码，丢失字段校验信息，导致后续对话猜测原因并提议改用整文档写入。

## Decision

写操作工具在提交审批前将 JSON 字符串正文解析为对象，审批摘要对应实际发送的参数。无法解析或根值不是对象的字符串直接在工具层拒绝。已有对象保持原值。业务 API 失败时，Amadeus 保留协议错误码、简短详情和首个字段校验错误，让模型与用户能看到失败原因。

## Alternatives considered

- **在业务 API 中接受字符串正文**：会放宽所有业务接口的请求契约，也让审批展示的参数与实际语义不同。
- **仅提示模型不要序列化正文**：无法修复已经观察到的模型输出，也不能解释其他校验失败。

## Consequences

新的审批记录展示对象正文，既有已失败审批不会自动重试或改写。工具只解析 JSON 对象字符串，不对其他类型做隐式转换。错误摘要保留长度上限；完整校验仍以业务 API 为准。

## Verification

- Web 单元测试覆盖字符串正文还原与非对象拒绝。
- 后端 API 测试覆盖业务操作 422 的错误码与字段位置。
- 桌面隔离烟测的模拟模型以字符串正文提交写操作，验证审批后仍能完成画布更新。
