# Agent Note: 文档表格按列调整宽度

Status: implemented

## Problem

笔记正文表格被限制在正文宽度内。拖动一条列边时，未单独记录宽度的列会一起分摊剩余空间，所以调整一列会让其他列同时变大或变窄。

## Decision

拖动列边只改变该列的像素宽度，其余列保持拖动开始时的宽度，表格总宽度等于各列之和。表格宽于正文时在表格区域内横向滚动，窄于正文时不再被拉满。尚未调整过的表格仍等分并铺满正文。已经有部分列宽时，缺宽的列在显示时沿用相邻的已定宽度，避免重新平分。

## Alternatives considered

- 保持表格总宽，只和相邻列交换宽度：总宽仍然固定，继续把一列的变化转嫁给另一列。
- 只去掉表格 `width: 100%`：没有显式宽度的列仍会分摊剩余空间，问题会在第一次拖动后保留。

## Consequences

- **收益**：每一列的宽度可以独立调整，其他列不再跟着缩放。
- **代价与已知上限**：列宽按像素保存。插入列沿用相邻列的显示宽度；双击按内容自适应、键盘微调不在这次范围内。合并单元格仍共用原有跨列宽度数组。

## Verification

- `web/tests/features/thought-table-resize.test.ts` 覆盖单列变化、缺宽沿用相邻列、写回时保持其他列，以及插入列后的显示宽度。
- 浏览器拖动三列表格：加宽第一列后其余列像素宽度不变，表格总宽增加并在表格区域内滚动；缩窄中间列或最后一列时，未拖动列保持原宽，列宽不低于 60 像素。
