# Agent Note: 桌面 SDK 节点输出版本接入

Status: implemented

## Problem

视觉工坊已提供节点输出历史、版本上传、托管素材追加和最终版本选择的 HTTP API 与具名 Python SDK 方法，但桌面 Agent 清单遗漏这些操作。通过桌面客户端回填浏览器成片时，即使已有正确项目和读写授权，版本查询仍返回 403，用户只能在界面逐个上传。

## Decision

在唯一桌面 Agent 白名单登记五个已有业务操作：分页查询版本、读取具体版本、上传本地文件为版本、追加项目内托管素材、选择最终版本。继续复用已有路由和输出用例，不新增 API、数据库字段、凭据或旁路写入方式。版本删除仍默认拒绝，其他未知节点操作同样拒绝。

## Alternatives considered

- 继续创建独立素材节点：保存了成片，但原生成节点仍无输出，不满足对应节点的版本回填需求。
- 开放整个视觉节点 URL 前缀：会隐式开放后续新增操作，因此只逐条登记现有五个方法。
- 修改已有版本或直接写数据库：会破坏版本与业务校验，沿用正式输出版本用例。

## Consequences

现有工作区读取授权可查询版本，写入仍要求读写授权、视觉工坊权限、项目素材归属和最新画布 revision。新上传或追加版本成为当前最终输出并重置认可标记，原版本继续保留；切回历史版本使用同一 CAS。该变更不提交模型任务。正在运行的桌面后端需经正式开发更新流程加载新清单，不热改运行中权限对象。

## Verification

- 使用临时数据目录、真实桌面后端与 Unix 网关执行具名 SDK 图片和视频版本流程：上传两版、分页与详情读取、追加第三版、切回第一版，确认历史完整、认可标记清除。
- 同一测试验证过期 revision 返回 409、错误节点和项目返回 404、只读客户端的三种写入均返回 403，且没有增加版本；删除操作仍不在白名单。
- 新增两项集成用例通过；SDK 生成物检查通过，HTTP/SDK 字段契约保持不变。
- 维护 `docs/operations/desktop-agent.md` 的方法、CAS、版本保留与上传示例，不重新生成受保护的产品文档中心。
- 相关桌面 Agent、节点输出与 Python SDK 共 51 项回归通过，Ruff、格式、`contracts:check` 和 Agent Note 校验通过。完整相关集首次运行中的另一个集成目录清单测试因三个 Skill 文件读取操作未登记而失败；使用修改前 HEAD 清单比较确认这些遗漏早已存在，未扩大本次修复范围。
- 通过应用内正式开发更新加载新清单后，现有授权成功查询并追加实际浏览器成片版本；69 个基础节点与 10 个修订节点获得 80 条关联，每次追加前后核对旧版本 ID 集合，旧版全部保留。制作回执保存在忽略的 `.local/character-replacement/wanan-steins-butler/phase2/browser-round-01/node-output-attachment/`，不把真实制作数据作为自动化测试输入。
