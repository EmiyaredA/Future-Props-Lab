# Agent Note: 远程应用鼠标事件绑定窗口

Status: implemented

## Problem

远程画面和输入通道均已连接时，Chrome 和 ChatGPT 仍有大量点击无效。原实现创建全局坐标的 CGEvent，再设置两个 window-under-mouse 字段并投递到进程；这两个字段没有将事件绑定到 AppKit 窗口。此前的[辅助功能控件点击补丁](2026-11-08-remote-app-chromium-clicks.md)只能覆盖部分控件，无法修复原始鼠标路径。

## Decision

通过公开的 NSEvent 鼠标构造器携带目标窗口编号，再将其 CGEvent 投递给已验证的目标进程。辅助程序不拥有目标 NSWindow，转换时以主屏幕高度补偿 AppKit 翻转，使序列化事件保留窗口内、左上原点的坐标。事件构造由 `WindowMouseEvent` 负责，窗口状态、授权与投递仍由 `WindowInput` 负责。

取消按应用名称切换 AXPress 和文本焦点的补丁。单击、双击、右键及拖动共用窗口绑定的鼠标事件。每次按下分配事件编号，抬起和释放沿用该编号。释放时使用最后验证过的窗口几何。

## Alternatives considered

- 继续修补 AX 控件父链：只能触发暴露相应动作的控件，无法恢复通用鼠标交互。
- 只补充 CGEvent 的 window-under-mouse 字段：相同页面与坐标的旧版对照测试不产生点击计数。
- 全局发布鼠标事件：扩大输入目标范围；保持 PID 投递以及既有前台、窗口和命中检查。

## Consequences

进程、窗口、Mac 解锁状态及辅助功能权限校验保持生效。鼠标事件格式不再依赖目标应用是否暴露 AXPress。此变更只涉及辅助程序，不改变信令协议或站点构建。

窗口关闭、最小化或尺寸变化仍暂停旧会话。录屏已建立不代表目标应用已处理具体点击。Mac 应用更新后的系统隐私授权需要重新复核。

## Verification

在隔离 WebRTC 控制端连接真实 Chrome 测试页。同页、同坐标对照中，旧原始鼠标实现的计数不变，新实现记录真实按下、抬起和点击。正式源码构建完成中文输入后点击、标准按钮、自绘区域、双击、右键及一轮连续 10 次点击；计数与操作一致。拖动可选中真实文本，但测试页的 `pointermove.buttons` 计数未增加，尚未据此验收自绘拖拽组件。

新增 macOS 回归测试直接检查序列化后的事件窗口编号、事件类型、点击次数、编号、修饰键和坐标，共 24 组，包含窗口移动和负坐标。测试不向任何应用发送输入；无 macOS 登录会话时明确跳过。

正式辅助程序安装后复核屏幕录制、辅助功能和解锁状态均通过。清零测试页后，仅由用户在 Windows 操作；Mac 侧读回标准按钮 3 次、自绘区域 3 次、按下和抬起各 7 次，输入框为 `ADA1`。用户反馈目前可用。ChatGPT 恢复情况依据用户反馈，未独立核对「输入后点新聊天」的最终页面。
