# Agent Note: 独立工坊共享局部导航与编辑保护

Status: implemented

## Problem

视觉入口修复后，其余多个独立入口仍用 `location.assign` 处理内部按钮，造成整页闪烁、身份重查和助手重建。
视频、音频、特效、演示文稿和表格已有功能 Guard；Galgame 和导演台主要依靠 `beforeunload`，不能直接以 History 替换导航。

## Decision

按 Studio 框架的入口装配边界，复用已有 History 控制器，以单工坊模块声明适配 `useWorkshopNavigation`。
定义中的应用根路径与具体路由共同限定归属，防止前缀相似的其他应用被错误接管。通用 Studio 壳通过显式 roots 与
`ApplicationNavigation` 提供单一控制器，页面与侧栏共用位置和动作；页面 Suspense 保留在稳定应用壳内。

导航事件提交与 Guard 入口集中在 `shared/ui/navigationGuards.ts`；删除旧入口辅助文件并更新全部消费者，避免永久转发。
视频、音频、特效和演示文稿通过共享注册适配器保留原功能检查；表格继续使用其原有上下文 Guard。
Galgame 增加保存状态保护，导演台通过只读 dirty/busy 端口报告状态并使用同一确认弹窗。导演台只在状态变化时通知 React。
项目编辑器按资源 ID 隔离挂载；页面只读权限、查询键、保存 CAS 和后台任务语义保持原有约束。

思绪工坊保留原有局部历史，同时将首次懒加载切页放在 React transition 内，旧内容保持可见直到新页面就绪。
共享 History 控制器也采用此机制。管理中台的返回入口复用自身的局部更新。
经 Guard 延迟并获确认的离开立即提交，避免旧草稿组件的守卫误拦截紧随其后的 Back；干净切页保留 transition。
面试、文件管理与编程智能体的跨应用跳转仍由目标应用承接。
门户自己的首页、应用目录和云控页面也使用同一局部导航，独立 Amadeus 工作区继续使用其单独装配。

## Alternatives considered

- 为每个入口复制 History 和 popstate：不能统一浏览器历史、链接手势和草稿保护，且会继续出现同类遗漏。
- 使用兼容网站的总路由：会引入其他工坊注册与实现，违反独立应用边界。
- 只替换 location 调用：会绕过仅依赖 beforeunload 的编辑器，也会留下整壳 Suspense 引起的闪烁。

## Consequences

工坊内操作保留 Document 与身份/助手实例；真正的跨应用切换继续加载对应程序。
导航机制不执行保存，保存与是否允许离开仍由功能所有者决定。没有数据库、配置或公开 API 变更。

## Verification

- 前端全量测试与隔离架构测试检查模块装配、既有功能与 Guard；历史表格文档与响应式覆盖失败单独记录。
- Chrome 旅程覆盖各项目工坊的真实独立入口、打开与返回、Back/Forward、工具与集成标签、模型侧栏、草稿拦截及导航文档请求。
- 表格浏览器导航用确定性所属服务 API 夹具；兼容网站有意拒绝该应用的存储请求，不为验收放宽服务边界。
- 全量前端 2031 项通过，4 项既有表格文档/响应式覆盖失败；新增及相关导航 21 项聚焦回归通过，架构 126 项通过。
- 14 条不同的 Chrome 旅程最终全部通过；表格截图等待实际网格就绪。类型、变更文件 ESLint/Prettier、Studio 构建与预算通过。
- 可再生成的日志、截图、隔离账号与数据库归 `.local/workshop-navigation-20261121/`，不用于正式服务。
