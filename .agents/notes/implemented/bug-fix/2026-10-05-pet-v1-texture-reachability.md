# Agent Note: 停用旧运动分件的纹理引用闭包

Status: implemented

## Problem

版本 1 人物运动部件已停止绘制，但其独占图片仍在每个服饰实例初始化时加载并上传到 GPU。直接按贴图名称删除会误伤原站姿共用的手腿素材，按当前站姿透明度过滤又会漏掉坐姿与其他服饰部件。

## Decision

humanFigure 内以同一确切部件 ID 集合表达已有回退隐藏规则，再仅对版本 1 从全部保留部件的纹理引用派生运行加载集合。只跳过永久隐藏部件独占的纹理；共享站姿、坐姿、服饰纹理及全部五官保留。初始加载和换装上传使用同一集合，不改变模型、网格、缓存、取消代次或版本 2 的原路径。

资源导入与更新仍校验完整模型、全部声明和 PNG。运行期不取某张图片不构成省略导入校验的理由，也不表示旧运动重新支持。

## Alternatives considered

- 按 motion/profile 名称筛除：名字没有唯一用途，不能保证共享原画保留，未采用。
- 只加载当前可见站姿：破坏后续坐姿、睡觉与换装，未采用。
- 删除旧网格或加入全局图片缓存：增加父子注册和账号／Workspace 生命周期风险，不在此范围。

## Consequences

本地归档样本减少 profile_head、joint_arm、joint_leg 三张独占图片，共 677888 像素；RGBA 基础输入估算约 2.586 MiB，含近似 mipmap 为 3.448 MiB／人物 GL 实例。这不是实际驻留显存测量，也不能证明 tile memory 警告根因。动态五官画布上传和其他资源开销没有改动；正式素材与 App 未更新。
