# Agent Note: 转场相邻普通切镜保留预览画面

Status: implemented

## Problem

播放器身份判断把“任一片段参与任一视觉转场”当作当前接点有转场。A → B 使用旋转模糊时，B → C 的普通切镜也被拆成独立播放器；C 加载和定位期间，B 的画布被卸载，露出底轨或背景。

只读核对「【牧铃】若不是你突然闯进我生活」revision 36：前一接点 12.894736s 使用 1s 旋转模糊，截图所指 22.866438s 接点没有转场，前段结束与后段开始精确相等，且切换到另一个素材。该接点符合错误重建播放器的条件。

## Decision

`previewVideoPlaybackKeys` 仅在视觉转场的 fromClipId、toClipId 分别匹配当前相邻两个片段时分离播放器。转场实际伙伴保持独立，转场前后的普通切镜继续复用已有播放器和画布。素材变化沿用既有源定位与帧发布校验，在新帧就绪前保留有效画面。

官方操作指南与技术说明同步明确相邻转场不改变普通切镜的显示缓冲生命周期；导入包随正文重新生成。工程数据只读诊断，不修改真实项目。

## Alternatives considered

- 预加载下一段：可以减少解码等待，但无法解决当前接点错误销毁画布的原因，也不能覆盖任意加载延迟。
- 对所有片段复用一个播放器：视觉转场需要同时显示两段，必须保留实际伙伴的独立解码器。

## Consequences

保留既有空隙清空、源跳剪定位、真实黑帧与视觉转场语义。没有新增持久状态、网络请求、公共接口或迁移；等待中的画面沿用现有最后有效帧保留机制。

## Verification

组件回归覆盖转场后的普通素材切换保留相同 video 与 canvas、定位成功前不发布新帧，以及转场前普通接点复用和实际伙伴分离。浏览器回归在隔离数据目录中通过正式 API 建立 A → B 旋转模糊、B → C 普通跳剪，采集红蓝有效源帧并核对播放器身份和画布不透明度。

347 项视频编辑器测试、5 项官方文档测试和 Chromium 浏览器回归通过。Web lint、修改文件格式、导入包 stale-check、Agent Note 树/格式/归档及文档中心保护检查通过。完整构建在未修改的 `web/src/features/thought-workshop/tableColumnResize.ts:466` 因编辑器 attributes 返回值不符合字符串索引类型而失败，未进入 Vite 构建阶段。
