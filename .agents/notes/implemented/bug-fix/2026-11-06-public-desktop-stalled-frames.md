# Agent Note: 公网桌面画面缓冲和断开诊断

Status: implemented

## Problem

公网转接收到图块后等待 guacd 的同步指令。同步迟到时，已收到的图块也停在 FPL 内存中。断开日志共用一个错误，难以区分 guacd 读失败、浏览器退出和授权复核失败。并发写入让工作台来源扫描碰到 SQLite 锁时，错误处理还会立刻尝试写失败回执。

## Decision

在字节上限之外限制图块的缓冲时间。首批最多等两秒，后续批次最多等 250 毫秒。到期压缩已收齐的图块，按原顺序发送，正在接收的图块保留原始指令。浏览器请求断开由转接主动结算。断开日志记录路径、协议状态码、图块及同步间隔和压缩耗时。授权存储失败关闭连接并单独记录，避免将数据库异常当作权限有效。

工作台扫描遇到 SQLite 忙时保留来源状态及排队回执，按已有退避间隔再次校准。回执在事务入口申请写锁，再核对归属和修订。

FPL 在 guacd 握手完成后每五秒发送本机保活。浏览器 ping 只用于测量 WebSocket 活动，回显受阻时本机保活仍可继续。保活随会话清理，并独立记录浏览器 ping 和已发送的保活数量。

## Alternatives considered

- 完全取消图块压缩会增加已完整收到的大批更新的公网流量。
- 延长浏览器超时无法缩短已经收到的图块在转接内的等待时间。
- 把首批图块的最长缓冲延长至八秒，在真实公网复测中首屏数据量仍约八 MB，因此保留两秒上限。

## Consequences

超时的更新仍可能包含尚未完成压缩的图块，浏览器使用 guacd 的真实同步指令呈现更新。断开日志只包含协议类别和数值。单个 SQLite 写者通常可与授权读并行，授权存储不可用时连接仍关闭。

## Verification

- 隔离转接测试在图块传输中途延迟同步，验证已收到的指令按原顺序发出，后续数据可继续读取。
- 隔离网站测试验证持有 SQLite 写锁期间本地及公网模式仍可打开桌面、转发键盘输入和复核注销。
- 工作台存储测试在竞争写锁期间保留回执，并在锁释放后完成扫描。
- 隔离网站测试在浏览器未发送任何指令时，确认 guacd 收到 FPL 发出的保活。
