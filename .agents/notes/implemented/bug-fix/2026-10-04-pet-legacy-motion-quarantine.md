# Agent Note: 停用已确认失真的旧人物运动路径

Status: implemented

## Problem

正式红莉栖版本 1 人物资源在攀爬时将独立缩放的侧头与正面身体混合，站姿切片旋转产生碎袖与比例突变。用户实际截图、只读正式资源副本及生产渲染器复现一致。此前新素材诊断没有覆盖正式 App 正在使用的资源，因此不能代表实际运行质量。

配置保存还只更新编辑器快照，已打开桌宠没有收到基线更新；文件夹标为实验室或女仆的第一轮隔离录像实际都是经典服饰。运行页长提示框遮挡了头部，进一步阻碍视觉核查。

## Decision

版本 1 人物包继续可读，但关闭旧切片／独立侧头的运动拼接与自主运动，恢复原完整站姿、坐姿、五官及换装。手动窗口移动保留，运行状态与试玩明确提示需完整动作资源；不写回用户已保存走动习惯，不自动更新包或启动新桌宠。缺失能力由 motionAvailability 的明确输入判断，渲染器通过公开失败接口反馈，控制器取消轨迹及在途请求。

编辑器 CAS 保存成功后，经既有可信角色编辑器私有桥通知同账号、Workspace 和项目桌宠重新读取已保存基线。通知失败显示保存成功但刷新失败，不重试 CAS 或声称保存失败；运行中的临时换装和走动档位继续独立。旧资源降级提示使用顶部短状态及完整无障碍名称，保留打开应用按钮，避免遮住角色。

## Alternatives considered

- 继续调旧侧头尺寸和切片旋转：无法恢复缺失的完整身体视角与袖口遮挡。
- 立即应用新候选：独立完整图检查仍有手臂过长和比例差异，违背视觉验收后才能正式应用的要求。
- 关闭手动拖动或将走动设置写成关闭：损害已有可用交互和用户默认偏好。
- 通知失败时重新保存：CAS 已成功，重试会产生重复提交或冲突。

## Consequences

旧包会保持原姿态，无法演示新版运动；这是已确认失真路径的临时降级，不能称行走、拎腰或四边爬行动作修复完成。完整计划和新资源仍在 proposed Note 中。无需数据库 migration、公共运动接口或真实模型调用。

## Verification

只读副本的旧 GPU 攀爬复现失败；停用旧路径后的三服饰 183 张采样及 45 个真实编码切换帧由独立 Agent 检查，完整站姿未见旧比例／碎袖问题。Chrome GPU 诊断与真实 Electron 窗口验收分别记录，不混淆。隔离 Electron attempt3 的服饰覆盖结论已撤回；attempt4 验证保存后实际三服饰、无自主移动、真实窗口手动拖动、坐姿联动与聊天暂停，具体画面与源帧频率以 ignored live-resource-audit 的独立报告为准。无正式 CAS 资源更新或 App 重启。

组件检查覆盖旧包暂停但可手动拖动、资源刷新不打断聊天、失败轨迹停止及成功保存／通知失败不重复 CAS。全仓质量检查中的并行思绪工坊错误及已有受保护文档变更单列保存，不覆盖其他任务改动。

本轮最终独立录像复核已完成：9 张窗口图、340 张真实源帧，限于站姿降级及手动移动。视频平均 47–58 fps，最大间隔 41／35／42 ms，严格连续 30 fps 条件不通过。最新 Web 桌宠 336、后端桌宠 210、Desktop 43 项通过；全仓并行错误和既有文档保护失败保留。正式应用尚未进行。
