# Agent Note: 原生编程 CLI 登录检测

Status: implemented

## Problem

Pi 的登录探测漏传供应商或模型，命令因此退出。OpenCode 的凭据查询执行失败时，也显示为未登录。命令分多次写入标准输出时，FPL 只读取第一段，可能漏掉 OpenCode 的凭据数量。

## Decision

Pi 在已有的隔离配置中检查默认供应商。没有默认供应商时，检查已配置的供应商，或在只有默认模型时按模型检查。使用不刷新凭据的模式，区分缺少认证和命令错误。Pi 启动前拒绝通过外部命令获取凭据的配置。OpenCode 使用纯模式读取凭据列表，分别报告空列表和检测失败。控制命令在现有超时和大小限制内读取完整输出。

## Alternatives considered

- 只检查 Pi 凭据文件是否存在，无法确认其中的凭据适用于所选供应商。

## Consequences

已安装的 CLI 保留版本信息，管理员可以根据登录状态或探测错误完成接入。

## Verification

- 原生 CLI 回归测试覆盖三个连接在启用前的状态，检查 Pi 调用参数，并区分 OpenCode 的空凭据列表和探测失败。
