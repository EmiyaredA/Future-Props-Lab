# Agent Note: Codex 压缩记录与工作台入口核验

Status: implemented

## Problem

Codex 的实际会话记录可能使用 `.jsonl` 文件名保存 Zstandard 数据。按扩展名选择解码器会遗漏这些历史，近期少量未压缩记录通过抽样不能证明完整来源可读。用户的桌面窗口还可能来自已冻结的旧源码，当前仓库存在应用注册也不能证明运行窗口可见。

## Decision

只读记录读取器在 UTF-8 解码前检查 Zstandard 文件头，同时兼容原有压缩扩展名。原生文件不解压、不重命名、不迁移，仍使用原来的完整记录边界与增量检查点。原生图片记录实测可超过 20 MiB，单条读取使用 64 MiB 上限，仍按批限制 I/O；普通日志通过 seek 恢复，不套用压缩展开累计限制，压缩流继续保留 256 MiB 展开限制。Codex 的归档判断同时考虑显式绑定的来源根与记录相对路径，避免直接绑定归档目录时丢失归档状态。

Codex 名称索引只在显式授权根内只读解析，用于标题和原端改名，不进入正文。适配器复制原检查点中的元信息再构造新状态，避免仅标题变化时修改调用方的旧检查点、导致增量提交被误判为无变化。

浏览器验收从应用中心的开发辅助分类进入工作台，再验证阅读与来源页面。正式窗口切换先核对实际进程源码根和登记迁移，正常退出后持有数据锁、完整备份并验证，再由登记入口迁移；刷新旧源码不作为上线方式。

## Alternatives considered

- 要求用户重命名或解压记录：改变原工具拥有的存储，违反只读边界。
- 仅抽样最近未压缩会话：无法发现旧记录的格式差异。
- 在旧开发窗口直接刷新：仍加载旧来源树，无法提供新入口和数据库结构。

## Consequences

压缩标识不再依赖文件后缀。读取成本和解压上限保持既有约束；真机抽样只保存格式、数量与来源证据，不保存聊天正文。Pi 尚未使用时保留真实空态；原生 HTTP 实例要求认证时使用其已明确绑定的本机存储，不关闭上游认证。

## Verification

`tests/test_agent_workbench.py` 验证从账号 schema 升级时原有数据和迁移记录不变，验证保留 `.jsonl` 后缀的压缩归档、追加压缩帧和增量读取，以及原生索引改名、内嵌大图片与普通日志分批越过压缩展开阈值。`web/e2e/agent-workbench.spec.ts` 从应用卡片进入，覆盖阅读、来源授权、主题切换当帧、四种宽度与键盘操作。

真机核验、正式切换回执和完整门禁结果保存在 `.local/agent-workbench/release/`。真实 APP／CLI 活动、完整链路延迟与隔离夹具结果分别记录，不用格式测试代替原生实例验收。
