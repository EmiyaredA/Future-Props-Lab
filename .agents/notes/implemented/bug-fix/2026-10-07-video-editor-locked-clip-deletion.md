# Agent Note: 锁定片段删除在提交前拦截

Status: implemented

## Problem

工程 revision 1391 的“画面 1”确实 locked=true。删除按钮仍把该轨的 removeClip 发进保存队列，后端正确返回 track_locked，但本可在本地识别的失败使整个队列暂停，并清除了片段选择。关联片段所在轨道锁定也受同一后端校验约束。

## Decision

`timelineSnap.ts` 提供 `clipDeletionLock`，通过既有关联组解析查找本次删除涉及的锁定轨道。`VideoEditorTimeline` 的共用删除入口在构建操作前检查，显示具体轨道名称和解锁提示，保留选择，不调用 commit。工具栏删除、波纹删除与右键删除共用入口。后端权限、锁定、版本校验和保存失败保护保持不变。

## Alternatives considered

自动解锁会修改用户设置，绕过锁定保护。忽略后端错误或自动重放删除不能确认用户意图和最新服务器快照。只禁用工具栏按钮会遗漏右键入口，也不能解释关联轨道为何阻止删除，因此采用共用入口的提示与拦截。

## Consequences

锁定删除不再造成可预判的保存失败；真正发生并发变化时仍可能由服务器拒绝。已有失败队列需要用户核对并放弃未保存操作后，再解锁重做，不自动丢弃或重放。真实工程只读诊断，不改变轨道锁或删除任何真实片段。

## Verification

三个入口分别覆盖目标轨道锁定、关联轨道锁定、提交未调用、选择保留、具体提示以及解锁后可以提交。官方操作指南补充现有失败队列的恢复步骤。
