# Agent Note: Thought 块菜单与图片设置的定位和焦点

Status: implemented

## Problem

首次悬停正文块时，拖拽按钮会落入固定顶栏，鼠标无法打开块菜单。已选图片在编辑宽度并跨过预览尺寸阈值时会立刻更换预览请求，导致仍在操作的图片设置面板被卸载。

## Decision

块拖拽按钮使用组件原生的绝对定位，使首次测量和最终定位共用编辑器容器坐标。已选图片在操作期间保持选中前的预览尺寸，取消选中后按新的显示宽度选取清晰度。原图裁剪继续通过独立的原件读取路径。

## Alternatives considered

- 把拖拽按钮移到固定顶栏上方。按钮仍会脱离实际正文块，滚动时会覆盖导航。
- 修改通用鉴权图片 Hook 以跨请求保留旧 Blob。当前问题只发生在 Thought 图片编辑期间，通用 Hook 保持已有的取消和资源释放契约。

## Consequences

首次点击会打开目标块的菜单。宽度提交时设置和键盘焦点保持可用。编辑放大图片期间沿用当前预览，取消选中后更新清晰度。

## Verification

隔离 Chromium 通过 `thought-block-editor.spec.ts` 和 `thought-image-toolbar.spec.ts` 共 7 项。覆盖首次悬停点击、插入引用、Enter 提交宽度、设置焦点、选中态裁剪，以及图片滚出内部正文区域后的工具栏隐藏与恢复。
