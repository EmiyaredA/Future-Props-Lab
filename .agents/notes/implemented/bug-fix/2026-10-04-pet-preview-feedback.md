# Agent Note: 桌宠预览能力反馈与保留草稿的重启

Status: implemented

## Problem

当前人物资源停用被拒绝的旧动作后，事件菜单仍允许选择张望、跳跃等动作，画面不响应却缺少针对当前选项的反馈。独立桌宠的大提示条遮挡编辑器舞台，能力提示和临时联动状态重叠。启动桌宠隐式保存草稿，使用户只想重开窗口也会推进项目 revision。

## Decision

`playback.ts` 根据实际动画模式和当前资源统一判断事件动作及表情能力；菜单保留已有值，缺失选项禁用并给出原因。整帧资源没有独立表情时不宣称支持附加表情，未接通的多阶段动作不因存在同名片段而开放。桌宠收件端也验证演示能力，失败反馈到编辑器；不只依赖按钮禁用。

`EditorStage.tsx` 保留唯一角色实例和原回调，用标题、状态及事件／动作／表情标签表示当前检查内容。棋盘背景使用主题变量，能力提示与联动开关位于舞台外。设计图中的缩放、时间轴等尚未接通的控件不进入产品。

`EditorHeader.tsx` 提供无状态导航与操作入口，`EditorPage.tsx` 分别编排 CAS 保存和窗口生命周期。启动、试聊及重启不隐式保存；重启先释放联动、关闭独立窗口，再读取保存基线重开。关闭成功而重开失败时保留草稿并允许再次打开，不重复 CAS。

独立桌宠的能力、联动和错误信息集中在可键盘展开的紧凑状态区；该区参与透明命中但不触发角色拖动。原站姿、表情、换装与手动移动保持原有范围，未通过视觉验收的新素材仍不进入正式资源。

## Alternatives considered

- 恢复旧拼接动作：会重新暴露已拒绝的人体扭曲，不能解决素材问题。
- 只禁用编辑器按钮：私有桥仍可能收到无法演示的请求，因此收件端必须复核。
- 启动前自动保存：窗口重开不表达持久化意图，未保存保护和 CAS 保存必须保持显式。
- 按设计图加入所有装饰性控制：缩放和时间轴未实现，不能提供无反馈的入口。

## Consequences

用户能区分未配置、当前资源缺失与通信失败，启动或重启不覆盖草稿。未提供合格新动作的包仍不能演示行走、拎起或四边攀爬；能力反馈修复不等于动作素材验收。没有新数据库 schema 或公共 API，也不应用并行任务尚未定稿的迁移。

## Verification

`web/tests/desktop-pet-editor.test.tsx` 覆盖草稿打开／重启及关闭后重开失败不保存；`desktop-pet-event-capabilities.test.tsx` 验证真实旧人物绘制和整帧能力；`desktop-pet-runtime-baseline.test.tsx` 验证收件拒绝、状态可达及重开保存基线。相关编辑器、联动、序列帧测试与 `web/e2e/desktop-pet-ui.spec.ts` 检查明暗主题、窄屏和菜单。实际 Electron 已关闭并重开同项目桌宠，编辑器仍显示未保存修改；未调用模型或写入正式项目。此次 UI 预览图、日志与隔离验收产物位于忽略的 `.local/desktop-pet/ui-redesign/`，最终质量检查结果在其中单独记录，并行失败独立列出。
