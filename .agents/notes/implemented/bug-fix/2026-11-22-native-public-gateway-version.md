# Agent Note: 热加载网关的公网探针标识

Status: implemented

## Problem

独立网关 CLI 从 `FPL_SERVICE_VERSION` 读取 `/build.json` 的构建标识，容器通过镜像环境提供该值。
原生热加载未提供此环境，Studio 与管理端均返回 `development`，不符合公网隧道要求的 20 位十六进制格式。
因此 `npm run dev -- --public` 在本机网关探测阶段退出，尚未创建 SSH 隧道。

## Decision

原生装配为 Studio 和管理端网关分别生成每次启动独有的 20 位十六进制运行标识，
显式传入其 `FPL_SERVICE_VERSION`，覆盖容器环境可能携带的旧值。
同一启动周期的源码重载复用该标识；新启动生成新标识，避免与另一实例混淆。
正式镜像构建标识、前端契约快照和公网探针的格式／匹配校验保持原契约。
公网子进程退出时，启动器同时提示具体日志路径。
SSH 在握手阶段退出而未匹配凭据拒绝等终止条件时，隧道显示 reconnecting 和固定的连接关闭／握手超时提示，
继续既有退避重连，不将服务长期显示为 connecting，也不记录原始 SSH 错误中的敏感内容。

## Alternatives considered

- 允许 `development` 通过探针：不能区分实例，也放宽了正式公网校验。
- 固定写入一个合法字符串：只解决格式，不能识别过期或错误的网关实例。
- 每次 Python 重载重新计算源码指纹：引入不必要的隧道版本变化，重载期间仍是同一套热加载服务。

## Consequences

热加载网关的 build_id 表示本次运行而非正式发布版本，源码变化仍由现有热加载机制管理。
只改变子进程环境，不修改正式配置、持久数据库或迁移账本。

## Verification

- 隔离装配同时覆盖 Studio 与管理端，将实际生成的子进程版本传入真实 `GatewayTunnel.check`，验证本机和公网探针契约。
- 验证不同启动的标识不同、Compose 原环境与数据库哨兵不变。
- 相关启动、隧道、网关契约及独立网关回归通过；隔离 Caddy/Vite 页面与 HMR 代理测试通过。
- Python 静态／格式、Agent Note 和文档中心保护检查通过；失败实例的监听端口已释放。
- 用户明确授权后临时实测，本机构建探针返回 200 且产生有效标识，不再因 development 退出。
- 云端 HTTPS 返回 502；SSH TCP 可建立，但在 banner 交换前关闭或超时，尚未进入密钥认证。
  临时服务与诊断隧道均已停止，真实公网连通性仍受云端 SSH 连接故障影响。
