# Agent Note: 完整原帧过渡共享区间与容器边界

Status: implemented

## Problem

每个已绘步相都需要对应收步、转向或转角原画。按每个来源帧创建独立片段会过快耗尽现有 64 片段预算；共用一条未经登记的通用收步又会改变承重和姿态。拼接多个收步到同一计时片段后，必须防止播放无关前后缀、误用局部索引、提前释放支撑或把整个过渡池当作普通动作。

## Decision

既有私有 frameSequences v1 的分支增加可选 range=[start,end]，使用已有非循环、无距离驱动的计时片段。显式区间为左闭右开，整数且非布尔，至少两帧且不越界；缺省仍播放整个片段，保留旧单帧桥。首尾原画及全部锚点严格匹配对应实际来源帧与目标首帧，来源索引仍完整覆盖。前后端不放宽端点、头部比例、PNG、ZIP、模型 JSON 或片段／帧预算。

输入经既有资源导入与 CAS 校验，所有服饰继续使用已授权的素材闭包。Web reader、能力判断、播放器和图集选择共用区间解析。播放器从区间自身时长和开始索引推进，向外反馈原片段绝对索引；取消保留当前局部位置，不追赶旧时钟。选中区间以外的前后缀不参与计时、结束判断或支撑释放。图集只解码所选区间、目标及实际已绘帧需要的素材，像素预算按每个被引用 PNG 的完整尺寸计算。

任何被部分区间引用的片段都推断为过渡容器，不能是 idle、transition.to 或普通动作。它仍可提供经过校验的分支，或作为已在播放时被打断的实际来源。显式全长区间和缺省不改变旧片段用途；不添加 mode 字段。能力判断也排除规范名称的容器，不能宣布不能播放的边缘姿势。draw 在解码前拒绝裸播，并保留明确原因，不被物理 stride 校验覆盖。

没有数据库 schema、公共 REST／运动 API 或 SDK 形状变化；模型仍是既有原始字典。没有临时配置写回、自动保存、正式资源安装或 App 重启。

## Alternatives considered

- 提高 64 片段或 JSON／图片预算：没有必要，也不能解决过渡池误播，未采用。
- 多段尾部作为普通 clip 直接循环或按当前目标选择：会播放其他来源步相，拒绝。
- 在总前缀时长上累计后从索引零逐项相减：独立复查用合法 0.1、0.1、1.1 ms 前缀复现浮点残差选到区间外帧，改为局部时钟及起点索引。
- 增加 cels 引用注册表：做过容量估算，但本次未实现；共享区间不代表完整四边最终包已满足 JSON 或 PNG 预算。

## Consequences

合法三服饰数值包中，37 独立片段可减少为 9，共 97 登记帧、32 来源分支，保留每个区间首尾。来源与目标原画必须实际制作；共享区间不能生成中间帧、修复人体比例或绕过稳定支点要求。过渡途中打断仍需要当前实际片段到新目标的直接资源。
