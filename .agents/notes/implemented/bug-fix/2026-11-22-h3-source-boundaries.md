# Agent Note: H3 正文删除与隐藏结构边界

Status: implemented

## Problem

结构化编辑器将显示光标映射到原文后，Backspace、Delete 和跨段替换仍可能改掉未显示的字段名、必需换行或对白结束标记。字段名一旦损坏，重新换行也不能恢复原有主体定义。用户截图已有 `subject_definition:`，导致主体标签失去定义。

## Decision

由 `h3SourceEdits.ts` 从纯解析结果显式计算隐藏结构范围。字段名及两侧最少换行、已收起的前言和 `<d>`／`</d>` 不属于普通可见正文；删除、剪切和部分选区替换保留这些范围。对白末尾的字符删除越过隐藏结束标记，作用于可见文字。整篇全选替换与清空仍可执行，完整协议编辑继续使用普通文本模式。

解析器精确兼容用户已有的 `subject_definition` 单数标题，映射到已有主体小节，只用于展示识别，重组、复制和保存不自动改写原始字段名。不使用模糊拼写修复或语义猜测。

这细化[H3 适配器直接编辑](../feature/2026-11-22-h3-adapter-direct-editing.md)的原文事务边界，不改变模型接入或持久化协议。

## Alternatives considered

- 只增加标题别名：能修复现有显示，不能防止再次误删结构。
- 每次输入重新生成标准化提示词：会擅自改变用户原文。
- 禁用正文删除：影响正常编辑，改为只保护不可见结构。

## Consequences

正文光标保持 UTF-16 偏移。源事务是纯函数，可独立验证；既有引用原子边界和字符删除规则保留。普通文字编辑不受结构保护约束，全选粘贴可以替换整个提示词。无新增 API 或数据迁移。

## Verification

组件测试覆盖无冒号、冒号和 CRLF 标题后的反复 Backspace、段末 Delete、跨小节替换、随后 Enter 及输入、对白结束处删除、全选替换，以及已有单数标题的恢复展示。浏览器通过隔离项目确认重复删除及重新换行后的主体、图片引用和保存原文保持正确，证据位于 `.local/h3-rich-rendering/`。
