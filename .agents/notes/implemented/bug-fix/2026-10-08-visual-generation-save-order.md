# Agent Note: 视觉生成前完成当前画布保存

Status: implemented

## Problem

节点草稿、连线更新在 React 状态 updater 内入队保存。生成处理器同步调用草稿保存与画布准备，但 React 可以延迟或重放 updater，导致准备阶段先返回旧 revision，随后本地保存才递增 revision，生成请求触发画布版本冲突。自动保存完成或立即保存取消计时器后未清空句柄，还会在准备阶段再次保存。等待期间新增的保存也可能未被初次取得的 Promise 覆盖。

## Decision

节点和连线更新先同步读取、发布本地快照并登记撤销历史和保存队列，再以普通状态赋值更新界面；状态 updater 不执行保存副作用。统一的保存调度在取消或触发计时器时清空句柄，延迟保存从最新节点与连线快照取值。草稿变更立即显示保存中。

画布准备反复等待当前保存队列并冲刷新增的延迟保存，直到队列稳定后返回 revision。真正的 CAS 冲突与网络保存失败仍阻止提交、保留本地草稿，不自动覆盖外部版本或重提模型任务。公共 API 与后端校验保持现有契约。

## Alternatives considered

- 在提交前固定等待一段时间：依赖渲染和网络速度，不能保证保存完成。
- 收到 409 后自动刷新并重试生成：可能丢失草稿或覆盖外部变化，也会把模型提交重试隐藏在交互内。
- 移除后端 revision 校验：无法保证生成使用的上游素材和画布快照一致。

## Consequences

看板、画布以及共用准备入口的生成和 Agent 操作使用完成保存后的版本号。同一事件中的多次节点、连线修改不依赖 React 的渲染时机。持续编辑会延长准备阶段的等待；提交之后发生的外部变更仍由后端 CAS 拒绝。

## Verification

`web/tests/features/visual-workshop-canvas-persistence.test.tsx` 在 StrictMode 下覆盖同一事件保存与准备、计时器清理、节点和连线连续更新、等待期间的新修改、真实冲突与网络失败。修复前四个核心用例全部失败，修复后通过。相关生成、画布、撤销、连线、剪贴板、助手与看板共 77 项组件测试通过。

`web/e2e/visual-workshop-generation-save.spec.ts` 使用临时隔离数据库与正式画布 API，延迟保存并在模拟模型提交时核对服务端 revision 和草稿提示词。看板与画布两个入口验收通过，不调用真实供应商。Web lint、格式检查与生产构建通过；Agent Note 树、格式与归档封印检查通过。
