# Agent Note: 代理虚拟 DNS 下的生成结果下载

Status: implemented

## Problem

供应商已完成的视频结果域名在 Models 容器内间歇解析为 `198.18.0.0/15` 和 `2001:2::/48` 的代理虚拟地址。下载器正确拒绝这些非公网 IP，却无法恢复正常公网结果，用户只看到生成失败。原下载过程在地址检查后再次按域名建立连接，也不能保证实际连接使用已检查的地址。

## Decision

结果地址验证返回可连接的公网 IP。仅当非本地域名的系统解析包含上述代理虚拟地址，且没有其他私网答案时，通过固定公网 IP `1.1.1.1` 的 HTTPS DNS JSON 接口核验 A/AAAA。解析请求只发送域名和记录类型，不发送素材路径、签名查询参数或供应商凭据。TLS 校验开启，响应有大小与超时上限，解析重定向不跟随，失败继续拒绝。

下载直接连接核验后的 IP，保留原 Host、TLS SNI 与证书验证，每次重定向重新核验。普通公网解析不使用外部 DNS 回退；私网、回环、链路本地、组播、混合私网答案和虚拟 IP 字面量不放行。恢复仍使用原任务的正式结果落盘重试，不重新生成。

## Alternatives considered

- 放行虚拟地址或按供应商域名跳过检查：削弱私网访问防护，拒绝。
- 修改机器或所有容器的 DNS／代理规则：影响其他服务，且代理可能继续接管普通 DNS，未采用。
- 校验真实解析后仍按域名连接：会再次受到虚拟 DNS 或重绑定影响，未采用。

## Consequences

代理虚拟解析的恢复增加对 Cloudflare HTTPS DNS 的依赖；其不可用或答案不安全时明确失败，不回退到非公网连接。HTTP 环境代理不参与结果或解析请求。此变更不修改公开 API、任务身份、计费提交、数据库结构或原任务输入。

## Verification

确定性测试覆盖虚拟 IPv4/IPv6、公私混合、本地域名、IP 字面量、解析错误与超时、响应上限、私网重定向、相对重定向、签名路径保留及 Host/TLS SNI 固定；同时运行既有下载、供应商任务和结果恢复测试。真实 Models 容器独立进程验证可信公网解析和固定 IP 的原域名 TLS 连接成功，存储根路径按预期返回 HTTP 403，未关闭证书或私网校验。

相关行为与架构检查通过 97 项。正式 Models 经 Agent 空闲门禁切换，运行时核验两个模块的摘要与候选一致；原结果下载失败的已完成任务通过同一结果恢复入口转为完成并返回素材，未重新提交供应商生成。最小发布只增加两个只读代码挂载，正式副本、原 Compose、摘要与回退脚本保存在被忽略的 `.runtime/deployment/releases/`，不改数据库或凭据。
