# Agent Note: 飞书知识库文档链接

Status: implemented

## Problem

在飞书知识库中新建或打开新版文档时，浏览器地址是 `/wiki/{节点标识}`，并常带 `create_from=create_doc_to_wiki` 等查询参数。文章同步把这种链接判为请求参数无效，用户无法检查或绑定已经授权的文档。同步目标仍然必须是新版 docx；知识库地址只是定位符，不能当作对外请求的主机。

## Decision

`/docx/{文档标识}` 与 `/wiki/{节点标识}` 都只提取标识并规范化，查询参数不进入后续请求。检查和绑定时，知识库节点通过飞书开放接口 `GET /wiki/v2/spaces/get_node` 解析为 `obj_token`。仅当 `obj_type` 为 `docx` 时继续读取和授权检查，绑定保存解析后的 `/docx/` 地址和文档标识。服务器只访问 `open.feishu.cn`。链接语义错误直接返回说明，不再被通用的参数校验文案覆盖。此决定补充 [外部连接与飞书文章同步](../feature/2026-10-08-external-article-sync.md)，不改变同步目标仍是已有 docx 这一约束。

## Alternatives considered

- **继续拒绝知识库链接并只改进错误文案**：能解释失败原因，但知识库是飞书文档的常见地址，用户仍要手动寻找另一条链接。
- **把用户粘贴的主机当作请求地址**：可以跟随租户域名，但会把外部链接变成出站目标，破坏现有的固定 API 域名边界。

## Consequences

- **收益**：知识库中的新版文档可以用复制到的链接完成检查和绑定；解析后的文档标识与直接粘贴 `/docx/` 链接共用同一绑定。
- **代价与已知上限**：应用需要知识库节点读取权限，并且这篇节点已把应用加为可编辑的文档应用。错误码 131006 在同步侧栏给出打开文档、开通「查看知识空间节点信息」和开启机器人的入口；错误码 99991672 先指向权限页。旧版文档、表格和其他节点会明确拒绝。未使用真实飞书凭据验证租户权限开通后的首次解析。

## Verification

隔离测试覆盖用户粘贴的知识库链接规范化、解析为 docx、绑定身份、非 docx 节点、131006 与 99991672 的可操作说明且不回传供应商原文，以及非法链接在出站前失败并返回具体说明。组件测试确认检查后绑定的是解析结果，并确认权限失败时文档链接与开放平台入口指向当前连接和所粘贴的节点。
