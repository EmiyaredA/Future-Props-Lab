# Agent Note：候选图保留当前与历史采用图

Status: implemented

## Problem

设定卡候选列表只读取候选素材及生成结果，独立保存的采用图不在其中。用户采用另一张候选并保存后，旧采用图没有加入候选集合，其素材归属也从卡片记录移除，导致无法再从该卡选择原图。

## Decision

编辑草稿初始化时把缺失的采用图补入候选集合，对已有集合保留顺序并按 ID 去重。切换选择保留选择前的完整集合，只改变采用标记；所有入口仍需显式保存。只读卡片也显示当前“已选中”状态。

服务端在已完成账号校验与 revision 比较的 prepare_card 上下文保留旧采用图及其原有素材归属，防止旧网页、SDK 或其他调用方遗漏它。保留后超过 80 张时整次拒绝，不截断或部分提交。候选任务的外部读取继续位于事务外，旧采用图的归属来自当前锁定的账号卡片快照，不增加跨应用私有存储读取。

项目图复制入库后同步候选 ID。刷新后，已完成任务仍指向项目原件时，通过现有账号文件内容身份接口核验是否为已保存候选的副本，再归一显示；不按名称或外观猜测。不删除原文件或改写任务历史。副本核验等待期间保留已保存的候选；失败时仍可显示未能归一的原件，不隐藏已有图片。

## Alternatives considered

仅在候选区补显示采用图不能防止下一次保存丢失旧图。仅靠前端保留无法覆盖其他写入入口。回退用户当前选择会覆盖用户已确认结果，因此数据恢复仅增加有明确快照依据的候选关联。

## Consequences

复用现有 candidate_asset_ids、adopted_asset_id 和更新接口，无数据库迁移。更换或清空采用图不再隐式移除原图。历史恢复通过正式 SDK，用受影响卡片的快照、版本和回执恢复关联，不直接写数据库。

## Verification

隔离后端覆盖三类设定的采用切换、清空、去重、容量失败、版本冲突及账号隔离；前端覆盖完整列表、顺序、只读选择状态与项目原件副本核验。浏览器旅程覆盖三类卡切换、失败恢复、保存、刷新后再次选择原图及取消未保存修改。

后端相关测试 16 项、前端相关测试 20 项通过；三类卡的完整浏览器旅程 1 项通过，截图保存在 `.local/card-candidate-retention/run.080HLn/results/`。TypeScript、Web ESLint、相关 Python Ruff 和格式检查通过。

按拆分时保存的确切卡片和素材 ID 盘点 148 张卡片，确认铃羽、红莉栖的 Q 版猫耳女仆各遗漏一张原采用图。正式 SDK 补回两处关联后分别恢复 4 张、5 张图片，保留用户当前采用图、卡片 ID、语音和归组，28 个现有项目的画布摘要与修复前一致。恢复快照及回执位于 `.runtime/card-candidate-recovery-20261122/`；临时测试和诊断位于 `.local/card-candidate-retention/`。

完成后的只读复核再次确认卡片关联；其中一个项目随后发生独立画布更新，保留该更新并记录在 `recheck.json`。本次恢复没有调用任何画布写入接口。
