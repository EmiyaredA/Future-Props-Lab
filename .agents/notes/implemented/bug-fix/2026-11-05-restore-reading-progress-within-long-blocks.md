# Agent Note: 恢复长段落内的阅读进度

Status: implemented

## Problem

刷新同一篇社区文章会跳回上次所在段落的顶部。长列表和其他高段落可能占据多屏，按段落起点恢复会丢失段内位置。Chromium 在官方技术文章中记录约 53% 的位置，刷新后只恢复至约 3%。

## Decision

阅读位置使用已有的正文修订号、相对滚动进度和段落文本。同一修订直接恢复相对进度，正文变更或旧记录缺少修订号时优先按文本找回原段落，找不到时回退到相对进度。显式链接定位继续优先。

## Alternatives considered

- 保存段内像素偏移。该方案需要扩展读写契约与已有记录，在不同视口和字体下还要重新换算偏移。

## Consequences

同一修订的长段落保留段内进度，旧版阅读记录继续可用。不同视口下按相对进度近似恢复，正文变更时仍可跟随文本。

## Verification

`thought-completion.spec.ts` 的社区官方文章用例在隔离 Chromium 站点通过。用例保存页面中部的进度，刷新后要求误差小于全文滚动长度的 8%。
