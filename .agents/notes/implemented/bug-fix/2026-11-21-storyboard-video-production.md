# Agent Note: 分镜对应镜头视频

Status: implemented

## Problem

分镜被固定为图像制作后，已有的视频关联无法在分镜中打开，画布定位、缩略图和白模参考回填也指向了图片。
用户明确每个分镜应对应视频生成节点，需要统一产品含义与各入口。

## Decision

使用“镜头视频”表示分镜的视频制作对象，所有制作入口采用 `video_node_id`。
新建分镜准备视频节点及草稿，保留分镜显式保存；剧本选段新建镜头先准备并保存视频节点，再保存镜头关联。
剧本选段重试保留已创建标识，保存失败不重复创建。纳入与关联仅列视频，并避免重复分配当前分镜列表中的视频。
正文通过选区事件、键盘释放与鼠标释放共同同步选段，避免原生选区已变化但操作面板仍未更新。
旧图片关联原样保留；缺少视频时可补建或关联，已有图片输出作为补建视频的固定参考。
不自动批量调用模型，不改写既有视频草稿或输出；视频生成时长沿用模型参数，规划时长独立保留。

本决定取代[分镜固定图像与属性区收紧](../simplification/2026-11-21-storyboard-image-workspace.md)的图像优先规则，
保留其紧凑属性布局；[未关联分镜布局](../simplification/2026-11-21-unlinked-shot-layout.md)的双栏结构继续使用，制作对象改为视频。
旧 Note 保留历史决定，本 Note 作为当前约束。

## Alternatives considered

- 只改标题：不能解决实际打开和写入图片节点的问题。
- 清除旧图片字段：会丢失已有参考，不符合保留用户素材的要求。
- 自动批量生成所有镜头：会提交未经逐项确认的模型任务，修正节点关联无需触发生成。

## Consequences

分镜、画布、剧本交接和白模采用共享视频主关联。存储仍兼容两种历史字段，快照与迁移原样重映射。
没有有效视频的历史镜头显示可修复入口；现有账号项目数据的逐项审计因正式 API 403 和直连方式审批拒绝尚未完成。
遵循[能力实现契约](../../../../docs/architecture/capability-contracts.md)、
[开发与验证流程](../../../../docs/operations/development-workflow.md)。

## Verification

- 组件回归覆盖视频优先、图片保留、图片参考带入、只读、导入去重、新建节点、保存失败重试。
- 隔离浏览器验证视频生成编辑器、桌面和手机布局、提示词版本列表间隔、剧本交接和画布定位。
- 截图与隔离数据库位于忽略的 `.local/storyboard-video/`，未通过数据库修改用户项目。
- 39 个相关组件用例、两条浏览器旅程、TypeScript、ESLint、构建与包体预算通过；Agent Note 与产品文档中心保护检查通过。
