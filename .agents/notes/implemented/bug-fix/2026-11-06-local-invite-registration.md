# Agent Note: 独立网站本机邀请码注册

Status: implemented

## Problem

独立业务站和公网共用同一前端构建。构建模式隐藏了本机注册入口，独立身份传输却仍接受公网的注册请求，与旧网站只在本机开放邀请码注册的规则不一致。旧浏览器用例也仍在业务入口查找管理页面。

## Decision

本机业务监听器的 `GET /v1/auth/me` 响应通过 `X-Fpl-Invite-Registration` 标示注册入口可用，包括未登录的 401 响应。网站依据这个响应显示入口。独立 Identity 先核验网关及监听器，公网和管理端的注册请求返回 404。兼容网站沿用真实 socket 判定和公网阻断。管理浏览器用例通过真实管理监听器创建邀请码，再用独立浏览器会话从本机业务入口完成注册。

## Alternatives considered

- 按浏览器的 hostname 或构建模式决定是否显示注册。内外入口共用构建，监听器证明由服务端持有。
- 加入一个公开探测 API。会话探测已存在，附加响应头保留原有响应体、认证要求与操作 ID。

## Consequences

管理与公网入口继续使用各自权限边界。管理浏览器验收需由隔离启动器提供两个回环地址和测试账号。

## Verification

Identity 与兼容网站的边界用例检查本机 401、入口标示、伪造入口头和公网拒绝。管理 Playwright 用例使用真实 Compose 检查八个页面及管理员与业务会话隔离。

定向后端检查通过 12 项。以 `68da47b0` 为其余服务基线替换 Identity、Portal 与 Presentation 后，完整 Compose 的 49 项浏览器检查及 5 项独立管理浏览器用例通过。公网伪造本机入口头后注册返回 404，本机账号成功兑换且管理端能读回兑换记录。
