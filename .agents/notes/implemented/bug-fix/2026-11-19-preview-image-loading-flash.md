# Agent Note: 分层预览不绘制图片加载占位

Status: implemented

## Problem

节目监视器复用通用 `ResponsiveImage`。新挂载的图片在 `load` 回调之前进入加载态，通用样式为整个图片矩形绘制深色脉动底色。透明人物、眨眼和口型片段频繁挂载时，底色遮挡已有图层；整幕切换时表现为闪黑，即使素材已经被浏览器缓存也会出现。

## Decision

`VideoEditorEffectImage` 使用无加载底色的原生图片，显式开启立即加载和同步解码。素材和文字 PNG 在加载阶段保持透明，已加载画面继续交给既有抠像、模糊和翻页画布处理。尺寸回调、素材地址、时间线和导出规则保持原契约。通用图片组件的加载反馈继续服务普通页面。

## Alternatives considered

- 仅预加载素材：不能消除每次组件挂载产生的通用加载态，也会增加预取和资源管理范围。
- 全局删除图片占位样式：影响普通页面的加载反馈，超出节目画面的修复范围。

## Consequences

节目画面不显示通用图片加载动画；首次网络读取尚未完成时，对应图层暂时透明。同步解码使已缓存的短片段图片在显示前完成解码。此修复不引入额外预取、解码缓存或持久状态。

## Verification

- 修复前实际 Chromium 连续采样 60 张播放画面，捕获人物黑块、全画面深色遮挡和切镜黑帧；修复后连续采样 65 张，以上缺陷未再出现。证据位于被忽略的 `.local/preview-flicker/`。
- 58 项相关 Web 测试通过，涵盖透明素材和文字的加载、短片段重新挂载、尺寸回调、接缝播放及方向/翻页转场。
