# Agent Note: 本机 Agent 门禁映射与视觉分镜迁移收尾

Status: implemented

## Problem

独立服务的本机装配复用已有数据库，但 Amadeus 和 Agent Runtime 的发布门禁仍默认读取容器绝对路径，无法确认本机暂停标识。视觉分镜功能的正式数据迁移与受保护 SDK 参考同步也需要在用户授权后完成。

## Decision

两侧 CLI 从既有 RuntimeLayout 解析门禁路径，应用构造器显式注入同一路径给请求中间件和健康探针。容器装配默认值不变，未配置目录保持原状态，不引入环境全局查询。

用户授权本次收尾后，仅通过登记的 Visual 迁移 CLI 执行 `0016_visual_storyboards`。停机前确认 Agent 与其他执行队列空闲，首次门禁安装先关闭新请求入口、正常停止服务，离线备份受影响的 Visual 数据库和恢复配置。隔离副本先验证迁移与旧版恢复，再迁移当前独立 Visual；停用的兼容数据库和旧 Docker 服务保持原状态。

SDK 参考使用官方生成器同步，受保护正文单独提交 `95cada5c`，未与代码、工程文档或本 Note 混合。实现背景见[视觉创作工作区](../simplification/2026-11-21-visual-project-creation-workspaces.md)。

## Alternatives considered

- 沿用容器硬编码目录：本机健康探针显示未配置，无法确认暂停生效。
- 手工修改迁移账本或将开发副本替换正式库：绕过登记迁移和既有账号数据，拒绝采用。
- 为同步参考重生成全部产品文档：本次只更新生成器判定过期的 Visual SDK 参考正文。

## Consequences

维护期间 Agent 新写入返回 503，读取健康状态可核对同一挑战标识。服务正常退出并释放锁后才备份和迁移；恢复点含数据库、配置和源码恢复依据，位于忽略的 `.runtime/deployment/recovery/visual-storyboard-20261121/`，不成为正式启动依赖。

迁移前后既有业务内容逐表校验。重启后的现有浏览器可自动保存画布，因此只允许内容完全一致时单独记录 revision 与更新时间的增长，不能忽略业务字段变化。服务探针必须等待启动就绪；首次探针的暂时 503 不代表迁移失败。恢复后核验两侧门禁均为 accepting。

## Verification

隔离测试覆盖两套装配的门禁路径、暂停标识和写入拒绝，沿用发布/回退门禁测试；Amadeus 与 Agent Runtime 受影响的主机测试使用假执行器验证。完整公共契约与受保护文档检查通过。

本次对实际独立库完成隔离迁移、旧版恢复和正式迁移；23 个服务就绪、7 个 Worker 存活、本机 3000/9001/9002 入口通过既有来源校验。31 个项目、31 份画布、129 张设定卡、4465 条输出及其余既有业务内容保留。正式恢复报告保存在上述恢复点的 report.json；可再生成的测试输出位于 `.local/visual-storyboard-release/`。
