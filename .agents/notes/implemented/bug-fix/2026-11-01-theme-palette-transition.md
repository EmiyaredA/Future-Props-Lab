# Agent Note: 主题切换避免浅底与亮字短暂混用

Status: implemented

## Problem

共享下拉和侧栏按钮包含背景过渡动画。亮暗主题的 CSS 变量立即切换文字颜色，但背景仍从旧主题插值，产生浅灰底与亮字混用。等待动画结束再截图只能掩盖问题，无法保证实际切换过程可读。

## Decision

`shared/ui/theme.ts` 在主题变化时为根元素添加短期 `data-theme-changing` 标记，提交新主题并刷新样式；`theme.css` 仅在这一窗口关闭过渡，两个绘制帧后恢复普通悬停／焦点过渡。标记属于显式 DOM 主题状态，不引入模块级共享可变运行状态。偏好存储、系统主题跟随与跨窗口同步沿用既有规则。

共享主题新增 `--accent-text`，浅色使用更深的橙红文字，深色保留原橙色。工作台内的下拉选中项、链接及选中导航使用文字色，强调填色与文字色分别表达职责；覆盖限定在工作台，其他工坊仍使用自己的品牌色。修正工作台筛选器的类名，使其字号规则命中自绘控件。

## Alternatives considered

- **延迟截图** — 能避免验收截图捕捉中间帧，但实际用户仍会看到闪烁，不能解决问题。
- **逐个删除控件背景动画** — 会丢失常规悬停反馈，也会遗漏其他使用主题变量的控件。
- **只给深色筛选器写固定背景** — 绕过共享主题，浅色及弹出菜单仍可能出现不一致。

## Consequences

主题配色同时提交，常规动画随后恢复。浅色选中项采用适合小字号的强调文字色。原有会话阅读与同步、身份与来源授权不改变。

## Verification

修复前，`web/e2e/agent-workbench.spec.ts` 的当帧颜色检查稳定捕捉到应为 `rgb(30,35,32)` 的深色筛选器仍显示 `rgb(232,230,225)`。修复后同一旅程在四种宽度与亮暗模式下验证底色、文字、至少 4.5:1 的普通筛选文字对比度、展开菜单与键盘状态，并更新截图。`web/tests/theme.test.tsx` 与工作台组件测试覆盖偏好保存、系统主题跟随与原有阅读流程。
