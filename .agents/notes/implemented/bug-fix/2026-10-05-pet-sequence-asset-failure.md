# Agent Note: 完整帧加载失败反馈与明确恢复

Status: implemented

## Problem

完整原帧异步解码失败保留了原站姿或最后正确画面，但共用渲染入口没有显示原错误。取消旧播放和自动回待机曾清空失败并隐式重发同一请求，明确恢复与后台重试未分开。隔离 Electron 实测还发现：整帧恢复后加载 alert 消失，桌宠顶部仍保留“桌宠状态异常”；原运动 hook 的严重错误分支不再读取渲染器已经恢复的状态。

## Decision

SequenceFigure 独立持有图集加载错误并通过只读 getAssetFailure 反馈，React 共用渲染入口在真实 render 后读取，仅在错误变化时更新文字。首次失败保留原站姿表面，后续失败保留最后完整帧；实际完整帧绘制提交后才清除加载提示。旧代次迟到回调不能污染新选择。

取消、自动回待机、聊天、运行待机和自主活动不清除失败。合法用户效果调整、明确重播或临时换装重新读取；菜单展开不属于重试。上层事件身份与播放模式共同区分用户操作和自动恢复，不能仅靠播放 key 递增推断用户意图。完整事件定时返回待机沿用同 key，不重新读取失败图集。

恢复中的运动错误反馈继续保留原 assetError，直到真实绘制提交，解码完成本身不代表可见成功。运动控制器区分渲染错误与通信错误；同一错误只取消一次，恢复后结束旧轨迹并重新等待活动间隔，通信错误遵守原显式恢复流程。仅明确返回 null 的已提交反馈解除原渲染异常；缺失或空反馈不冒充成功，新失败准确替换旧原因。

## Alternatives considered

- 每次 cancel 或 idle 切换清空失败：会形成后台重试，错误也会在未恢复时消失。
- 仅在构造入口捕获异常：不能覆盖后续整帧图集异步读取。
- 把所有失败降为资源缺失警告：会掩盖支撑、登记和通信失败。
- 解码成功就清除运动错误：尚未绘制时可能启动运动，破坏既有保留画面规则。

## Consequences

状态仅保存在实例与 hook 内存，不修改配置、revision、CAS、资源或数据库。缺少动作仍由能力与运动反馈说明，PNG 读取错误不等同于资源能力。隐藏表面释放遵循[独立生命周期决策](2026-10-05-pet-hidden-render-surface.md)。这个修复不能证明新动作自然，也不能归因 Chromium tile 警告。
