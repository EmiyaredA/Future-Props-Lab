# Agent Note: 精确预览不阻塞时间轴保存

Status: implemented

## Problem

精确停帧接口在异步请求中直接执行同步 FFmpeg 解码、Pillow 合成与 PNG 编码，文字图层接口同样同步渲染。单进程部署下这些操作阻塞事件循环，正在分割片段的保存请求必须等待预览结束，界面持续显示“保存中”。

## Decision

`VideoEditorFrames` 在所属请求中完成 Workspace、项目、revision、时间范围和素材校验，构造独立文档值对象与素材路径后，通过 `asyncio.to_thread` 执行精确帧渲染、缓存读取和写入。文字图层的渲染与编码也进入工作线程，错误继续映射为原有领域错误。AsyncSession 与 ORM 查询不传入线程，不改变时间轴 CAS、批次回执和保存失败策略。

同一版本与时间点的并发预览使用独立 UUID 临时文件，再原子替换同一个确定性缓存路径，避免以进程 ID 命名时相互覆盖或删除临时文件。每个请求仍返回其已校验版本的画面；后续请求按当前 revision 校验，不跨版本复用缓存。

旧站精确帧解码失败时检查工程派生目录。如果工程已被并发删除，沿用工程不存在的领域错误。工程仍在时保留原解码错误，已完成的帧也继续遵守现有缓存清理规则。

## Alternatives considered

- 分割立即更新本地时间轴：只能掩盖等待，不能解决后端事件循环阻塞，也增加保存失败恢复的状态负担。
- 关闭精确停帧：能绕开触发条件，但失去用户启用的像素检查能力。

## Consequences

分割保存无需等待预览解码完成，预览本身的渲染成本仍然存在。工作线程仅处理只读渲染和派生缓存，不共享请求会话或增加持久化格式。请求取消不会强制终止已经执行的同步渲染；缓存原子写入与清理由工作线程完成。

## Verification

- 新增 `tests/test_video_editor_preview_concurrency.py`：通过正式 API 挂起精确帧或文字渲染，确认分割返回成功且 revision 递增时渲染仍未结束；修复前两个分支均因事件循环阻塞失败。
- 同一精确帧并发发布验证独立临时文件、完整缓存结果、临时文件清理与缓存命中。
- 分别在解码失败时保留和移除工程目录，核对错误类型及目录状态。
- 运行视频编辑器后端回归、架构检查与前端分割／保存队列回归；无真实供应商调用，无持久数据库写入。
