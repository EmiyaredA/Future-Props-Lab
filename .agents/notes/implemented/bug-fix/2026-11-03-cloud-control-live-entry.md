# Agent Note: 云控改动同步到当前运行入口

Status: implemented

## Problem

云控已在独立服务集成工作树实现并验证，但当前网站由主目录的开发入口提供页面和 API。只修改工作树不会更新正在使用的网站，应用列表仍展示旧入口。

## Decision

将云控导航、管理员权限、工作台路由与两项主机工具删除的兼容改动同步到当前主目录，通过既有热加载生效。沿用当前数据库和采集实现，不引入新 schema，不触发数据迁移或整套服务切换。

工作台 API、附件、扫描回执与 SSE 检查 `cloud-control.access` 和原有 Session、归属及本机入口约束；采集器通过显式回调检查当前账号资格。降级停止任务但保留副本与检查点。旧工作台链接规范化到 `/agents` 并保留查询参数；已删除工具链接回到工具目录。

云控与应用目录共用 `ApplicationCard` 的 96px 紧凑卡片、品牌图片、单行简介和能力标签，入口元数据由装配显式传入，不在云控导入应用页面注册表。

独立页面、进程、数据库、原生采集协议与发布周期的实现仍归独立服务集成分支，由「调整为纯网站体验」任务按原门禁发布。当前兼容入口不代表独立服务已正式切换。

## Alternatives considered

- 只要求刷新：源码不在运行目录，无法改变页面。
- 将整个服务化分支合入：当前主目录包含并行未提交修改，独立服务切换仍有门禁；本次不扩大到正式数据转移。

## Consequences

当前网站立即呈现管理员专属云控和新的工具目录。既有账号数据、来源归属和未提交改动保留。工程图和官方导入包描述当前兼容实现，避免把独立服务验收状态写成已经发布。

## Verification

工作台、工具、权限治理、SDK 文档与架构检查共 86 项通过；入口、导航、首页和工具组件 39 项通过。浏览器回归 9 项通过，覆盖明暗主题、390/768/1280/1616 宽度、键盘访问、普通账号门禁、旧工具收藏及来源同意。工作台因共用原卡片改用相同无障碍名称，更新定位器后单独复验通过。

当前 `127.0.0.1:3000` 中卡片实测约 261×96px，工作台 `/agents` 保持同步连接。构建、lint、格式、契约与 SDK 生成物、Agent Note 和文档中心保护检查通过。测试使用临时配置和数据库，不修改现有运行数据。
