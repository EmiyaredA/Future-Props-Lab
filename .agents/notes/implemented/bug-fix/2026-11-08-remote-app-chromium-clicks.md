# Agent Note: 远程应用的 Chromium 控件点击

Status: implemented

## Problem

Chrome 能收到远程画面和键盘输入，但窗口命中检查通过后，投递给 Chrome 进程的鼠标事件可能没有抵达页面控件。输入框也因此无法通过远程点击获得焦点。浏览器和主机都报告就绪时仍可复现。

## Decision

ChatGPT 和 Chrome 的单次左键点击用已核对进程和焦点窗口的辅助功能控件执行。按下、抬起必须命中同一可按控件，取消或离开窗口时丢弃待执行动作。点击可编辑控件时先设置其焦点，再沿用原进程鼠标事件。拖动达到阈值时改走原进程鼠标事件，补送按下前复核起点仍属于所选窗口。

命中阶段可以沿辅助功能父节点确认窗口。可按控件查找沿已验证的命中路径进行，允许节点缺少独立窗口属性；遇到其他进程、明确指向不同窗口的节点或窗口根时停止。

## Alternatives considered

- 为进程鼠标事件增加事件编号或窗口坐标，两种隔离实测均未触发 Chrome 测试按钮。
- 向整台 Mac 发布系统鼠标事件会扩大单应用会话的输入范围，因此保留进程和窗口检查。

## Consequences

可按控件和文本焦点使用公开的辅助功能接口。依赖原始鼠标事件的内容继续使用进程投递。主机授权和会话策略由既有入口复核。

## Verification

后续连续使用仍复现点击失效。此处的控件动作补丁由[绑定窗口的鼠标事件](2026-11-08-remote-app-window-mouse-events.md)替代；下列单次验收不能证明持续交互稳定。

隔离 WebRTC 控制端通过 Mac 辅助程序触发了真实 Chrome 页面按钮，并点击输入框后验证英文和中文文本落到目标页面。两项操作分别读取 Chrome 的实际控件状态核对。

同一控制链路向 ChatGPT 草稿输入测试文字，通过远程画面核对后清空草稿。

正式部署更新辅助程序后，从 Windows 浏览器复测 Chrome。测试页收到点击回执，Mac 上的目标输入框显示 Windows 端键入的文字。
