# Agent Note: Studio 切换时核对旧站来源和历史授权

Status: implemented

## Problem

从固定候选目录封存旧站时，网站配置的相对数据库路径可能解析到候选目录。旧站的
`code_agents` 设置也可能包含已停用工作台的合法授权，导致覆盖检查无法完成。

## Decision

封存命令通过 `--source-config-root` 显式指定相对数据库路径所属的旧站根目录。它仍要求
解析结果与待封存数据库一致，并保留原始配置字节。已登记的 `agent_workbench` 授权与旧工作台
历史一并封存在回滚快照中，覆盖检查继续拒绝无法识别的设置。

## Alternatives considered

改写正式配置可以消除相对路径，但会改变旧站启动输入和恢复摘要。关闭覆盖检查会掩盖其他
未处理的设置。

## Consequences

使用固定候选目录执行封存时，操作单要传入正式站的项目根目录。工作台旧历史和旧授权可从
快照恢复，本机 Happier 继续使用自己的 Relay 和权限。

## Verification

隔离 SQLite 覆盖相对路径、错误根目录拒绝、配置字节保留、已知旧工作台授权归档和未知设置拒绝。
