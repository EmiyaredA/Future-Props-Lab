# Agent Note: 桌宠控件主题、紧凑工作区与聊天阅读位置

Status: implemented

## Problem

资源包更新入口暴露浏览器按钮外观，说明文字与按钮挤在同一行。浅色下拉菜单沿用深色焦点背景。编辑器小窗口依赖三栏挤压或纵向堆叠，长标题和默认滑块不稳定。聊天所有消息变化都滚到底部，加载旧消息或阅读历史时会失去位置。

## Decision

桌宠字段、动作、选中态与 Radix 单选菜单使用应用主题变量；菜单保留 Portal 与 Radix 的碰撞定位，用勾选标记表示当前值、背景表示操作焦点。上传按钮通过隐藏文件输入调用现有业务用例，不变更接口。

1200px 以下复用紧凑面板导航，以 CSS 显示列表、预览或属性。三个面板始终留在原编辑器实例中，选择只在内存保存。布局与控件样式按职责拆分，项目弹窗仍归 workshop.css。预览选择、保存 CAS 与桌面联动流程不变。

聊天阅读位置归 useChatHistoryScroll，消息分页与请求仍由 ChatWindow 拥有。前插历史使用更新前后的高度差保持阅读锚点；距底部 48px 内跟随新内容，阅读旧消息时保留位置并提供“回到最新”。用户发送后恢复跟随，历史请求单次在途，失败只允许手动重试。

## Alternatives considered

- 保留窄屏纵向堆叠：用户选择与其他工坊一致的面板切换，减少列表、预览和属性之间滚动。
- 全部改用共享 CustomSelect：现有 Radix 菜单已负责焦点和边界，仅需要单选语义与主题修正，无需替换交互基础。
- 每次消息变化滚到底部：无法阅读旧消息，也会抵消分页入口的作用。

## Consequences

UI 状态不进入持久项目，公共 API 和数据库无变化。样式拆分提高职责清晰度，但多个入口必须持续保持透明窗口与主题规则一致。真实角色包仅作可选本地验收输入，不作为可再分发测试资产；自动验收默认使用合成数据包和隔离运行目录。
