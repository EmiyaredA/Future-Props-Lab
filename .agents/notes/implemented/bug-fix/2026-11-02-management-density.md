# Agent Note: 管理页面密度与日志筛选布局

Status: implemented

## Problem

首页与管理页面的卡片、标题和留白占用较大。日志筛选栏仍使用包含旧作用域控件的三列布局，中等容器宽度下五个下拉框挤在第一列，文字被截断，筛选按钮占据宽列。旧浏览器用例还引用了已移除的工作区查询。

## Decision

紧凑尺寸由页面和 Studio 导航各自持有，不调整根字号，也不缩放整个应用。共用文件浏览器仅在文件管理页宿主下收紧，编辑器与文档正文保留原比例。日志中等宽度使用两列网格，搜索独占一行，快捷筛选组和固定宽度按钮占下一行；窄屏沿用筛选抽屉。长选项在菜单内换行，列表字段按业务列约束宽度。触屏主要控件保持 44px 高度。

## Alternatives considered

- 全局缩小字号或缩放页面会改变编辑器、阅读排版与触屏操作尺寸，因此未采用。
- 仅减小筛选字号无法修复列空间分配错误，因此修复容器布局并验证实际文字空间。

## Consequences

无 API、权限、数据库或查询参数变更。浏览器用例使用当前账号调用凭据和日志契约，覆盖中间宽度的文字可见性、长名称、局部滚动和触屏尺寸；验收产物保存在 `.local/ui-density/`。

## Verification

69 项相关 Web 组件测试通过；5 项 Chrome 浏览器用例通过，覆盖六种主页面宽度、日志中间断点、长名称、触屏、项目卡片与编辑器/文档隔离。lint、格式、OpenAPI/SDK stale-check、构建及文档中心保护检查通过。改动前后截图保存在 `.local/ui-density/`。
