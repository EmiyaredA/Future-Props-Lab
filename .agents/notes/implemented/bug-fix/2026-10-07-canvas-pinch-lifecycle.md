# Agent Note: 画布切换后的触控板缩放监听

Status: implemented

## Problem

视觉工坊画布与看板共用持续挂载的控制器，但画布 DOM 在切换视图时卸载并重新创建。缩放监听的 effect 只依赖数据就绪状态，因此往返看板后仍绑定旧画布；默认以看板打开项目时也无法在随后显示的画布上绑定监听。Mac 触控板捏合和普通滚轮缩放失效。

## Decision

画布通过稳定的回调 ref 向控制器报告实际 surface 元素，同时保留现有 ref 供坐标转换、拖动和工具操作使用。缩放监听随元素身份及数据就绪状态绑定和清理；清理时重置未结束的原生 gesture 基准。控制器、视口与节点草稿继续跨视图保留。

## Alternatives considered

- 用看板／画布模式作为 effect 依赖：会把 DOM 生命周期与页面模式隐含耦合，不能直接覆盖其他重挂载原因。
- 重建整个控制器：会破坏切换视图时保留选择、草稿和视口的约定。

## Consequences

监听只作用于当前挂载的画布，旧元素不再处理手势。沿用现有缩放范围、光标锚点、滚轮算法与检查器普通滚动规则；不更改 macOS 设置、Electron 页面缩放、API 或持久数据。

## Verification

新增两个组件回归用例先复现监听未清理与默认看板打开后未绑定问题，修复后通过。相关 91 项组件测试通过，覆盖重复往返、原生 gesture 的连续 scale 与锚点、异步挂载及检查器滚动。隔离 Chromium 旅程使用 Ctrl wheel 模拟触控板捏合，验证 25% 放大、往返视图保持视口、刷新默认看板后重新缩放，且页面自身缩放保持 1；未执行真实触控板硬件测试。

lint、格式与构建检查通过。回归日志、截图和隔离测试数据位于已忽略的 `.local/canvas-pinch/`；测试只通过正式 API 创建隔离项目，不读取或修改桌面正式数据。
