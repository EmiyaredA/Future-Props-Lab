# Agent Note: 视频播放预览只发布已定位的源帧

Status: implemented

## Problem

工程 revision 1364 在时间线 125.865408s 的两个 18-v2 片段相接，但源时间从约 7.32s 跳到 8.858068s，且没有视觉转场。旧 DOM 预览按片段重建视频元素，立即显示和播放尚未定位的解码器，可能发布素材开头或旧位置的帧。离场转场伙伴的 localUs 被夹在末尾，但播放器仍自由播放，漂移容差也允许越过裁切结束点。

此前的[连续接点交接修复](2026-10-07-video-editor-seam-preview-handoff.md)只复用源区间连续的解码器。本修复扩展相邻视频的显示缓冲生命周期，不改变精确帧或导出采样契约。

## Decision

`VideoEditorProxyVideo.tsx` 隐藏原始视频元素，使用画布发布有效解码帧。loadeddata、seeked、视频帧回调和无视频回调浏览器的 rAF 均先验证最新定位、解码状态和源区间；发起 seek 的同一次事件不发布旧解码帧。播放仅在定位完成后启动，重复播放请求合并，夹在末尾的转场伙伴暂停。源区间边界校验优先于 120ms 播放时钟容差，视频帧回调也拒绝结束点及之后的 PTS。

`previewPlayback.ts` 为时间线上直接相邻的视频维持显示缓冲身份，允许源跳剪、速率变化和素材切换复用最后的有效画面。源连续时继续播放，源不连续时精确重新定位；需要同时显示的视觉转场伙伴独立，真实空隙卸载缓冲。抠像仍通过既有画布算法处理，视频帧回调去重继续生效。

## Alternatives considered

只降低漂移容差不能阻止初始 loadeddata 或延迟 seek 发布旧位置的帧。单纯隐藏未就绪的视频会让底轨或背景露出。提前预热下一片段不能覆盖快速拖动和任意解码延迟，因此使用发布校验与持久显示缓冲。

## Consequences

普通视频也经过画布，增加一次纹理复制；按视频解码帧回调发布，避免每次时间线刷新重复绘制。等待期间短暂保留最后有效画面，精确停帧、正式导出和持久时间线均不变。真实工程仅经 SQLite 只读连接查询，浏览器验收使用隔离数据库和合成视频。

## Verification

- 组件覆盖源开头拒绝、加载中不启动、快速更新目标、跳剪显示缓冲复用、裁切范围优先与转场尾帧暂停。
- 既有媒体时钟、抠像帧回调去重、连续接点、精确停帧及转场测试回归。
- Chromium 使用绿色开头、红色有效区间、蓝色有效区间的合成视频，逐次采集可见画布，验证播放跳剪只出现红/蓝且无绿色或透明黑闪；同时验证真实空隙和黑幕。
