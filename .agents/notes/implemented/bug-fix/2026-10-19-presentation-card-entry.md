# Agent Note: 文稿封面直接打开与显式预览

Status: implemented

## Problem

点击已有文稿封面会先打开预览弹窗，再次点击才能进入文稿；悬停时还会自动弹出前三页，增加操作和遮挡。

## Decision

调整[原列表预览决策](../feature/2026-10-15-presentation-library-preview.md)：已有文稿封面与名称直接调用原打开入口，封面右下角使用独立、常显的“预览”按钮打开完整预览弹窗。两者为同级按钮，避免嵌套交互和事件冒泡误打开。版式卡片仍通过点击预览并确认使用，空白版式直接新建；所有卡片移除自动悬停预览。

预览数据仅在显式打开弹窗后通过 owner query key 读取，保持缓存、取消、重试与只读支持。关闭预览恢复预览按钮焦点，进入文稿或命名流程时不抢回焦点。预览状态只在内存保存，不改变 API 或持久化格式。

## Alternatives considered

- 保留封面预览、只通过名称进入：仍需要用户区分同一卡片的进入方式。
- 在封面按钮中嵌套预览按钮：破坏按钮语义，键盘与点击传播更容易出错。

## Consequences

用户单击封面即可进入文稿，触屏和键盘用户也能直接发现独立预览入口。悬停不再请求完整文稿；翻页、错误重试和预览后打开继续使用原弹窗。

## Verification

19 项组件回归通过，覆盖点击与 Enter／Space 直接打开、悬停和聚焦不加载预览、显式预览翻页、失败重试、关闭取消及恢复焦点。2 项隔离 Chrome 浏览器旅程通过，检查封面与名称直接进入、独立预览，以及明暗主题和 390／768／1600 宽度；产物位于已忽略的 `.local/presentation-card-entry/`。

Web lint、本次文件格式、Agent Note 树／格式／归档封印、文档保护和官方导入包检查通过。全量 Web 构建受到范围外连接图层 `layer` 和 `onOrder` 类型变动影响，完整格式检查也发现其他正在修改的文件，未修改这些无关内容。
