# Agent Note: 视觉画布容量与长依赖链校验

Status: implemented

## Problem

保留分镜、原速参考、独立返修与输出历史的大型视觉项目达到 500 个节点后，后续合法复合候选无法通过完整画布校验。删除既有节点会破坏固定输出引用和历史追溯；只提高节点数量还会让递归环检测在长依赖链上触及 Python 调用栈上限。

## Decision

画布完整文档允许最多 1000 个节点和 2000 条连线，维持原有有界的节点与连线比例。完整 PUT、批量 operations 和视觉助手仍共用同一 Pydantic 最终文档校验；Web 粘贴预检同步对应上限，并通过 OpenAPI 契约测试防止漂移。节点 ID 唯一性、固定输出归属、类型兼容、CAS、批次幂等与原子失败规则保持原有语义。

依赖环检测采用迭代拓扑遍历，时间与空间均为 O(节点数 + 连线数)，避免有效的 1000 节点链依赖调用栈深度。该修复不改变持久格式、数据库、迁移、部署配置或运行服务。

## Alternatives considered

- **删除或覆盖旧节点** — 可以暂时腾出容量，但会丢失历史和固定引用，不满足制作追溯要求。
- **取消数量上限** — 无法约束画布请求、序列化与浏览器渲染成本，因此保留明确上限。
- **只提高递归深度** — 会改变进程全局行为，也没有消除输入规模与调用栈耦合，因此改为迭代校验。

## Consequences

- **收益**：大型项目可继续保存返修候选，旧版本与引用无需清理；最大尺寸无环图不会因递归深度失败。
- **代价与边界**：最大画布序列化、校验和 Web 渲染工作量增加，仍以 1000/2000 为明确边界。一次 operations 请求仍最多 1000 个操作，超限文档不部分保存。

## Verification

`tests/apps/visual_workshop/test_visual_canvas_capacity.py` 验证新数量边界、最大长度依赖链及末端环、公开 OpenAPI 与 Python SDK 上限、从 500 节点经正式 HTTP operations 增加到 1000 节点，以及失败后图和输出历史保留。Web 容量测试核对生成 OpenAPI 边界与粘贴预检，既有粘贴旅程验证超限不改变画布和撤销历史。执行契约生成/检查、相关后端与 Web 测试、Ruff、Prettier 和 Agent Note 校验；受保护产品文档中心逐文件 SHA256 前后核对不变。
