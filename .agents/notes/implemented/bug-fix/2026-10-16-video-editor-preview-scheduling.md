# Agent Note: 预览解码释放连接与持续帧回调

Status: implemented

## Problem

分割保存仍可能被慢预览拖延。精确帧与文字图层虽已进入工作线程，请求会话仍在解码期间保留只读事务和连接；多次预览能占满池，新的保存请求等待可用连接。实际桌面日志存在源帧探测超过 30 秒的记录。

播放预览的 layout effect 依赖每次播放头更新，反复取消并重新注册视频帧回调。同素材连续分割处，解码时钟略落在右片段起点之前也会强制暂停并 seek，破坏已有解码缓冲。

## Decision

精确帧在构造文档、缓存路径和素材路径后结束只读事务，缓存 I/O、渲染及文字编码不持有数据库连接。单帧 FFmpeg 解码补充 30 秒期限。权限和 revision 校验保留，工作线程只接收独立值对象与路径。

代理视频将当前参数同步与播放器回调生命周期分开：每次界面更新维护最新参数，播放器挂载时注册一次帧回调，卸载时取消。回调读取最新参数，连续切点在原播放容差内允许解码器自然追上起点，未追上时保留已发布画面；暂停、源跳剪及源结束边界保持严格定位。转场伙伴、真实空隙和正式渲染的时间契约沿用原规则。

## Alternatives considered

- 增大数据库连接池：只延后资源耗尽，不能解决解码持有连接的问题。
- 只放宽播放漂移容差：不能解决回调反复撤销，也会放大音画偏差。
- 用乐观时间线更新遮盖分割等待：不能消除后端资源排队，并增加失败恢复状态。

## Consequences

慢预览仍可能等待媒体解码，但不会长期占着读取工程的数据库连接。播放回调不会因时间轴刷新不断重挂；源跳剪仍需要真实定位，不能保证所有媒体都即时解码。数据库、API 和工程格式不变。

项目在只读解码期间被正式删除时，迟到的缓存发布不重建已删除目录；若目录仍存在而发布失败则继续上报错误。
