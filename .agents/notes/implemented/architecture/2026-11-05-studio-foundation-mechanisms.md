# Agent Note: Studio 基础机制归位

Status: implemented

## Problem

首批应用迁移后，通用文件、CAS、账号绑定和订阅机制仍从旧网站命名空间导入，掩盖独立服务的实际依赖。配置类型也与网站数据库目录混放。

## Decision

十五个配置及通用模块按职责移入 Studio。数据库机制接受调用方提供的 Session 或工厂，不创建全局连接；文件模块只处理显式传入的内容与路径；授权订阅负责取消和清理，授权规则仍由调用方提供。设置类型移入 config，导入只定义类型与显式读取入口，不读取部署文件。

旧网站数据库与隐式加密助手仍由后续网站装配批次处理，本次不将其隐藏到通用基础层。现有账号 Session 信息属于存储隔离上下文，与业务依赖发现不同，不删除该保护。

## Alternatives considered

- 通过旧路径转发会留下两个长期入口，因此同步迁移调用方并移除原模块。
- 将网站全局数据库一起搬入 runtime 会保留导入即配置的副作用，本批不这样处理。

## Consequences

配置键、HTTP、存储布局与迁移内容保持兼容。代码、测试、构建闭包和当前技术说明同步使用新路径；历史 Agent Note 与受保护产品文档保留原状。

## Verification

配置、架构、源码闭包、账号任务、网站与归属回归 131 项通过。独立进程验证导入配置模块不读取配置，也不加载 ORM 或旧应用。Python Ruff 与格式检查通过；官方导入包按技术正文重新生成，未接触运行期笔记。
