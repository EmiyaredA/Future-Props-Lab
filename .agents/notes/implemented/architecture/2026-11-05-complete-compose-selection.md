# Agent Note: 完整部署清单选择

Status: implemented

## Problem

服务逐步增加独立镜像和 Compose 清单后，Mac 管理启动器只能加载少数早期服务。单项验收可手动指定清单，但正式入口缺少完整组合，Remote 的辅助进程也不在业务启停边界。

## Decision

启动器从 TOML 中选定的镜像和功能配置推导固定顺序的清单。功能挂载在所属服务之后追加，声明不完整的挂载或缺少配套镜像时提前退出。数据库预检覆盖全部显式选中的业务服务。Guacamole 随 Remote 启停，管理端公开的服务目录继续由服务登记表维护。

## Alternatives considered

- 命令行临时拼接清单使隔离测试与实际启动使用不同配置。
- 自动载入部署目录中所有文件会要求未启用功能的凭据，也会把新文件直接纳入生产启动。

## Consequences

启用可选功能需要在 TOML 中提供对应的全部配置。管理启动器清除继承的 FPL 和 Compose 值，所有生产参数都来自明确配置。选定的业务数据库仍由维护流程显式迁移。

## Verification

管理主机测试核对完整选择、依赖缺失、环境隔离和 Remote 辅助进程的启停。真实 Docker Compose 用合成配置解析 28 份文件，解析结果包含 23 个登记服务和 Guacamole，各服务状态目录独立，只有网关和管理端绑定回环端口。
