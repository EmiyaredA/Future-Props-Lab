# Agent Note: Studio 命名空间与音频标注端口

Status: implemented

## Problem

独立服务入口、共享业务和跨进程协议分散在多个 `fpl_` 包与 `app/apps/`。仅建立新目录不能明确源码归属；包重命名还可能改变镜像闭包、数据表归属、配置定位和维护命令。音频标注把 SQL、编辑转换及依赖发现混在一起，无法独立替换存储。

## Decision

原 `fpl_*` 包移入 `studio`，原 `app/apps/` 的十个切片归并到业务所有者。`contracts` 拥有纯协议，`runtime` 拥有数据库、HTTP、文件和任务机制，`host` 按本机动作归类。各独立应用的 `application.py`、`cli.py` 与维护装配位于 `assembly/independent/<owner>/`，数据库模型及历史迁移留在所属应用 `storage/`。不保留旧包转发、软链接或重复实现。

跨进程公共客户端由协议所有者维护。镜像源码闭包只放行明确登记的客户端模块及无副作用父包，继续检查每一个递归依赖；未知客户端、其他服务存储和主机实现仍被拒绝。静态循环检查排除仅用于类型检查的边，不放宽运行期依赖。业务客户端没有权限绕过账号归属或自行裁决另一应用的状态。

音频标注 `EditDocument` 依赖 `DocumentEdits`，纯规则只转换输入快照。账号范围已绑定的存储适配器原子提交文档 CAS 与幂等回执，重复请求读取原回执，摘要变化冲突，并发失败核对提交结果，取消回滚。请求入口显式提供素材、转录和暂存目录，业务不再从 Session 信息字典获取这些组件。

本批接在网站任务 `f65cfa5b` 之后，保留其工作台排队、插入指令、源码预览和历史迁移实现。配置键、服务 ID、HTTP/SSE、迁移 SQL 和持久数据格式不因源码目录改变。受保护 SDK 生成脚本的权限清单路径经用户明确授权，只作单行更新并独立提交为 `d494f658`。

## Alternatives considered

- 隐藏旧目录或留下转发包仍会保留原来的依赖与多份归属，无法证明迁移完成。
- 把全部原运行模块放进新的通用目录会继续混合业务协议、客户端和基础机制。
- 直接依据新包名推断所有数据表归属会错误转移兼容表；视觉项目素材引用仍由素材库拥有。

## Consequences

可执行命令使用 `python -m studio.assembly.independent.<owner>.cli`，Mac 入口为 `studio.assembly.host.cli`。Python 打包只登记 `app`、`studio` 和 `db`；构建脚本、镜像定义、运维入口、测试和技术文章代码路径同步迁移。

本批没有宣告[整体提案](../../proposed/architecture/2026-11-05-studio-component-ownership.md)完成。`app/llm`、`app/capabilities`、`app/console` 等兼容实现，以及其余业务逐用例的端口化、完整前端/测试目录整理仍需后续批次。当前 `website` 适配中的 SQL 与业务混合不能被视为目标分层。
