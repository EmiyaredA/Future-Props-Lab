# Agent Note: 预览与取帧共用用例及输出生命周期

Status: implemented

## Problem

文件预览、缩略图与取帧仍分别由旧素材包及独立 Rendering 执行。临时成片由 HTTP 后台回调清理，发送中断时无法保证回调执行；素材来源释放和派生输出释放也没有独立契约。

## Decision

五类媒体读取统一由 `ReadMedia` 调用来源、执行与授权端口。预览和取帧 HTTP 适配归 Rendering，兼容网站原文件管理路由不再编排这些操作。旧素材包的预览、缩略图转发和取帧业务实现删除。

`MediaOutput` 表达文件名、媒体类型、长度、读取和幂等关闭，不包含路径。输入借用结束后，输出仍有效；授权复核失败或取消时用例关闭输出，响应开始后由响应适配器在 `finally` 中关闭。临时文件响应禁用服务器路径交接，保证发送完毕后再删除；持久缓存关闭只释放句柄，不删除其他请求可能读取的缓存。

## Alternatives considered

- 继续使用响应后台任务清理：发送异常和取消可能跳过后台回调。
- 在用例结束时删除全部文件：会在 HTTP 读取输出之前删除成片，也会误删共享预览缓存。
- 业务返回路径：将宿主存储和清理责任泄漏到业务接口。

## Consequences

公开 URL、操作 ID、schema、下载类型和账号归属不变。两套装配共用处理规则。文件路径仍由 I/O 层及 HTTP 的文件传输优化持有，内存输出实现通过同一协议工作；旧渲染算法目录的迁移仍属下一批。
