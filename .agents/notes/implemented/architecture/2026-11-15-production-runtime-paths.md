# Agent Note: 正式部署不依赖可清理的中间目录

Status: implemented

## Problem

正式 Mac 启动器、Worker 导入路径、前端版本、网关清单与证书留在 `.local/` 的历史验收目录。
清理中间结果会破坏运行与重启；启动登记还未反映后来增加的管理包装入口。

## Decision

`.local/` 只存可再生成的中间结果。正式部署副本归 `.runtime/deployment/`，服务数据和回执继续归
`.runtime/independent-services/`；兼容网站构建与共用启动器状态分别归 `.runtime/website/` 和
`.runtime/dev-server/`。受版本管理的源码及主配置入口仍遵循现有职责和配置契约。

本机迁移复制线上冻结代码与构建，逐文件比对后切换引用，不发布工作区代码、不更换镜像、不迁移数据库。
管理启动器直接使用与其迁移注册表匹配的冻结副本，替代预先导入包的临时包装入口。
Compose 解析与执行使用线上冻结版本，保留该版本仍选择的旧功能叠加文件；工作区的新选择器不能作为线上事实。
启动登记归 `.runtime/deployment/active-launch.plist`，拒绝旧目录登记、指向 `.local` 的代码链接和导入环境。
已封存的恢复包整体同盘改名至 `.runtime/deployment/recovery/`，封存数据与校验清单保持原字节。

涉及 Agent 的路径切换复用空闲门禁，复制同一暂停标记后切换挂载；只有本机、公网、Worker 和两侧门禁
验证通过才恢复入口。健康检查等待容器重建和公网 SSH 隧道恢复，短暂 502 不立即判定最终失败。

## Alternatives considered

- 直接运行当前工作区：会带入其他任务尚未发布的改动及不匹配的迁移注册表。
- 在正式路径建立反向链接到 `.local`：依然无法安全清理中间目录。
- 只改启动目录：前端、网关、工具与证书的实际挂载仍依赖中间结果。

## Consequences

同一正式版本在迁移期间保留副本，增加少量部署磁盘占用；117 GB 历史完整恢复包使用同盘改名，不重新复制。
旧临时目录的清理与迁移验收分开，制作源码及无关任务产物继续按各自授权处理。
冻结恢复包原说明中的历史绝对路径通过恢复目录外的新位置说明解析，不修改原始封存清单。

## Verification

- 38 项启动、前端切换、迁入、发布门禁和部署预检测试及 8 项网站测试通过；相关 Python lint 与格式检查通过。
- 23 个正式容器保持原镜像 ID；实际挂载、安装的 LaunchAgent、主配置和可执行链接不引用仓库 `.local/`。
- 当前启动登记与已加载管理进程一致；本机和公网 `/ready`、容器健康及两个 Agent 接受入口通过。
- 迁移过程中执行过旧配置及启动定义回退，确认恢复健康后重新完成切换。
- 三个历史恢复包改名后目录 inode 与顶层校验文件摘要不变；完整包解释器可导入 SSL、SQLite 和 FastAPI，导入路径不含仓库 `.local/`。
- 独立比对后清理 12 项旧依赖，保留正式副本与恢复包；旧路径不存在时，手动启动入口及本机、公网就绪复核通过。
