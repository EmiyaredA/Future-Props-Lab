# Agent Note: 网站构建与工作台执行边界

Status: implemented

## Problem

发布后仍打开的标签页可能请求旧哈希资源。工作台的目录 I/O、审批收据和 CLI 适配混在执行流程中，慢目录会延长全站写锁，不同入口也可能对同一 CLI 给出不同的就绪结果。

## Decision

共享发布继续以原子指针切换当前构建。只对当前构建找不到的清单内哈希资源回查旧构建。退役记录保留最多两版、每版最多 24 小时，清理跳过持有共享读取锁的目录。

工作台在写事务外校验磁盘路径，进入事务后复核账号、项目绑定和审批状态。工作台存储模块原子提交轮次与审批收据。执行中的副作用与 SQLite 收据无法同时提交，取消或重启保留结果未知的状态。SSE 在发送前释放数据库连接。

CLI 能力拥有对话传输和就绪检查。Codex 的专用登录和隔离策略决定就绪状态，模型目录单独探测。工作台和 Amadeus 分别拥有自身工具与运行状态。工作台项目将本机目录和部署预设归一为内部值对象，文件访问复用描述符遍历与私有路径原语。

## Alternatives considered

- 只保留旧目录并提示刷新。实际资源请求仍只访问当前构建，导致现有标签页按需加载失败。
- 将目录检查与审批都放入同一写事务。文件系统和 SQLite 并不共享事务，慢磁盘会阻塞其他写入。
- 以成功读取模型目录代表对话就绪。目录故障不能说明专用登录、隔离或对话传输失效。

## Consequences

- 旧标签页可继续读取仍在保留范围内的哈希资源。连续发布超出两版或退役达到 24 小时后需要刷新。
- 项目、CLI 和存储各自承担明确边界，现有 HTTP、SSE 与 SQLite 格式保持兼容。
- Codex 就绪探测额外启动短生命周期 app-server，只读取配置，不创建线程或提交推理。

## Verification

隔离用例覆盖双入口旧资源寻址、淘汰与读取锁、慢目录与绑定变更、SSE 连接释放、审批重放与重启、Codex 隔离及模型目录故障。Web 组件测试独立挂载项目选择器并验证焦点恢复。
