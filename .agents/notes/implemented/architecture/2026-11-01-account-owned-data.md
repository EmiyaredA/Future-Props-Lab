# Agent Note: 账号直接拥有数据

Status: implemented

## Problem

单机部署同时维护平台账号、Workspace、成员角色和功能权限策略，导致数据归属和授权重复。用户要求移除 Workspace，保留账号私有数据与显式文章共享。

## Decision

账号是唯一私人数据所有者，资源与任务保存 `owner_user_id`，操作者字段独立。固定 `admin/user` 两种角色；管理员不能读取其他账号的私人正文、模型目录或调用日志。空间治理、成员邀请、公开展台、跨空间日志和可配置权限矩阵被移除。平台账号治理、注册邀请码、API Key 最小授权、账号/实例运行额度及文章级分享保留。

HTTP、SSE 与 WebSocket 从认证结果取得账号，业务根资源、文件路径与后台恢复显式传递账号。ORM 查询和写入约束作为附加边界，禁止跨账号修改；业务请求不能选择其他私人数据所有者。发布用例先检查文章可读/可编辑授权，再建立源账号会话，不因此开放源目录或其他素材。

管理员维护角色模型模板，可按角色批量同步或选择指定账号；预览保留数量，不暴露私人模型名称。CLI Agent 部署连接保持 TOML 配置，授权按账号、Agent 与用途保存。模板同步使用目录版本校验，保留稳定模型 ID、自建配置和有效默认选择。

迁移 `0116_account_ownership` 将旧空间归唯一活动 Owner，同一账号的多个空间合并，保持资源 ID、历史和文章授权。角色合并为两种身份，旧 Session 与 Management API Key 全部撤销。历史迁移不改写；表重建保留格式降级保护触发器。没有唯一 Owner 或存在无法认领的数据时拒绝升级，不猜测归属。

schema 迁移只生成文件归属清单。正式布局 API 通过短事务更新逐根进度，文件 I/O 在事务外执行；目标为 `accounts/<user-id>/`，头像仍按账号保存。复制使用大小、SHA-256 和原子落盘校验，拒绝路径穿越、链接与异内容覆盖，跨账号验证素材记录。失败保留进度与原文件，重试不重复覆盖。升级期间普通 API 与后台执行器暂停，完成后必须重启应用。正式桌面数据不用于开发升级或自动验收。

本机笔记和多维表格草稿使用 IndexedDB 版本升级，将旧空间索引改为账号索引，保留正文、待提交操作、版本和标签页标识；多个旧草稿使用独立迁移键，避免合并覆盖。社区草稿继续使用文章作用域。

## Alternatives considered

- 仅隐藏空间界面：保留重复权限和默认空间隐含来源。
- 所有账号共用数据：不符合用户选择的账号隔离。
- 每个原成员复制空间：重复素材且改变发布与任务身份。

## Consequences

删除的空间 REST/SDK 接口返回不存在；客户端改用账号身份和有效权限。旧凭据需要重新登录或签发。旧空间原成员不会自动获得 Owner 私人数据；需要共享的文章继续显式发布和授权。

文件迁移保留旧文件作为惰性恢复副本，正常业务不读取旧路径；磁盘空间需要容纳副本。路径冲突和无法唯一归属的旧状态安全停止，须通过正式管理能力处理后重试，不允许直接修改持久数据库。多个原空间的同名接入配置作确定性区分，资源 ID 保持稳定。

产品文档中心受保护路径保持原样；新的账号行为、升级与 API 说明更新在 `docs/reference/account-governance.md`、SDK、官方知识导入源、AGENTS 与项目结构文档。受保护文档仍有旧空间说明与 SDK 引用，需要独立维护，不以生成覆盖消除差异。
