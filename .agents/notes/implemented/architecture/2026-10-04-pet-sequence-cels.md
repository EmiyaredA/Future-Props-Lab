# Agent Note: 完整序列帧登记与片段引用

Status: implemented

## Problem

收步、转向和转角片段需要复用相同完整原画及支撑登记。重复保存完整帧对象会提前耗尽既有 128 KiB 模型 JSON 预算；仅增加片段共享区间不能消除多处相同帧登记。需要减少重复，同时保留完整帧校验、原包兼容、授权素材闭包和原有容量边界。

## Decision

私有 frameSequences v1 增加可选 cels 字典，值是完整帧对象；clips.frames 可混合原有内联对象与登记 ID 字符串。登记不能是别名、引用对象或包含覆盖值。前端安全读取所有声明，对每次引用生成独立帧及嵌套锚点；只查 own key，避免继承属性被误认为已登记帧。合法字典自有的 constructor、toString 或 __proto__ 与其他安全 ID 一样处理，缺失时拒绝。

后端在临时独立副本上展开并沿用原帧、过渡分支及区间校验。所有声明，包括未使用声明，进入授权贴图闭包；每套服饰验证实际 PNG 尺寸和裁切。原始上传 JSON 保留引用形式，CAS 不重写模型。运行内部 clips 仍消费原帧对象，播放器、实际索引、区间时钟、首尾身份及支撑语义不变。

声明数加全部片段帧使用次数共同受原有 2048 限制，同一引用重复使用仍逐次计数。64 片段、每片段 128 帧、128 过渡、128 KiB JSON 以及 PNG／ZIP／解压预算不变。整包图片校验包括未用声明；figure 的懒加载只校验已加载的所选片段，不因登记存在而预载未使用或相邻区间图集。

没有新增公共 REST、SDK 形状、数据库 schema、自主事件或运行配置写回。正式资源、持久数据库与正式 App 重启未在本次实现中操作。

## Alternatives considered

- 扩大 JSON 或图集预算：增加内存和解压成本，不能解决重复登记，未采用。
- 只共享过渡区间：已在此前实现，但每次帧登记仍重复；本次沿用区间并增加独立登记。
- 引用带锚点或时长覆盖：难以核对相同原画身份且易误用支撑，拒绝。
- 运行保留原引用字符串或共享可变对象：会改变 player 接口或让修改影响其他片段，未采用。

## Consequences

共享登记减少元数据体积，不减少实际原画制作、图集像素或视觉验收成本。合法容量样例不能作为完整三服饰和鲸鱼动作包已经满足预算的证明；数字通过也不证明人体自然。旧内联包保持原路径，新资源仍需通过原有 CAS、兼容与隔离逐帧验收。

## Verification

前后端各 49 项新增测试覆盖引用、内联混用、独立复制、未用声明校验、继承／稀疏值、原预算及旧分支／区间兼容。后端全桌宠 473 项通过，隔离 API 验证原引用保留、revision +1、配置和聊天保留、非法包 422 与陈旧 revision 409 不覆盖。前端全桌宠 47 文件 791 项通过；全 lint、format 和公共契约 stale-check 通过。

独立前后端 45 项共同 JSON、16 项额外 JS 恶意输入与 13 项纯资源包案例符合预期。真实隔离 Electron 中引用与展开格式逐 rAF 像素相同，实际图集请求证明 unused 和相邻区间尾段未加载；真实越界 PNG 在解码完成后拒绝且未绘制。首轮过早采样失败保留，修正仅限 ignored harness 等待。证据在 `.local/desktop-pet/frame-cels-contract-qa/`；源码冻结在 `.local/desktop-pet/sequence-cels-frontend/` 与 `.local/desktop-pet/sequence-cels/backend/`。

该 Electron 检查使用合成 PNG，不证明自然动作、完整 App 交互或正式角色资源通过。新原画仍遵守[完整帧修复提案](../../proposed/bug-fix/2026-10-04-pet-whole-frame-motion.md)；此前区间决策见[共享区间 Note](../bug-fix/2026-10-04-pet-sequence-ranges.md)。
