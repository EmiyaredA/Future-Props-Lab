# Agent Note: Models 调用日志迁移

Status: implemented

## Problem

旧站调用日志包含用户请求、供应商响应与用量历史。部分历史任务保存日志标识。目录和凭据迁移结束后，任务迁移之前需要先恢复日志。

## Decision

Models 在隔离维护监听器上按账号与日志 ID 分页，每页一条。保留日志内容、时间、用量和历史密钥描述。目标以批次绑定原账号，写入日志和回执，随后比对源、目标的摘要与计数。

## Alternatives considered

只迁移用量摘要会丢失历史调用内容及任务引用。把日志混入目录迁移页会让请求大小随多条日志的体积增长。

## Consequences

源中计划外账号、错误摘要或目标记录冲突会停止迁移。单个请求超过维护请求上限时也会停止。日志正文通过受控回环维护连接传输，命令报告只保留摘要和计数。

## Verification

`tests/test_model_call_log_transfer.py` 通过隔离监听器验证账号、超过旧维护请求上限的历史响应、错误摘要及重启后重放。
