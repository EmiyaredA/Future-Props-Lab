# Agent Note: Runner 生命周期依赖

Status: implemented

## Problem

多个兼容网站后台执行器把全局数据库工厂和缓存配置作为默认参数。构造另一实例不能明确说明其数据来源，工作台轮次甚至绕过所属 Runner 直接取得全局连接。

## Decision

十三类后台执行器显式接收会话工厂，需要配置的执行器同时接收配置值。网站装配传入其持有的依赖，测试也明确提供隔离工厂。工作台的每个 Turn 继承所属 Runner 的依赖；关闭一个 Runner 不影响其他实例。

数据库短事务、账号绑定、任务租约、恢复及取消规则不变。此批只是装配依赖解耦，执行器内部仍有存储适配逻辑，不把它标为完成全部业务端口化。

## Alternatives considered

- 延迟读取全局工厂只能推迟副作用，不能证明两个实例的数据归属独立。
- 保留默认工厂并新增可选参数仍允许生产调用方遗漏依赖，因此必需依赖没有默认值。

## Consequences

后台执行器构造参数显式化，不改变 HTTP 或持久数据格式。剩余全局数据库消费者与网站工厂继续在后续批次消除。

## Verification

双实例并发测试验证工作台分别使用各自工厂并释放会话，关闭一个实例后另一个继续工作。相关后台任务回归首轮 311 通过、2 跳过；修正一处测试依赖导入后，将其与三项需要回环监听的测试一起在允许监听的隔离环境复查，4 项均通过。依赖边界与实例隔离补充回归 18 项通过，Ruff 与格式检查通过。
