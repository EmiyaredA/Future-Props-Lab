# Agent Note: 文件机制归位与导演台存储独立

Status: implemented

## Problem

公共文件格式声明、字节检查、归档编解码与素材数据库实现混在同一个包。导演台继承素材库的路径适配，并在未注入存储时读取全局配置，导致独立导演台镜像仍依赖素材实现。

## Decision

允许文件类型及 MIME 集合归素材公开契约，格式表只读。MIME 归一化与字节签名、完整文件检查、安全文件名、SVG 规范化、摘要和项目归档编解码分别归 `runtime/files/` 的明确模块，保持原格式和验证行为。旧 policy 与对应实现文件删除，调用方直接使用实际所有者。

目录暂存机制接受已确定的路径，不判断账号权限或业务归属。数据库与文件补偿通过分别定义的创建、删除布局接口运行，具体目录和业务事务仍由调用方决定。导演台独立拥有自己的布局与恢复扫描；文件和动作适配必须接收显式存储，网站与独立装配均构造 `DirectorStorage`。

## Alternatives considered

- 把整个素材包列为共享依赖：会让导演台携带不属于自己的表、媒体规则和配置。
- 复制素材存储后再删方法：产生两份暂存／还原实现，难以保持错误行为一致。
- 一个大文件工具包：继续混合格式声明、文件检查和数据库事务，替换范围不清晰。

## Consequences

文件格式、归档格式、历史表及文件布局保持不变。导演台不再继承素材存储或读取全局配置；业务和存储的进一步用例拆分仍属后续工作。此次保留原有数据库／文件补偿语义，不宣称已完成所有提交结果未知的恢复验收。
