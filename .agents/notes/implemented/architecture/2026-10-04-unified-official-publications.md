# Agent Note: 官方文档统一到普通笔记发布

Status: implemented

## Problem

静态官方文档与用户发布形成两套正文、编辑和维护机制。管理员无法使用现有笔记功能维护官方内容，升级替换静态资源也无法保留其修改。

## Decision

官方是 Publication 的受控库级标记，只有平台超级管理员／管理员能设置；只读、逐篇可见范围、账号授权和角色编辑授权独立保存。新发布默认只读，现有发布迁移为非官方、非只读以保留行为。社区写入统一校验有效角色，再进入同一 Notes、素材或多维表格用例；能力字段显式返回。

管理员主动将来源包导入当前 Workspace，复用普通 version 7 备份事务，创建新笔记及首页，重映射跨库引用。来源映射与成功回执随内容一起提交，重复请求返回原结果。导入不发布，升级不覆盖笔记。旧官方 URL、引用和收藏只解析当前可访问的官方发布；没有静态阅读回退。

本决定替代[静态官方库](../feature/2026-10-02-official-knowledge-libraries.md)、[官方阅读](../feature/2026-10-03-official-knowledge-reading.md)、[图形静态来源](../feature/2026-10-02-technical-knowledge-canvas.md)、[社区](../feature/2026-10-03-knowledge-community.md)及[编排](../feature/2026-10-03-document-layout.md)中关于官方独立静态阅读的约束。旧记录保留当时决定和验证证据。

## Alternatives considered

- 保留静态只读阅读器并增加专用管理员编辑：形成双正文及双授权机制，不能复用普通笔记生命周期。
- 升级自动导入或覆盖：可能未经确认发布内容，且覆盖管理员改动。

## Consequences

管理员需要明确导入与发布。多个独立导入可以产生多个官方发布，旧链接此时显示可访问的选择。来源文件只构建导入包，运行期社区不依赖来源清单。新增迁移保存发布属性、映射和回执；正式数据升级须遵守桌面迁移与停机流程，不在热加载测试中执行。

产品文档中心保持保护；生成 SDK 与 OpenAPI 时使用独立生成命令，不重生成受保护产品正文。

## Verification

后端隔离测试覆盖权限、导入重试、迁移兼容、旧链接及跨发布表格。Web 来源、兼容入口与发布弹窗测试覆盖相同概念；浏览器隔离旅程检查导入、真实发布、图形、刷新和响应式页面。`knowledge:seed:check`、架构、契约、构建与保护检查用于防止漂移。验收结果以本次执行日志为准，未执行的正式数据操作不视为完成。

本次隔离验收：相关后端 182 项通过，迁移兼容新增用例复核 3 项通过；Web 全量 1489 项通过，阅读初始化修复后的相关组件 108 项通过；桌面 Agent 临时数据测试 13 项通过。浏览器验证管理员导入／发布、旧链接选择、全部 93 篇来源文章（阻断外网）、31 个技术图、明暗主题与窄屏、刷新阅读位置及未保存保护。构建、Python／Web lint 与格式、OpenAPI／SDK、导入包漂移检查通过。

文档中心保护命令因任务开始前已有的两份 SDK 正文变更未通过；与起始快照逐字对比确认本任务未改动受保护内容。正式数据库未迁移，管理员私人知识库未实际导入或发布。
