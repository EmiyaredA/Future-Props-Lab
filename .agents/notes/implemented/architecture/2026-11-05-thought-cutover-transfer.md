# Agent Note: Thought 的身份保留迁移

Status: implemented

## Problem

网站的备份导入用来复制内容，会重分配资源标识。正式拆分需要保留文档、修订、历史、访问授权和素材归属，还要从部分已落盘的迁移恢复。

## Decision

封存的旧站数据库只由受控回环维护入口读取。Thought 按原账号和稳定游标传输原始业务标识，先导入根和父节点，再导入历史、表格、个人状态和发布授权。批次内容和结果摘要与写入共用一个事务，同一迁移计划可以在目标进程重启后续跑。旧逻辑空间成员在个人状态中的身份与迁移后的账号归属分别保留。

Thought 重建正文、历史、模板素材关联与文档引用索引，并核对相同来源的摘要。独立 Assets 仅在同轮文件摘要回执已存在且归属匹配时接收知识库、笔记、模板和发布封面的投影。

## Alternatives considered

- 使用普通归档导入会重分配 ID，并改变历史作者及跨服务引用。
- 直接复制整库会跨越服务归属边界，也无法按服务核对回执和文件。

## Consequences

维护入口必须使用独立端口、同一封存来源与显式目标目录。发布、同步与素材原件仍需各自服务的迁移验收。整站切换由覆盖检查和最终验收控制。

## Verification

`tests/test_thought_cutover_transfer.py` 经兼容站正式 API 建立样本，封存后验证旧站恢复、两个独立回环进程中的中断续跑、关系摘要及四类素材投影。演练核对表格删除后保留的附件、文档和表格历史、读者授权以及错误 SHA256 与跨账号引用的拒绝。
