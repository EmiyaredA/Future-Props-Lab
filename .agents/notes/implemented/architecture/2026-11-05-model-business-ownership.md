# Agent Note: 模型业务与主机执行归属

Status: implemented

## Problem

模型服务已有独立数据库与装配，但兼容网站的目录、供应商、日志、任务和治理实现仍分散在旧包。跨应用只需恢复判断或演示地址时也会加载模型实现，目录移动还可能遮蔽同名模块。

## Decision

模型目录、供应商、推理、测试台、转录、模板、额度和演示实现统一归 Model Service，兼容网站协议归 `transport/website`。各类 ORM 在 `storage/models`，父包不聚合加载。独立角色模板为 `templates/policy.py`，避免 `templates.py` 与包重名。

Mac 下载、安装、worker 和进程控制归 `studio/host/local_models`。worker 与依赖锁从主机适配目录定位，配置目录只保存声明。消费方需要的演示地址与结果恢复判断是公开纯契约。

取消的合法状态仍由模型和视觉业务分别定义。共用 `transition_task` 只执行 ID、revision 和业务谓词约束的原子更新；事务由调用者持有，不在原语中提交。

## Alternatives considered

放宽镜像白名单会使 Integrations 携带模型执行器，因此提取地址契约。继续通过模型存储取消视觉任务会混淆业务状态所有者，因此只复用不含状态规则的数据库更新原语。

## Consequences

服务 ID、公开接口、表名和数据格式不变。设置适配继续访问原有登记分区，不因代码搬迁迁移数据。此批完成所有权归并，剩余用例端口化和跨应用内部依赖仍需继续处理，整体提案保持 proposed。

## Verification

模型、推理、本地执行、生成、取消、恢复、额度及演示回归 290 项通过；架构与镜像边界检查 86 项通过。全部 23 个服务源码闭包通过。OpenAPI 不变，部署清单只更新模型源码路径，276 条表归属的表名、所有者与模型名集合保持相同。测试均使用隔离数据库或本地替身，未调用真实模型供应商或安装权重。
