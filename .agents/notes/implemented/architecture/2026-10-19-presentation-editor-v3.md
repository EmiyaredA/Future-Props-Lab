# Agent Note: 演示工坊 v3 与 React 编辑会话

Status: implemented

## Problem

编辑器入口接近文件上限，文件、画布、命令和面板逻辑混合；原文稿缺少原生数据元素和本项目文件互通，导出边界难以清楚表达。

## Decision

保留 React、Workspace 和原项目 API，参考本地 PPTist 的紧凑操作流程。会话、命令、页面操作、对象内容、文件转换与放映按职责拆分，唯一草稿继续拥有 100 步历史、串行保存、输入法保护与 CAS 冲突。

v3 保留既有字段，按类型增加表格、图表、公式、媒体、路径、样式与动画。登记迁移 0101，保留内容、身份、revision 和更新时间；拒绝可能丢字段的旧格式覆盖。临时选择、视口、手势和放映进度不持久化。

后端无写入预检转换 PPTX、JSON 和 `.fplppt`，确认导入重新登记并重映射素材和对象。文件准备位于短写事务之外，失败清理本次文件。全部实际素材引用沿用公共文件库的 Workspace 校验和删除保护。PPTX 用 python-pptx 保留常用原生对象，差异报告标明近似与遗漏；文稿包保留源码与动画。

ECharts 按需使用 SVG；公式用 KaTeX 预览，MathJax 与 TeX 字形在应用本地生成 SVG。构建前把较大字形数据发布为 JSON 资源，公式功能按需读取，不扩充 JS 体积预算。浏览器静态导出共用页面渲染器。放映使用独立临时状态，同源观众窗口先验证项目权限，再接收随机会话通道；Electron 只开放可信发送者的固定演示路径。

## Alternatives considered

- Vue/Pinia 内核嵌入与已确认的 React 范围冲突，也会形成第二份编辑状态。
- PPTX 整页截图无法满足常用对象可编辑要求，未知对象改用逐项报告。
- 含素材身份的 JSON 无法合法继承源空间素材，跨空间采用包内文件重新登记。
- 直接提升前端预算会掩盖依赖成本，采用职责分块和本地字形数据资源。

## Consequences

工坊动画和批注不转换为 PowerPoint 动画或批注。PPTX 导入不是完整 Office 排版引擎，主题字体、母版装饰、复杂路径和样式近似必须检查转换报告。浏览器打印依赖用户选择打印目标；自动播放受浏览器策略约束。

新增面板遵循统一列宽和控件网格，字段说明独占一行，标签不换行；响应式验收检查实际截图，根级不溢出不等于面板整齐。

弹窗使用工坊专属尺寸与密度样式，复杂编辑器在桌面并排显示预览和编辑区，窄屏纵向排列；标题和操作栏固定，长数据及报告局部滚动。共享确认和输入弹窗仅通过可选 `className` 启用工坊外观，不改变其他功能默认布局。图表预览通过容器尺寸重绘 SVG，不缩放固定尺寸画面。

## Verification

覆盖 v3 迁移幂等与身份保留、防降级、隐藏场景导出、原生八类图表、表格及音频关系、文稿包素材重映射与删除保护；前端覆盖共同命令、搜索、页面批量语义、复制身份和对象编辑。浏览器使用 `.local/presentation-refactor/` 的隔离数据库检查新元素保存重开、冲突、放映与五种宽度的明暗主题。质量检查与实际验收结果记录于本地同目录，不使用正式数据。

弹窗紧凑化回归覆盖 34 个组件测试文件、272 项测试与 18 条生产构建浏览器旅程，检查六种宽度、低高度、明暗主题与触控尺寸；复验 Esc 分层关闭、输入法、Tab 循环、焦点恢复、保存撤销和文件交付。实际截图和最终记录位于 `.local/presentation-refactor/dialogs/`。
