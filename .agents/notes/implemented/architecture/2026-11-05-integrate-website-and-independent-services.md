# Agent Note: 合并网站修复与独立服务

Status: implemented

## Problem

兼容网站的构建、工作台、CLI 与公网桌面修复需要随独立服务源码一同维护。两边同时改动了工作台存储、桌面传输和公开契约。

## Decision

兼容网站使用统一构建保留策略。工作台在自身写事务外访问目录，再核对账号和绑定；独立 Agents 复用账号范围的 transcript 读取、恢复和 SSE 版本查询。Agents 追加自有目录绑定迁移，独立项目执行仍由原 Mac 执行就绪门禁控制。共享桌面传输复用公网图像压缩和心跳，保留独立服务的摘要票据和授权回调。Codex 对话共用隔离检查，固定面试任务继续检测其既有执行方式。

## Alternatives considered

- 分别保留两套桌面传输或 transcript 逻辑。两边都会产生协议和恢复行为差异。
- 合并时切换正式启动目录。当前网站会热加载源码，正式数据切换另有停机和迁移门禁。

## Consequences

源码以统一历史维护。独立服务继续拥有各自的数据库和公共路由。兼容迁移 0122 与独立 Agents 的 0003 各自追加，原登记迁移保持原样。

## Verification

兼容网站、独立 Agents 和 Remote 回归覆盖旧资源、账号边界、受控的项目执行路由、审批恢复和桌面传输。由公开 OpenAPI、SDK、服务归属和官方导入包生成检查核验合并后的契约。
