# Agent Note: 热加载的显式公网入口

Status: implemented

## Problem

独立服务热加载入口只生成本机网关，直接把域名转发到 Vite 或本机 API 会遇到来源拒绝，
也可能混淆公网与本机权限。用户需要通过启动参数选择公网访问当前源码，同时保留既有账号和数据。

## Decision

`npm run dev -- --public` 为当前独立热加载进程开启 Studio 公网；
`--public-management` 额外开启管理端，且必须同时指定 `--public`。
参数通过 npm 别名传递到统一启动器；无参数仍只启用本机模式。
域名、端口、SSH 可信指纹与身份文件来自已有配置，密钥不经命令行或日志传递，不改写正式配置。

开发配置投影显式传入公网来源；网关复用正式路由与 Identity 校验，为每个受选网关增加专用回环监听。
Host 与 Origin 精确校验，身份头先剥离再由入口重建，公网请求始终标记为 public。
API、媒体、SSE、业务 WebSocket 和程序清单继续走原路由，页面、源码与 HMR 转发到 Vite。
Vite 只添加明确配置的公网域名，浏览器 HMR 使用当前来源；文件读取范围保持限制。

Caddy 的站点地址中写回环主机只会增加 Host 匹配，并不将监听 socket 限制到回环。
开发模式所有监听显式设置 `bind 127.0.0.1`；公网监听用无站点主机名的地址，
在路由中精确校验公网 Host，避免站点匹配先把合法公网请求拒绝。

启动器先检查凭据和端口，待 Vite 就绪再启动受监督的隧道子进程。
隧道复用 `GatewayTunnel` 的严格 SSH、构建探针、重连与关闭逻辑；部分启动失败和取消均关闭全部已选隧道。
进程登记保存启动参数，重复启动不能静默改变现有模式。

## Alternatives considered

- 直接把公网代理到本机 API：公网请求会进入本机身份边界，不能保证权限一致。
- 只转发 Vite 并改写 Host／Origin 为本机：会掩盖入口来源，并给公网请求本机权限。
- 另起一套业务服务或复制数据库：引入第二实例、锁冲突和数据分叉。

## Consequences

公网访问当前开发源码与现有业务数据；Python 重载会中断在途请求。
云端需有已配置的 HTTPS 及反向 SSH 转发，并支持同源 WebSocket。
管理端保持单独选择和独立凭据／端口；正式服务、数据库迁移和发布流程不由开发参数接管。
状态、日志和运行投影均存于 `.runtime/native-development/`；验证中间结果存于任务 `.local/`。

## Verification

- 隔离配置验证参数传递、凭据权限、端口冲突、Identity 来源投影、重复启动和隧道取消清理。
- 真实 Caddy 与 Vite 使用临时回环端口验证页面、HMR、来源拒绝、未登录拒绝、内部路径拦截与身份头防伪。
- 既有本机启动、网关契约和独立管理隧道相关回归通过；Python 静态检查、Web 类型与代码格式、Note 和文档中心保护检查通过。
- 架构检查有一项与本次改动无关的失败：素材库 `references.py` 使用 `session.info["owned_models"]`，违反会话上下文边界；其余 125 项通过。本次不改写素材库行为。
- 不使用正式数据库，不切换实际公网隧道；真实云端连通性需在用户使用参数启动后核验。
