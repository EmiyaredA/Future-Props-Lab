# Agent Note: 演示工坊自动对齐与尺寸匹配

Status: implemented

## Problem

原有拖动只提供页面级边缘与中心吸附，缩放不支持尺寸参考。对齐命令按元素执行，完整分组可能被打散；面板和悬浮栏各自声明命令，无法统一尺寸基准与禁用反馈。

## Decision

`layoutObjects` 按编辑范围解析同级逻辑对象。未展开分组作为整体，以视觉边界排列；进入组内后参考当前组边界与同级对象。选区顺序决定尺寸基准，框选沿用文稿顺序；任一成员锁定时禁用整个排列命令。

`layoutSnapping` 使用屏幕 6px 触发、10px 释放阈值，分别计算移动对齐、相邻等距和缩放约束。缩放通过现有固定对侧锚点的几何函数求解，只合并可同时实现的约束。图片、矢量图和含旋转成员的分组保持比例，避免无法表达的剪切变换。

两个排列入口共用命令类型、说明、禁用原因与提交函数。辅助线仅在画布预览中绘制；一次手势或命令经 `updateScene`、原草稿历史和 CAS 保存提交。Alt 清除吸附，取消手势与无变化手势不提交。无公共 HTTP、SDK 或持久化结构变更。

## Alternatives considered

- 继续以各个成员做排列目标：会破坏分组内部排版，不能表达同级对象。
- 强制图片匹配任意宽高：违反保留比例的交互选择，改为明确禁用冲突命令。
- 独立保存参考线或尺寸关联：会增加文稿契约与导出复杂度；本功能只提供编辑辅助，不创建持续约束。

## Consequences

统一尺寸保留对象中心和文字字号，不自动调整文本字号或修复溢出。含图片、矢量图或旋转成员的分组可能不能同时匹配不同纵横比；用户可选择统一一个维度。参考图、归档图像与连线不作为布局对象。

## Verification

几何测试覆盖逻辑分组、选择顺序、锁定、等距、屏幕阈值、旋转八方向缩放和比例冲突。组件测试覆盖两个入口、禁用原因、Alt 和取消手势。浏览器旅程使用隔离数据，经正式 API 创建文稿，检查参考线、一次撤销重做、保存与重新打开。

布局几何及控件 35 项测试通过；演示相关回归 20 个文件通过。Chrome 的布局、分组与选区 11 项旅程通过，候选去重后重新运行布局 3 项旅程通过，并核对等距和尺寸辅助线截图。200 元素重叠压力场景通过合并重复约束，把本机每次缩放计算从约 40ms 降至约 1.4ms。

构建、Web lint、改动文件格式、契约检查、官方导入包、Note 与文档保护检查通过。扩展架构检查 55 项通过，`HomeHeroPet.tsx` 的跨功能内部导入导致一项无关失败；全量格式检查另有两个无关文件未通过，均保留原样。
