# Agent Note: 本机 Agent 会话读取与同步

Status: implemented

## Problem

本机 APP 和 CLI 已有编程会话分散在各工具的私人存储中，现有编程智能体目录只回答是否可以执行固定任务，不能提供历史阅读、来源区分和持续同步。将个人会话塞进 Amadeus 的临时执行器会丢失原生身份，也混淆任务授权与私人记录归属。

## Decision

Agent 工作台作为独立 App，按当前账号显式绑定来源。五种只读适配器归 `capabilities/agents/sessions`，账号投影、检查点、FTS5、扫描回执及 SSE 归 `apps/agent_workbench`。Native I/O 在事务外完成，条目和检查点同事务提交；提交后发送持久失效事件。每个来源独立调度，文件监听与周期校准互补，原生 OpenCode SSE 触发快照补读。

APP／CLI 来自原生证据，无依据时保留未知；同一原生身份在多个文件出现时去重。Pi 保留元信息祖先与分支路径。原端格式升级、任务执行、发送和控制不进入本批。阅读能力不依赖 CLI 登录或执行开关。

新来源绑定同时要求浏览器 Session 与桌面传输校验后的私有标记。SQLite 串行化来源分配，阻止不同账号通过重叠根目录认领同一私人来源。投影、全文检索、变化流和附件都校验账号；SSE 周期性重验会话有效性。附件只允许已引用、在授权根内的普通文件，以目录描述符逐层打开并拒绝链接。

## Alternatives considered

- **复用受限 CLI 对话执行器** — 配置和事件已有基础，但其临时会话策略与个人持久记录不兼容，且不能代表原 APP 实例。
- **只做历史导入** — 能快速提供列表，但不能跟随原端后续活动，无法满足核心需求。
- **统一接管所有原进程** — 上游协议、宿主和独占写入能力不同，本批保持只读，后续按实测能力独立实现续聊。

## Consequences

- 原生记录是上下文真源，FPL 保留可重建阅读副本和检查点；停用／解绑不删除上游数据，清除副本是独立 CAS 操作。
- 追加 `0117_agent_workbench`，使用已有单进程 SQLite 和账号隔离；不引入 Workspace、远程中继或通用 Shell。
- 日志跟随只展示已提交完整记录；无宿主标记时无法可靠区分 APP／CLI。Pi 默认目录缺失时需要选择实际来源。旧 DSH 格式不自动迁移。
- `watchfiles`、`zstandard` 明确登记依赖；桌面打包收集压缩模块及其原生依赖，许可证沿用现有 notices 收集流程。
- 私人会话接口不加入桌面 Agent 操作白名单，不扩大 Amadeus、工坊或个人 CLI 工具权限。

## Verification

`tests/test_agent_workbench.py` 在独立 FPL 数据库和合成原生来源上验证历史、增量、轮转、压缩帧、Pi 分支、只读 SQLite／HTTP、账号、CAS、附件及 SSE 失效。`web/tests/agent-workbench.test.tsx` 验证筛选、授权和暂停恢复。`web/e2e/agent-workbench.spec.ts` 在独立账号和数据库上验证四种宽度、明暗主题、滚动位置与来源交互。其余契约、架构及构建检查按仓库入口执行；真机矩阵和压力测试的实际执行范围记录在本地验收报告，未执行的项目不计为通过。
