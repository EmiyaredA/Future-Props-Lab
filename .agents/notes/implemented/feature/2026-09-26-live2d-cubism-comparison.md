# Agent Note: Live2D 工坊 Cubism 对照与尽力转换

Status: implemented

## Problem

FPL 原生角色文档可以编辑图层、骨骼和动画，但不能读取 Cubism 运行模型。用户需要在同一工坊对照已有模型的动作与表情，并把可映射的绘制网格和参数带入新工程；原项目及其可编辑格式不能被转换覆盖。现有编辑器的树和属性控件也占用过多空间。

## Decision

保留 `CharacterDocument` v3 和原生渲染器。一个 FPL 项目可在同一 Workspace 挂载一个 Cubism ZIP 附件；服务端检查路径、引用、格式与容量，浏览器再用用户提供的官方 Cubism Web SDK 5-r.5/Core 真正加载 `.moc3`。模型页提供 FPL、Cubism、并排视图、参数试调、头像和半身取景及七种执行状态映射；运行包只有一个明确命名的待机动作组时自动预填待命映射，其余不确定的状态留空。转换从 SDK 读取绘制网格、UV、贴图和参数关键值，生成新的 v3 工程包；报告不支持的物理、姿势、遮罩和混合差异，确认后以源项目 revision CAS 原子创建新的可编辑项目。附件写入和映射保存也使用 CAS。带附件导出采用 `.fpllive2d` 包版本 4，并原样保存运行 ZIP；无附件仍为 v3。

编辑器树使用搜索、折叠和约 24px 行高；常用按钮约 28px，正文及次要文字分别约 12px、11px。项目卡片维持现有统一组件。官方 SDK 和着色器固定在仓库的 `web/vendor/cubism-sdk-5-r5/` 与 `web/public/cubism-shaders/`，记录压缩包哈希及原始许可文件；不带入 SDK 示例角色。Amadeus 运行头像不在本次切换。

## Alternatives considered

直接将 `.moc3` 宣称为 FPL 可编辑模型会误导用户，也无法重建 Cubism Editor 源工程。让转换覆盖原项目会破坏现有绑定与版本历史。复用 Open-LLM-VTuber 的示例模型或运行代码会引入第三方素材与不明确的再分发边界，因此只参考其模型清单、动作组和表情映射交互。

## Consequences

迁移 `r0073_live2d_cubism_attachment` 增加附件记录，源 ZIP 位于项目的 `cubism/` 子目录。转换保留可检查的原始运行模型，但多参数联动、复杂遮罩、混合、物理和姿势只能近似或留给后续手动绑定；转换副本不伪造骨骼。SDK 使用范围是本地内部验证，支持任意模型的产品对外发布前必须核查 Live2D 可扩展应用许可。受保护的产品文档中心没有因本决策重新生成。

## Verification

后端测试覆盖预检、缺失资源、旧版格式、附件 CAS、七状态映射、v4 往返和转换创建新项目。隔离 Chrome 用官方 SDK 示例模型完成 `.moc3`、动作及物理真实播放，并检查 34 个绘制部件、25 个参数的转换包可由后端解析和渲染；实际测试样本不提交。迁移在临时数据库升级测试中验证。Web 相关单元测试、定向 lint、格式、OpenAPI 与 SDK 生成文件检查通过。完整 `contracts:check` 仍报告受保护文档中心的 Live2D SDK 参考陈旧，按仓库保护规则未改该文件；全仓既有的 TypeScript、lint 与资产哈希错误单独记录。
