# Agent Note: 文件真实预览与紧凑卡片

Status: implemented

## Problem

首页和文件库只为图片请求缩略内容，视频、音频和文档显示固定图标，无法辨认实际素材。文件和应用卡片的固定列数与留白降低宽屏信息密度。

## Decision

asset_store 在归属校验后捕获不可变素材信息并结束读取事务，提供受限预览元数据和 revisioned 派生图。media_rendering 负责有超时的视频帧、时长和前 60 秒真实波形；Pillow 编码 WebP，不增加 FFmpeg libwebp 要求。PDFium 每次只在独立子进程读取或渲染一页，30 秒超时，最多两个处理槽位。缓存命中不跳过账号校验，派生输出原子替换，取消时等待写入线程结束再清理。

Web 文件模块统一缩略内容、文本阅读、PDF 翻页和自绘播放器，首页分类导航与预览按钮分离，原始媒体只在打开弹窗时读取。文档正文最多 64 KiB，Markdown 按文本展示；Office 与压缩包保留下载。Radix 管理弹窗焦点与键盘约束，鉴权 Blob 沿用统一取消和 URL 回收。

文件网格按容器宽度渐增至六列，媒体卡约 160px；应用宽屏三列、最小高度 140px。减少留白与图标尺寸，保留文字字号和触摸操作目标。

## Alternatives considered

- 浏览器列表直接加载原始音视频：会因大量文件造成带宽和解码开销，改为按可见性请求小派生图。
- 装饰性随机波形或文档骨架：不能证明实际内容，使用真实采样、真实 PDF 页和正文。
- 浏览器原生 PDF／媒体工具栏：外观及交互跨浏览器不一致，采用项目控件和分页图像。
- Office 转换服务：超出第一版格式范围，也会增加部署依赖，暂用下载。

## Consequences

增加 pypdfium2 依赖和只读预览接口，无 schema 迁移。私人派生缓存占用账号目录空间；原始媒体播放仍在点击后通过现有 Blob 读取，不引入后台自动播放或供应商请求。SDK、OpenAPI 与 API 参考同步；文件 SDK 参考仅因公共契约变化由原生成器追加方法和页码参数，不因 Note 整理迁移、重写或删除文档中心内容。

## Verification

后端测试覆盖真实视频及短片回退、音频波形、扫描及多页 PDF、文本截断、加密损坏输入、跨账号缓存拒绝、并发原子写入与超时清理。Web 测试覆盖懒加载、导航与预览分离、文本转义、PDF 翻页缩放、播放进度音量、重试及只读入口。浏览器验收使用隔离数据库与 `.local/file-previews/` 产物，检查真实播放及 390/768/1280/1600/1920 宽度和明暗主题。

最终验收：102 项相关后端／SDK／架构测试、全量 Web 283 文件／1818 项测试、最终 3 条 Chromium 旅程通过；最终代码另跑 26 项文件相关 Web 测试。lint、format:check、contracts:check、build、官方导入包检查和三项 Agent Note 校验通过。文档中心保护脚本仅命中文件 SDK 参考页的新增接口生成内容，需与工程 Note 整理分开提交；无其他保护路径变更。
