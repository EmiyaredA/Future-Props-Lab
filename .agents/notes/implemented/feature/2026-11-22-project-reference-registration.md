# Agent Note: 项目内参考与上传图片登记

Status: implemented

## Problem

参考区原本可直接选择账号设定库、公共文件或其他项目素材，绕过项目已收录集合。新图片上传只成为文件，不会出现在人设、场景或道具中。原有建卡和项目收录是两次保存，响应丢失或重试可能留下遗漏和重复；异步登记与排队草稿保存也可能互相覆盖项目卡集合。

## Decision

- 所有参考入口限制当前项目，设定卡列表和分类标签只消费已收录卡。外部来源先通过项目素材管理明确导入或收录。新增关联在服务端检查成员资格，历史关联保留并在生成前要求修复。
- 点击上传和本地拖入共用分类流程，新图片按用户明确选择创建独立主卡，视频与音频只进入项目文件。文件上传和 Visual 元数据结算分开，网络和文件 I/O 不占数据库写事务。
- 项目图片登记核验原件内容身份，在同一 Visual 事务中创建或复用卡、更新项目收录和记录回执。复用仅限当前项目同类有效卡，多个匹配须明确选择；不推断语义、不覆盖采用图、不自动创建变体。
- 回执使用既有 `visual` 资源种类与分域请求摘要，兼容独立库的既有 CHECK 约束；内容登记键按分类和经过 Assets 校验的内容身份分域。两种装配显式提供素材检查和画布保留检查，不通过 ORM 元数据探测服务表。
- 登记进入画布保存队列。登记期间已排队的草稿补入本次新卡，保留并行节点编辑；登记之后的显式移除不被恢复。失败保留上传文件和原请求身份，切换目标后迟到结果不绑定到新镜头。

## Alternatives considered

仅在选择器过滤无法阻止拖入或直接 API 建立外部关联。前端连续调用建卡和收录不能保证原子性。新增表保存登记映射会要求迁移，而现有操作回执已提供账号和项目作用域的持久幂等键，因此复用该机制。

## Consequences

账号设定库仍可独立管理，项目设定列表改为严格成员视图。历史未收录引用可以继续查看和编辑其他内容，但生成须先补收录、替换或移除。已经完成的上传即使登记或引用失败也保留在项目中；重试不会再次上传文件。工程契约、OpenAPI 和 SDK 更新，不重新生成受保护产品文档中心。

## Verification

隔离的兼容网站与独立服务测试覆盖三种分类、内容复用、多个匹配、CAS、回执重放、并发、跨项目和账号限制，以及历史关联修复。Web 测试覆盖分类取消、混合上传、失败重试、范围过滤和登记期间的草稿保存。Playwright 验证项目选择器、上传分类建卡、侧栏即时收录、分镜拖入、刷新恢复和历史参考生成拦截；类型、格式、架构、生成契约与构建按工程流程检查。

定向后端 20 项、Web 参考相关回归及完整 Playwright 流程通过；类型、ESLint、Ruff、契约生成物、Agent Note 和生产构建检查通过。扩大回归发现两个既有问题：Assets 删除保护读取非约定的 `session.info["owned_models"]`，以及独立快照导入将素材类型字典直接与集合做并集；本次未改动这两个职责。历史迁移测试需本地回环端口，放开测试端口后通过。验收输出保存在忽略的 `.local/project-reference-registration/`。
