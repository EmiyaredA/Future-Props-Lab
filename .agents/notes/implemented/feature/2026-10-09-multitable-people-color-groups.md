# Agent Note: 多维表格人员、填色与编组

Status: implemented

## Problem

多维表格已经能筛选、排序和按字段分组，但还不能按条件给整行上色，不能记录空间成员，也不能把相邻字段收成表头编组。飞书里的字段捷径不是这次要补的能力。

## Decision

人员、填色条件和编组都写进现有表结构。人员单元格保存用户 ID；新出现的 ID 必须是当前 Workspace 的有效成员，文档里已经存在的离开成员可以继续保留。查询页只返回本页仍在空间中的显示名，社区页面不读取成员目录。填色条件挂在视图上，表格和看板按保存顺序使用第一条命中规则。编组挂在数据表的 JSON 列上，表头只合并当前视图里相邻的同组字段。

备份输出 version 9，并继续读取 version 1–8。缺省编组和填色条件在读取时补空，不改写旧历史。

## Alternatives considered

- **把编组放进每个字段的 config** — 名称会在多个字段上重复，改名和删除容易不一致。
- **查询时返回整个成员目录** — 社区读者会看到源空间的全部成员，超出单元格本身需要的显示名。
- **离开成员一律清空** — 历史记录会在成员退出时被改写。

## Consequences

- **收益**：填色、人员和编组随现有原子批次、历史和备份一起保存。
- **代价与已知上限**：社区编辑不能从源空间成员目录里改人员；把已经从文档中消失的离开成员重新写回会被拒绝。静态导出和 CSV 仍使用用户 ID。不提供字段捷径、公式或跨表关联。

## Verification

`tests/test_thought_table_people.py` 覆盖成员、离开成员、非法编组、version 9 导出和缺省字段的 version 8 读取。前端组件测试覆盖填色入口、选项色块、离开成员显示和编组菜单。
