# Agent Note: 多维表格界面与应用主题统一

Status: implemented

## Problem

多维表格把数据表、视图、配置和危险操作挤在同一工具栏，表头常驻列宽滑块、单元格常驻下拉框。信息层级弱，宽度不足时进一步挤压记录；未定义文字色变量和固定紫色背景也偏离应用主题。

## Decision

界面沿用应用的暖白／米灰和橙色强调，以及深色灰绿主题。数据表导航、视图标签、工具栏各自承担单一职责；容器低于 900px 时自动收起 184px 数据表侧栏，个人折叠偏好按账号、访问上下文与文档隔离，响应式切换不覆盖偏好。

视图配置共用一份本地草稿，分基本、筛选、排序、分组和列显示页签。新视图确认校验后提交，关闭不创建空视图。历史、CSV 和删除操作收进现有自绘菜单，权限和确认流程继续由主编辑器维护。

网格使用 40px 表头、44px 虚拟记录行，固定行号与名称列。列边界拖动只修改本地展示，完成后提交一次共享列宽，取消恢复原值；已保存宽度优先。选项颜色是用户数据，仅作为标签色点及混合底色，文字保持主题对比度。记录详情使用同一 Radix Dialog 的右侧抽屉变体并恢复调用方焦点。

手机网格将固定名称列的展示宽度限制在可用网格的一半，避免遮住可滚动字段；该展示适配不改共享列宽，回到宽屏仍读取已保存宽度。

## Alternatives considered

- 直接照搬预览图蓝白配色：与应用主题不一致，因此只采用布局层级。
- 保留顶部数据表标签：省横向空间但表与视图层级不明确，改为可折叠侧栏和窄屏选择器。
- 拖动每帧保存：增加批次和冲突风险，改为结束时一次提交。

## Consequences

展示组件经显式回调使用现有控制器，不改后端、API、数据库或草稿保存协议。菜单、配置页签和个人布局切换不产生文档写入。正文嵌入和社区只读沿用当前权限；弹层、看板与日历采用相同主题与焦点规则。
