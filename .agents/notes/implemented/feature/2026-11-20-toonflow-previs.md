# Agent Note: 视觉工坊 Toonflow 画布与白模预演

Status: implemented

## Problem

视觉工坊已有项目、画布、模型生成与验收，但缺少从搭景、演员走位和机位到逐镜交付的白模工作流。

## Decision

固定 Toonflow 上游版本。Vue Flow 承载画布视口，现有控制器维护节点、连线、布局和编辑历史。按需载入 TrumanMap，在同一项目下保存多个场景。用户可切换回旧画布。

场景格式版本独立于 revision。两种部署均校验视觉项目归属。快照复制得到新场景身份和 revision。已回填素材保留生成时的原始场景版本。

导出使用本地 WebGL 和 WebCodecs，长边 1280，24 fps，优先 MP4，其次 WebM。PNG 与成片复用节点上传。每个文件使用独立请求 ID 确认与重试，未完成的批次留在当前页面内存。镜头表作为自包含 HTML 下载。

场景管理页与画布复用项目顶栏。左栏列出场景，右栏承接新建；加号将焦点移至同一名称输入框。布景插图以局部 WebP 随前端构建分发。窄屏保持只读，列表置于工作区上方。

## Alternatives considered

- 整体迁移 Toonflow 服务端涉及替换项目、凭据、生成驱动和资产契约，超出首期范围。
- 另建白模项目会增加场景、镜头和生成素材的手工同步。场景直属视觉项目并共用快照和素材生命周期。
- 整套上游大型素材包会放大编辑器构建产物。首期保留基础素材、常见布景、角色动作和编辑器依赖的造型库。

## Consequences

网站和独立服务分别通过接续迁移加入场景存储。编辑器使用内置素材。模型驱动的脚本拆解、镜头批产和时间线交接留给后续。

## Verification

隔离后端测试覆盖场景 CRUD、冲突、账号隔离、快照和回填回执。浏览器验收使用隔离的真实服务。构建核对分包大小和静态依赖环。

新版工作区的画布入口和编辑布局见 [统一新画布与嵌入白模编辑器](2026-11-20-previs-embedded-workspace.md)。
