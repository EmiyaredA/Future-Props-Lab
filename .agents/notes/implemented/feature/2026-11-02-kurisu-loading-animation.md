# Agent Note: 红莉栖统一加载动画

Status: implemented

## Problem

页面、内容区和部分素材预览使用不同的圆环或纯文字反馈。用户要求它们采用视频创作项目中的红莉栖小跑，同时保留按钮内紧凑反馈、真实传输进度和等待提示。

## Decision

共享 LoadingState 的 page 与 region 模式使用 LoadingCharacter；独立文件预览、剪辑工作区、创意详情与素材选择等内容等待入口接入相同反馈。行内按钮和受限缩略入口保留原有反馈，任务执行状态不与素材播放状态合并。

素材取自 dsh-pet 的 `pet-packs/kurisu/source/library/a010/attempt-6/原地小跑.mp4`，源 SHA-256 为 `fd19d8ecc3afe1cd879bf8bb0296a1bb7aa49f6d8c217e11ba9d0906a31f0631`。用户反馈原 48 帧剪辑存在回摆感后，重新核对连续步态与首尾五帧的姿势、手臂和脚部运动方向，选取第 113–131 帧的 19 帧完整周期；首尾手臂与脚步运动方向余弦分别为 0.91、0.93。使用原有透明抠像帧，按 alpha 包络加 8px 边距裁切 `[208,44,440,338]`，以 Lanczos 等比缩小并居中于 150×192 画布。视频按原始 24fps、VP9 CRF 30、yuva420p 编码为约 0.792 秒循环，不倒放、不停帧、不补帧、不叠化、不重新生成角色。派生视频 69466 字节，PNG 首帧 40983 字节；输出哈希由生产资源检查固定，素材纳入 Git LFS。同一周期另以原画布 640×360 无损编码并完整重复 12 次，生成 9.5 秒项目候选，按用户要求上传 a010 节点供查看。

视频在 150ms 加载延迟结束后挂载，开始播放前保留静态图，失败后仅显示静态图。减少动态效果时不挂载视频；页面隐藏时暂停，恢复后继续，卸载清理监听与播放。人物为装饰，无障碍状态、进度与错误恢复仍由原组件和业务入口拥有。

浏览器可能在资源已完整缓冲后仍仅停留在 HAVE_METADATA；播放请求不能以已解码首帧为前提，否则静态首帧可能一直不被替换。组件显式声明自动播放与默认静音，可见时立即请求 play，由播放 Promise 等待媒体就绪；保留隐藏暂停、失败回退和卸载保护，不再依赖 loadeddata 触发播放。

## Alternatives considered

- 直接引用账号内素材 API：加载反馈会依赖认证与业务资源生命周期，不适合全站启动。
- 发布完整 10 秒、约 8.6 MB 的视频：内容为重复周期，增加等待与解码成本。
- 把按钮内图标一并替换：超出用户确认的范围，也不适合紧凑操作区。

后续统一视觉与行内调整见[琥珀仪表方案](2026-11-03-unified-kurisu-loading-scene.md)。

## Consequences

新增约 201 KiB 静态资源，播放不依赖 dsh-pet 本机目录或账号文件。不支持 VP9 透明视频的浏览器仍可通过静态图与文案理解加载状态。后台任务、账号数据与 API 契约不改变。

## Verification

82 项相关组件测试和 4 项素材检查测试通过，覆盖延迟、page/region、行内保留、首帧与缓冲回退、动态效果偏好变化、播放及解码失败、后台暂停、卸载与过期 Promise。浏览器测试覆盖明暗主题和桌面／手机宽度下的整页、区域播放、连续循环及透明通道，并验证减少动态效果时静态回退。构建、Web lint、格式、Git LFS 与文档保护检查通过；Note 树、格式、归档校验通过（使用 `node --import tsx` 避免沙箱限制 tsx 的 IPC 监听）。验证记录、逐帧对照及截图保存在已忽略的 `.local/loading-kurisu/`。

2026-11-03 的预览回归复现首个视频 HAVE_METADATA 且暂停、其余视频正常播放。修正后检查全部 13 个动态实例 readyState=4、data-playing=true，连续采样的 currentTime 全部变化；暂停和恢复均覆盖所有实例。回归测试覆盖尚无已解码帧时仍发起播放请求，防止只检查元素存在而漏过实际播放停滞。
