# Agent Note: 参考素材格直接上传

Status: implemented

## Problem

生成器通过“添加素材—本地上传—素材类型”才能选择文件，空素材图标没有直接操作。
画布和看板的版本选择器横向撑满，与大量分隔线、留白共同挤占提示词编辑区域。

## Decision

共用 `ProjectMediaPicker` 的主按钮直接调用自身隐藏文件输入；图片、视频、音频分别使用
对应格式过滤与媒体图标。全能参考区按图片、视频、音频排列，每类素材末尾各保留一个对应类型上传格。
模型不支持的类型不新增入口；已有不兼容引用保留原修复路径。
本项目、跨项目、文件库及设定卡来源保留在小型“更多来源”和“引用”入口。
主操作不再打开来源菜单，键盘焦点和 Escape 返回该菜单的实际触发按钮。

上传继续调用账号范围的正式文件接口，受原有引用数量、只读和处理中限制。
取消文件选择不写入；失败显示原错误并允许重新选择同一文件；上传本身不提交生成任务。
静态参考缩略图不下载完整视频，主动预览仍读取正式内容。
紧凑上传格和素材预览共用 64px 边长，全能参考标题行统一 24px；旧列表按钮样式只作用于直接子按钮，避免三列模板挤偏图标和缩略图。
提示词版本选择限制在 120px，操作按钮紧邻；制作区收紧间距、移除装饰分隔线，
视频／分镜图及画布定位改用带标签与提示的图标按钮。

分镜制作类型切换随后按用户要求由[分镜固定图像与属性区收紧](../simplification/2026-11-21-storyboard-image-workspace.md)
取代，分镜工作区仅编辑图像；本文的参考素材上传规则继续适用。

## Alternatives considered

- 继续以多层添加菜单作为主入口：不能满足直接点素材图标上传的操作要求。
- 删除项目和设定卡来源：会损失已有素材复用能力，保留为次要入口。
- 为画布和看板分别实现上传逻辑：容易导致权限、数量、错误和草稿行为分叉。

## Consequences

不新增接口、存储或迁移，不改写项目分镜和素材关联。已有拖放、引用排序及草稿保存沿用原实现。
素材较多时在参考条局部横向滚动，各上传格跟随在对应类型素材末尾；窄屏版本操作按自然宽度换行。
遵循[能力实现契约](../../../../docs/architecture/capability-contracts.md)与
[开发与验证流程](../../../../docs/operations/development-workflow.md)。

- 生成器、分镜、引用拖放与提示词版本用例验证原草稿与生成提交契约。
- 实际浏览器验证三个格子均触发文件选择器；验证画布图片生成器、分镜视频制作区、
