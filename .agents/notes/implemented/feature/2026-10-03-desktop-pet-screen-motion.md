# Agent Note: 桌宠连续运动、边缘攀爬与拎起姿态

Status: implemented

## Problem

运行窗口按间隔瞬移，角色迈腿与移动距离脱节；拖动只播放一次反应，无法持续表达被拎起。透明空白决定边界时角色无法真正靠边，也不能可靠检查攀爬和高处滑翔。编辑器、聊天及多个移动入口容易让迟到请求恢复旧轨迹。

## Decision

`locomotion/controller.ts` 唯一管理活动、手势、暂停和休息。常走动／多待着每次活动结束后等待 7／17 秒；轨迹以 DIP 和尺寸比例推进，随机源可注入。150 毫秒或超过 4 DIP 进入持续拎起，松手留在确认位置，仅自主决策可滑翔。攀爬与滑翔分别由习惯布尔值控制，“不乱动”关闭所有自主活动；Live2D 继续使用原有水平移动。

公开 `setLocomotion` 接收运动帧，物理姿态与作者事件分离；表情、台词与音效仍来自原事件。步相只由宿主确认的位移推进，攀爬使用纵向距离，避免侧边姿态校正驱动脚步。可见 alpha 保护全部肢体，脚底用稳定的骨架锚点，不能把抬起的脚当作新的地面。拎起围绕抓取点补偿缩放与摆动，红莉栖通过部件身体、手臂和腿部姿态表达滑翔，保留三套服饰及遮挡结构。

桌面私有协议仅接受可信桌宠主窗口。环境 revision 拒绝旧显示器边界，generation 取消未完成活动，sequence 拒绝重复与乱序。客户端每次仅有一个在途请求，使用最新目标；旧回执不能恢复取消的姿态。手动移动可换屏，自主活动限定当前工作区；窗口透明边缘可以越界，角色、气泡和按钮向内布局。聊天、联动和隐藏在宿主及客户端中断自主运动，失败停在确认位置并显示原因。

试玩在虚拟工作区使用相同运动帧与分层引擎，五种姿态可同步到已有桌宠，但不自主移动真实窗口。`PetHabits.edgeClimbing` 与 `highGliding` 默认 true，旧 JSON 读取补默认，不写回；配置保存继续使用 document CAS，不新增事件、公共路由或数据库 schema。

## Alternatives considered

- 给每种运动添加独立运行定时器：取消、聊天与显示器变化容易争抢窗口。
- 用一次性的拖起或跳跃事件模拟拎起：事件超时会让长按姿态恢复待机。
- 松手立即下落／滑翔：破坏用户放置在高处的位置。
- 以透明窗口或逐帧最低 alpha 作为脚底：前者留出大空白，后者因抬脚而抖动。
- 直接修改动画内部状态或整体硬转人物：耦合运行页与角色材质，服饰接缝和头部姿态不自然。

## Consequences

运动轨迹、位置回执、摆动和试玩只在内存，关闭或身份变化后清理，不恢复未完成活动。二十多项实际轨迹／动画测试与 Electron 窗口测试守住契约；旧桌面桥保留降级行为。红莉栖服饰资源更新沿用并行任务的公开上传与授权快照接口，没有替换其素材。通信失败不重试旧轨迹，需重新打开或收到新的宿主环境后恢复。

## Verification

组件与纯控制器测试覆盖阈值、按住稳定、拖动摆动、取消、松手原地、开关、速度缩放、左右攀爬、滑翔阈值、落地、负坐标与暂停恢复。真实分层引擎验证脚部顺序、忙碌反应替换、左右接触、展开手臂、持续悬挂和抓取点连续性。私有宿主测试覆盖可信主窗口、序号、取消代次、显示器拔除、手动换屏、聊天、隐藏恢复与关闭；前端测试覆盖单请求、迟到回执及失败恢复。

隔离 Electron 使用本地鲸鱼与红莉栖三服饰数据包，记录真实位置回执、连续截图和明暗姿态图；同时回归实时草稿联动、保存、恢复、换装、点击穿透与聊天，不调用真实模型。OpenAPI、Web 和 Python SDK 类型已更新。产品官方使用与排障正文、允许维护的 API 参考及目录职责同步更新；受保护 SDK 正文保持原样，其已知 stale 检查单独报告。
