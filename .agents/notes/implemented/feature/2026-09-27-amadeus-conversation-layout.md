# Agent Note: Amadeus 对话侧栏与数字人舞台布局

Status: implemented

## Problem

当前上下文位于消息上方，占用对话阅读高度；历史对话默认关闭且切换会话后自动收起。数字人展开时，首次约 520px 的窗口也难以同时容纳侧栏与对话。

## Decision

Amadeus 的左侧栏上下放置当前上下文和对话历史，两块卡片在页面加载时均展开，并可独立收起。历史列表在固定搜索框下独立滚动，切换或新建会话不关闭历史。当前上下文以紧凑窗口行呈现标题、所属应用和实际选中控件；单窗口不重复显示窗口数量、活动状态、空选中或普通页面路径。三个及以上窗口保留当前窗口摘要和“展开全部”，其余窗口按列表展示。消息区仅保留对话、相关操作和输入框，会话文件改为浮层。数字人舞台首次加载收起，用户可通过现有按钮展开。

首次打开窗口的基础宽度约为 900px；已有尺寸按工作区约束后恢复。舞台展开期间只持久化收起状态的基础宽度，页面重新载入时同步收起原生舞台，避免重启或热重载后得到意外加宽的窗口。窄窗口通过侧栏缩放和输入工具栏换行保持对话可用；舞台在空间不足时覆盖于右侧。

## Alternatives considered

- **历史与上下文各占一列** — 两列会明显压缩对话宽度，用户明确选择同一左栏的上下卡片。
- **保留消息上方的上下文面板** — 仍占用对话阅读空间。
- **继续以约 520px 首次打开** — 两块展开卡片会使对话区过窄。

## Consequences

- **收益**：上下文、历史和数字人各有稳定位置，对话区不再被持久信息面板占据。
- **代价与已知上限**：已有窄窗口仍按保存尺寸打开；在此尺寸展开舞台时使用覆盖式侧栏。卡片开合状态只在当前页面会话中保留。

## Verification

`web/tests/features/amadeus-context-panel.test.tsx` 和 `web/tests/features/amadeus-layout.test.tsx` 覆盖卡片默认及独立开合、多窗口摘要与舞台默认状态。`desktop/tests/amadeus-window-geometry.test.cjs` 覆盖首次宽度、保存尺寸恢复和舞台基础宽度。`npm run test:desktop:amadeus` 在临时数据目录验证热重载收起舞台、历史切换和 400/520/900px 布局。另运行 Web 测试、lint、格式、构建及 `npm run verify-notes`。
