# Agent Note: 基模型中心高保真 UI 重设计

Status: implemented

## Problem

基模型中心已经具备模型目录、连接管理、模型测试、测试工具和调用日志等完整业务流程，但各页面的视觉层级仍偏向通用表单与大块留白，供应商、模型能力、测试状态和日志详情之间的关系不够快读。上一轮紧凑化解决了间距和侧栏行为，但没有形成一套能承载多栏工作区与高密度数据的页面视觉语言。

## Decision

以本轮生成的高保真视觉稿作为呈现层基准，在不改变 API、权限、路由、保存机制和测试数据结构的前提下，完成基模型中心四个子页面的统一视觉重设计。模型服务使用供应商概览卡与模型密集表格；模型测试使用会话、测试区、参数三栏工作区；测试工具使用工具列表加详情/试运行检查器；调用日志使用统计、筛选、密集表格和详情抽屉。所有页面复用现有暖橙主题 token，并使用靛蓝辅助信息、橄榄绿健康状态和浅色/暗色表面层级。

桌面端优先呈现完整上下文，平板和移动端继续使用现有抽屉、堆叠与局部滚动行为。文本对话、图片生成、视频生成、语音识别和实时语音五种测试入口共用同一工作区头部与主题，不复制业务状态。新视觉层通过模型功能样式入口集中加载，避免继续扩大各子页面之间的样式漂移。

## Alternatives considered

- 只继续增加全局 CSS 覆盖：改动快，但无法表达供应商概览和模型测试三栏的信息层级，且容易让不同子页面继续各自漂移。
- 只重做模型服务目录：能改善最常见入口，但测试、工具和日志仍然割裂，不能形成基模型中心的一致工作台体验。
- 以营销型大卡片和渐变作为主视觉：视觉冲击较强，但会牺牲模型基础设施场景需要的扫描速度、表格密度和暗色主题可读性。

## Consequences

- 模型服务、模型测试、测试工具和模型调用日志获得一致的紧凑高保真视觉语言，橙色保持品牌主操作焦点，靛蓝与橄榄绿承担辅助信息和健康状态。
- 既有模型测试模式、参数保存、任务状态、错误反馈、详情抽屉、筛选和表格交互继续复用原有业务逻辑；未新增后端接口、数据结构或权限规则。
- 桌面多栏布局在窄屏下收敛为堆叠和局部滚动，测试模式标签保留横向可操作入口，移动端触控尺寸与键盘焦点行为沿用公共组件。
- 文档中心受保护路径保持不变；本轮生成图只作为视觉参考，不作为产品运行时资产。

## Verification

- 模型中心专项测试：6 个文件、43 项测试全部通过。
- Web lint、改动文件 Prettier 检查、Web build 和文档中心保护路径检查通过。
- 覆盖模型服务、模型测试五种模式、测试工具和调用日志的浅色/暗色 token 复用与 390/768/1280/1920 宽度规则。
- 新增视觉层文件保持在项目要求的 600 行 CSS 单文件上限以内。
