# Agent Note: 视觉工坊剧本、设定卡与白模交接

Status: implemented

## Problem

项目需要保留分集剧本和设计依据，能够把一场戏试排到白模，再将选定镜头或预演视频回到项目。角色、场景与道具设定和候选图也需要独立于画布节点管理。

## Decision

- Visual 拥有可按集与场编辑的剧本、角色／场景／道具设定卡和场景来源。剧本与卡按版本控制并发写入。父卡和采用的父图随变体固定。项目快照随工程迁移素材并重映射卡片和模型引用。
- 文本模型输出结构化的剧本线索和原文依据，规则生成初始布景和镜头。试排使用真实 3D 视口，确认后创建场景。设定候选图由现有图片队列生成，重复请求重放同一任务。
- 白模使用固定版本的 Toonflow 内置素材表。项目导入只接受内部资源自包含的 GLB，由 Assets 校验归属并保存。导出沿用原镜号，选中镜头使用同一播放顺序渲染画面、视频和 EDL。
- 左侧导航在项目工作台下放置项目素材库。已有项目上下文直接带上项目 ID，从工坊首页打开可搜索的项目选择页。

## Alternatives considered

- 用同一个场景文档保存剧本文字、卡片和白模。独立文档让预演保留来源版本并避免互相覆盖。
- 按上游桌面工作流导入任意外链模型。工坊保存用户上传的自包含 GLB 和不透明素材 ID，读写保持在私有项目范围。

## Consequences

- 国内外模型可用性决定模型按钮能否运行。基础规则可在没有文本模型时试排。候选图先走已有授权、预算和生成任务页面。
- 完整模型目录增加视觉入口的构建内存。运行时按需加载几何和缩略图。导出视频依赖浏览器编码能力。
- 兼容网站迁移是 `0133_visual_creative_workflow`，独立 Visual 对应 `0013_visual_creative_workflow`。旧场景的来源字段为空。

## Verification

- `tests/apps/visual_workshop/test_creative_workflow.py` 校验账户边界、版本冲突、候选任务幂等以及带模型与卡片的快照回读。
- Chromium 验收覆盖脚本到试排、项目素材库入口、上传 GLB、选择原镜号并回填，以及原有白模下载和画布回填。
