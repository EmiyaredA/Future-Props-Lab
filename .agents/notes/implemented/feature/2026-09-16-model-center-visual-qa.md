# Agent Note: 基模型中心视觉对比验收

Status: implemented

## Problem

基模型中心已有高保真视觉参考和页面样式改动，但仅凭功能测试与文字报告无法证明实际页面是否接近参考图。现有截图分散在端到端测试产物中，没有固定演示数据、统一视口、浅色/暗色成对截图，也没有把参考图与实际页面放在同一份可查看的对比报告里。额外入口的生图还可能自行重绘产品壳层，因此不能把生成图误当成现有导航的实现要求。

## Decision

建立独立的模型中心视觉验收流程：使用四个基模型子页面的浅色/暗色单页参考图，以固定演示数据和当前 Workspace 数据分别运行页面，在严格的 1600×1000 桌面视口与 390×844 移动视口截图；模型测试真实切换文本对话、图片生成、视频生成、语音识别和实时语音五种模式；调用日志打开详情抽屉；使用 `visualize` 生成总览、逐页并排图和差异说明。

验收中冻结现有品牌壳层：左侧目录的项目、顺序、品牌区与顶部栏不因生图而重组；紧凑化只作用于内容区和基模型页面内部的信息层级。生图工具无法稳定遵守壳层约束的扩展入口参考图不进入项目验收基准，也不作为生产实现依据。

## Alternatives considered

- 只依赖 Playwright 断言：能证明控件存在和交互可用，但不能证明页面层级、留白、颜色和密度接近设计参考。
- 只把当前截图作为报告：缺少稳定参考图，无法区分产品设计偏差和数据状态差异。
- 只生成一张四联总览图：能快速看方向，但单页细节和暗色表面层级不足以支持逐项验收。
- 直接采用生图工具生成的扩展入口壳层：会把模型自行改写的导航和品牌结构带入产品，违背保留现有目录的约束。

## Consequences

- `.local/visual-qa/model-center/` 下形成稳定的 reference、fixed、real 三类素材，以及可筛选的 HTML 对比页。
- 参考图与实际图共用 1600×1000 画布，移动端证据使用 390×844；真实 Workspace 为空时明确记录为加载态烟测，不冒充固定数据效果。
- 视觉报告能够逐页核对壳层、标题、主操作、表格/卡片密度、详情抽屉、暗色表面和移动端堆叠；不新增 API、数据库、权限或文档中心内容。
