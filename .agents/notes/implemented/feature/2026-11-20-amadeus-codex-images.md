# Agent Note: Amadeus 的 Codex 原生生图

Status: implemented

## Problem

Amadeus 接入 Codex 时固定关闭原生生图，且只接收文字和 FPL 动态工具事件。直接开放工具仍会丢失原件、超过事件体积限制，也不能恢复纯图片回复或区分上传确认丢失与供应商失败。

## Decision

Amadeus 每轮保存 `codex_image_generation`，新会话默认开启，界面恢复上次发送的选择。生图只在 Codex、Agent 模式及有效账号有写权限时启用。共享 CLI 的默认仍为关闭。启用时使用只读本轮私有目录的命名权限档案，保持 Shell、插件、其他宿主工具及通用网络工具关闭。用户明确要求生图后直接执行，其他 FPL 写操作的审批规则不变。

Host 归一化原生图片项，处理内联数据和当前线程的受控原件路径，不消费任意宿主路径。原件保存端口由调用方提供；兼容网站直接调用 Amadeus 保存用例，独立 Worker 经有租约的 multipart 接口交付。成功事件只在校验、原子文件落位及持久事件提交之后产生，消息只保留会话文件引用。沿用现有 JSON 快照、事件和输出目录，无新增数据库迁移。

运行与图片项派生不可变文件名和幂等键。同一图片重复交付不会覆盖原件，确认丢失时读取已提交的回执；无法确认时保留原件并报告未知结果，不重新生图。取消等待实际文件 I/O 停止，已保存图片在中断与重启后保留。

## Alternatives considered

- 仅打开 Codex 功能开关：缺少原件交付、账号检查和历史恢复。
- 将 Base64 放入普通事件：突破事件限制，造成重复传输和持久存储膨胀。
- 继续调用 FPL 模型服务：不满足用户使用 Codex 自带生图及额度的要求。

## Consequences

会话支持图片生成状态、逐图展示、放大、下载和后续改图，原件限制为 50 MiB、4000 万像素。事件不包含图片字节和宿主路径。Codex 登录、供应商和图片额度仍决定真实可用性。部署需要匹配的 Amadeus 服务、Worker 和前端契约；该改动不修改正式数据或自动发布。

## Verification

隔离测试覆盖两套执行入口、纯图片回复、透明度、重复通知、关闭开关、Plan、越界与符号链接、损坏原件、取消、账号隔离，以及大图上传确认丢失后的回执读取。架构检查通过。浏览器覆盖 1440、768、390 像素下的图片展示、放大、下载和开关恢复。使用已登录的 FPL 专用 Codex 0.166.0 实际生成一次，原件 1536×1024，隔离 Amadeus 存储、重开引用与下载摘要核验通过；测试使用独立数据库，没有修改正式会话。

图片与 Codex 定向回归 39 项通过，相关前端回归 63 项通过；类型检查、前端构建与包体预算、工程契约生成物检查通过。完整契约命令仍提示受保护的 SDK 参考文档过期，本次没有重新生成产品文档。扩大回归另发现 Claude 实时输入路径未结算和数据库锁，保留该验证缺口，不扩大生图改动范围。全仓 lint 也受到其他在途改动影响，本次变更文件的 Ruff 与前端 ESLint 检查通过。
