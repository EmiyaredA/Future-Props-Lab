# Agent Note: 视频工坊统一转场语义与音频重叠接缝

Status: implemented

## Problem

视频工坊曾把效果名称和放置位置混在一起：效果库包含“黑场淡入”“向左擦除”，片段属性又使用“入场 / 出场”，导致同一效果在片段头、片段尾和片段之间的方向语义不一致。预览中的黑白场依赖透明度，不能保证出现完整纯色画面。独立音频轨虽然允许片段重叠，却没有描述重叠区双边增益的时间线转场，预览和导出只能各自处理片段头尾淡化。

## Decision

效果和位置使用独立模型。视觉效果使用中性的 `crossfade`、`fade-black`、`fade-white`、`wipe`、`zoom`、`blur` 和 `flash`；位置由片段的 `transitionIn`、`transitionOut` 或时间线 `placement: between` 表达。`wipe-left`、`wipe-right` 以及旧 `direction: in/out` 只作为读取兼容输入，API 输出和重新保存统一为 `wipe` 与空间方向。

黑场、白场和闪白都通过全画布颜色遮罩渲染。黑白场覆盖完整转场曲线，闪白仍是切点附近的短脉冲。擦除只裁切后一画面，不额外降低透明度。缩放和模糊在片段头尾使用互反曲线，在片段之间分别作用于前后画面，并在正常画面端回到单位缩放和零模糊。Web 预览与确定性导出使用相同的进度和缓动定义。

时间线 `VideoEditorTimelineTransition.kind` 增加 `audio-crossfade`。它只连接同一独立音频轨中按时间排序相邻且存在正重叠的两个音频片段。持续时间由完整重叠区派生。前一片段增益按缓动从 1 降到 0，后一片段从 0 升到 1，再与音量关键帧和片段头尾音频淡化相乘。移动或裁切保留正重叠时，API 自动更新持续时间；重叠归零或关系失效时，API 删除该接缝。Web 把删除加入同一次历史操作，撤销时恢复片段状态和接缝。

## Alternatives considered

- 为擦除继续保存四个效果种类。这样会让方向和效果继续重复编码，增加旧数据与新界面的组合状态，因此只保留一个规范效果值。
- 用两个片段各自的头尾淡化模拟音频交叉淡化。它无法保证完整覆盖实际重叠区，也无法在移动或裁切后保持一条可选择、可撤销的接缝记录。
- 为音频接缝增加独立时长。独立时长可能小于或大于真实重叠，产生没有声音来源的区间或未处理的叠音，因此时长固定派生自重叠区。
- 为重叠接缝增加数据库表。时间线已经是带 revision 的 JSON 聚合，转场与片段必须在一个 CAS 操作中修改；新增表会拆散事务和撤销语义。

## Consequences

- 新建和重新保存的擦除转场只写入 `kind: "wipe"`，方向只对擦除有业务含义。
- 音频片段可以重叠，视觉和混合轨仍禁止片段重叠；混合轨视频自带音频不提供独立音频接缝。
- 音频接缝没有可编辑时长，时间线胶囊始终覆盖真实重叠区。
- Web 历史层需要根据移动和裁切后的片段几何补充接缝删除与恢复操作；API 仍负责最终规范化，以覆盖 SDK 和其他客户端。
- 公共 OpenAPI、Web 类型和 Python SDK 使用同一转场枚举，不需要数据库 migration。

## Verification

- 后端模型测试覆盖旧擦除值、旧方向值、音频重叠时长规范化、重叠归零删除和撤销恢复。
- 渲染测试覆盖连续接缝不回退，以及两种频率测试音在真实 FFmpeg 导出中的交叉增益。
- Web 测试覆盖单张擦除卡、中性位置和缓动文案、音频重叠区添加入口、胶囊、增益公式与撤销操作组装。
- 预览测试覆盖黑白全画布遮罩、闪白脉冲、擦除不叠加透明度，以及缩放、模糊和交叉淡化的连续曲线。
