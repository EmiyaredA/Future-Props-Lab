# Agent Note: Amadeus 消息操作与上下文用量

Status: implemented

## Problem

分屏输入区的文字按钮挤占模型和发送控件的空间。上下文占用只出现在每轮回执，用户无法从输入区判断最近一次使用量或查看对话累计值。事件拆分的回答也缺少指向实际保存消息的操作。

## Decision

输入区用图标和可聚焦提示呈现工具。两个独立的用量入口都读取当前会话的运行快照，按运行 ID 去重。上下文占用取当前轮或最近一轮的实测值，Token 逐字段累计并保留缺失记录。

置顶和分叉用已保存消息 ID。事件渲染替代整段保存回答时，只在最后一段映射该消息。多选仅在当前会话临时保留。分叉复制截止消息的正文，业务引用按当前账号经工坊所属服务的只读端点复核。新会话正文和分叉请求回执在同一事务写入。运行、工作文件、审批和加载的能力仍由其原会话管理。

## Alternatives considered

以流式段落为分叉锚点需要再定义跨运行事件的历史截断语义。供应商账号额度属于部署连接，与账号自己的对话 Token 统计是不同权限范围。此处只展示已保存的会话用量。

## Consequences

独立 Amadeus 和兼容网站各新增一个显式迁移，旧消息的置顶状态默认为未置顶。分叉拒绝跨账号消息 ID，相同请求可恢复原分叉结果。跨工坊检查仅允许登记的项目读取路径。正式部署需要对应的 Identity 委托规则、网关契约和应用版本一起验证。

## Verification

确定性测试覆盖运行快照去重、零值和缺失、已保存消息锚点，以及分叉并发重放和跨账号隔离。Chromium 使用隔离数据库和固定用量记录验收视觉工坊分屏、弹窗及独立页触摸操作。
