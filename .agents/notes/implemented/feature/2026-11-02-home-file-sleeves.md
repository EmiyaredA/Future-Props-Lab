# Agent Note: 首页分类文件套

Status: implemented

## Problem

首页文件区的平铺小卡片难以表达分类中的多个文件，缩略内容与分类入口的层次也不够清楚。用户选定了由彩色文件套托住真实媒体卡片的设计。

## Decision

首页沿用文件模块的列表查询与账号缓存，按接口已有的更新时间倒序为每类取前三份文件。三层卡片分别展示真实缩略内容；缺少文件时以无内容背卡补足几何层次，不伪造文件或预览。最前卡片打开该文件的预览弹窗，文件套标题进入类型过滤后的文件库，后卡不提供额外交互或键盘焦点。

四类文件套使用灰绿、蓝灰、灰紫和暖灰褐色。布局在 1000px 以下为两列，窄屏保留可点击目标。样式限定在首页，继续复用文件模块的图片、视频帧、音频真实波形、PDF 页面和安全文本摘要，以及弹窗的键盘与焦点管理。

## Alternatives considered

- 整组只进入分类：会移除已经支持的首页直接预览能力，因此保留两个明确入口。
- 仅前卡真实、后卡固定装饰：请求更少，但不能展示最近多份素材，采用最多三份真实内容和可见性懒加载。
- 用参考图中的景观和文档作固定配图：会误导用户对私人文件的判断，始终从现有鉴权文件 API 读取实际内容。

## Consequences

每个首页最多挂载十二份缩略内容，继续按可见性获取派生图并回收鉴权 Blob URL。视频和音频原文件仍只在打开预览后读取。没有新增公共接口、持久状态或迁移；上传、重试、只读、分类导航和区块折叠沿用现有用例。此决定扩展[文件真实预览](2026-11-02-file-content-preview.md)的首页展示，不改变文件模块的所有权。

## Verification

组件用例覆盖四类文件分别为零、一、二、三和超过三份时的顺序、数量上限、背卡与非交互后卡；回归上传重试、只读、加载失败、分类导航、弹窗预览和焦点恢复。浏览器在隔离账号与数据库中检查真实媒体预览、两种主题、多种宽度、触摸目标、减弱动态效果和卡片与页头间距。
