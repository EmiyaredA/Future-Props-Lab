# Agent Note: 视觉看板的信息层级与密度

Status: implemented

## Problem

看板的空分类、分组工具与节点管理占据较多空间，提示词和生成按钮容易落到首屏外。状态卡采用相同的大图布局，没有按结果、准备条件、运行与失败的不同重要程度分配空间。

## Decision

保持米白与橙色，使用页面、面板和预览舞台建立层级；深色使用相应的背景、文字与状态颜色。素材树空分类默认收起，无自定义分组时直接列出素材。分类管理与节点删除进入可键盘操作的菜单，分类、分组和标签通过紧凑的整理入口编辑。

工作台编辑与结果约为 40%／60%，桌面分别滚动，窄屏纵向排列。生成组件使用显式 layout 参数适配工作台，画布布局继续采用默认值。提示词、常用参数和生成按钮集中呈现，音频支持展开编辑。输出历史采用横向版本条；当前预览与最终输出独立标记，同一项目页的历史预览在画布／看板切换后保留，并按项目隔离。

状态卡根据真实状态与媒体形式分配空间：准备与可生成使用紧凑卡，生成中突出进度，完成图片突出缩略图；无图片缩略图的媒体使用紧凑行。错误详情与额外标签按需展开。每列独立滚动，标题保持可见；状态不通过拖动改变。

## Alternatives considered

- 统一缩小全部控件：会削弱提示词、结果和状态的可读性。
- 保留统一的大图卡：没有输出或没有图片缩略图时会浪费空间。
- 直接覆盖共享生成器样式：会影响画布中的生成交互，因此使用明确的布局参数和局部样式。

## Consequences

不改变 API、持久化、输出版本与生成规则，不增加供应商调用或全历史预加载。菜单使用方向键、Escape 与焦点恢复；窄屏采用素材抽屉。组件按素材树、菜单、元信息、状态卡和文本编辑职责拆分，样式按 shell、工作台与状态卡维护。

## Verification

相关视觉工坊组件测试和三条隔离 Playwright 旅程通过，覆盖 30 节点、长名称、多标签、空分类、分类编辑、21 版本分页、手动最终版本选择、预览跨视图保留、文本保存、音视频播放与生成按钮、明暗主题及窄屏。1440×900 首屏可见提示词、模型、常用参数、生成按钮和主要预览；密集状态列验证局部滚动。lint、格式、构建以及 OpenAPI／Web 类型／SDK 代码生成检查通过；受保护文档中心保持不变。
