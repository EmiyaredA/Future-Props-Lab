# Agent Note: 表头字段配置与显示格式

Status: implemented

## Problem

全表字段弹窗无法就地配置当前列；日期和数字没有持久展示设置。直接将格式化文本用于编辑和交换会丢失数字精度、破坏日期往返；旧历史加入缺省字段属性后也会在备份链比较中出现误报。

## Decision

表头名称和类型图标进入同一字段浮层，窄屏避让为可滚动弹窗，复用 Dialog 焦点锁定和回焦。全表管理和浮层共用 FieldForm，名称字段继续保持文本。单选／多选沿用稳定选项 ID 和主题安全色点；支持排序、颜色和名称。风险变更预览后确认，显示格式和名称可直接保存，所有写入仍经受控串行队列、CAS 与本机恢复草稿。

FieldSpec.config 保存六种日期预设及数字精度、千位分隔，迁移 0085 为旧字段添加空 JSON。日期仍为 ISO 日期，数值完整保存。前后端展示投影仅用于界面和静态正文导出；原始值继续用于编辑、TSV、CSV、筛选和排序。数字舍入只影响展示，类型相关配置受严格后端校验。

字段草稿按打开时的原始结构比较，保存前完成待提交记录，再合并最新结构；当前字段已变化时保留草稿并报错，其他字段和视图不被覆盖。元数据变化不触发值转换，多选验证保留选择列表顺序。

备份输出 version 8，继续读取 version 1–7。旧历史实体的缺省配置在导出与导入校验时归一化，不重写历史表；复制和恢复复用现有 ID 重映射。官方指南来源与管理员主动导入包同步，升级不覆盖已导入笔记。

## Alternatives considered

- 将显示格式写回记录：影响日期与数值语义，改为独立投影。
- 每个入口分别实现配置：容易出现校验和控件差异，复用同一表单。
- 修改旧迁移或历史：违背不可改写约束，追加迁移并在读取边界兼容。

## Consequences

公共 FieldSpec 契约和数据库增加字段属性，但路由不增加。旧默认显示保持不变，选择字段仍保存选项 ID；公式、时间与时区、自定义模板不在本次范围。正在编辑的字段配置属于未提交本地状态，显式保存后进入既有恢复机制。

## Verification

- 隔离迁移检查旧字段空配置及原记录值；API 验证非法配置、转换原子性、选项引用保护、CAS、历史与旧备份。
- 组件测试验证六种日期格式、展示与编辑分离、草稿合并、颜色和选项 ID、类型预览、浮层回焦和窄屏布局。
- E2E 覆盖表头配置保存刷新、原始值编辑、三视图、正文嵌入、CSV／备份、断网与冲突，截图放入 `.local/field-config/`。
- 全量 `npm test`：后端 1,333 passed、2 skipped，Web 1,764 passed；补充模板、复制历史、静态导出与网格 TSV 原值断言后，相关后端 22 项、组件 27 项及 3 条 E2E 均通过。
- 跳过项是需打包 runner 的 Amadeus 沙箱用例与需显式 QA 输出的百页演示内存用例，与多维表格无关。
- 1600／1024／768／390px 明暗主题检查通过；5,000 条记录、50 字段的分页与虚拟滚动通过。E2E 使用静态构建与隔离数据库，避免开发服务器热更新打断旅程。
- lint、格式、Web 构建、契约／SDK、架构、官方导入包、Agent Note 与文档中心保护检查通过；正式数据未用于验收。
