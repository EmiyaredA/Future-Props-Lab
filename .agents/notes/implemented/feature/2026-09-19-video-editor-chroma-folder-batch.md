# Agent Note: 视频剪辑抠像与文件夹批量操作

Status: implemented

## Problem

绿幕、蓝幕或其他纯色背景素材需要进入多轨合成，但剪辑时间线此前只有几何、透明度和亮度调整。文件夹编排虽已存在，上传默认落到未分类，逐项整理和上轨对多素材场景效率低。

## Decision

视频和图片 Clip 在既有时间线 JSON 中可选 `chromaKey`；缺省保持原画面。按[共享媒体渲染边界](../architecture/2026-08-24-media-rendering-and-video-handoff.md)，共享媒体求值器在几何变换前生成透明度，精确停帧、单帧导出与成片复用这一算法。浏览器代理预览采用相同的 RGB 距离、软阈值和溢色规则，并将画布处理限制在 960 像素宽；暂停分屏通过精确帧接口的 `withoutChromaClipId` 只读参数获取原图，缓存键区分对比片段。

文件夹“添加素材”沿用现有上传 API；上传成功后再用时间线 CAS 批量归类，冲突时读取最新修订重试，最终失败则保留素材在未分类并提示重试。文件夹多选只属于当前文件夹；移动一次提交编排，上轨按选中顺序追加到时间线末尾，删除逐项调用现有正式 API、保留失败项并显示原因。分段导出继续输出原始片段，在界面说明它不烘焙时间线画面效果。

## Alternatives considered

- **抠像只做 CSS/浏览器预览** — 交互最快，但导出和精确帧会与所见结果不一致。
- **将文件夹上传与多选另建持久表和批量删除 API** — 能提供更强的原子性，但当前文件夹属于 revisioned 时间线文档，新增第二真源和迁移成本不匹配。部分失败以显式结果和重试入口处理。
- **分段导出透明 MP4** — 可把效果带出，但现有 H.264 MP4 不保留透明度，且分段导出语义是原片段交接；因此维持原语义并提示成片导出入口。

## Consequences

- **收益**：旧项目兼容；抠像进入完整渲染链路；素材上传、归类和批量操作复用现有权限与 CAS 保护。
- **代价**：浏览器代理与服务端源帧在编解码、缩放下可有轻微像素差异；逐项删除和上传后归类不是单个事务，界面必须保留并报告失败项。浏览器播放画面处理需要限制代理像素数以控制资源开销。

## Verification

绿、蓝、自定义颜色及 Alpha 叠加的后端测试；前端属性、播放对比、文件夹上传与批量选择测试；运行视频编辑器回归、契约、SDK、格式、lint 与构建门禁。
