# Agent Note: 桌宠数据包支持 Q 版人物骨架

Status: implemented

## Problem

桌宠本地快照把鲸鱼娘部件、DeepSeek 名称和八套配色当成固定条件，其他分层人物无法导入。独立缩放生成的拆分部件还会改变脸型与关节位置，静态预览不足以发现动作中的残留轮廓。

## Decision

数据 ZIP 保持原 manifest、HTTP 路径、来源枚举和 Workspace 存储结构。`model.json` 增加可选 `rigProfile` 与 `character`，缺省仍使用鲸鱼娘；`human-chibi` 验证人物必要部件、父级、坐姿与表情精灵。所有包继续执行路径、PNG、体积和数据白名单校验，不上传执行代码。

Web 以骨架类型选择人物绘制适配，复用原行为引擎与网格渲染。项目名称、人设与配色数量来自资源包，人物默认关闭主动台词，已有聊天设置优先。人物资源按同一原画坐标分层，生成补画只填遮挡区域；本地资源不进入内置资产。纯姿态函数与渲染生命周期分离，切换配色和卸载时释放旧纹理及网格。

## Alternatives considered

- **为人物新增来源枚举和数据库表** — 容易区分来源，但骨架属于资源描述，现有快照生命周期与隔离契约已能承载，无需迁移。
- **独立生成并缩放各部件** — 拆分容易，但实际组装改变脸型并导致关节穿帮；改用原画坐标和遮挡补画。
- **整张图随身体摆动** — 保持静态造型，但无法提供独立四肢、坐姿、眨眼和外套摆动。

## Consequences

旧鲸鱼娘数据包与人物共用正式导入入口和配置 CAS。人物包作者需要显式提供分层、枢轴与表情坐标，坐姿需要额外下半身纹理。长发和外套使用弹簧与网格近似，并非 Cubism 工程。

## Verification

`tests/test_desktop_pet_human.py` 验证导入、名称、缩略图、人物默认配置、保存、revision 冲突、Workspace 隔离与损坏包拒绝。原桌宠及聊天测试一并运行，18 项通过。Web 编辑器、聊天与人物姿态测试 5 项通过。隔离 Electron 烟测覆盖资源包、预览、配色、聊天、透明窗口与交互，DS 八套配色回归通过；人物明暗背景动作图用于复核脸部、手脚、坐姿和长发遮挡。构建通过。全仓库 lint、format、contracts 与架构门禁受同时进行的思绪工坊改动影响，相关失败不属于桌宠变更。

正式数据窗口运行旧后端，纯人物包首次导入返回“鲸鱼娘骨架定义无效”。只读兼容检查确认开发更新被待执行迁移或校验和漂移阻断，因此不绕过启动器、不执行热加载迁移。另提供数据兼容包：保持人物骨架与实际图层，增加旧校验器要求的透明占位部件、眼睛纹理与枢轴；占位数据同时通过现有严格人物校验和旧版校验，隔离 Electron 烟测再次通过。

兼容包已通过当前正式 UI 导入并以正式重命名入口保存“牧濑红莉栖”；角色人设通过编辑器保存，正式桌面窗口已显示人物。主动台词在私人聊天小窗关闭并经重新打开验证；既有用户聊天记录保留。项目卡片以本地资源包与项目名称显示来源，编辑器按实际配色数量显示说明，避免旧后端遗留的 DS 名称与八套配色文案。旧 DS 项目保留。截图和交付资源位于 `.local/desktop-pet/kurisu/`。Note 树与归档封印校验通过；全仓库 Note 格式检查和文档保护检查分别受现有思绪工坊提案缺少 Risks 标题与 SDK 文档改动影响。
