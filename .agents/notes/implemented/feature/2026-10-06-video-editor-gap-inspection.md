# Agent Note: 视频剪辑的精确空隙检查与显式批处理

Status: implemented

## Problem

缩放后的时间线无法可靠辨认几十毫秒的画面空隙。后续移动、裁切和变速可改变原接点，吸附本身不能保证所有后续编辑都保持连续。长留白也可能是作品意图，不能默认消除；源素材黑帧与时间线无画面是两种不同问题。

## Decision

工具栏提取为有明确编辑职责的组件，检查面板与纯检测、编辑规划、定帧准备分别维护。检测可见视觉／混合轨的内部画面覆盖，使用微秒差值，文字与其他轨道画面不掩盖结果，默认全部显示且不勾选。

延长模式保留后续时序，逐一检查按速度消费的关联源素材。前移模式统一计算多轨与关联组最终位移，拒绝不一致位移、锁定、负时间、重叠和破坏画面转场的选择。默认不添加替代画面。

用户追加要求的定帧作为第三个显式模式：提取左片段末尾源画面，固定末尾变换，新增静音图片填齐区间，不冻结字幕或其他轨道、不补音频。复用现有源帧提取和素材上传，源取样按该接口毫秒精度、宽度上限 1920 执行；填补区间保持精确微秒。准备素材完成后才提交整批时间线。

延长／前移使用 restoreClipStates，定帧使用 addClip 与 removeClip；复用 TimelineSaveQueue、音频转场协调、权限和 CAS。整批一次撤销，版本或素材信息变化清除选择，构建操作时再次检查。409 与保存失败沿用暂停流程，不自动重试，没有新增 API、数据库或 SDK 契约。

## Alternatives considered

- 自动吞并短空隙：会抹掉有意节奏，因此由用户筛选并显式选择。
- 按显示帧数再取整：非帧网格接点会重新出现微小间隔，因此只在显示时估算帧数。
- 把节目监视器整帧作为定帧：会冻结其他轨道和字幕，因此提取单个源帧并保留该片段表现参数。
- 分轨依次保存：关联冲突可能产生部分修改，因此先规划整组并一次 CAS。

## Consequences

检查结果表示该轨缺少画面，不能推断节目整体黑屏。源黑帧、纯黑片段和已有定帧需要人工预览。前移会改变画面与独立音乐／字幕的对齐，面板明确提示。

定帧准备有素材上传副作用，取消、失败及撤销可保留未使用图片；时间线仍原子保存，素材列表允许核对。定帧单批受现有 200 操作上限约束，不通过拆批损害撤销原子性。当前 APTMV 工程在本次功能实施中保持不变。

## Verification

纯函数测试覆盖微秒接点、49.707 毫秒、多轨、文字覆盖、隐藏轨、纯黑与定帧覆盖；延长／前移验证关联源、速度、锁定、冲突、非帧网格、未选间隔和整批撤销重做。面板测试覆盖筛选、全部处理、权限、版本／素材失效、重复提交和失败暂停；隔离 API、源帧与短输出测试及响应式浏览器旅程验证实际保存和画面。

运行相关测试、lint、格式、构建、契约、官方导入包、Agent Note 与受保护文档检查。测试工程使用隔离数据，所有工程修改通过正式 API。

本次验收：新增 33 项前端规划／面板／定帧测试通过；视频剪辑前端回归 305 项通过后补验新增音频转场用例；相关后端 66 项与架构／官方发布 72 项通过。隔离 API 的 6 个 30/60 FPS 短输出无空隙黑帧；浏览器旅程覆盖 390/768/1600 宽度、明暗主题、实际 PNG 像素、三种处理、撤销重做和真实 CAS 409。lint、格式、构建、契约、官方包与文档保护检查通过。全局 Note 格式检查报告另一个桌宠 Note 的标题／状态错误，本 Note 的树结构和格式未报错。
