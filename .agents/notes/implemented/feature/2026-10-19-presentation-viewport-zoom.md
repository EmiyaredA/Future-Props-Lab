# Agent Note: 演示工坊画布手势缩放

Status: implemented

## Problem

演示工坊已有底部缩放条，但触控板捏合和修饰键滚轮没有进入画布缩放链路，用户查看细节需要反复操作底栏。仅改变比例会让所看内容偏离鼠标位置，放大后的局部滚动也必须保持正确的元素坐标。

## Decision

`useSlideViewport` 拥有适应比例、缩放锚点和滚动补偿。画布注册非 passive 的 wheel 监听，将 Ctrl 捏合以及 Ctrl／⌘＋滚轮转换为连续比例，手动范围沿用 25%–200%，底部控件仍为 5% 步长。普通滚轮与双指滑动保持默认滚动。监听只在画布内拦截修饰键滚轮，边界和变换中仍阻止浏览器默认缩放。

手势捕获鼠标下的文稿坐标，底部控件使用可视中心；布局提交后补偿容器 scrollLeft/scrollTop，并由浏览器在边缘限幅。适应模式重置滚动，ResizeObserver 按实际容器及响应式留白重新计算比例。连续同帧事件累计请求比例，避免仅使用上一次 React 提交值而丢失手势增量。

编辑器现有 zoom 状态仍是唯一手动比例来源。SlideCanvas 的可选 onZoomChange 显式通知编辑器，拖动、旋转、框选按下期间和裁剪期间忽略手势缩放。只读权限不阻止查看缩放。全部状态只在内存中，不进入文稿、保存队列、撤销或导出。

## Alternatives considered

- 整体页面缩放：同时改变工具栏和侧栏尺寸，不符合只放大幻灯片的需求。
- 独立 CSS transform 或第二份缩放状态：会使现有底栏、选区和裁剪坐标不一致。
- 每个滚轮事件固定变化 5%：触控板微小增量会造成跳动，因此手势采用连续比例，底栏保留离散步长。

## Consequences

原生画布局部滚动承担放大后的浏览；边缘或完整居中显示时，锚点受到可滚动范围约束。重新打开默认适应页面，不新增持久偏好或 API。监听和观察器随画布卸载清理。官方指南、技术说明、图形、目录索引和导入包同步维护，保留已有未提交改动与受保护文档中心。

## Verification

158 项相关组件与官方内容测试通过，其中 10 项视口测试覆盖连续事件、修饰键与默认滚动、单位换算、比例边界、变换阻断、中心补偿、实际留白、窄屏适应、只读和监听清理。

新增 3 条隔离浏览器旅程通过，验证鼠标锚点、底栏中心、四角可达、窗口与备注适配、明暗主题、重新打开、不触发保存和撤销，以及拖动期间阻断缩放。扩展至 22 条旅程后，21 条首次通过；旧文字替换旅程出现一次内容追加的时序失败，在独立隔离实例复查通过，未修改文字编辑逻辑。裁剪保存重开、图片填充、文字选择、八向变换、悬浮栏定位和不同缩放比例的拖动回归通过。实际画面检查确认画布局部滚动与居中布局正确。

Web lint、类型与生产构建、契约/SDK、官方导入包、Agent Note 和文档保护检查通过。改动范围格式检查通过；全 Web 格式检查仍有两个既有失败：受保护的 `web/src/docs/styles-components.css` 与无关的思绪工坊 help.md。所有隔离数据库、截图、导出与日志位于被忽略的 `.local/presentation-zoom/`；未启动正式桌面数据。
