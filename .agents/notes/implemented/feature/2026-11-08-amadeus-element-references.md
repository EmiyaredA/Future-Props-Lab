# Agent Note: Amadeus 引用工坊项目元素

Status: implemented

## Problem

工坊选区与浏览器控件缺少稳定的项目和元素标识。消息需要明确区分用户主动添加的引用和页面中的临时选区。

## Decision

编辑器在账号侧栏提供的页面上下文中登记选择、命中和定位。DOM 标记只传对象标识，特效画布和导演台复用渲染器的命中检测。Amadeus 统一处理点选、键盘取消、预览与发送，显式引用最多二十条。幻灯片元素和导演台实体同时保存父级 ID，定位时可切换页或场景。输入区和历史消息使用同一个紧凑标签，点击直接定位，高亮前一个元素时切换到最新目标，悬停和键盘聚焦显示详情。

引用快照由消息和运行请求共同使用。可选结构化目标沿用 JSON 字段。旧快照没有目标时继续按历史引用显示。原生选区只用于本地展示，提示构建也过滤旧客户端传来的被动选区。自动恢复历史会话时保留刚添加的引用，明确切换会话时按目标会话重置引用草稿。

## Alternatives considered

用 DOM 文案推断项目元素会把工具栏和同名对象混在一起，也无法定位画布对象。把编辑器选区随每条消息传输会让用户无法控制数据范围。

## Consequences

目标仅提供定位信息。工坊业务操作仍校验账号、权限与版本。草稿引用会提示保存。面试房间的登记读取提供材料元数据，原件下载沿用面试助手授权入口。

正式发布先更新可读新旧快照的 Amadeus 服务，然后更新工坊前端。产生新格式历史后回退前端时保留兼容新格式的服务。

## Verification

隔离后端用确定性 Agent 接收消息与运行快照，检查旧引用、非法类型、草稿和跨账号的读取隔离。九个工坊的 Chromium 用例覆盖分屏原生选择、点选取消、工具栏忽略、引用去重、主动发送、加载历史时保留引用、跨页及跨场定位。产品文档中心的 Amadeus 与 Code Agents SDK 参考仍需单独同步。
