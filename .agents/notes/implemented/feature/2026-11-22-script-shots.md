# Agent Note: 剧本按集和分镜组织

Status: implemented

标题拆分与整理入口已由[整集分镜视图决定](2026-11-22-script-episode-overview.md)替代；下文保留原决定及其验证记录。

## Problem

剧本目录以场次为编辑单位，一场正文包含多个镜头。用户需要按每集、每个分镜查找和编辑，并继续使用已有制作关联。

## Decision

剧本目录、编辑、新建、排序、删除和剧本到白模入口统一使用分镜。保留现有 `episodes[].scenes[]` 和 `scene_id` 协议字段，避免为展示术语变更引入迁移。新建条目的示例限定为单镜，包含景别、机位、时长、动作、对白和声音。

保存剧本时，纯规则 `script_shots.py` 仅识别同一正文中两个及以上独立行的中文方括号编号镜头标题。每段成为同集的独立条目；首段保留前言和原 ID，其余获得新 ID。分段拼接逐字符等于原文，空白和换行不变，标题采用镜头标题，场景信息继承。单镜和无结构文本保持原样。前端检测相同格式并提供“按镜头标题整理”入口；多镜正文整理前暂停选段创建制作、提取设定和预演交接，防止将旧完整正文交给拆分后的首镜。

账号校验、剧本 revision 检查、拆分后限制校验、剧本与制作来源更新在 `SqlCreativeRecords` 的同一短事务内完成。来源摘录优先核对 UTF-16 范围，其次查找唯一相同原文，完整落在单段内才重定位。受影响制作文档同步推进 revision，其他窗口继续以 CAS 冲突保护草稿。前端完成整理后使制作查询失效。

## Alternatives considered

- 只改场次名称：无法拆开截图中同一正文内的多个镜头。
- 浏览器依次保存拆分剧本和制作文档：部分失败会留下只完成一半的来源更新。
- 从普通叙述推断分镜：不能确定作者意图，可能改变动作与对白的组合。

## Consequences

读取不改写持久数据；已有多镜正文在用户保存或点击整理时转为逐镜。拆分仍受每集 200 项与文档大小限制，超限整体失败。跨镜、歧义或失效摘录保留旧来源和摘录，用户可继续核对；设定卡与白模仅保存粗粒度来源，继续指向首镜原 ID 和历史 revision。拆分不新增制作节点、不提交生成、不删除素材。诊断和浏览器产物位于忽略的 `.local/script-shots/`。
