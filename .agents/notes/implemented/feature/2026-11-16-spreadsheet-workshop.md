# Agent Note: 独立表格工坊

Status: implemented

## Problem

研究所需要可嵌入自身应用体系的 Excel 类编辑能力。仅比较上游宣传功能无法证明开源范围，也不能解决账号隔离、持久保存、文件转换和自动化入口。新应用必须沿用其他工坊的独立服务边界。

## Decision

使用 MIT FortuneSheet 1.0.4 开源源码，增加 `spreadsheet` 独立镜像、迁移、SQLite 和私有原件目录。Identity 签名上下文提供账号及固定权限；Gateway 登记精确路由，网站装配只导出契约。业务包不读取其他应用存储。

工作簿以版本化稀疏快照持久化。CAS 和稳定请求 ID 的事务回执避免并发覆盖与未知提交后的重复写入。前端串行提交，冲突保留草稿供重新加载或另存副本。自动化通过同一组 HTTP 操作生成 SDK、CLI/MCP 发现清单。

XLSX/CSV 使用自有有界转换器；导入先显示损失提示，再以原件哈希和转换器版本确认。原件写入先于数据库提交，未知提交不冒险清理，启动恢复移除无引用文件。公式只由浏览器计算，自动化修改标记待算；XLSX 输出要求打开重算。

FortuneSheet npm 发布包无法按语言拆包，因而保留上游源码与许可证，通过 Vite 别名使用源码，类型及依赖仍锁定 npm 1.0.4。只注册中英文，构建 ID 包含 vendor 输入。共享 Pixi 代码按强连通分量和依赖次序分包，保持静态图无环并满足现有体积限制。

头像采用用户指定的红莉栖女仆形象，沿用现有铜色齿轮徽章风格；生成图和标准缩略图进入统一资产体系。

## Alternatives considered

- 直接挂入兼容网站数据库：违背独立服务与业务存储隔离，不能独立发布及恢复。
- 直接使用 npm 的完整多语言编译包：无法满足现有单包预算。
- 接入社区 Excel 插件并假定完整兼容：无法保证许可、维护及损失边界；显式映射更容易验证。
- 服务端模拟 Excel 计算或第一版加入实时协作：引入额外计算引擎及冲突模型，超出已选范围。

## Consequences

编辑器开源功能可用于本应用，但不等于完整 Excel 兼容。宏、图表、透视表、图片、外部连接不进入可编辑副本；部分条件格式和数据校验不能输出 XLSX 时明确报错。原件可下载。预览和回执当前没有后台自动过期清理，需监测本服务容量；不提供历史版本 UI。

源码供应链、稀疏格式转换和客户端公式兼容需要随上游升级独立回归。新服务不改变已有应用的数据库，也不自动执行正式迁移或部署。工程说明见 `docs/reference/spreadsheet-workshop.md`。
