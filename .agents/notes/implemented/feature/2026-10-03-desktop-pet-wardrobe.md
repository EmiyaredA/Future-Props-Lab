# Agent Note: 桌宠原项目资源更新与服饰姿态

Status: implemented

## Problem

本地分层角色只能首次导入，新增服装会创建另一个项目，不能继续原项目的默认配置和私人聊天。长裙和大褂仅替换站立贴图时，坐姿仍会显示原腿部且衣物遮挡不一致。

## Decision

POST replace-package 只更新当前 Workspace 的本地分层项目。完整 ZIP 复用路径、图片、体积与数据白名单校验，骨架保持一致，当前默认外观和交互引用必须有效。文件 I/O 前结束读事务，全部素材以新 ID 准备，再通过项目 revision CAS 切换模型和映射；异常、取消或冲突只补偿本次文件。提交后的旧文件清理失败不把已提交更新变成失败响应。标题、来源名称、配置和聊天均不进入更新值。

编辑器在有未保存修改或桌面联动时禁用上传，用户明确选择完整 ZIP。冲突保留现有工程并提供载入最新版本，不自动重试。可信主 frame 的角色编辑器可通知同账号、Workspace 和项目的桌宠重新读取鉴权快照；运行页拒绝较旧 revision，不关闭聊天窗或重新发送消息。

人物 schemes 的可选 outfit 登记 standingParts 与 seatedParts，两组必须是现有部件、互不重复。坐姿过渡同步淡出站姿下摆、淡入补画坐姿，衣袖使用手臂变形器，头饰跟随 head，外套下摆使用 coat。缺省保持旧包行为；三套共享表情、骨架和画布，首套经典服饰保留原像素。人物原画、图层、提示词和合集 ZIP 属于本地忽略资源，不进入内置资产。

## Alternatives considered

- 每套服装另建项目：分裂聊天与设置，不能满足原项目换装。
- 覆写原素材文件：部分失败会破坏旧快照，也无法通过 CAS 保护并发更新。
- 关闭并重开桌宠刷新：会销毁聊天窗口和当前消息流；使用独立资源变更通知。
- 将所有下摆绑定站姿：坐下会保留不合适遮挡；使用每套可选姿态部件。

## Consequences

无需新的数据库 schema；模型 JSON、新 HTTP 路由、权限登记和 SDK 具名方法同步维护。经典资源和缺省鲸鱼骨架不需要新增姿态定义。上传先暂存完整新包，期间占用额外磁盘空间；进程突然终止可能留下无引用新文件，但已提交快照不会指向未完成的文件。正式更新仍遵循已有停机、完整备份和已登记迁移流程，不把本地换装验收视为强制终止旧启动器的授权。

## Verification

后端测试覆盖项目/配置/聊天保留、新素材映射、实际并发保存造成的 CAS 冲突、损坏包、骨架和默认服饰不兼容、写入失败补偿及 Workspace HTTP 隔离。Web 测试覆盖上传键盘操作、同文件手动重试、未保存保护、冲突反馈、服饰出现、姿态淡入淡出和运行快照刷新不打断聊天。Electron IPC 测试覆盖可信主 frame、账号和空间约束，并确认资源通知不创建或销毁聊天窗口。

隔离 Electron 从经典包导入，经编辑器更新三套合集，验证同一项目、默认保存、重新加载、换装、透明窗口、拖放、屏幕边缘、点击穿透与气泡/对话消息流；每套输出站姿、坐姿、表情和真实步周期的明暗截图。正式数据接入和受保护 SDK 文档更新保留待授权边界，验收状态记录在忽略目录。
