# Agent Note: 持久化视频生成执行信息与紧凑状态展示

Status: implemented

## Problem

ZEALMAN 的简化结果在长时间生成期间只返回 pending。应用不能区分排队、执行与等待结果，用户也无法判断显示的百分比属于整个任务还是单个采样节点。独立实时连接还可能替换原控制台的连接。

## Decision

供应商适配层将任务账本、队列及带 prompt_id 的实时事件归一化为 TaskExecutionInfo。通用任务驱动器用短事务保存 execution_info，不改变提交快照、完成判定或重提规则。0093 仅为三个共用驱动器的任务表追加可空 JSON 列，旧记录保持为空。

每个执行器明确拥有 ZealmanLiveMonitor，新增提交使用独立 fpl 客户端身份。只有此类身份建立实时连接，旧控制台身份仅查询 HTTP，避免抢占连接。连接按任务隔离，严格过滤 prompt_id；连接数、消息长度、队列及空闲时间有上限，停止执行器会关闭连接，断线退避重连。WebSocket 不决定成功、失败或输出落盘，终态继续由正式结果接口与驱动器结算。

前端消费供应商无关字段，紧凑显示阶段、队列位置、节点、采样步数、上游报告值与更新时间。采样进度单独标注，不把账本值当成整段视频完成度。采样信息过期或实时连接断开时恢复不定值动画；旧输出版本保持可查看。二进制预览及未经任务身份校验的事件不进入公共接口；尚未确认 U17 可用中间帧。

## Alternatives considered

- 仅轮询简化结果：无法解释任务当前阶段，也没有节点或采样信息。
- 复用上游控制台 client_id：可能抢占用户控制台连接。
- 将执行信息混入 request_payload：破坏提交输入快照与执行状态的生命周期边界。
- 将上游百分比视作整体进度：其含义未获保证，不能据此预测完成时间。

## Consequences

已有任务仍可取得队列和账本信息；节点与采样信息取决于上游支持，并且仅新提交的应用独立连接可接收。实时连接故障不会触发生成失败或重复计费提交。执行信息随任务持久保存，连接本身在重启后重建。正式数据需按正常迁移流程应用 0093；桌面开发热加载不自动迁移真实数据库。

## Verification

确定性测试覆盖队列身份、无效百分比、跨任务事件过滤、采样节点切换、断线回退、连接关闭、历史升级及执行信息重新加载。界面测试覆盖排队、采样与上游报告的区别、过期反馈及保留旧输出；浏览器验收使用隔离数据库与模拟任务，不提交真实模型请求。
