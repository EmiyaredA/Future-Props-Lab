# Agent Note: 演示工坊按页归档图像版本

Status: implemented

## Problem

先生成整页图像再重建可编辑幻灯片的制作流程需要保留每页的原始生成图。画布图片元素会参与交付，参考图承担编辑对照，均不能清晰表达独立归档用途。

## Decision

每页使用可空 `image_asset_id` 关联一张当前 Workspace 公共文件库图片，与 `reference` 独立。图片从已有文件上传或选择入口进入，项目用例在既有 CAS 事务中验证 Workspace、素材类别和可见归属，再统一同步引用保护。批量操作通过 slide update 设置或清空同一字段，不新增路由或存储表；fragment 不允许夹带页面归档。

`0097_presentation_image_version` 为已有文稿中缺失字段补 null，保留既有图像引用、页面顺序、版本、revision 和时间。ORM 仍保存同一文稿 JSON。复制页保留关联，移除、替换、删页或删文稿解除对应引用，不删除源图；仍有其他引用时文件删除继续返回 409。

右侧页面面板拥有添加、更换、预览、下载与移除入口，复用鉴权 Blob URL、文件库、自动保存和撤销队列。只读允许预览下载。上传绑定组件对应的页，关闭、切页、卸载或权限变化使迟到结果失效；失败不替换旧关联，成功上传但未绑定的文件仍留在文件库。

归档图不参与画布、缩略图、放映和 PPTX。导出沿用仅收集渲染元素素材的筛选，不复制、解码或计入仅归档图片的导出预算。

## Alternatives considered

- 将参考图兼作归档：编辑对照和原始生成图无法独立替换，归档语义不明确。
- 将整页图作为背景或图片元素：改变放映与导出结果，也影响继续编辑。
- 新建多版本附件表与专属上传 API：当前需求为每页一张，已有文稿、素材与 CAS 足以表达，避免第二套生命周期。

## Consequences

每页仅保留当前一张关联，不自动截图、调用模型或维护多份图像历史。需要保留多张旧图时文件库继续保存源文件。旧客户端整篇覆盖文稿时仍须遵守当前完整文稿契约；未携带可选字段表示未归档。

未对正式桌面数据应用新增迁移；迁移先在隔离数据库验证，正式数据启动仍遵守桌面迁移检查流程。
