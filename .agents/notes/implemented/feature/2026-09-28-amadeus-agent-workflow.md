# Agent Note: Amadeus Agent 与 Plan 工作流

Status: implemented

## Problem

Amadeus 原有执行链在浏览器 Worker 中等待审批结果。窗口关闭时 Promise 消失，运行及待审批操作被取消；工具记录集中放在消息末尾，用户也无法在对话中完成单题提问或先规划再执行。

## Decision

每个运行记录 Agent 或 Plan 模式及可空的来源运行。Plan 与只读子任务只暴露读取工具；Agent 的写操作仍需服务端参数摘要审批。提问和审批使当前运行转为持久等待状态并释放活动运行占位。用户回应后，新运行从已保存的消息、工具调用、答案或操作结果继续，不重放旧写入。一个来源运行只能继续一次；未知的外部执行结果不自动继续。子任务只由主 Agent 在需要两项独立调查时发起，最多两个并行，使用同一运行的只读模型桥接和折叠事件记录。

对话区按消息与运行事件时间呈现精简工具卡、单题表单和审批卡；数字人及左侧布局沿用既有设计。视觉创作工坊的视频项目画布新增视频生成草稿节点作为最小确定性验收用例，不启动生成供应商任务。

## Alternatives considered

- **保留 Worker 内存等待**：实现较少，但关闭窗口后无法恢复用户回应。
- **为每个只读子任务创建独立持久运行**：提供更细的历史，却会与当前单账号单活动运行约束冲突，并增加无必要的审批面。
- **在同一 Worker 中重放暂停前的工具调用**：可能重复执行写入，因此使用新的关联运行和已落盘结果。

## Consequences

- 待处理卡片可跨窗口重开；写入继续受现有单次执行和项目 revision 保护。
- 继续流程依赖完整的运行事件与消息历史，前端按时间重建模型对话。结果不明时需用户检查项目状态。
- 公共契约新增运行模式、来源、持久提问及等待状态，需同步 migration、OpenAPI 和 SDK。

## Verification

- 隔离数据库 migration、后端 Amadeus 工作流及视觉创作工坊画布 API：相关后端测试 21 通过、3 跳过；Web 对话与布局组件测试 16 通过；桌面单元测试 12 通过。
- 隔离桌面烟测完成 Plan → Agent、审批跨重开、单次画布写入及过期 revision 拒绝；全程使用确定性模拟模型，不调用生成供应商。
- 契约与 SDK stale-check、Agent Note 检查及改动范围 lint/格式检查通过。全仓 lint/格式检查被其他工坊既有文件阻断，构建被缺失或校验失败的 Git LFS 资产及缺失的 vendor/pi 文件阻断。
