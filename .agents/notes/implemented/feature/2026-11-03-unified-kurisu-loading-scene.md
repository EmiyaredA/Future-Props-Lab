# Agent Note: 同源红莉栖琥珀仪表加载场景

Status: implemented

## Problem

整页、内容区已有红莉栖小跑，但行内按钮、生成状态、传输和导出仍混用圆环。用户确认第二版仪表设计，要求所有加载反馈都有跑步红莉栖，并在空间受限时保持清晰。

## Decision

LoadingScene 只负责视觉，接收 page/region/inline 尺寸、active 与可选 paused；LoadingState 保留文案、150ms 延迟、真实进度与超过十秒的等待时间，并透传暂停控制。人物播放仍归 LoadingCharacter，业务请求与任务状态不迁入共享 UI。用户最终明确整页与内容区均保留所有道具：两档采用同一完整八道具构图等比缩放，舞台最大320px和128px，人物占舞台高度45%（约144px和58px）；行内人物28px，不放置不可辨认的微型道具。均保留仪表扫描弧。可交互控件容纳32px紧凑舞台，不挤压正文或依赖裁切。

本决定取代[此前加载动画方案](2026-11-02-kurisu-loading-animation.md)中“行内保留圆环”的决定。静态状态分类使用普通图标，不因分类名称包含生成中就播放加载动画。

八件道具使用独立生成的透明插画，导出最长边256px WebP，合计86724字节；原始1254px PNG保留在已忽略的本地验收目录。按用户后续清晰参考将普通绿色乌帕替换为具有黑边圆耳、环形眼睛、深色面纹和折线嘴的金属乌帕；保留两只底脚与一条后尾巴，不误画成两条侧肢。主体调整为稍宽的球形，近侧圆耳直径约为身体的三成，远侧耳更小并由球体遮挡；后续摆正耳朵朝向，整体显示尺寸缩小15%且保持中心位置，不通过CSS纵向拉伸道具。另加入Dr Pepper瓶与带太阳能板的时间机器。运行时仅读取本站静态资源，二进制资产纳入Git LFS与哈希校验。仪表SVG是原生UI图形，与初始HTML共用，不将概念图整张烘焙到界面。

首帧使用9998字节WebP并保留PNG兼容回退，跑步WebM保持69466字节；八道具与WebP首帧、视频合计166188字节。LoadingState在150ms结束前不挂载媒体，HTML启动场景也在延迟结束且页面可见后才设置媒体地址，快速交接不请求媒体。高清道具只在用户打开本地素材查看器后读取。

保留19帧24fps连续跑步，不倒放、不重新生成角色。扫描弧八秒循环，光点反向缓慢移动，扫描线四秒渐变，道具小幅悬浮。用户要求增强特效后，加入低透明度雷达扇形、分段渐隐彗星拖尾、反向能量环和少量粒子。装饰不表示进度，也不使用强闪烁。页面隐藏、屏幕外或显式暂停时冻结动效；滚回视野时保留原视频实例并恢复。减少动态效果与播放失败保留人物静态首帧。HTML启动控制器独立于React，在成功或失败交接时清理。

## Alternatives considered

- 各业务分别绘制动画：无法确保持续跑步、静态回退和主题一致，继续增加重复实现。
- 按钮放入完整道具：32px小尺寸不可辨识且破坏控件布局，行内采用同源精简结构；整页与区域遵循用户最终选择，均保留全部八件。
- 直接播放整幅生成概念图：无法保留真实进度与现有角色动作，且模糊道具细节。

## Consequences

用户进一步要求乌帕与手机体量接近：乌帕显示框改为舞台宽12%、高13.2%，保留中心位置与原图比例；整页与内容区同步等比缩放。

LoadingState 原调用方式保持兼容；行内布局为角色预留32px并提高必要控件行高。初始HTML与React共用SVG符号及样式，静态资源失败不影响数据操作。主题跟随页面，不引入新路由、后端API、配置或持久化状态。预览直接复用生产组件，避免独立演示与正式实现漂移。

## Verification

组件测试覆盖三档道具数量、人物与状态播报、暂停不重建视频、可见性监听清理、首帧未解码时请求播放、减少动态效果、失败回退、HTML启动延迟与清理，以及既有真实传输与等待提示。浏览器验收检查明暗主题、390/768/1280宽度、人物和道具透明度、连续帧推进与跨周期播放；预览、截图和检查记录位于已忽略的 `.local/loading-kurisu/implementation/`。
