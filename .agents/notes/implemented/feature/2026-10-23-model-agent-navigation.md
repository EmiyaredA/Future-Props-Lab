# Agent Note: 模型与智能体统一导航

Status: implemented

## Problem

模型服务与本机编程智能体分列在基模型导航中，用户难以把两种接入能力关联起来。智能体页面的连接状态、用途授权和外部客户端说明缺少清晰层级，且长路径与配置挤占首屏。

## Decision

侧栏使用统一的“模型与智能体”入口。app 层装配公共页头，通过显式 renderHeader 插槽接收各功能的操作，两个功能继续拥有各自查询、权限和状态。页头采用标题、约 360px 的视图切换和当前操作三列；不足容纳时切换栏换行。

`/model-service` 和 `/code-agents` 分别确定选中视图，沿用应用导航和历史处理，不创建第二套隐式视图状态。连接卡片直接展示后端 status，available 不作为连接状态的替代。用途授权表保持已有 revision 和旧授权接管规则，保存期间锁定账号与开关，冲突后重新读取而不自动重提。

外部客户端区默认收起，从账号功能公开的 useDesktopAgentAccess 读取桌面状态。读取与开启分离，浏览器、读取中和读取失败不伪装为关闭。配置复制保留真实换行。

## Alternatives considered

- 保留两个侧栏入口：改动小，但无法表达统一接入的导航关系。
- 合并业务状态与查询：界面装配简单，但会混淆模型配置权限、本机连接状态和按用途授权的不同职责。

## Consequences

- 导航统一，模型目录及智能体授权保持独立边界；公共 API、数据库、部署配置与授权规则不变。
- 页头支持明暗主题和窄屏；授权表仅在自身容器横向滚动。客户端配置需要展开查看。
- 状态与授权均依赖真实响应，测试使用隔离数据或确定性模拟，不调用真实 CLI 或供应商。

## Verification

`web/tests/features/code-agents-ui.test.tsx` 覆盖页头切换、状态映射、详情和复制、授权旧数据保留、保存锁定与冲突、桌面桥状态及显式开启。模型目录、只读、导航、本地模型与桌面接入运行现有回归测试。

响应式浏览器用例覆盖两个原地址、历史切换、明暗主题和 390/768/1280/1600px 宽度；本地截图与视觉对照记录归档到 `.local/model-agents-ui/`。使用相关 lint、格式检查、构建、verify-notes 与 check-docs-center-protected 验证交付。

验收结果为 105 项相关组件测试、6 项端到端测试通过，Web lint 与生产构建通过。Note 校验脚本使用 `node --import tsx` 执行，与 npm 入口的校验逻辑一致；源码指南同步生成官方导入包并通过 stale-check。全局格式检查仍报告六个本次未改动文件的问题，本次改动单独检查通过。视觉对照结果见 `.local/model-agents-ui/design-qa.md`。
