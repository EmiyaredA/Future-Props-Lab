# Agent Note: 全项目设定卡整理与固定看板入口

Status: implemented

后续变体展示由[横排变体与弹窗交互](2026-11-20-visual-variant-filmstrip-and-dialog-dismiss.md)取代；本篇保留当时决定及素材整理约束。

## Problem

账号已有通用设定库，但项目旧人设和场景节点没有关联卡片，图片副本使用不同素材 ID。看板分为文件和常用设定两个标签，已有卡片按 UUID 平铺，变体不易找到。普通更新禁止修改父关系，重新建卡归组会改变被引用的卡片身份。

## Decision

看板同栏展示固定的人设、场景、道具分组和下方项目文件。主卡按名称排序，变体折叠显示相对名称，悬浮保留完整名称。分组支持展开；单类超过六个设定族时默认收起，搜索会展开匹配项。已关联且已收录的旧图片节点不再重复出现在文件树，卡片菜单可以进入原节点查看版本与引用。

卡片缩略图与分类内容左边缘对齐，取消内层横向留白。缩略图使用 32px，卡片行上下 padding 为 2px，分类上下 padding 为 6px，分组标题与内容间隔为 2px；只保留变体层级所需的小幅缩进。

归组使用独立的账号级 CAS 命令，保留卡片 ID、采用图和来源，不放宽普通 PUT 的父关系约束。同类主卡与所选变体在短事务中检查 revision；子卡必须显式包含，不能制造循环或悬挂关系。图片归属元数据沿用同账号主卡已经核验的采用图。

整理使用正式 SDK。先按全部项目的节点、嵌套文件目录与设定节点历史输出收集图片，逐图核对后生成明确清单；内容摘要识别相同图片的副本。可复用的执行器默认 dry run，实际清单、锁、导入回执及受影响卡片和画布的恢复信息保存于 `.runtime/`。诊断图片和验收产物位于被忽略的 `.local/`。不删除原素材或直接写数据库。

## Alternatives considered

按文件名直接合并容易混淆不同身份和镜头成图；每个项目重建同名卡会重复。复制一张新卡再归档旧卡会改变 ID，因此采用显式归组动作。保留双标签仍需要来回切换，不能直接替代旧素材入口。

## Consequences

无需新增数据库迁移。个人整理清单不进入版本管理。重复执行先核对已有卡和已提交的图片导入，遇到 revision 冲突或图片变化停止，保留恢复记录。不同身份不因外形相似合并；分镜、动作、白模姿势和封面保留原用途。

## Verification

当前账号全部 31 个项目完成盘点，447 张去重画面逐项记录：254 张归入设定卡、193 张保留为项目制作素材。补建六张场景卡和三张桌宠变体，补充十九张已有卡；24 个项目关联 275 个图片节点，十个错放节点回归制作参考。其余七个项目没有本次可收录的独立设定素材。单人裁图及冈部前景手部也纳入对应角色的参考图，补充处理具有独立恢复回执。

SDK 复跑没有新增卡、图片导入或项目修改。全量读取核对 3459 个节点、3455 条连线与 288 个设定历史输出；原媒体和最终版本不变。保存会将旧的空输出序号序列化为等价的零。最终读取复核生成草稿与整理前一致，处理期间出现的更高 revision 不由整理器覆盖。

隔离后端测试覆盖归组身份与媒体保留、账号隔离、完整子卡、类型不匹配回滚、revision 冲突和幂等。执行器测试覆盖部分失败后续跑、重复执行、素材变化拒绝与私有原子回执。前端与隔离 Chromium 验收覆盖固定三类、变体和来源、刷新恢复、固定历史引用、明暗主题与窄屏。实际账号页面确认角色及变体替换旧入口。
