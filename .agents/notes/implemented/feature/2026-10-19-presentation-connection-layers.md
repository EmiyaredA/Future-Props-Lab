# Agent Note: 演示工坊连接线参与元素层级排列

Status: implemented

## Problem

连接线固定绘制在全部元素之下，无法将关系线放到背景形状上方，也不能调节交叉连接的顺序。仅增加面板按钮或 CSS 会导致保存、放映与 PPTX 不一致。

## Decision

连接新增 layer，表示其下方元素数量，0 保留原有绘制行为，同层按 connections 数组顺序。scene/stacking.ts 统一解析顺序并提供置顶、置底、逐层前后操作；元素现有层级入口同样消费该函数。连接面板仅对已创建连接开放层级按钮，边界禁用，不修改端点与 waypoints。沿用文稿历史及串行 CAS 保存，不增加独立状态。

文稿 schema、OpenAPI 和 SDK 同步生成。登记 0098 只补缺失 layer，不修改已有值、页面顺序、revision 或更新时间。JSON 文稿仍由 PresentationProject.document 持有，无新增 ORM 列。复制片段换算局部层级，粘贴换算目标页层级；删除元素同步减少保留连接下方的元素数。

画布、缩略图与放映使用相同 DOM 顺序。PPTX 按相同顺序排列连接及标签；连续的分组保留原生组。由于 PowerPoint 组是不可分割的叠放项，成员与外部对象交错时，仅展开受影响的导出组，优先保持画面，不修改源文稿。

## Alternatives considered

- 仅提供连接之间的排序：不能解决线被背景遮住的问题。
- 给全部元素和连接增加 z-index：重复元素数组已有的顺序，并扩大持久化与复制的同步范围。
- 无条件保留 PPTX 分组：无法表示组内成员与外部连接交错的顺序。

## Consequences

旧页面保持连接在底层，已保存修改可撤销、重做与重开。每页至多 200 个连接，独立 SVG 参与 DOM 排列，保持命中检测和键盘选线。PPTX 交错分组的可编辑成员仍在，但该组不再作为整体导出；交付指南明确此边界。

## Verification

- Web 测试覆盖逐层跨越连接和元素、边界、DOM 顺序、路径保留、撤销重做、片段复制粘贴与删除。
- 后端测试覆盖默认值、非法层级、幂等迁移、API 保存重读与批量操作，以及 PPTX 分组和标签顺序。
- 浏览器旅程覆盖重叠处命中、置顶、撤销重做、保存重开与放映。

验收结果：演示工坊 Web 173 项通过；后端演示、迁移与架构检查 161 项通过、1 项性能测量按条件跳过。现有 HomeHeroPet 跨 feature 内部导入使架构全量检查失败，该项未改动；全量格式检查另有两处既有格式问题，包含受保护的文档中心样式，未修改。构建、lint、契约、SDK、导入包和文档保护检查通过。Chrome 隔离旅程通过，并检查了明暗主题及 390px 面板截图。正式持久数据未执行迁移。
