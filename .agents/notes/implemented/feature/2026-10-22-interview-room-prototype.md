# Agent Note: 面试室独立前端交互原型

Status: implemented

## Problem

用户需要评审从 JD、简历提交到面试复盘的完整交互，仅有四屏视觉稿不能验证任务状态、回答记录、设备检查与重练流程。

## Decision

原型独立保存在被忽略的 `.local/interview-room-prototype/`，沿用 FPL 的品牌素材、暖白与陶土橙配色，面试阶段使用深色界面。使用 React 内存状态、固定输入快照和确定性模拟任务；回答及其时间点直接传递给复盘和导出，不生成与用户输入无关的假记录。

原型不注册生产 Web 路由，不修改后端、模型测试、Workspace 权限或正式文档入口，也不引入真实 RAG、外部 Agent、媒体采集或持久化。任务目录与交付验收只表达未来契约的可视化示例。独立开发服务器只监听本机地址。

## Alternatives considered

- 直接加入 FPL 的应用与后端：会扩大当前仅评审交互的范围，且需要另行评审产品边界与服务契约。
- 仅用静态图或固定页面跳转：不能验证自定义输入、准备失败、真实回答定位、暂停和重练取消等状态。

## Consequences

原型与正式应用隔离，修改或刷新不会影响真实运行数据。刷新清空内存记录；PDF / DOCX 仅显示文件名，需手动粘贴摘要；反馈由文本规则模拟，候选人照片为生成的虚构示意图，不存在真实音视频分析。

源码、依赖、生成图、报告与浏览器截图均保存在该 `.local/` 子目录，完整验证记录由目录中的 `design-qa.md` 维护。新增 HTML 仅为本地原型入口，不属于生产 Web 响应式路由清单。

## Verification

- `node --test tests/interview-data.test.mjs`：验证自定义 JD / 简历进入提问、输入快照、真实回答引用、时间点、空回答与报告导出。
- 原型目录内 `npm run build` 与 `npm run test:sites`：验证静态构建与模板打包边界。
- 应用内浏览器验证材料、准备失败重试、资料来源、设备检查、面试暂停、模拟设备切换、回答记录、提前结束、反馈定位、简历建议、Markdown 下载与单题重练。
- 桌面和窄屏视觉证据、修复与对照结论记录在原型目录的 `design-qa.md`。
