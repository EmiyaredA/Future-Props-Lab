# Agent Note: 视频剪辑工坊可选择的音频转场

Status: implemented

## Problem

原有接缝仅有线性交叉淡化，且用户必须手动先重叠两段音频。转场面板无法预听不同声音曲线，修改时长也不能直接调整真实重叠。

## Decision

沿用独立接缝转场模型和时间线操作 API，新增等功率、淡出再淡入和频率扫掠，保留旧 `audio-crossfade` 的线性语义。片段头尾仍只使用既有淡化。Web 的音频效果卡先暂存选择与时长，再预听或提交；接缝标记显示当前效果与真实重叠时长。

`setAudioTransition` 在一个 revision CAS 批次中创建或更新接缝，并将 B 及同音频轨后续片段和关联组整体移到所选重叠位置。A/B 与画面关联时要求先分离，移动涉及锁轨、负时间或非法时间线时整批失败。Web 撤销保存原片段状态和原转场；无新数据库字段。预听与编辑器播放共享增益、缓动和扫频函数；FFmpeg 导出实现对应增益表达式与动态滤波命令。

## Alternatives considered

- 只更新转场记录里的时长：记录会与真实重叠不一致，预览和导出会不同步。
- 用片段边缘淡化模拟接缝：无法表现等功率和扫频，也会改变片段自身的头尾行为。
- 每个后续片段分别提交：可能出现部分移动，且会突破单次操作批量限制。

## Consequences

- 应用音频转场可能使后续关联画面片段整体提前或延后；UI 必须让用户明确提交，并可撤销。
- 频率扫掠会增加预览中的 Web Audio 节点和导出中的 FFmpeg 滤波器；长接缝按固定步数更新频率。
- 旧项目中的 `audio-crossfade` 继续按线性增益解释，不需要迁移。

## Verification

- `tests/test_video_editor_audio_transitions.py` 验证四种增益、扫频方向、自动重叠、关联组跟随、撤销／重做、拒绝行为和合成音频导出。
- `web/tests/video-editor-transitions.test.tsx` 与音频曲线测试验证效果选择、首尾相接默认时长和操作形状。
