# Agent Note: 设定卡详情按页签编辑

Status: implemented

## Problem

设定卡详情将语音、文字字段和素材／生成折叠项纵向堆叠，常用信息被分散，查看与编辑需要反复展开和滚动。用户要求右侧改为 Tab，并将「确认的设定」改称「描述」。

## Decision

详情默认打开「设定」，角色语音放在设定内容内，其余入口按现有权限显示「关联」「生成」。使用已有 Radix Tabs 提供方向键、Home／End 和焦点管理；编辑草稿、素材选择、生成参数与任务观察继续由编辑器持有，切换页签不保存、不生成任务。关联面板保持挂载以保留项目舞台选择；离开设定页签时卸载语音，避免隐藏后继续播放。生成页签因归档或权限变化隐藏时回到设定，避免留下空白面板。

桌面弹窗使用稳定高度，媒体与详情分别滚动，标题和保存栏始终可见；窄屏回到单列滚动与横向候选图。采用图保持视觉优先，候选图明确标记已采用项。编辑与只读文案统一为「描述」，继续使用原有 `design` 字段和保存契约。

## Alternatives considered

- 继续使用折叠列表：不能满足用户明确提出的分 Tab 交互。
- 所有页签都卸载：项目舞台的未提交选择会随切换丢失。
- 所有页签都保持挂载：语音会在隐藏面板中继续播放。

## Consequences

没有新增持久状态、接口或依赖。只读入口保留设定及角色语音试听，不出现关联修改和生成页签；生成权限与归档约束保持一致。候选图片组件仅展示当前图片集合并发出采用操作，草稿与持久化仍由编辑器持有。诊断和浏览器截图归忽略的 `.local/card-editor-tabs/`。

## Verification

隔离 Chromium 的三个浏览器旅程通过，覆盖三类设定卡、键盘页签切换、跨页签草稿保留、保存、素材选择、语音上传及解除绑定、窄屏和深色主题。播放器、卡片分组与侧栏的十六项单元测试通过。改动文件的 ESLint 通过，截图位于上述本机诊断目录。全站类型检查发现并行内容标识接口尚未进入生成类型，不属于本次界面改动。
