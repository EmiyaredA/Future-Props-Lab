# Agent Note: 看板项目素材分类切换

Status: implemented

## Problem

看板侧栏同时展开人设、场景、道具和项目文件，空设定也占据文件列表上方空间。随着素材增加，查找文件与设定需要在同一长列表中滚动。

## Decision

采用用户选定的左侧纵向导航，固定显示文件、人设、场景、道具四类及数量。右侧仅挂载当前视图，搜索按视图保留。导航使用 Radix Tabs 提供上下键、Home/End、焦点和选中态语义。

导航数量基于未搜索的项目文件节点和已引用设定卡；设定库的其他卡片不计数，重复引用不重复计数，读取失败不伪装为零。关联设定卡的图片节点沿用原有去重规则，旧分类素材继续留在文件树中。

各视图复用原有设定卡和文件管理操作；切换不写数据库、不改变节点选择或运行中的任务。文件新建采用主按钮与类型菜单组合，菜单创建所选类型，主按钮继续创建最近选择的类型。禁用条件沿用画布就绪、冲突与等待状态。

## Alternatives considered

- 设定/文件两页签：入口更少，但访问设定类型需要再选择一层。
- 顶部四类页签：保留列表宽度，但窄侧栏中横向标签与数量更拥挤。
- 继续折叠三类设定：减少空态占位，但仍使设定和文件在同一滚动区堆叠。

## Consequences

侧栏宽度在桌面为 340px、中等视口为 300px，窄屏使用不超出视口的浮层。导航、标题、搜索和导入入口保持可见，内容独立滚动。搜索和页签是页面内临时状态，不跨账号或浏览器持久化。

## Verification

- 看板管理测试覆盖视图切换、空态添加、项目范围计数、分别搜索、键盘导航和类型菜单创建。
- 原有设定卡变体/来源、节点管理、上传和恢复测试继续验证既有操作。
- 浏览器截图与视觉检查证据保存于被忽略的 `.local/materials-view-switch/`。
