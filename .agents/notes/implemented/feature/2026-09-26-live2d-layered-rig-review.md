# Agent Note: 红莉栖分层骨骼先行验收

Status: implemented

## Problem

现有内置 Amadeus 工程用单张成品画面的相互重叠裁片建模，难以逐层核对遮挡、眼口独立性和关节蒙皮；在未核准绑定质量前继续制作七状态动画会把素材缺陷放大。工坊也缺少图层独显、透明轮廓、贴合 PNG 的网格与直观的权重试调。

## Decision

保留 FPL v3 文档、项目 API 和当前运行头像。新增由用户确认原画出发的审阅专用构建脚本，将可见像素分配给独立透明 PNG，补绘遮挡下额头、颈肩与关节连续面，并输出分层 PSD、无正式动作的 `.fpllive2d`、关键静态姿态和实际尺寸头像。工坊对象树提供临时独显，画布显示选中图层透明轮廓，导入 PNG 根据 alpha 区域生成网格；绑定面板提供骨骼权重热图、归一化画笔和不落盘的姿态试调。拓扑重建在清除蒙皮与关键形前显式确认。

## Alternatives considered

直接在当前工程包继续增加动画会保留裁片缝隙。接入 Inochi2D 运行库会改变已确认的原生工作流，本阶段只参考其先分层、再蒙皮、最后做动画的制作次序。将新草案立即设为内置头像不符合用户要求的先验收流程。

## Consequences

草案保存在 `.local/output/live2d-rig-review/`，不会自动写入用户数据库。隐藏手部资产为备用图层，因为选定的半身原画没有可见手；其可见性需在后续动画制作时再决定。半身相机位避开原画下缘的画布截断；头部侧倾时领口与发束仍有细碎接缝，须在绑定验收前继续修整。当前工程仍承担线上头像，待用户验收分层与骨骼后再制作动作和切换。

## Verification

构建脚本重新解析 PSD 的 36 个图层；独立检查脚本通过正式工程包解析器检查素材引用、文档、16 根骨骼权重和无动作状态，并比较重组中性像素与选定原画。关键姿态和 48px、76px、半身舞台图可逐张审阅。后端工坊与权限测试 23 项、Web 工坊测试 17 项通过；隔离 Chrome 的四条工坊流程通过，包括图层独显、热图与试姿态。浏览器流程发现空项目导入 PSD 后相机位仍为旧画布尺寸；现在首次导入会同步设置头像和舞台相机位。契约与相关文件静态检查通过。全库构建、格式和 LFS fsck 的已有仓库问题在任务记录中单独报告。
