# Agent Note: 官方知识库写作与阅读体验

Status: implemented

## Problem

官方知识库已有 12 个库和 84 篇文章，但部分内容以功能罗列和重复技术模板呈现，读者难以判断从哪里开始、执行后看到什么，以及图形如何对应实际代码。目录与大纲占用同一阅读侧，长文章也缺少明确的后续路径。

## Decision

保留稳定库、文章 ID 和独立路由，重写知识库版中文正文，不迁移原文档中心。操作指南围绕实际任务、步骤、成功标志和排错；技术文章用具体实例衔接至少两幅图，并把源码入口放在末尾。写作参考 Claude 官方快速开始、API 入门与原理解释的组织方式，产品事实仍以当前源码与验证流程为准。

文章目录增加简介与相关阅读。桌面采用目录、正文、大纲三栏，中屏收起大纲，窄屏复用目录抽屉。阅读块提供三类受控提示框、本地语法高亮、代码复制和标题链接；大纲监听正文滚动容器。首页、前后篇和相关阅读共用目录元数据。

Markdown 关闭原始 HTML，不引入 MDX。内容和高亮资源随构建发布，不新增数据库、HTTP 路由或笔记格式。图形渲染组件的身份独立于外层导航与弹窗回调，确保打开复制对话框时保留视口。

官方阅读不接入账号阅读偏好 API，避免隐含写入和旧位置覆盖章节链接。表格渲染同样保持组件身份；前后篇使用可视分组目录顺序，文章切换后将焦点交给新标题或指定章节。个人副本回归发现并修复了草稿检查期间提前挂载只读编辑器的竞态，见[草稿检查挂载边界](../bug-fix/2026-10-03-note-recovery-editor-mount.md)。

## Alternatives considered

- 只调整配色：无法解决正文缺少可执行步骤和失败恢复的问题。
- 全文套用统一标题模板：方便批量生成，但掩盖各应用不同的数据与交付边界。
- 引入远程文档站或 MDX：增加离线依赖和执行面，与现有静态只读资源契约不符。

## Consequences

后续行为变更需要同时维护正文、简介、相关阅读和技术图。写作及阅读组件约定集中在 `docs/operations/official-knowledge-writing.md`。文章级路由稳定；章节锚点沿用源位置，正文改写后旧章节偏移可能改变。
