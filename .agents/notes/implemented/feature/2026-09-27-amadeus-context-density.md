# Agent Note: Amadeus 当前上下文自适应密度

Status: implemented

## Problem

Amadeus 将当前窗口数量放在一行摘要中，展开后又将路径、保存状态和选中对象拼成长文本。单窗口场景无法快速读到页面信息，多窗口场景则缺少活动窗口优先级，占用聊天空间。

## Decision

当前上下文在 1–2 个窗口时默认展示每个窗口的标题、路径和选中对象；3 个及以上时默认展示活动窗口摘要、剩余窗口数量和应用计数。展开的多窗口列表按应用分组，活动窗口置顶，并在受限高度内独立滚动。手动展开状态在同一密度档内保留，跨档时恢复默认。页面标题使用既有桌面桥接消息的 `title` 字段，不改消息格式。

## Alternatives considered

- **始终展开列表** — 无需状态切换，但窗口增多时会持续挤压聊天内容。
- **浮层或侧边抽屉** — 能减少纵向占用，但会遮挡内容或压缩窄桌面窗口的聊天宽度。

## Consequences

- **收益**：短上下文可直接阅读，长上下文先呈现与当前操作最相关的信息；手动引用仍独立留在输入框上方。
- **代价与已知上限**：折叠摘要只展示活动窗口和最多三个应用计数；其余信息需展开查看。最小窗口尺寸下列表需要滚动。

## Verification

`web/tests/amadeus-context-panel.test.tsx` 覆盖密度切换、活动窗口优先、分组和实时更新；`npm run test:desktop:amadeus` 使用临时数据验证桌面链路。另运行 Web 测试、lint、格式检查和构建。
