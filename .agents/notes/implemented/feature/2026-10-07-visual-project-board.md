# Agent Note: 视觉项目看板与节点输出历史

Status: implemented

## Problem

自由画布适合编排依赖，但缺少按用途整理节点和逐任务创作的入口。节点只保存一个素材指针，重新生成会清空素材；上传、生成和手动预览没有统一的历史与最终版本语义。

## Decision

画布与看板共用同一节点文档和连线。分类为单一主分类、可选分组与附加标签。输出版本由视觉工坊服务端登记；生成、上传和文本保存自动成为最终输出，预览历史与选择最终输出分开。输入绑定上游最终输出或固定版本；提交时解析并记录快照，不自动重生成下游。新增方舟 Seedream 原生多图适配，通过共享 GenerationTaskDriver 处理同步结果，提交中断不重提。状态页通过 current_nodes 投影读取节点当前关联与运行记录，不遍历整个生成历史；记录状态变化或运行记录退出投影时刷新输出。助手指定已有节点时复用身份并保留最终输出。

## Alternatives considered

- 新建独立看板任务模型：会让节点和任务身份分裂，产生同步与重复导航。
- 前端轮询后覆盖素材：关闭页面时无法归档，也会覆盖手动选择的历史版本。
- 拼接参考板：用户选择原生多图接入，因此不把合成图当成多图模型能力。

## Consequences

历史分页、上传版本、文本版本、最终输出、跟随与固定引用在两种视图一致。旧项目与快照保留可识别历史；不同 Workspace 的节点、素材和输出不能交叉引用。所有网络与迁移验收在隔离数据和模拟供应商上执行。

## Boundaries

外部供应商的新协议影响模型中心与独立推理入口，必须统一能力与参数校验。背景输出登记必须在短事务中读取最新文档，不能覆盖编辑快照；文件删除需要保护历史版本。生成产物与验收日志保存在忽略的 `.local/task-board/`。
