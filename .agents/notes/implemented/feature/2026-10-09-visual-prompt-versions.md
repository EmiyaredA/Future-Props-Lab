# Agent Note: 视觉工坊提示词多版本

Status: implemented

## Problem

生成节点只能保留一份提示词，比较多个文字方案需要反复覆盖或复制节点。输出历史记录生成结果，不能表达尚未提交、可以独立编辑的文字方案。

## Decision

图像、视频和音频草稿保存 1–20 份具名文字版本及当前选择，原 prompt 字段同步为当前文字。版本只拥有文字，模型、参考素材与生成参数共用。字段归属媒体草稿的 JSON 契约，保存沿用画布整体 CAS 和操作批次，不引入独立表或版本 API。后端验证 ID 唯一、当前版本存在以及当前文字一致；旧客户端省略两个版本字段时，画布用例保留已存版本并更新当前文字。

前端共用版本 hook 以同步快照提交文字编辑和版本管理，防抖保存与失焦保存读取同一份最新数据。输入不依赖 React 渲染完成才进入快照，旧失焦回调不会写回已切换版本。版本管理立即排队保存，模型提交等待已有保存队列，失败与冲突保留编辑且不提交。参考图片重排同时更新所有版本中的编号。节点复制和项目包保持版本集合；任务保存实际提交文字，输出历史继续独立。

迁移 r0089_visual_prompt_versions 仅补齐已有媒体草稿的 v1，保留文字、配置、布局、连线及原 revision。旧项目包通过 schema 归一化；迁移不导入应用模块，正式数据只通过已登记迁移入口升级。

项目包导入同步重映射共用 prompt_reference_names 的素材 ID，使所有文字版本继续识别已改名素材块；不改变版本文字或当前选择。未包含在包内的失效素材名称不取得导入后素材的身份。

## Alternatives considered

- 手动历史快照：不能直接编辑多个并行方案，也需要额外恢复动作。
- 每次生成自动留版：不能保留未生成的方案，重复提交容易产生无意义版本。
- 保存整套生成配置：增加参考素材和参数的独立生命周期，与本次仅切换文字的需求不同。

## Consequences

单节点版本 ID 只在节点内使用，复制节点可保留 ID，文字没有跨节点可变引用。20 个版本和每版 6000 字符限制约束整体画布自动保存体积。旧客户端更新单份文字不会清空其他方案；新客户端显式版本数据不一致时返回 422。共用参考发生删除或替换后仍需检查各版文字，版本不冻结媒体。无新增权限或路由；编辑权限与 Workspace 隔离继承画布 API。
