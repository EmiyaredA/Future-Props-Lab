# Agent Note: 节目监视器直接变换画面

Status: implemented

## Problem

视频剪辑已有位置、缩放、旋转和关键帧契约，但节目监视器只能显示选中轮廓，用户需要反复输入数值才能构图。精确停帧覆盖实时媒体，直接把手势绑在媒体节点上无法稳定命中，也无法在拖动中反馈画面。

## Decision

节目监视器将裁切媒体与变换操作框分开。媒体尺寸和图层样式归属 `previewGeometry.ts`，`VideoEditorMediaLayer.tsx` 拥有代理视频和图片显示；`previewClock.ts` 共用既有媒体时钟纠偏。操作框按画布坐标计算旋转、镜像、锚点和转场缩放后的角点，手柄尺寸保持屏幕像素。外层监视器容器进入全屏，内部画布保留工程比例。

`transformModel.ts` 提供纯几何及逐属性变换操作，四角保持当前比例、四边独立拉伸，缩放固定对侧点，旋转围绕既有锚点。`usePreviewTransform.ts` 持有指针快照、捕获和本地草稿，通过编辑器显式把草稿提供给属性检查器。草稿不进入时间线，不逐帧发送请求。精确帧在拖动期间退出，重新挂载的对应版本图片加载成功后恢复显示。

单次手势通过已有保存队列提交一个 `TimelineEditBuilder`，提交时重验工程版本、片段和轨道锁，并捕获真实逆操作。已有动画的属性更新或新增当前时刻关键帧，未动画的属性更新基础变换；接缝转场的当前时刻沿用渲染器连续媒体时间求值，保证拖动与检查器写入被当前画面实际消费。镜像只施加到媒体像素，不反转锚点与操作框的几何区域；检查器采用同一契约，保留输入中的草稿。失败沿用未保存操作保护，不自动重试。手势失去捕获、Escape、版本、时间、选区或舞台尺寸变化时取消。抠像分屏保留自己的拖动命中区域，变换手柄开始操作时退出对比。

## Alternatives considered

- **直接修改 DOM 媒体节点** — 精确帧遮挡命中区域，数值、关键帧和撤销记录会脱节，因此采用显式草稿和独立操作框。
- **每个 pointermove 写入时间线** — 引入请求积压、版本冲突和大量撤销条目，因此只在结束时提交一个批次。
- **整体平移已有动画** — 对动画曲线施加全段偏移会改变其他时刻；用户选择只修改当前时刻。

## Consequences

- 视频、图片和纯色共享操作框；文字保留现有移动行为，多选继续使用批量检查器。
- 不改变 HTTP、SDK 或持久化字段，不增加迁移；所有写入仍使用现有正式时间线 API 和 CAS。
- 拖动期间使用代理预览，最终效果以加载完成的精确帧为准。完全移出画布的片段通过检查器移回。
- 拆出画面适配按钮与媒体组件，使编辑页和预览页继续低于单文件上限。官方流程正文和管理员导入包同步更新，已导入文章不自动覆盖。

## Verification

- `web/tests/video-editor-transform.test.tsx` 覆盖几何、锚点、镜像、转场缩放、关键帧、CAS 构造、单批撤销重做、实时草稿、取消、权限、锁定、保存失败和数值输入保护。
- `web/e2e/video-editor-transform.spec.ts` 通过正式 API 创建隔离视频工程，使用真实鼠标验证变换、精确帧版本和像素、撤销重做、刷新、明暗主题、全屏比例和画布边缘手柄；所有数据库、素材和截图落入 `.local/video-transform/`。
- 验证入口：视频编辑器 Web 测试、`tests/test_architecture.py`、Web lint、格式检查、构建、`npm run contracts:check`、`npm run knowledge:seed:check`、`npm run verify-notes` 和 `npm run check-docs-center-protected`。

验证结果：33 个视频编辑器 Web 测试文件共 251 项通过；架构测试 48 项、官方导入与发布测试 8 项通过；Chromium 真实鼠标与像素验收通过。根级 lint、format:check、生产构建、contracts:check、官方包 stale-check 与文档保护检查通过。Note 三项校验通过 `node --import tsx` 执行同一校验脚本，避免受限环境中 tsx CLI 的 IPC 监听。
