# Agent Note: 思绪工坊统一阅读布局与多级章节目录

Status: implemented

## Problem

文档大纲占据正文左侧留白，查找又单独形成横栏，阅读和编辑入口的正文对齐不一致。原目录仅通过缩进表达层级，长文章无法折叠子章节；滚动定位和底部章节判断依赖窗口，知识库实际滚动容器却是 knowledge-main。普通只读入口还把文档树展平成列表。

## Decision

普通笔记、首页和社区文章共用温暖简洁的正文布局与明暗主题，正文最大宽度 820px。页面可用宽度达到 960px 时将 220px 章节目录停靠右侧，窄窗口通过顶栏入口打开自绘弹层。正文查找和目录按钮通过页面显式提供的 Portal 宿主并入顶栏；独立阅读器保留本地工具入口。首页标题进入同一正文列，编辑首页入口归顶栏，自定义封面仍保留。

页面通过 useDocumentChrome 持有工具宿主和整栏展开偏好，不共享模块级可变状态。章节目录从现有 H1–H6 派生父子结构，跳级压缩空层级，重复标题按节点位置区分。父级折叠不改变正文；编辑事务映射折叠位置与当前章节，正文删除同步清理失效位置。滚动更换当前章节时展开其祖先，手动折叠当前分支不会立即被高亮撤销。定位、顶部避让和底部判断使用实际滚动容器。

卡片保持目标引用和原数据格式，实时授权解析标题与简介。引导卡片提供开始阅读入口，页面摘要按样式限制行数，HTML 导出保留完整简介。只读文档导航复用 KnowledgeTree；权限、保存、未保存保护和阅读位置仍由原有功能拥有。顶栏工具、主题和窗口变化不重建编辑器及图形实例。

## Alternatives considered

- 保留独立工具横栏：持续占据阅读空间，无法实现用户选定的布局。
- 为社区文章建立独立阅读器：造成目录、图形、保存与权限契约的重复实现。
- 持久化标题 ID 与目录偏好到正文：增加无必要的数据兼容成本，目录操作也会污染正文 revision。

## Consequences

无 HTTP、SDK、数据库或正文 JSON 契约变化。整栏展开偏好只保留于当前页面会话，章节折叠随文章切换重置。目录展开、定位与临时显示折叠正文均不执行保存。导入来源指南更新后生成新的可选导入包，不回写已有导入文章。原产品文档中心不修改，验收数据和截图保存到被忽略的 .local/thought-reader-ui。

## Verification

- web/tests/features/thought-document-outline.test.tsx 的 9 项测试覆盖六级标题、跳级、重名、输入法、编辑映射、撤销重做、折叠状态、滚动展开及页面状态隔离；导航导出、顶栏和社区相关 21 项测试通过。
- 浏览器测试覆盖右侧定位、内部滚动、临时展开、顶部工具、只读多级文档树与不写正文；普通首页和社区阅读／编辑使用实际授权接口创建隔离验收数据。
- 实际预览覆盖 1600、1440、1024、768、390、320px 与明暗主题，检查内部和页面宽度、弹层边界与编辑器实例稳定性。
- 相关 12 个浏览器用例分别通过，包含全部 31 篇技术文章与图形缩放保持；官方导航夹具显式导入并发布，不依赖其他测试的执行顺序。
- Web 全量 232 文件、1545 项测试通过，后端文档导航和官方发布 16 项测试通过；生产构建、lint、格式、契约和官方导入包检查通过。Agent Note 树、格式和封印以 node --import tsx 执行同一检查脚本并通过，避免沙箱限制下的 CLI IPC。
- 全仓文档中心保护检查因本次工作开始前已有的两处 SDK 参考文章改动失败，本次没有修改这些保护路径。
