# Agent Note: 工坊标签页使用应用头像

Status: implemented

## Problem

独立工坊 HTML 共用站点 favicon，多开应用后只能通过截断的标签页标题区分工坊。
用户希望标签页显示与应用中心一致的头像，同时本机热加载和正式版本路径都能正确加载。

## Decision

十个独立工坊的 HTML 显式声明各自既有头像；`web/applicationIcons.ts` 的 Vite HTML 插件
通过既有 `imageVariants` 清单选择 64px WebP，保留 `%BASE_URL%`，不复制或重新生成图片。
正式独立构建继续使用服务自己的不可变资源前缀，通用站点入口保留站点图标。
新插件加入独立前端源码指纹，插件变化会生成新构建版本。

## Alternatives considered

- 所有页面继续使用站点图标：多开标签页时无法区分应用。
- 直接使用原始大图：不必要地下载高分辨率头像，既有轻量派生图已经可用。
- 在 HTML 中硬编码派生图摘要：更换头像并重新生成清单后容易失效。

## Consequences

头像与应用中心复用同一素材，独立服务资源清单已经包含对应派生图。
现有标签页可能需要刷新后更新浏览器图标缓存。兼容单体页面不新增独立工坊入口。

## Verification

- 两项 Web 测试覆盖十个工坊的独立头像、有效 WebP、资源大小和入口前缀保留。
- 隔离 Chromium 验证十个实际工坊页面：十个唯一图标 URL 全部返回 200，均可解码为 64×64，无脚本异常。
- Video 独立前端完整构建通过，图标文件包含在版本化资源清单中。
- Web TypeScript、ESLint 和格式检查通过；未修改或生成受保护的产品文档。
