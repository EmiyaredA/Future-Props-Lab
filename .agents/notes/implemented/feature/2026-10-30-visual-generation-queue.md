# Agent Note: 视觉工坊持久生成队列

Status: implemented

## Problem

生成任务创建前直接领取并发额度，满额时拒绝新请求；宫格整批领取额度也使大于账号并发上限的批次无法执行。已有 queued 状态并不代表独立等待容量，长队列还可能挤占已提交任务的轮询页面。

## Decision

治理台账为新图片／视频子任务保存独立账号归属、等待标记与唯一任务引用。等待任务不计入运行并发；账号等待容量跨工作区合计，按角色配置 0–1024，默认 20。图片宫格逐张占位，任务与画布 CAS 整体接纳；容量不足整体回滚。SDK 与视觉助手使用相同接纳入口，音频与模型测试保持原有额度规则。

应用装配向视觉执行器注入治理回调，生成驱动器在短 SQLite writer 事务中复核任务、权限与额度并完成 queued → submitting。候选选择跳过额度阻塞的账号，同账号不能越过更早等待者；先轮询已提交任务再调度等待任务。台账按任务类型批量结算，避免每个等待任务一次查询。

取消使用 expected_revision 与 queued 条件更新，只有未提交图片／视频可以取消。cancelled 是持久终态，失败结算也使用条件更新避免覆盖取消。取消不请求供应商，不删除旧输出。宫格剩余任务继续结束，并汇总取消、失败和完成计数。重启保留等待，submitting 中断安全失败，禁止重提；供应商超时从提交时间计算，排队时间不占供应商时限。

追加 0114 migration 重建受状态 CHECK 约束的任务与批次表，保留既有快照、外键、索引及台账归属；新任务提交时间与批次取消计数同步 ORM。迁移只在隔离数据库中验证，不在开发正式数据启动流程中应用。

## Alternatives considered

- 只扩大原并发额度：不能形成等待队列，仍会同时提交供应商。
- 内存队列：刷新后难以解释归属，重启会丢失等待任务。
- 宫格整批占一个名额：隐藏实际调用数量，难以准确限制并发和等待容量。

## Consequences

降低等待上限保留已接受任务并限制新增；0 关闭新增排队。队列满返回 429，取消与开始提交竞争返回 409 及当前快照。前端复用任务状态和查询键，节点、看板与任务页提供取消入口。任务详情和 SDK 支持 cancelled，官方指南与技术图同步队列边界。

## Verification

真实鉴权 API 与独立 SDK 测试覆盖竞争接纳、容量不足整批回滚、跨工作区同账号计数、取消竞争、重启与权限失效；隔离迁移测试验证数据、CHECK、外键和索引。组件测试覆盖看板、画布、任务页、宫格子任务取消、错误反馈与配额 CAS。相关驱动器、治理、架构、契约与构建检查独立运行；仓库已有范围外失败在交付中单独报告。
