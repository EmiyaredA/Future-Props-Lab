# Agent Note: 编程智能体接入向导

Status: implemented

## Problem

编程智能体页面只显示登录命令，首次接入的用户难以判断 CLI 安装位置、登录方式和启用顺序。Codex 启用需要通过登录检测，但专用登录命令又要求连接已启用。

## Decision

所选 Agent 的连接区域显示安装、登录和验证三步。安装与认证进度根据连接目录的状态显示，切换列表项只改变本页内容。检测和管理员启用复用原有接口，外部客户端接入继续在底栏提供。

Codex 专用登录脚本用一份内存配置解析可执行文件，允许在启用前准备凭据。配置仍由正式启用流程校验和保存。

教程用 `npm --prefix` 显式定位 FPL 安装目录，用户可以在任意终端目录启动同一个登录脚本。

## Alternatives considered

- 将步骤放在独立帮助页面会让用户在诊断和教程之间来回切换。
- 先手动启用 Codex 再运行专用登录，会绕开网页已有的登录后校验顺序。

## Consequences

不同 CLI 的安装入口和登录说明随所选连接切换。登录发生在运行 FPL 的 Mac 上，连接检测仍以服务端返回的状态为准。

外部接入的位置由[编程智能体教程中的外部客户端配置](../bug-fix/2026-11-05-inline-code-agent-mcp-guide.md)更新。

## Verification

- Web 组件测试覆盖教程、复制反馈、检测重试和启用权限。
- 隔离的假 CLI 测试覆盖停用时的 Codex 登录与失败路径。
- 浏览器旅程覆盖键盘操作、登录状态更新与明暗主题布局。
