# Agent Note: 视觉画布新增避让与主动整理

Status: implemented

## Problem

工具栏新增使用窗口中心，看板新增与批量上传仅小幅错开坐标，连续操作会覆盖已有卡片。节点增多后，手动排列流程与素材缺少可撤销的整体操作。

## Decision

节点卡片尺寸沿用 NODE_SIZE，新增预留 32 个画布单位间距。有界候选搜索优先使用操作锚点附近的空位，工具栏优先使用排除固定控件的可见区域；密集区域向已有内容外扩展。节点组只整体平移，已有内部重叠保持原样。后台自动生成沿用同一默认规则，并由共享 JSON 样例约束前后端一致性。显式 API 坐标保持原契约。

主动整理默认按无环依赖图的最长路径分层，从左到右排列独立流程，独立素材放入网格；菜单提供全部网格和选区整理。选区整理把未选中卡片当作障碍物。纯计算模块只返回位置；控制器通过一次快照提交保存并记录一次撤销。无变化不保存，冲突、拖动、连线和上传期间不执行整理。

新节点需要时只平移视口，整理后适配目标卡片区域。临时展开的编辑面板不参与持久布局，看板分类与视图切换不触发整理。宫格合成先完成草稿保存，再从最新节点与 revision 计算结果位置并提交。

连续新增验收发现看板编辑区的同级子组件重复使用节点 ID 作为 key，产生 React 重复标识警告。编辑区父容器已经按节点 ID 重建，移除冗余子 key，保留原切换节点时的状态重置行为。

## Alternatives considered

- 每次新增整理整个项目：破坏用户手动位置，拒绝。
- 继续固定小幅错开：没有考虑卡片尺寸，无法消除遮挡，拒绝。
- 引入布局依赖或持久布局配置：当前无环图和固定卡片足以支持确定性布局，暂不引入。

## Consequences

原项目不自动迁移或重排。卡片避让与布局不提交模型请求、不改分类或引用绑定。节点组避让采用整个节点组的外接矩形，可能保留较大空白，但能保留组内相对位置。前后端存在两份纯默认避让实现，共享样例与尺寸测试防止漂移。

后台宫格占位节点也逐项计入避让；Agent 生成省略坐标时使用默认避让，显式坐标仍原样校验和保存。

## Verification

算法与前后端共享样例测试覆盖密集区域、混合尺寸、坐标边界、稳定布局和整组平移。组件测试覆盖各新增入口、上传失败停止、单次撤销／重做、无变化不保存与冲突保护；隔离浏览器旅程覆盖视图往返、刷新、不同缩放、侧栏和窄屏菜单。验证结果以本次测试与质量门禁为准，不使用真实供应商或正式桌面数据。

本次全量测试通过后端 1558 项（2 项跳过）和 Web 2439 项；新增后台宫格占位与 Agent 默认位置后，相关后端与架构回归 76 项通过。浏览器布局与原有缩放旅程共 5 项通过。Lint、格式、构建、官方导入包一致性、Note 与文档中心保护门禁通过。OpenAPI 和 SDK 代码契约检查通过；总契约检查仍受 HEAD 中已有的三篇过期 SDK 文档阻断，未修改受保护正文。
