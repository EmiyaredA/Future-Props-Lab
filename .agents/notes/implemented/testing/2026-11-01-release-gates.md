# Agent Note: 公网访问发布前的回归与文档门禁

Status: implemented

## Problem

旧 Amadeus 测试仍假设客户端持有模型运行，新 Agent 应用与账号隔离的文档缺少完整导航和技术正文。完整回归无法证明当前访问入口可以上线。

## Decision

测试通过已登记的隔离 CLI 适配器执行真实运行、审批、恢复和继续流程，验证旧接口拒绝而非继续模拟旧行为。面试助手测试等待异步场次恢复完成再编辑，避免依赖缓存刷新时序。草稿恢复测试逐例恢复 Promise mock，避免延迟回调使用已清理实现；复杂编辑器全量验证串行运行以隔离资源争用，不更改既有超时。视觉草稿断言遵守当前归一化字段及有效范围。

用户明确授权修复文档门禁，因此同步官方知识库与受保护文档中心的账号、新应用及 SDK 说明；受保护内容单独提交，保留原保护检查器。官方导入包仍由管理员主动导入，不覆盖已有笔记。

部署在完整回归及构建通过后进行。云端仅发布经过清单验证的程序资源；正式应用停止并持有数据锁后备份完整数据与配置，再由已登记迁移入口升级。新运行时默认关闭访问，旧隧道通过桌面原生流程接管。

## Alternatives considered

- 跳过旧失败或提高构建预算：掩盖实际契约差异，不采用。
- 在运行的数据库旁启动第二个后端：破坏唯一运行时边界，不采用。
- 把文档保护检查改成忽略授权路径：削弱之后的保护，不采用。

## Consequences

保留原有未提交修改、真实账号数据与旧配置恢复资料。完整备份随素材体量增加耗时；近期密码验证仍由管理员在应用内完成，不从聊天接收密码。
