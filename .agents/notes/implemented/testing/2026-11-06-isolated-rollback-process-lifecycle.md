# Agent Note: 记录隔离回滚演练的旧站就绪与停机

Status: implemented

## Problem

隔离回滚演练启动正式兼容网站入口。并行构建和回归期间，实际就绪用时可超过 20 秒。原进程清理还可能用第二个超时覆盖原始失败，导致报告无法区分未就绪和停机超时。

## Decision

演练通过真实 `/ready` 响应确认就绪，单独记录就绪和停机时间。就绪和停机分别有等待上限，失败时记录最后一次就绪探针结果或异常退出状态。只有演练未发生其他失败时，才把异常停机报告为主要失败。超出停机上限时清理子进程并阻止该次成功演练继续封存。

## Alternatives considered

- 固定延时后继续演练。这样无法确认服务已经就绪，也无法诊断退出。
- 强制停止后继续封存。这样会跳过旧站正常停止这一项演练条件。

## Consequences

测试仍要求真实网站启动和退出，耗时与执行日志可以用于区分加载慢、就绪失败和退出失败。演练的等待上限仅用于隔离测试，部署入口继续使用原有启动和关闭设置。

## Verification

使用双账号隔离配置运行封存、迁移中断续跑、回执重放与旧站恢复，核对两次就绪与停机记录，并从恢复后的网站验证账号与素材权限。
