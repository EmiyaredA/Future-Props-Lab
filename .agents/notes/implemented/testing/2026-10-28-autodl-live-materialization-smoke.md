# Agent Note: AutoDL 低成本实测与已有结果恢复

Status: implemented

## Problem

已有生成任务取得视频地址后，结果域名被本机 Clash Fake-IP DNS 解析为
`198.18.0.8`，触发结果下载的公网地址校验。重新生成会重复消耗额度，
也无法证明下载、素材入库和输出版本发布是否恢复。

## Decision

保留应用的公网地址校验。只把实际结果域名
`cg-comfyui-prod.tos-cn-beijing.volces.com` 加入本机代理的真实解析例外，
保留原有规则并刷新 DNS 与 Fake-IP 缓存。通过现有“重试保存”API 恢复已有任务，
不重新调用供应商生成。

用户明确授权的真实供应商验收使用独立视觉工坊项目。参考素材经正式文件 API
下载、截取前 1 秒并重新上传，再以正式画布与节点输出 API 建立输入和版本。
每个工作流串行提交一次，先落盘提交状态和任务 ID；恢复时先查询已有任务，
结果不明确时停止提交，不自动重放。检查下载哈希、预览、完整媒体解码、
节点输出发布和真实页面播放。诊断、原始请求参数、任务时间线与成片统一保留在
被忽略的 `.local/autodl-e2e/`，不把供应商密钥或签名结果地址写入报告。

## Alternatives considered

- 放宽公网校验：会把本机代理配置问题转化为应用下载安全边界的退化。
- 重新生成已有失败任务：已有可下载结果，重复提交增加成本且不能解决 DNS 根因。
- 直接修复数据库任务状态：绕过正式状态转换、素材落盘和输出发布规则。
- 并发提交全部工作流：不利于低成本诊断及中断后判断是否已经提交。

## Consequences

本机代理配置需要在后续配置切换后继续保留该精确域名例外。生产代码、公共 API
和数据库结构不因本次 DNS 问题而变更。真实供应商实测与确定性测试分别留证；
可播放成片不等于精确满足时长，供应商返回的时长偏差按原样记录，不裁剪隐藏。
上游没有提供 Base64 素材内容回显，编码路径由适配器回归覆盖，真实任务成功作为
供应商接受请求的证据，不宣称抓取了供应商内部接收记录。
