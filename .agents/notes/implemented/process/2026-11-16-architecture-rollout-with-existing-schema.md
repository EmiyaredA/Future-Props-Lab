# Agent Note: 保留线上 schema 的架构修复发布

Status: implemented

## Problem

架构修复通过全量回归，但正式环境为既有独立服务部署，部分服务仍使用较早的 schema。直接从当前分支重建全部镜像会混入旧视觉对话退役等无关数据变更。工作区还存在独立的加载样式修改，产品文档必须与代码分别提交。

## Decision

产品文档提交为 `96adc7d1`，架构及测试提交为 `77cd5f23`。原加载样式保持未提交且哈希不变。依据实际源码闭包确定发布范围：8 个可执行代码变更服务使用固定线上镜像作为基础，仅叠加本次提交的相关源码；Galgame 的格式及注释差异不触发替换。依赖、公开契约及注册迁移完整保留，不剪裁或改写迁移历史。

Portal、Assets、Annotation 和 Visual 前端以线上真实契约快照构建并校验。Visual 当前源码只额外接受两种响应枚举值，已有返回值兼容，未依赖新增请求。先校验并暂存不可变构建，再原子切换指针，旧资源保留。生产代码、镜像、构建、配置回退和门禁计划位于 `.runtime/deployment/`，验收中间产物不参与服务运行。

发布先按账号任务记录只读确认 Agent 空闲，再通过仓库门禁暂停两侧新工作、验证实际挑战值、执行切换和全部健康检查。失败路径恢复配置、镜像和网页并再次核验；成功后恢复接单。管理进程仅为重读镜像固定版本重启，其他 Mac Worker 保持原运行代码。

## Alternatives considered

- 全量使用当前源码镜像会混入尚未执行的历史功能迁移与数据清理，不属于本次修复发布。
- 删除或修改当前源码的迁移注册表来匹配旧库，会损害账本真实性。
- 复用工作区构建会混入另一项样式修改；使用已提交源码快照并记录真实线上契约输入。
- 直接重启开发入口会接管现有独立服务的运行路径，不能替代其 Compose 和 LaunchAgent 发布流程。

## Consequences

本次是 8 个后端补丁镜像与 4 个前端的功能等价发布，不能据此认为当前分支所有历史功能或迁移均已上线。没有修改正式 schema、没有清理旧对话、没有执行全量数据库备份。回退最小范围为受影响的配置原件及其权限、旧镜像和旧网页构建；已验证可用，未触发实际回退。源码和文档提交未推送到远程。

原任务全量后端 2971 项通过、4 项跳过，Web 1966 项通过，隔离浏览器 9 项通过。候选 8 镜像的导入、CLI、隔离 schema 初始化与账本数量检查通过。4 个程序构建及其逐文件哈希、API 指纹通过。

正式切换后 23 容器、7 个 Worker 及管理进程运行正常，本机和公网就绪，8 个更新服务内部 ready 返回 200，4 个程序的新清单和旧 JS 资源均通过。私人 API 两侧均拒绝匿名读取，Agent 两侧恢复 accepting。schema 账本摘要前后一致；浏览器真实文档入口无脚本错误且新章节可见。文档独立提交检查通过，原加载样式补丁哈希不变。持久发布和回退记录在 `.runtime/deployment/releases/architecture-77cd5f23/`。
