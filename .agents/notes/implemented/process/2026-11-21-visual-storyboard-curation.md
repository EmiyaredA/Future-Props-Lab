# Agent Note: 既有视觉项目的分镜内容整理

Status: implemented

## Problem

项目画布的制作节点、旧分类和分镜文档独立保存。历史项目可以已有视频与分镜图，
但新分镜栏仍为空。直接按图片或视频节点逐个建卡会把共用参考、同镜重试与整片合集
误算成镜头，也会丢失现行合并制作与历史拆分方案的区别。

## Decision

使用内容专用清单，结合实际媒体代表帧、原分组、提示词、连线和制作记录人工确定
制作单元。现行镜头优先排列，独立历史方案以标题明确标记；同镜候选继续留在原节点。
不自动改变采用输出、通过标记、生成任务、素材或节点内容。

`scripts/demo/visual_storyboard_curate.py` 通过公开 SDK 提供 inspect、apply 和 verify。
调用者显式指定账号接入配置、项目 ID、清单和输出目录。清单使用项目和逻辑镜头键
派生稳定 UUID，记录原分镜 revision、画布摘要、镜头依据、制作节点和未纳入原因。
每个媒体节点必须有去向，新增引用必须属于当前项目，重复身份和漏项在写入前拒绝。

全批次先预检，再按项目独立执行正式分镜 CAS。重复执行只确认相同结果，不重复写入；
并发变更保留给人工复核。PUT 回执丢失时先读回，未确认成功不盲目重放。
最小恢复点仅包含该项目写入前的分镜文档、revision、目标及画布摘要，保存在 `.runtime/`；
可再生成的清单、媒体抽帧和核验报告放在被忽略的 `.local/`。

用户追加要求画布按分镜编组。`scripts/demo/visual_storyboard_layout.py` 先读取最新画布，
根据同一份内容清单生成可核验布局，再以正式画布 CAS 保存。只允许节点位置与可视分组变化；
提示词、节点顺序、连线、输出和分镜文档必须保持一致。同镜图片、视频和候选放入同组，
可唯一归属的说明及音频随镜头归组；共用素材另列，现行与历史方案分区排列。
现有分组契约至少两个节点，单节点镜头独立排列，不为创建分组复制素材。
所有布局单元按实际节点外框计算，预检互不重叠；保存前在 `.runtime/` 留存原画布恢复点。
布局 apply 也先做整批预检，并支持回执丢失后的读回确认与幂等重跑。

## Alternatives considered

- 对所有图片/视频逐节点导入：无法区分同镜候选和独立镜头。
- 按标题正则自动完成全部分类：旧项目含通用名称、重复名称与历史重编号，证据不足。
- 直接修改持久数据库：绕过账号、引用和 CAS 校验，违反正式维护契约。
- 把全部旧方案折叠为现行卡片：不满足用户明确要求的历史独立镜头保留。

## Consequences

工具不承担通用自动分镜识别，不新增服务接口或数据库结构。内容清单不含凭据，
不进入源码仓库。没有独立镜头内容的项目可以保留空分镜文档。
媒体抽帧仅支持归纳和镜头关联核对，不代表逐帧或音频质量验收，也不改变既有验收结论。

遵循 [能力实现契约](../../../../docs/architecture/capability-contracts.md) 的分镜引用与
版本约束、[开发与验证流程](../../../../docs/operations/development-workflow.md) 的
内容维护脚本规则，以及[文件暂存与数据库事务](../../../../docs/operations/file-transactions.md)
的正式 API 维护约束。

## Verification

- `tests/integration/test_visual_storyboard_curation.py`：现行与历史镜头归并、稳定重跑、
  账号和项目隔离、预检拒绝、并发保护、已有手工分镜保留、回包丢失与失败恢复。
- 正式应用前逐项目记录画布摘要，保存后按清单读回分镜与画布，确认写入范围。
- `tests/integration/test_visual_storyboard_layout.py`：归组、单节点、共用音频、无重叠布局、
  业务内容不变、并发拒绝、稳定重跑、回执丢失、恢复点及正式请求 schema。
- 浏览器核对项目分镜栏数量、列表、镜头选择与媒体预览。
