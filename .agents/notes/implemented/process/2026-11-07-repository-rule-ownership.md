# Agent Note: 仓库规则归属

Status: implemented

## Problem

根 AGENTS.md 混合日常编码规范、应用装配、能力行为和生产运维。部分规则还出现在贡献指南和项目目录索引，
导致正式迁移与契约生成的入口说明不一致，局部改动也难以判断需要阅读哪些内容。

## Decision

仓库保留单一根 AGENTS.md，列出通用编码、验证和数据保护规则，并按任务链接 docs 中的专题。
Studio 框架契约管理应用接入和共享机制。各能力专题管理自身行为。开发与验证流程、生产部署和 Agent Note
分别维护对应操作。目录索引用来定位代码所有者。

## Alternatives considered

继续扩充根文件可以让所有规则直接可见，但每次任务都要读取应用细节。逐目录添加 AGENTS.md 会把共享工坊契约
拆散，也会使跨应用任务遇到多个入口。现行布局使用一份根入口和按任务查阅的专题。

## Consequences

改动工坊注册、公共契约或正式启动流程时，先按根入口定位专题。修改规则时更新对应专题，适用范围改变时更新根入口。
行数阈值、架构测试白名单和产品文档中心保护按当前门禁执行。

## Verification

核对根入口到工坊框架、公共契约和正式启动的链接，逐条检查原规则的归属，并运行 Agent Note 与产品文档中心保护检查。
