# Agent Note: 用普通笔记与多维表格组织调研

Status: implemented

## Problem

[调研 Skill 初版](2026-10-08-research-to-document-skill.md) 的专用项目总览、证据侧栏和报告审阅界面把内容组织表现为一项新功能。用户要求保留笔记定位并善用现有多维表格，而非增加独立调研管理台。

## Decision

`research-to-document` 直接将普通父笔记作为报告草稿，子文档承载多维台账、长篇摘录和有意义的阶段记录。来源、方案比较、验证记录和问题按需要选择数据表；较多证据与结论才另拆表。新增 `ledger-tables.json` 提供六种原生 TableSpec 模板，筛选、网格、分组、看板和正文 multitableView 嵌入只复用已有契约，不要求创建所有空表。

用户可编辑笔记与表格是当前内容真源，Agent JSON 只作为恢复与校验快照。续做先读取并合并用户改动，home_note_id 与 report_note_id 默认指向同一父笔记；旧记录兼容保留，不改持久化 schema。正文中的精简表格视图引用原表，避免独立复制和重复维护。原预览保留，v0.2 使用现有笔记树、多维数据表导航和通用记录编辑的呈现方式，不增加生产页面或应用内 AI 入口。

## Alternatives considered

- **独立调研工作区再导出到笔记**：用户希望复用现有基建，独立工作区扩大职责。
- **全部使用普通正文表格**：来源筛选、同维度比较和验证状态不容易维护。
- **把所有内部记录强制分成六表**：小调研产生大量空结构，增加阅读负担。

## Consequences

Skill 和内容模板保持唯一维护源，个人 Codex 符号链接自动采用调整。资料链接、状态与短摘要适合结构化；长篇解释保留普通笔记。开放增长的业务 ID 使用文本，不虚构跨表外键；笔记／附件字段使用真实授权 ID 数组。原生日期只保存 YYYY-MM-DD，精确时间留在文本或恢复快照。

真实 App 存档没有在本次设计调整中执行；缺少用户指定目标时不自行选择知识库。原型使用虚构数据并在本地隔离运行，不能作为调研证据。

## Verification

原生 TableSpec 和 validate_table 逐表校验全部模板，包括筛选字段、选项、看板单选状态与主字段规则。Skill 结构、引用记录校验和相关测试共 15 项通过。v0.2 原型检查数据表与视图切换、未读筛选、搜索、CSV 导出、记录本地编辑、正文嵌入导航与小屏局部滚动；生成预览和安装包到已忽略的 `.local/research-workbench-preview/v0.2/`。
