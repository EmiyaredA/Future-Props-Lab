# Agent Note: 独立服务的本机热加载入口

Status: implemented

## Problem

主机已经使用独立服务数据库，旧日常开发入口仍要求单体数据库。正式 Docker 网关占用 3000，
而容器内服务名、文件挂载和固定网关二进制路径不能直接用于 Mac。本机开发需要保留现有数据、
账号隔离和服务间鉴权，同时避免重新启动正式容器或把旧单体数据当成当前数据。

## Decision

日常 `npm run dev` / `npm start` 根据已有配置选择独立本机启动器或原兼容入口。
独立模式从已登记 Compose 的 bind 挂载和命令生成私有配置投影，不调用 Docker，也不初始化、
复制或自动迁移业务数据库。各服务仍通过自有独立装配和启动锁运行。

CLI 显式接收运行资源表、监听地址和端口。应用装配显式注入 `LocalServiceTransport`，
将逻辑服务地址连接到固定回环端口，同时保留原始 HTTP 路径、Host 和身份断言。
网关默认状态探测器也由 CLI 显式接收本机 transport，不能仅向业务客户端注入连接映射。
普通容器入口默认参数不变。网关复用既有精确路由、Identity 校验和原生凭据，仅生成回环监听器。
Vite 多入口提供实时前端源码；本机程序契约快照保留各应用的 API 版本检查，不改写正式发布目录。

本机启动器持有独占运行锁，先只读检查全部迁移，等待所有服务健康后启动 Mac Worker 与 Vite。
Python 源码变化重启依赖它的服务和本机 Worker；代码错误保留源码监听以便修正后再试。
关闭时对进程组使用同一个正常退出窗口并清理后代，锁保持到退出完成。
本机与当前源码的正式管理启动器共用模式锁。启动器拒绝已加载的正式 Worker 和占用端口。
本机网关重载在持有自有服务锁时，仅回收确认无监听者、属于当前用户的残留 Unix socket；
普通文件、符号链接、其他用户的 socket 或仍在监听的 socket 均拒绝替换，容器入口默认不启用回收。

## Alternatives considered

- 直接复用旧 `npm run dev`：当前配置已明确停用单体库，无法承载独立服务数据。
- 在开发时重新合并数据库或创建空单体库：数据来源与账号/任务恢复语义不一致。
- 修改系统 DNS/hosts，或运行时改写 socket/httpx 全局行为：连接依赖不明确，也影响其他应用。
- 继续用正式 Docker 服务挂载源码：不能实现本次用户要求的本机运行与正式停机。

## Consequences

本机复用原业务数据，开发时的正常业务操作也会持久化；自动测试始终使用隔离配置。
配置、依赖、公共契约和启动器修改需重新启动；Python 重载可能中断在途请求或原生任务，
未知供应商结果按原应用恢复规则处理，不自动重提。Guacamole 等可选本机能力仍要求其自身运行依赖。

运行工具、配置、日志、缓存和状态存于 `.runtime/native-development/`；密钥投影为 0600，
Vite 只能读取前端源码和指定依赖，后端配置和运行期密钥返回 403。正式 LaunchAgent 的暂停状态
单独记录在私有运行目录，不删除原定义。恢复正式版本须先确认镜像与迁移后的数据库兼容。

本机切换发现 Visual 0011、Models 0021/0022、Assets 0020 待执行。三份隔离副本先通过已登记迁移、
完整性和外键检查；仅为受影响的三库保存并校验恢复副本，经用户明确授权后通过各服务 CLI 执行。
未手改迁移或账本，素材原件保留。
