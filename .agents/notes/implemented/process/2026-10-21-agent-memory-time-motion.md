# Agent Note: 时间变化通过同一场景的动作解释

Status: implemented

## Problem

多条相似时间轴和交叉连线增加辨认负担，但全部改成带日期的静态记录又削弱了时间推进。用户先要求构思，随后要求推进观看效果。此前实现见 [二维卡通样片](2026-10-20-agent-memory-visual-argument.md)。

## Decision

在独立的 26 秒无配音动态预演中实现六个动作：日历向前翻、搬家时延续同一条住址有效期带、查询放大镜回看历史、迟到信封到达、描述日期归到旧时段、查询返回当前。只保留一条明确标注的事实有效时间带，不为报告收到时间新增横轴。日历表达故事现在，查询镜表达所问日期；镜内明确标注历史回看，实际人物留在上海。信封邮戳保留收到时间，其内容日期落到旧时段，补充历史依据。放大镜移动时缩小、停到查询日期后展开，避免遮住现实人物。当前只完成短预演，未替换完整日语样片或制作四集正片。

## Alternatives considered

继续多轨时间图需要解释轴与连线。只保留日期记录损失了动画中的过程。让真实人物在历史查询时倒退会混淆查询与事实变化。通过单一时间带、日历和查询镜分别承担明确职责，保留时间运动并减少连接关系。

## Consequences

内置生图工具生成的六格分镜及完整提示词保存在 `.local/research/agent-memory/anatomy-v4/concepts/temporal-motion-storyboard-v3.png`；动画由独立 SVG 部件重建，不能把生图日期位置当作真实刻度。`time-animatic-model.mjs` 统一故事时间、查询日期、人物位置与证据落点；HTML 与 Remotion 共用模型与图形。交付独立 HTML、1080p／4K 视频与源码包，保留旧样片。角色只在结尾作示意动作，显式 `silent` 属性保持闭嘴，不借用旧音轨制造假口型。迟到报告案例未运行 Graphiti，也不保证任意矛盾都能正确处理。

## Risks

查询镜可能被误读为人物移动或放大一张静态图；镜内必须明确标注历史回看，并以选择日期驱动画面变化。生图可能改变场景比例或错误暗示未来状态，最终画面需以已核实的教学数据重建。

## Verification

已检查六格概念和 12 个实际渲染关键帧，修正查询落点遮住城市名、说明文字与查询针相交、手动日期改变但回答气泡仍写三月，以及行李箱接地点偏高等问题。780 帧检查故事时间单调推进、真实人物不随查询移动、有效期边界、证据落点和确定性。390px／1280px 浏览器检查实际播放、手动查询与说明一致、键盘操作、明暗、减少动态不自动播放、无横向溢出和无配音闭嘴。两个最终视频均为 26 秒、30fps，完整解码并检查黑帧，抽查 33 个编码帧；无配音预演不声明完成日语音画对齐。完整系列与观众对运动可读性的反馈仍未完成。
