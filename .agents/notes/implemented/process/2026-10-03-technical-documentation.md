# Agent Note: 技术文档知识库的分层编排

Status: implemented

## Problem

原有 22 篇技术原理文章提供机制与应用概览，但组件状态归属、公开契约、应用交接和数据流缺少连续阅读路径。目录把结构、运行与交付混在平台基础中，读者难以据此判断一次改动应落在哪个模块。

## Decision

知识库名称为「Future Props Lab 技术文档」，保留 technical ID 与既有 22 篇文章地址，新增九篇组成 31 篇。目录按系统全景与架构、组件化设计、数据模型与数据流、模型与执行机制、各应用实现、工程验证与设计取舍六组排序。

正文采用分层解释，先给出具体问题和图形，再展开所有权、输入输出、版本、失败恢复与代码入口。带图片笔记保存、图片生成和视频输出贯穿公共机制；应用文章解释自身差异并关联基础文章。每篇保留可编辑 CanvasScene 与 Mermaid 图，不添加新的运行 API 或数据库结构。

目录、标题、简介、相关阅读、分组说明与图形同步维护。图形复制的新个人笔记显示「来源：官方技术文档」，已有副本不改写。官方资源继续随版本打包，阅读偏好仍使用原标识；正文重写不保证旧章节偏移锚点稳定。原文档中心不修改。

## Alternatives considered

- **保留旧目录，只补文章** — 改动较少，但无法形成组件与数据流的独立阅读路径。
- **完整套用 arc42 的十二章结构** — 覆盖面完整，但不贴合现有应用知识库的阅读和复制图形入口；采用其静态结构、运行场景与决策区分即可。
- **更名并替换所有文章 ID** — 命名统一，但破坏旧链接与阅读偏好；只修改展示名称并新增必要文章。

## Consequences

- **收益**：读者能从全景定位到组件与数据所有者，再深入应用实现；公共机制避免在十篇应用文章中重复。
- **代价与边界**：新增内容与图形需要随实现维护，分组顺序成为导航契约。官方共 12 个库、93 篇；不把数量检查当作内容准确性的替代。
- **验证策略**：内容检查覆盖身份、链接、标题和图形安全，组件检查跨组导航，浏览器按正文中的实际图形数验证离线资源和副本行为。

## Verification

- 官方内容、技术内容、阅读与个人阅读位置四个测试文件：22 项通过。内容检查覆盖六组顺序、31 个 ID、93 篇总数、标题与简介、相关阅读、源码入口及图形结构和安全性。
- 后端架构与画板测试：66 项通过；全量后端测试 979 项通过、2 项跳过。全量 Web 测试 1224 项通过，桌宠动作测试 `desktop-pet-articulation.test.ts` 的攀爬接触断言失败，属于已有范围外改动。
- 生产构建通过；本机 Chrome、临时 SQLite 和 Vite preview 的 11 项浏览器验收通过，覆盖 93 篇外网阻断加载、旧 URL 与刷新返回、搜索和跨组导航、图形视口、个人副本编辑保存、只读界面、390/768/1600 宽度与明暗主题。截图复核后为新增图形及重写的素材图指定连接锚点，避免跨行连线穿过其他卡片；93 篇离线加载、31 篇图形和原有个人阅读标识同步的三项复验通过。
- Web lint、任务涉及文件的 Prettier 与 `git diff --check` 通过。全仓 lint/格式被范围外 `human_motion.py` 及桌宠 Web 文件阻断；不覆盖这些未提交改动。
- OpenAPI、Web 类型和 SDK 生成检查通过；契约总检查被受保护的桌宠 SDK 参考文档过期阻断，该文档未重生成。
- Agent Note 与文档中心保护检查通过；运行日志和截图保存在被忽略的 `.local/technical-docs/`，没有使用桌面正式数据或调用真实模型供应商。
