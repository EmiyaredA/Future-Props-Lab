# Agent Note: Studio 统一启动和迁移备份

Status: implemented

## Problem

故障恢复后，运行中的 LaunchAgent 可能与磁盘上的自动启动定义指向不同版本。历史验收又留下了多份候选代码和数据副本，难以判断哪些文件仍用于启动和回滚。

## Decision

正式 Studio 通过同一命令启动。本机登记正在运行的固定版本，手动启动核对登记、安装和已加载定义。独立部署切换验收通过后，该命令改由同一份登记管理独立服务启动器。两种后台不能同时启动。日常启停沿用当前数据和构建。每次正式数据迁移先停写、封存和核验，保留一份已验证的完整恢复点。历史验收归档结果和摘要。

## Alternatives considered

立即重启到项目当前代码会让整理工作同时承担切版风险。维持两份指向不同版本的定义会让下次登录改变线上版本。

## Consequences

上线版本由当前安装和登记的启动定义确定。修改项目源码或清理历史候选不会自动更新线上版本。新恢复点通过核验后才替换上一份。

## Verification

对比运行中和已安装的启动定义，验证手动启动复用当前进程。对回滚备份检查文件 SHA256、SQLite 完整性和隔离启动预检，并核对清理前后两端就绪状态和构建号。
