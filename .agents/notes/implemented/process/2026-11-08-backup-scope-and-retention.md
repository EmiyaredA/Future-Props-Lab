# Agent Note: 按变更范围备份与保留恢复点

Status: implemented

## Problem

配置、凭据或单个数据库变更若沿用整体迁移的备份流程，会反复复制未变更的素材、模型和派生文件。旧恢复点没有明确的保留条件，也会让完整包长期堆积。

## Decision

按持久写入和恢复依赖确定最小备份范围。跨存储迁移或无法可靠隔离影响范围时完整封存，并记录原因。默认保留最近一份已验证、可独立恢复的完整回滚包。旧恢复点需要明确用途和到期条件。

## Alternatives considered

- 每次都封存整个运行目录。恢复操作一致，但局部变更也会重复保存大量未改写的数据。
- 在已有封存包内删掉重复文件。可以缩小目录，但会破坏快照清单和原恢复流程的校验。

## Consequences

变更执行者先确定影响范围和恢复依赖。清理旧包前核验保留包，并确认启动登记和进程均无旧包引用。缩减保留范围后，过期的时点不可再用于回滚。

## Verification

备份范围和保留规则见[生产部署](../../../../docs/operations/production-deployment.md#备份与恢复)。操作前逐文件核验保留包并检查恢复验收记录，操作后对照服务状态和磁盘可用空间。
