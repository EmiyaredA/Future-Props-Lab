# Agent Note: 整站迁移步骤和核验记录

Status: implemented

## Problem

整站迁移由多个服务的回环维护命令组成。单服务命令可以重试，但需要可验证的整站顺序、来源覆盖和持久验收记录，避免遗漏阶段或将过期的成功记录用于当前目标。

## Decision

一个入口先核验封存快照和来源表归属，再按固定依赖顺序执行已登记的服务命令。它以独占锁串行执行，在每步通过后原子保存证据。重跑仍经维护 API 读回记录和原件，并将结果与同一计划的前次证据核对。最终对照封存表计数、分区、重建关系和来源清单，再标记传输完成。

## Alternatives considered

人工串联命令依赖操作者追踪步骤和完整性。直接跳过已成功步骤会把旧记录用于当前目标，无法验证重启后数据和回执仍可读。

## Consequences

同一计划的重试需要再次读取来源和目标，耗时包括读回核验。报告记录迁移证据，旧站恢复、浏览器联调及生产窗口仍由各自门禁验收。

## Verification

`tests/integration/test_site_migration.py` 校验端点清单、来源缺口阻断、中断续跑、摘要变化和最终计数。用同一封存快照运行 37 个真实隔离维护入口，覆盖 20 步传输、故意断开 Integrations、重跑和完整重放，再启动旧站恢复目录验证历史。
