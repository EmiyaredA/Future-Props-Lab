# Agent Note: 统一使用现有数据的热加载网站入口

Status: implemented

## Problem

独立开发前端、隔离开发后端和正式静态网站同时存在时，页面能打开却无法登录，账号与数据也难以辨认。用户明确选择沿用现有账号、模型和素材，取代本机原静态服务。

## Decision

`npm start`、`npm run dev`、原前后端别名与原 LaunchAgent 使用同一启动器。浏览器固定访问回环 3000，后端固定回环 9001；配置和密钥继续来自已有 `backend/config.toml`，数据沿用 `.runtime/`。不生成第二套账号库。

启动器持有单例锁，先等待后端就绪再启动 Vite，任一子进程退出或收到停止信号时清理整套进程。Uvicorn 重载父进程持续持有数据锁；应用工厂在每次 worker 导入数据库前重新检查迁移。前端代理改写 Host，后端只额外允许精确的本机前端 Origin，实际监听 socket 仍决定本机管理权限。

公网附加监听器、SSH 和 Runner 保持同一 worker 生命周期；公网继续使用发布资源，不暴露 Vite。自动测试仍使用临时隔离配置与数据库。

本机公网静态根目录通过 TOML 固定到 `.local/studio-published/<build-id>/` 的已发布快照，按发布清单逐文件校验大小与 SHA256。普通构建输出 `.local/studio-release/` 不覆盖当前公网快照，避免另一项本机构建导致下次热重载时公网版本校验失败；正式发布后再按停机快照流程切换该配置。

## Alternatives considered

- 保持两套数据库：与用户明确要求沿用既有账号和素材不符。
- 仅启动开发前端：后端缺失时登录失败，两个进程也无法一起管理。
- 对外暴露 Vite：使开发源码入口进入公网，超出本机热加载需求；公网保持受控构建发布。

## Consequences

修改后端会同时重载本机与公网 API，并可能中断在途生成或连接；既有恢复用例负责结算，不自动重提模型任务。新增迁移时重载拒绝加载，仍须停机备份和显式迁移。配置或依赖变更通过正常停止、重启统一服务生效。

## Verification

隔离测试覆盖配置复用、禁止继承测试覆盖、后端就绪门控、失败清理、端口冲突、服务及命令别名一致性与每次 worker 迁移检查；网站鉴权测试覆盖前端 Origin、CSRF 和公网权限隔离。切换时停止原服务及独立 Vite，保留完整恢复快照，再由原 LaunchAgent 启动统一服务并验收登录、代理与热加载。
