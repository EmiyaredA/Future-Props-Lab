# Agent Note: 提示词模板与显示方式独立选择

Status: implemented

## Problem

普通文本作为模板选项混在自动识别与 MiniMax H3 中，用户切换原文和渲染时必须打开菜单，而且会丢失原先选择的模板。

## Decision

模板菜单仅保留自动识别与已登记适配器。在说明图标左侧提供独立的“渲染提示词”开关，以图标和无障碍状态反馈普通文本／渲染展示。显示方式和模板各自保留，选择模板、编辑原文或切换提示词版本不隐式改变显示方式。

此决定细化[单行控制区](2026-11-21-prompt-controls-single-row.md)与[H3 展示](../feature/2026-11-22-h3-rich-references-and-shot-properties.md)：模板与显示方式继续只属于编辑器会话，紧凑与标准生成入口共用控件；原文、保存、复制及生成数据不因显示切换改变。

## Alternatives considered

- 继续把普通文本放在模板菜单：需要重复打开菜单，也无法保留渲染模板选择。
- 同时展示两组编辑器：增加占用并引入两个输入焦点，采用单一编辑区切换。

## Consequences

开关支持鼠标与键盘，使用 `role="switch"` 和 `aria-checked` 表达状态，焦点留在开关。渲染模式中无法识别的内容仍回退原文编辑；显式选定模板时继续显示未识别说明。普通文本模式隐藏该说明，继续允许编辑和引用。新增控件沿用同排布局及窄区域局部滚动，无持久字段或迁移。

## Verification

组件测试覆盖独立开关、键盘和焦点、模板保留、普通文本粘贴、版本切换、原文复制和保存／生成屏障。浏览器旅程检查明暗主题、1440px 与390px单行布局、开关往返及原文未发生保存变更；证据保存于忽略的 `.local/prompt-display-toggle/`。
