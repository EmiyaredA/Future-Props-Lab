# Agent Note: H3 标签按标记显示

Status: implemented

## Problem

主体标签从描述中截取名称，并将定义中提到的图片或视频显示为主体的代表缩略图。即使引用关系来自原文，这种呈现仍会把内容单元误表现为单一素材。自然语言的运镜词、引号和对白内的说话人文字也可能被额外解释。

## Decision

按用户明确要求替代[富引用展示](../feature/2026-11-22-h3-rich-references-and-shot-properties.md)中的主体命名和缩略图规则：主体固定显示“主体N”，正文、引用菜单和普通文本引用块均不为主体分配素材或缩略图。点击只展示原始定义文字，不选择代表来源。图片、视频、音频只按自己的明确标记和调用方提供的实际槽位显示素材。

任务类型、保留关系、语言和转场标记保留原始值，不转换为推导描述。只有完整协议标记被识别；基础指南明确使用的裸 `Picture N` 仍支持。普通运镜句子、引号和裸 `Subject N`／`Video N` 保持正文文字。说话人选项只来自明确解析到的 `(Sx)` 标签，不从对白文字提取，也不自动补一个 S1。

小节标题及“主体／图片／视频／音频／镜头”这些类型名称仍使用固定界面文字；复制与生成保留用户源串。

## Alternatives considered

- 改善实体名称抽取：仍然超出用户要求的基本渲染。
- 用第一张显式来源图代表主体：无法表示一图多主体或一主体多来源，也会暗示文件绑定。
- 完全移除结构展示：用户仍需要类型、编号、明确媒体引用和直接编辑。

## Consequences

移除名称截取、主体代表素材和自然语言分类分支。没有修改实际生成输入、引用顺序、主体定义或持久数据；所有变化限于 MiniMax H3 前端适配器。

## Verification

测试确认主体编号、无主体缩略图或 file 属性、定义原文保留、独立图片预览、缺失引用不顺移、普通句子及对白中的标记不产生新选项；回归源串逐字重组、复制、插入和保存。明暗主题及窄屏浏览器证据位于 `.local/h3-rich-rendering/`。
