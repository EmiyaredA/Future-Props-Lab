# Agent Note: 知识库首页就是一篇普通笔记

Status: implemented

## Problem

打开知识库时，首页被做成只读落地页：标题换成知识库名称，空内容提示去点「编辑首页」，正文下方再挂一份不能编辑的根文档列表。用户无法像写其他笔记那样直接修改这篇文档。侧栏已经有目录，页内列表的条目也不是首页的子文档。

## Decision

没有文档 id 的知识库地址仍然打开首页笔记，侧栏「首页」仍指向它。页面使用与其他笔记相同的编辑器和阅读切换，默认进入编辑。可编辑标题是笔记自己的标题，新建时为「首页」；知识库名称留在侧栏和面包屑。切换文档时阅读状态回到编辑。

正文下方只列出 `parent_id` 等于当前笔记的子文档。首页不能作为父文档，因此不再出现「知识库目录」。反向链接与其他笔记相同。首页仍不能单独删除或移动。自定义封面在首页路由上继续显示。

此决定替换 [统一阅读布局](../feature/2026-10-04-thought-reader-ui.md) 中「编辑首页入口归顶栏、首页标题使用知识库名称」的部分。正文列宽、章节目录和封面保留。它也与 [知识库目录与通用正文编排](../feature/2026-10-03-document-layout.md) 一致：页内导航只表达真实父子关系，知识库结构仍由侧栏目录承担。

## Alternatives considered

- **保留只读首页，只把目录改成可点击编辑**：仍然要先进入另一种模式，首页和其他笔记不是同一份界面。
- **把知识库名称绑定成首页标题**：改标题会改库名，或库名继续不可编辑，两种都让首页标题和普通笔记不同。

## Consequences

- **收益**：进入知识库即可写首页。根文档只出现在侧栏，不再占据正文。
- **代价与已知上限**：首页顶栏改为笔记菜单。封面、发布、备份和移入回收站从「全部文档」等非笔记视图的知识库菜单进入。已有首页笔记的标题若仍是「首页」，页内大标题不再显示知识库名称。

## Verification

`web/e2e/thought-knowledge.spec.ts` 中「knowledge home opens as an ordinary editable note」确认标题为「首页」、正文可编辑，且页内没有「知识库目录」。依赖「编辑首页」按钮的旅程改为等待笔记标题或直接编辑正文。
