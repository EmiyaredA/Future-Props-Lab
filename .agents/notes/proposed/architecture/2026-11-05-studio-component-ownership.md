# Agent Note: Studio 组件归属与分层迁移

Status: proposed

## Problem

网站与独立服务共用业务实现，但入口、协议、存储和主机适配散布在 `app` 与多个 `fpl_` 包。业务通过数据库 Session 的信息字典取得依赖，纯编辑规则间接加载 ORM，替换能力时难以明确边界。

## Proposal

后端统一采用 `studio` 命名空间。`apps` 按业务所有者组织用例、规则、传输和存储；`contracts` 按协议所有者保存可独立加载的数据契约；`runtime` 只保存无业务归属的机制；`config` 拥有配置格式；`host` 拥有主机适配；`assembly` 拥有网站、独立服务与主机的依赖装配；`deployment` 拥有构建工具。

每个组件显式声明输入、输出、状态归属及失败语义。用例决定事务边界，存储适配提供原子操作。业务规则不导入 ORM、HTTP 框架或供应商 SDK。跨业务只消费公开契约，执行器回执由业务所有者裁决。账号、revision、幂等键、取消和未知结果必须在接口内明确表达。

保留前后端分区。前端 `app` 装配，`features` 拥有业务与缓存键，`platform` 拥有浏览器适配，`shared` 拥有通用展示。父包初始化不得隐式导入业务实现。

## Alternatives considered

- 全局按四个技术层集中代码，会使单个业务的生命周期横跨多个全局目录。
- 只删除前缀，无法解决事务、依赖注入和实现类型外泄。

## Acceptance criteria

- 配置、纯契约和基础机制先迁移，再以音频标注验证完整业务链。
- 网站协同任务完成当前工作台批次并封存提交后再迁移相关组件。
- 每批同步入口、镜像源码闭包、打包、契约归属与测试，不保留永久转发包。
- 业务、存储、模型、素材与主机适配具有可替换的明确接口和契约测试。
- 架构检查覆盖依赖方向、父包初始化、尺寸限制及循环依赖。
- 已登记迁移和正式数据保持原有兼容契约，正式切换单独验收。

## Risks

本目录与网站任务共享工作区，路径与导入的迁移必须串行协调。配置文件定位、镜像动态导入及静态源码闭包需单独验证。产品文档中心遵守保护规则。

## Verification

按批次记录测试结果；整个迁移完成并通过最终验收后转为 implemented。
