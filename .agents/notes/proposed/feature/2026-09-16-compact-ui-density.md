# Agent Note: 全局紧凑化 UI 密度与侧栏状态

Status: proposed

## Problem

上一轮 UI 刷新统一了暖橙主题和主要壳层，但许多工作台、列表、表格、筛选器和编辑器仍保留较大的间距与面板留白，桌面端单屏信息量不足。现有移动抽屉导航也需要和桌面端的紧凑布局共存，不能通过简单缩小所有控件造成触控误操作。

## Proposal

在现有 `codex/ui-refresh` 视觉系统上增加“专业紧凑”密度层：桌面端优先压缩页面内边距、面板间距、列表行高和非关键辅助说明；移动端保留至少 44px 的触控尺寸。扩展公共 `ResponsiveSidebar` 支持桌面端完整/图标两种模式，默认展开，用户切换后通过明确的本地存储键记忆；移动端仍使用抽屉导航。复杂编辑器只压缩面板和布局留白，保留按钮、拖拽、缩放和时间线操作尺寸。

## Alternatives considered

- 极致压缩所有元素：可以获得最高单屏信息量，但会降低表格可读性并增加误触风险。
- 只用全局 CSS 覆盖：实施快，但容易破坏编辑器局部布局和移动端触控边界，难以让辅助信息按场景分层。
- 固定完整侧栏：可发现性最好，但会持续占用桌面主内容宽度，和提升工作台密度的目标冲突。

## Acceptance criteria

- 桌面工作台的页面、卡片、表格、列表、筛选器和弹窗使用统一紧凑尺度；移动端不牺牲主要操作的可点击区域。
- Studio 与所有工坊壳层都支持可记忆的桌面图标侧栏，折叠状态不影响路由、权限和键盘导航。
- 次要描述可在紧凑列表中隐藏或折叠，但标题、状态、主操作和必要错误信息始终可见。
- 编辑器局部滚动、拖拽、缩放、时间线与保存行为不变；无根级横向溢出。
- 通过主题、侧栏、响应式、公共组件和既有业务测试，并保持 API/数据库契约不变。

## Risks

- 新旧 feature CSS 并存时可能产生覆盖顺序问题；按公共尺度、壳层、工作台、编辑器顺序迁移并通过视口测试收口。
- 侧栏状态使用 localStorage 时需要隔离 Studio 与不同工坊，避免一个页面的折叠状态误影响另一个页面。
- 隐藏辅助说明不能让关键信息只存在于视觉上不可见的区域；需要保留可访问名称和详情场景的完整上下文。
