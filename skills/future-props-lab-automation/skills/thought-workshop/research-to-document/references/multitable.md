# 善用已有多维表格

父笔记是报告，子文档「调研台账」是一份已有的 multitable 文档。依据内容选择表，不要求全部建立。`assets/ledger-tables.json` 是可直接装入 `table.put` 的 TableSpec 模板数组，仅是内容模板，不是新 API 或持久化 schema。

| 数据表 | 适用内容 | 有用的字段 | 视图 |
| --- | --- | --- | --- |
| 参考资料 | 在线文档、论文、代码、视频、实验来源 | 来源 ID、标题、类型、链接、版本、读取状态、摘要、原文位置、证据 ID、摘录笔记、附件 | 全部资料；未读／受限；按类型分组 |
| 方案对比 | 产品／技术候选的同维度比较 | 方案、维度、结果、适用条件、验证依据、来源 ID、限制 | 完整比较；关键维度；按方案分组 |
| 验证记录 | 操作验证、复现、小实验与失败 | 验证项、状态、方法、预期结果、实际结果、条件、证据 ID、实验笔记、附件 | 网格；按状态分组的看板 |
| 待办问题 | 数量较多的开放问题 | 问题 ID、问题、优先级、状态、结论 ID、下一步 | 全部；未决问题；状态看板 |
| 证据摘录 | 一份来源有多处关键依据 | 证据 ID、来源 ID、原文位置、摘要、依据类型、条件、问题 ID、笔记 | 网格；按来源分组 |
| 结论核对 | 较多结论及其支持／反证 | 结论 ID、结论、性质、状态、支持证据 ID、反证 ID、限制、问题 ID | 全部；有条件／争议 |

先创建有内容的参考资料表。存在真实候选比较再创建方案对比；需要实测／复现时创建验证记录，可以提前记录尚未执行的计划并标「待执行」。不生成虚构实际结果。问题或证据数量增加时再拆表。不要把长篇正文拆成很难阅读的几十列。

## 字段与关联

- `single` 保存类型／状态，值为 option ID；`multi` 仅用于相对固定的标签。开放增长的 Q/S/E/C ID 使用文本，多个 ID 用明确分隔，不当作已实现的跨表关系。
- `url` 仅保存真实可打开的网页链接；本地路径写普通文本／笔记引用，不能冒充网页 URL。
- `note` / `attachment` 的值是实际获授权的笔记／素材 ID 数组；不是标题、路径或用户提供的原始字符串。缺少真实 ID 时留空。
- 数据模板先读取契约与现有结构。复制新表时生成合法唯一 ID；已有表按稳定记录 ID 合并，保留用户增加的字段、视图与内容。
- `date` 字段只接受 YYYY-MM-DD；需要精确时刻时在文本字段或 Agent 快照保留带时区的 ISO 8601。日期表示真实发布／读取／验证时间，未知留空；版本、配置和指标无法比较时写明条件，不猜测。

## 报告中的嵌入

正文只嵌入与当前论点直接相关的视图，如关键维度对比、待验证事项或引用资料。完整台账留在子文档。使用已有 multitableView 节点：

```json
{"type":"multitableView","attrs":{"noteId":"真实多维文档 ID","tableId":"真实表 ID","viewId":"真实视图 ID"}}
```

三个 ID 均来自正式成功响应。正文与表格必须可访问；嵌入保留对原表的引用，不能把数据复制成另一份独立表格。报告中的长篇解释和最终建议仍是普通正文。

## 恢复和用户监督

续做时分页读取各表记录及当前视图／字段定义，把用户新增资料、状态调整和验证反馈合入分析。JSON 快照不覆盖当前表格。失败原因和下一步直接写在验证记录／问题字段；阶段变化沿用普通笔记记录与已有历史，不新增调研进度面板。
