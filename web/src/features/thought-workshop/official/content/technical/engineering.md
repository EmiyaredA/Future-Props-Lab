# 构建与契约测试：如何证明版本一致

## 先理解它解决什么问题

生成契约、运行资源和功能测试分别守住不同事实。TypeScript 编译成功不证明权限正确，单元测试通过不证明打包资源齐全；验证应沿着数据从源码到安装包的路径进行。

**贯穿实例：** 新增画板节点后，需要验证后端内容校验、前端编辑、Markdown 转换、完整备份及实际打包中的渲染器。只测试新增按钮可见是不够的。

## 实现与设计取舍

生成类型不手工编辑；公共接口变化通过统一生成流程传播。架构测试限制依赖方向与路由权限，响应式清单覆盖页面入口。Agent Note 解释设计原因和验证证据，产品使用指南解释用户怎样完成任务，二者职责不同。

## 异常、验证与当前边界

Git LFS 指针不是可用图片或字体，构建需验证实际对象。真实供应商凭证缺失应报告未执行，不以收费调用替代确定性测试。全仓已有失败与本次回归分别记录，不能因为局部测试通过就宣称发布检查全部通过。
