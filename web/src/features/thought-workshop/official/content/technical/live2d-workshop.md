# Live2D：参数绑定、网格与动作

拖动“头部转向”参数时角色能正常偏头，播放动作时却出现形变。这通常需要分别检查参数值从哪里来，以及这个值怎样转换成网格和变换。

原生角色不是把多张姿态图片轮流播放。分层素材提供视觉内容，参数关键形描述不同值对应的形态，动作曲线随时间提供参数值。本文沿这个求值过程解释默认姿态、插值与参数组合。

## 动作驱动参数，参数驱动角色形态

动作数据和角色绑定缺少其中一项，会发生什么？

```fpl-canvas
live2d-workshop
```

图例：动作曲线和角色绑定是两类独立输入：前者改变参数，后者规定参数怎样影响形态。只导入动作并不会自动为未绑定的图片生成网格变形。

动作只有数值变化，绑定规定数值怎样影响目标网格或变换。未绑定的参数即使在时间轴上变化，也不会自动产生预期形变；反过来，已有关键形但没有动作输入时，角色仍可能停在默认参数。

## 单次角色画面求值

播放到某一时刻后，参数值怎样变成最终图层？

```mermaid
flowchart LR
  A[动作时间] --> B[参数值]
  B --> C[关键形插值]
  C --> D[网格与变换]
  D --> E[图层合成]
  E --> F[角色预览或输出]
```

图例：箭头依次表示时间采样、参数求值、关键形插值与合成。图为原生角色解释；Cubism 运行资源的兼容与转换要按实际导入报告判断。

求值先取得参数，再在关键形区间内插值，更新网格与变换，最后按可见性和层级合成。位于参数范围之外的输入会被限制到范围内，不能通过超范围值绕过角色文档约束。

## 同一个参数可能有多种来源

当前参数求值按以下顺序形成最终数值：

| 顺序 | 数据来源     | 对已有值的作用             |
| ---- | ------------ | -------------------------- |
| 1    | 参数默认值   | 建立初始姿态               |
| 2    | 指定表情     | 覆盖表情提供的参数         |
| 3    | 指定动作轨道 | 在当前帧采样并覆盖对应参数 |
| 4    | 显式覆盖值   | 应用调用者的最终输入       |
| 5    | 参数范围     | 限制最小值与最大值         |

参数绑定的形变会以默认关键形为基准应用变化。多个参数共同影响一个目标时，需要检查组合后的结果；只把每个滑块分别拉到极值，并不能证明同时播放时正确。

## 原生工程和 Cubism 资源的边界

原生工程保留图层、网格、参数与动作，PNG 序列交付画面，素材交接包供外部工具继续制作。Cubism 运行资源的导入或转换还有自己的兼容范围，物理、复杂遮罩和联动不能假定完全等价。

素材交接包不生成 moc3 或 cmo3。排查形变时先确认使用哪一种资源路径，再检查默认姿态、绑定目标、网格顶点数、参数范围与图层顺序；导出后用实际目标环境复核。

> [!TIP]
> 为头部转向至少检查默认、左右极值和与表情同时激活的组合。若单参数正确、组合错误，优先检查共同绑定目标及默认关键形。

## 参数求值与编辑保存分开协作

角色工程拥有部件、网格、参数关键形、变形器与动作描述。前端 PixiJS 管交互，shared/live2d 提供共用纯姿态与网格装配；后端项目用例保存角色，公共媒体 Live2D 能力负责确定性参数求值。预览当前姿态和编辑选中部件不等于新的角色默认文档。

头部转向值进入参数求值，再转成部件变换和网格顶点。动作与手动参数可能有不同来源，需要按实际求值组合检查，而不是从当前画面猜测默认姿态。保存角色修改与导出、Cubism 对照预览承担不同职责；原生工程不自动保证原生 Cubism 物理和编译能力。

## 固定快照与动作异常的证据

桌宠只通过 public 入口读取固定版本角色，校验使用的素材完整后拥有自己的副本。验证参数端点、中间值、默认姿态、多参数组合、缺失部件与来源版本变化，分别追到 projects、CharacterDocument 和纯求值入口。动作失效先检查输入值与绑定，再检查素材和显示，不在消费者中直接改 Live2D 的内部记录。
