# 录音标注工坊：常见问题与能力边界

遇到字幕按钮不可用、导入后时间错位或识别失败，先区分“工作稿完整性”“源录音对应关系”和“模型输入限制”。下面的处理方法保留当前标注，修复后再重新试听验证。

## 按现象处理

| 现象                           | 常见原因                                 | 处理与成功标志                                              |
| ------------------------------ | ---------------------------------------- | ----------------------------------------------------------- |
| SRT 按钮不能点击               | 有片段缺少说话人或非空正文               | 根据弹窗遗漏数量补齐；按钮可用后再导出。未完成稿可先存 JSON |
| JSON 导入后没有音频            | JSON 不携带录音二进制                    | 选择对应音频并核对时长、开头和中段内容                      |
| 导入后字幕整体错位             | 使用了不同剪辑版本的录音                 | 换回对应音轨，抽查多个片段；相同文件名不能证明时间一致      |
| 文本 JSON 回填被拒绝           | 片段 ID、时间或说话人被改动              | 从当前项目重新导出，只修订允许的文本、情绪与校对字段        |
| 紧接操作后句首或句尾丢失       | 当前边界被吸附到相邻片段                 | 试听后修正；紧接上一段只改开始，紧接下一段只改结束          |
| 能播放但不能识别               | 浏览器与模型对格式、大小、时长的支持不同 | 查看所选模型输入要求，使用正式处理入口准备合适音频后再提交  |
| 删除情绪词条后旧片段仍有该文字 | 删除只移出词库，保留已有标注文案         | 若需变更旧标注，逐项检查或使用适合的重命名流程              |

> [!NOTE]
> 一个片段可以有多位实际发言者。多人重叠并非必须消除的错误；逐人情绪也应分别绑定，不把旁观者加入发言列表。

## 重新识别前做什么

先保存或导出当前项目 JSON，明确自己要处理的是哪些录音与片段。模型输出后逐段核对人物、正文和时间戳，不因总文本通顺就直接标成已校对。

手工标注无需模型；模型失败不代表已有标注或原录音损坏。优先检查当前选项和输入要求，避免反复提交同一份不兼容文件。

## 修复后验收

循环播放问题片段及相邻两段，确认没有吞音或重复正文。导出一份字幕并与原录音同时播放；交接工作稿时另存 JSON 和音频。

> [!WARNING]
> 录音标注不自动保证转写正确，也不是实时共同编辑系统。版本冲突时先保留本地草稿，最终交付仍需人工试听。
