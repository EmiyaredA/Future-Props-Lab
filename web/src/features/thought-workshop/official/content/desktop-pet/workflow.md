# 桌宠工坊：主要操作流程

一只桌宠可以在被摸头时做表情、拖起时播放提示音，也可以在独立聊天窗口里回答文字。先配置确定性的事件，再配置可选的模型聊天，便于分别验证外观、触摸和对话。

## 配置外观与触摸事件

打开已创建的桌宠。在 Live2D 来源项目中，新建皮肤后为目标部件上传同尺寸 PNG；新贴图继续使用原网格和动作。分层资源包来源则使用包内配色，不能照搬同一套部件换肤操作。

在交互页选择待机、点击身体、摸头、拖起、放下或自主走动，配置该事件的动作、表情和提示音。每次只改一个事件，用“播放事件”检查结果，再换到下一个。

摸头依靠头部热区，其他角色区域通常触发身体点击。若两者看起来完全一样，先检查热区和事件配置，不必先改角色绑定。

## 编写事件台词

1. 在台词页选择对应事件，写一条短句并保存。
2. 每个事件最多八句，每句 1–140 个字符。先用明显不同的句子区分事件，确认触发正确后再润色。
3. 在试玩中触发该事件，核对气泡、动作和声音是否与句子匹配。
4. 再配置主动台词和习惯，检查它们在日常运行中的频率。

> [!NOTE]
> 事件和主动台词来自预设内容，不会在每次触摸时调用模型。文字聊天是另一条流程，可能产生模型费用。

## 试玩并设置默认习惯

设置大小、走动频率、拖拽、气泡与声音，并选择最多四个悬停按钮。先测试触摸，再测试拖起和放下；角色不应超出屏幕可用区域。保存编辑器配置，才能作为下次启动的默认值。

## 让桌宠进行文字聊天

在聊天页填写简介、性格、说话方式和开场白，保存到项目。运行时打开聊天小窗，选择可用文本模型，先发送一条短消息，检查流式回复和停止当前轮次。

私人聊天历史、模型和偏好按账号、Workspace 及桌宠隔离。清空聊天不会删除角色工程或共享人设。中断后先查看已有轮次状态，再决定是否重新发送。

> [!TIP]
> 在人设里写具体表达偏好，例如“回答先给一个结论，再给简短理由”。通过少量短消息检查效果，再调整文本，避免同时改模型和全部人设。
