# Galgame 工坊：主要操作流程

本篇以“开场 → 做一次选择 → 回到主线”为例，说明剧情逻辑、舞台演出和时间安排怎样配合。开始前已有一条可从入口试玩到结束的短线路。

## 先设计分支如何返回

1. 在章节中确认入口 Fragment，检查章节顺序与启用状态。
2. 为选择后的内容创建目标片段；需要条件时先建立变量，再配置条件和分支。
3. 使用 Branch、If 或 Call Fragment 指向目标片段。
4. 在调用位置之后写好继续执行的内容，试玩每个选择并观察返回点。
5. 用叙事地图检查因果链、不可达片段与循环，双击问题位置回到剧本修正。

**完成标志：** 每个关键选择都进入预期片段，目标片段结束后回到正确位置，后续主线仍能继续。

> [!NOTE]
> Branch、If 与 Call Fragment 执行目标片段后会返回调用位置。它们不等于永久跳到另一条路线；不要按“跳走后不回来”的假设安排后续 Block。

## 再安排角色与舞台

登记角色、场景、CG 和媒体，再在具体 Block 中引用。调整立绘、位置、镜头、对话框或声音前，确认当前 Fragment 和选中对象。

个性化设置集中管理对话框底图、颜色、字体、聚焦、口型与 UI；设置中维护画布和角色默认位置。某段演出的覆盖参数可能改变默认效果，所以验收时既检查默认值，也检查当前 Block。

## 精确时间轴与配音

1. 对需要精确安排的片段，按时间轴放置画面和声音。
2. 在关键动作前后播放，核对字幕、角色变化和声音起止。
3. 模型配音前检查文字、角色和声音设置，完成后先试听，再用于演出。
4. 使用主音轨剧情时，以完整音频为时间基准，检查是否又叠加了逐句配音。
5. 有多语言版本时分别核对文本与媒体，不假设修改一种语言会自动修改全部版本。

主音轨重复播放、字幕节奏不符时，先核对声音来源和时间基准，再决定重新生成音频还是只调整时间轴。

## 把工程检查放进编辑流程

完成一轮修改后：保存 → 工程检查 → 定位修正 → 再保存 → 实际试玩。检查范围包括入口、素材、变量、路线和结局；实际试玩再核对演出是否自然。

已标记完成的工程在故事变化后会回到草稿。新的分支或语言版本需要重新验收，不沿用旧的完成状态作为证明。

## 小范围修改的检查点

改角色引用后看所有相关场景；改分支条件后走两侧路线；改音频后核对整段时长；改入口后从头试玩。每次只修改一个可定位问题，比同时重写结构和演出更容易判断结果。
