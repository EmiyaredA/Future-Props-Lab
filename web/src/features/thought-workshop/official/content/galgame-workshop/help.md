# Galgame 工坊：常见问题与能力边界

故事问题通常来自入口和流程、资源身份、时间基准或旧快照。本篇按现象排查，修正后再把工程检查与实际试玩结合起来。

## 开始前记录

记下工程、章节、Fragment、当前语言以及能复现问题的选择路线。先确认 Story 保存状态，再判断问题是否只发生在预览或某次导出视频里。

## 按现象处理

| 现象                   | 可能原因                             | 处理步骤                                           |
| ---------------------- | ------------------------------------ | -------------------------------------------------- |
| 章节或分支走不到       | 入口、启用顺序、条件或调用关系有误   | 检查入口章和章内入口，运行工程检查并沿实际路线试玩 |
| 分支执行完又回主线     | Branch、If、Call Fragment 的返回语义 | 检查调用位置后的 Block，按返回流程安排剧情         |
| 新片段在列表里却没播放 | 没有从实际执行路径进入               | 在叙事地图检查可达性，再定位到调用处               |
| 角色没有出现           | 引用身份、时间范围、可见性或位置不对 | 检查 Block 实际引用和舞台参数，不只看名称          |
| 同名素材表现不同       | 名称相同但稳定身份不同               | 打开被引用资源核对内容，再明确替换                 |
| 配音重复               | 主音轨与逐句声音叠加                 | 核对当前语言和声音来源，按主音轨时间基准整理       |
| 字幕与声音错位         | 时间轴或语言媒体不匹配               | 试听完整片段，再修正对应时间范围                   |
| 修改后旧视频没变化     | 导出使用提交时的快照                 | 保存新 Story，预览并明确创建新导出                 |
| 完成状态变回草稿       | 故事内容发生修改                     | 重新检查受影响线路后再验收                         |
| 导出被阻止             | 素材失效、循环、版本或输出环境问题   | 按任务原因修复，重新检查后提交                     |

## 一次有效的复核

1. 在问题 Fragment 修正一项具体原因并保存。
2. 运行工程检查，确认对应错误消失。
3. 从真正入口或相关调用路径试玩，而不只查看单个 Block。
4. 检查被修改路线以及可能受影响的另一条分支。
5. 问题涉及视频时，再导出短试片验证。

> [!TIP]
> 把“播放不到”和“播放到了但看不见”分开排查。前者先看流程，后者先看身份、可见性、位置与时间范围。

## 保存冲突时

保留本地故事，读取服务器快照，明确决定采用或覆盖哪些内容。连续重复旧版本提交不会解决冲突，也不应手工改数据库或素材目录。

## 当前能力边界

Galgame 工坊适合叙事、分支和舞台演出，不是通用实时多人游戏引擎。工程检查验证结构与可达性，不能代替每条关键线路的叙事验收。

最终视频呈现一条确定路线，无法恢复互动分支、角色配置和全部 Story 数据。需要继续编辑时同时保留工程与素材包。
