# Galgame 工坊：保存与素材管理

故事看起来已经改好，还需要确认当前 Story、资源和导出快照属于同一版本。本篇说明保存边界、资源引用与完成状态，帮助你避免“编辑器已更新，交付还是旧片”的情况。

## 保存一轮故事修改

1. 完成当前章节、Block 或设置修改，观察保存状态。
2. 等待“已保存”，再进行当前版本的试玩与工程检查。
3. 修复发现的问题，再保存一次。
4. 需要导出时，核对任务将使用的路线和当前故事版本。

**完成标志：** 当前 Story 保存成功，重新预览使用的是刚修改的内容。

Story 作为整体文档进行版本检测保存。项目名称有独立版本，其他故事设置随 Story 保存，因此标题变化与剧情变化不能仅凭同一个界面动作推断。

## 冲突时怎么做

保存失败或冲突时先保留本地故事，读取当前服务器快照，按界面提供的载入或明确覆盖流程处理。不要连续提交旧 revision，也不要通过手工修改磁盘文件绕过版本检查。

> [!WARNING]
> 如果两处同时改了整个 Story，需要明确决定保留哪些变化。自动重试旧文档可能覆盖另一处修改，系统不会把重试当作安全合并。

## 维护角色、场景和媒体

| 资源操作             | 需要检查的地方                           |
| -------------------- | ---------------------------------------- |
| 重命名角色或场景     | 显示名称变化，但原身份仍被引用           |
| 替换素材             | 所有使用该素材的演出、时间范围与语言版本 |
| 删除角色、场景或媒体 | 其他章节、隐藏线路和未当前显示的片段     |
| 使用模型输出         | 输出是否完成落盘、能否试听或预览         |

引用依据稳定身份，不是名称。遇到缺失素材时恢复或替换正确资源；改磁盘路径不会自动修复故事里的领域引用。

## 草稿与完成状态

任何故事修改都会让已完成工程回到草稿。“完成”表示经过当前流程验收，不会锁死后续编辑，也不会证明新增线路已经检查。

重新标记完成前，至少运行工程检查，并试玩本轮影响到的线路、声音和结局。

## 导出为什么不跟着编辑变化

导出任务冻结提交时的 Story 快照。提交后继续编辑，不会修改正在运行的任务；旧任务结果也不会自动加入新对白或素材。

提交顺序应是：保存工程 → 预览当前版本 → 推演目标路线 → 提交导出。下载后发现仍是旧内容时，先核对任务提交时间和快照，再决定是否需要新任务。

需要长期保留可编辑内容时使用工程快照或项目包；单独的视频只保存确定路线画面，不能恢复完整故事结构。
