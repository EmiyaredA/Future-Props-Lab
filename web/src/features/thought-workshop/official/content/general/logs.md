# 调用日志与排查

遇到“失败”时，最有用的问题是：失败发生在认证、模型处理、结果下载，还是作品保存？调用日志帮助你把一次用户操作和具体请求对应起来，而不是反复提交同样的任务。

## 开始前收集线索

记下大致时间、应用、模型名称和任务 ID；保留错误提示。确认自己有日志查看权限。部分管理账号可以选择获准的跨空间范围，普通内容阅读权限不会自动开放完整日志。

## 定位一条调用

1. 打开调用日志，确认空间范围与时间范围。
2. 用可用筛选缩小到相关模型、来源和状态。刚从其他空间切回时尤其要重新检查范围。
3. 打开详情，核对调用来源、时间、状态、耗时及请求和响应摘要。
4. 有后台任务时，同时查看原任务记录，比较任务阶段与调用结果。
5. 记录明确错误，再决定修配置、换输入、恢复结果还是重新请求。

**完成标志：** 找到的记录能与那次操作对应，并能说明下一步要修哪一层。仅找到同名模型的一条失败记录还不够。

## 用一个例子分辨处理方向

“视频没有出现在素材区”可能来自不同阶段：

| 日志或任务反馈             | 意味着什么                   | 下一步                           |
| -------------------------- | ---------------------------- | -------------------------------- |
| 认证失败                   | 请求未通过服务认证           | 回模型服务核对连接和凭证         |
| 输入不支持                 | 模型拒绝当前媒体或参数       | 按能力要求缩小或转换输入         |
| 供应商结果已返回，下载失败 | 生成与本地保存结果不同       | 优先恢复现有结果                 |
| 生成完成，作品保存冲突     | 输出与项目引用写入不同       | 保留结果，处理项目版本冲突       |
| 流式响应中断               | 已有部分输出，调用未完整结束 | 查看最后错误，确认是否需要新请求 |

## 统计与单次详情怎么配合

统计用于观察用量、状态和趋势，详情用于确认某一次实际调用。比较数字前，保证时间、空间与筛选条件一致。统计变化不能单独证明某个任务已完成或某份结果已下载。

## 提供可复核的诊断材料

按界面提供的入口查看或下载诊断内容，再附上这五项：操作步骤、发生时间、记录或任务 ID、预期结果、实际反馈。这样接手者可以定位同一条调用，而不是猜测截图对应哪个版本。

> [!WARNING]
> 日志可能包含提示词、附件名称、私人对话或服务地址。分享前检查内容；不要补充真实 API Key、登录 Cookie 或客户端凭证。

## 找不到记录时

先清空过窄筛选、扩大正确时间范围，再确认当前空间和权限。没有权限时请获准成员协助；不要借用他人密钥，也不要把“没有看到日志”当成请求未发送的证明。
