# 调用日志与排查

调用日志帮助理解一次模型请求使用了什么能力、从哪里发起、经过哪些阶段以及失败原因。完整日志与诊断内容受工作空间权限约束，部分管理账号可显式选择获准的跨空间范围。

## 找到对应调用

1. 记下操作发生时间、应用名称、模型名称及任务 ID。
2. 打开调用日志，选择当前有权查看的空间范围，使用筛选定位记录。
3. 打开详情，核对调用来源、状态、耗时及请求和响应摘要。
4. 有后台任务时，同时打开任务记录，区分供应商调用和结果保存的问题。

例如视频已经由供应商返回，但下载保存失败，处理重点是结果恢复；如果认证失败，则应回模型服务修正连接。

## 阅读错误

认证、超时、额度、输入不支持和本地素材问题需要不同处理。先看明确的错误信息，再缩小输入复现。不要仅凭最终“失败”标记重新发送整套请求。

统计数字与单次详情用途不同：统计适合观察用量和趋势，单次详情用于确定实际调用。切换筛选后确认时间范围和空间范围，避免把不同条件下的数字直接比较。

## 提交诊断材料

按界面提供的入口查看或下载诊断包。分享前检查提示词、附件名称、私人对话和服务地址；不要添加真实 API Key。描述“哪个操作、哪个时间、哪个记录、预期什么、实际什么”，比只提供一张报错截图更利于排查。

没有日志权限时请有权限的成员协助，官方知识库不会赋予额外访问权限。
