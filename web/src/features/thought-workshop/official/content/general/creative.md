# 创意工坊与固定版本安装

发现别人分享的工具或方案后，你可以把它安装到自己的账号，再补充本地配置。本篇以“找到一个工具 → 检查依赖 → 安装副本 → 验证可用”为目标，解释为什么安装完成后往往还需要配置。

## 开始前

确认目标账号与集成管理权限。创意工坊在同一部署内分享工具 API、MCP、Skill 和组合方案；公开内容不会把发布者私人凭证交给安装者。

## 查找并安装

1. 打开创意广场，按类型或关键词筛选，进入详情阅读用途、作者、版本与依赖说明。
2. 执行“检查安装依赖”，核对固定版本、目标名称以及待配置项目。
3. 如果提示名称冲突，修改目标名称后重新检查。不要假设安装会覆盖旧资源。
4. 确认安装，完成后到集成中心找到新建副本。
5. 为当前环境补充认证或连接参数，验证后再启用和使用。

**完成标志：** 不仅出现了安装副本，还完成了当前环境下的验证；需要助手使用时，再在对话能力中选中它。

## 安装后哪些内容要自己配置

| 内容      | 安装后的处理                           |
| --------- | -------------------------------------- |
| 工具 API  | 默认禁用，补充目标环境凭证并验证       |
| HTTP MCP  | 默认禁用，检查连接与认证               |
| Skill     | 默认禁用，阅读文件与依赖后启用         |
| stdio MCP | 由目标账号管理员配置本机命令和运行依赖 |
| 组合方案  | 逐一验收其固定依赖，再验证组合用途     |

> [!NOTE]
> 安装的是独立副本。发布者更新不会自动修改你已有的配置，组合方案也不会因为安装完成就自动运行。

## 为什么要固定版本

方案引用具体依赖版本，便于说明安装了什么。依赖版本撤回可能阻止新的安装，但不会自动删除你已安装的副本。若需要换版本，先阅读新版变化与依赖，再明确执行相应安装或维护操作。

## 发布自己的内容

在“我的创作”建立草稿，写清适用场景、输入、输出、依赖和限制。发布前检查凭证、本机私人路径与素材授权；真实密钥应由安装者在自己环境配置。

按界面的版本流程发布、修改或撤回内容。发布后用安装者视角核对说明是否足够完成配置，不只检查作者环境能否运行。

## 常见卡点

| 现象                 | 可能原因                     | 处理                           |
| -------------------- | ---------------------------- | ------------------------------ |
| 依赖检查不通过       | 名称冲突或依赖版本不可安装   | 修改名称或选择有效版本后再检查 |
| 安装成功却无法调用   | 副本禁用、缺凭证或依赖未就绪 | 回集成中心逐项配置并验证       |
| 作者更新后副本没变化 | 固定版本独立副本的预期行为   | 阅读新版说明后决定是否升级     |
| 组合方案失败         | 单个依赖尚不可用             | 先验证每个能力，再测试组合任务 |
