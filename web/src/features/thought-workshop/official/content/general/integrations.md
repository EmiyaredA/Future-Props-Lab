# 工具 API、MCP 与 Skill

当你需要让助手调用一个服务、使用 MCP 工具或遵循一份任务指引时，从集成中心配置对应能力。保存条目、验证连接、启用资源、在对话中选择使用，是四个不同步骤。

## 先选对类型

| 类型     | 适合什么需求            | 开始前准备                           |
| -------- | ----------------------- | ------------------------------------ |
| 工具 API | 调用已有 HTTP 接口      | 方法、地址、认证、输入 Schema 与模板 |
| MCP      | 连接提供工具的 MCP 服务 | HTTP 服务信息，或本机命令与依赖      |
| Skill    | 提供任务步骤和配套资源  | 可导入的 Skill ZIP 及依赖说明        |

配置与验证需要对应管理权限。外部服务由部署机器访问；本机路径、网络环境和浏览器所处环境不一定相同。

## 配置工具 API

1. 创建条目，填写名称和说明，让使用者能判断什么时候调用它。
2. 选择请求方法，填写 HTTPS 或允许的本机回环地址。
3. 按服务要求选择无认证、Bearer Token 或指定 API-Key 请求头。
4. 用 JSON Schema 描述输入，再配置查询和请求体模板，检查参数将被发送到哪里。
5. 修正 JSON 格式提示，保存后使用受控输入验证。

**完成标志：** 验证返回预期结果，输入参数和目标服务实际收到的数据一致。仅成功保存表单不表示工具已经可用。

> [!WARNING]
> 验证可能真实调用目标服务。首次选择你能控制且后果明确的测试输入；修改密钥时区分保留、替换和清除。

## 连接 MCP

HTTP MCP 填写远端连接和认证信息；stdio MCP 配置部署机器上的命令与参数。保存后查看验证反馈及工具列表，再启用条目。

启动失败时，先核对连接类型。HTTP 连接检查地址和认证；stdio 检查本机命令、参数和依赖是否可用。把浏览器文件路径填进服务器命令，不会自动安装或启动服务。

## 导入 Skill 并用于对话

1. 通过正式 ZIP 导入入口导入 Skill 包。
2. 阅读名称、说明、文件结构与依赖，确认它适合当前任务。
3. 在 Amadeus 的“能力”选择中勾选所需 Skill、工具 API 与 MCP。
4. 应用选择，再发送任务；取消能力弹窗不会保存此次变更。
5. 检查实际工具结果或工作产物，确认流程执行到了预期步骤。

Skill 是指引和资源。启用它不会自动执行全部步骤，对话中的能力选择也不等于外部服务一定健康。

## 按顺序排查不可用能力

当前空间与权限 → 条目启用状态 → 验证结果 → 服务依赖与凭证 → 当前对话是否选择了该能力。先修复最早失败的一环，再重做小样本验证。
