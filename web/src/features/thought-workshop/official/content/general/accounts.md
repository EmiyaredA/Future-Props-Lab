# Workspace 与账号权限

如果你能打开笔记，却看不到模型凭证；或者切换空间后原来的项目“消失”了，通常需要先确认身份和权限。本篇帮助你判断资源在哪里、谁能操作，以及自动化应该使用什么凭证。

## 开始前：确认当前身份

在账号或工作空间入口核对当前账号与 Workspace 名称。业务资源跟随服务端识别的当前空间；在请求里填一个其他空间 ID，不会获得那个空间的访问权。

| 你想做的事                 | 需要确认的权限         |
| -------------------------- | ---------------------- |
| 浏览已有作品和官方知识库   | 对应内容阅读权限       |
| 创建文档、修改时间线或文稿 | 内容写权限             |
| 调用模型                   | 模型使用权限及可用模型 |
| 维护供应商、工具和凭证     | 对应配置管理权限       |
| 查看调用详情、管理成员     | 日志或治理权限         |

权限按实际账号授权决定。不要因为一个按钮出现在指南里，就认为所有角色都能使用。

## 切换到另一个空间

1. 先处理当前编辑器中的未保存内容，等待保存成功；发生冲突时先完成冲突处理。
2. 打开工作空间入口，从自己已加入的空间中选择目标空间。
3. 切换后再次核对名称，再打开需要的应用。
4. 检查项目、模型和文件列表。需要继续原作品时，回原空间，或使用应用支持的导出与导入流程建立副本。

**完成标志：** 当前空间名称正确，列表显示的是目标空间资源。旧项目没有跟过来是隔离机制的预期行为。

## 加入空间与变更角色

需要加入新空间时，使用正式邀请流程。拥有相应治理权限的成员管理邀请、成员和角色；收到邀请后核对目标空间，再完成加入。

角色调整后，先刷新账号状态再验证对应操作。只读成员浏览与管理员相同的官方文档正文，管理员也不能在应用内编辑官方原文。

## 为 SDK 创建凭证

1. 在有授权的管理入口创建 Management API Key，确认绑定的 Workspace 和授权范围。
2. 在明文展示时保存到自己的秘密管理工具。不要写进笔记、源码、截图或公开内容。
3. 用该凭证做一次只读查询，核对返回内容确实属于预期空间，再执行写入。
4. 需要替换时创建新凭证、确认新连接可用，再撤销旧凭证。

> [!NOTE]
> Management API Key 明文只展示一次。浏览器登录使用 Cookie，会话凭证与 SDK Key 的用途不同，不应复制 Cookie 充当长期自动化配置。

## 访问问题排查

| 现象                 | 可能原因                           | 处理                               |
| -------------------- | ---------------------------------- | ---------------------------------- |
| 项目返回不存在       | 空间不对、资源已删除、无资源访问权 | 核对当前空间，再查看对应回收站     |
| 阅读正常但无法编辑   | 当前为只读权限                     | 请有治理权限的成员核对角色         |
| 日志或配置入口缺失   | 内容权限不包含该管理能力           | 申请具体所需权限，不借用他人密钥   |
| 登录失效后操作未完成 | 会话过期或被撤销                   | 重新登录并查询现状，再决定是否重做 |
