# Live2D 工坊：导入导出与交付

交给同事继续绑定、交给剪辑制作画面、交给 Cubism Editor 重建模型，需要三种不同材料。先确认接收方的工作目的，再选择输出；本节的验收标准是对方能打开对应材料并继续预定流程，而不只是成功下载一个 ZIP。

## 输入材料分别承担什么角色

PSD 和透明 PNG 用来制作原生角色；`.fpllive2d` 用来交换完整工程。动作或表情 JSON 只包含可映射的参数数据，目标角色需要已有相应参数，不能靠动作文件补出网格和绑定。

Cubism 运行 ZIP 应包含 `.model3.json`、`.moc3`、贴图和引用资源。先通过预检再挂载，随后可以在 FPL、Cubism 或并排视图中对照效果。

## 选择输出

| 需要完成的事              | 输出材料                                         | 接收后检查                                       |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| 继续编辑原生角色          | `.fpllive2d` 工程包                              | 素材、部件、绑定、动作及附件是否齐全             |
| 使用透明动画画面          | PNG 序列 ZIP                                     | 帧序、透明边缘、遮罩和时长                       |
| 在 Cubism Editor 重新绑定 | PSD、逐层 PNG 与可映射动作／表情 JSON 素材交接包 | 分层和参数映射是否可用，继续完成目标软件中的绑定 |

> [!WARNING]
> 素材交接包不生成 `.moc3` 或 `.cmo3`。它提供重建所需材料，不是 Cubism 模型编译器。

## 导出透明序列

1. 保存角色，更新交付预览，再选择表情与动作组合。
2. 设置裁切、输出尺寸、帧率和范围，完成兼容与范围检查。
3. 确认结束帧不包含在输出区间内；静态输出为一帧，动作则按范围生成序列。
4. 提交后从导出记录下载，按帧序播放并检查默认姿态、运动极值和透明边缘。

## 转换 Cubism 前先看报告

转换会读取可映射的网格、UV、贴图与参数，展示报告后再由你确认创建新的原生工程。物理、姿势、复杂遮罩和多参数联动可能近似或无法转换。完成后先验收默认姿态和极值，再比较动作，不要直接用转换成功替代视觉检查。

> [!NOTE]
> 工程包可继续编辑，透明序列是完成画面。交付动画时若还需要后续修改，建议两者同时保留。
