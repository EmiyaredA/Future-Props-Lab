# Live2D 工坊：常见问题与能力边界

角色能加载却不好看时，先分清原画、绑定、动作预览和运行格式四个层次。下面的顺序从可直接检查的部件开始，帮助你修正问题并保留已有工程，不把所有异常都归因于导入失败。

## 从现象找到检查入口

| 现象                     | 常见原因                                  | 处理与成功标志                                       |
| ------------------------ | ----------------------------------------- | ---------------------------------------------------- |
| 参数变化时拉伸或断缝     | 网格、父级或权重与原画不匹配              | 先检查单部件，再分别试默认值与两端极值；轮廓应连续   |
| 部件移动幅度像是加倍     | 父级变换与参数影响叠加                    | 逐级检查父级和绑定，单独试调后再组合参数             |
| 播放动作仍停在手动姿态   | 手动参数预览值覆盖观察结果                | 清除手动预览值，再核对关键帧、范围和插值             |
| 动作循环跳变             | 首尾参数没有衔接，或动作范围不合适        | 连续播放两个循环，调整首尾关键帧而非只检查最后一帧   |
| Cubism 对照加载失败      | ZIP 缺引用资源，或部署未满足运行 SDK 条件 | 核对模型、贴图和附件提示；原生工程与运行附件分别检查 |
| 保存角色后助手头像没变化 | 尚未设置当前使用的角色                    | 回项目卡片选择“设为 Amadeus 形象”，核对账号          |
| 桌宠还是旧样子           | 桌宠保留固定来源快照                      | 在桌宠试玩与来源区域明确检查更新，处理兼容提示       |

> [!WARNING]
> 版本冲突时先下载本地文档备份。重新读取服务器版本会放弃当前草稿，不是修复形变或合并修改的快捷方式。

## 导入与交付的边界

Cubism 转换只能尽力映射可读数据，无法恢复原始 `.cmo3`；素材交接包也不直接编译 `.moc3`。原生交付使用完整工程或透明 PNG 序列，不能把输出图片重新导入后当作原绑定。

当前指南不把视频输出、外部输入驱动或完整原生物理模拟列为已支持能力。若目标依赖这些能力，应先确认实际可用的输出入口与接收流程。

## 修复后的验证

按默认姿态、单参数极值、多参数组合、动作循环四步检查。保存后重新打开，再做一段短序列输出；这样能同时验证持久数据和实际画面。
