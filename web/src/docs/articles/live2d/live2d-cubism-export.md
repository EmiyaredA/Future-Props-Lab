# Cubism 对照、转换与角色交付

原生角色工程和 Cubism 运行模型使用不同的绑定与渲染规则。先确认自己要保留编辑能力、对照现有模型，还是交付最终画面。

## 挂载运行模型并对照

在「模型」页挂载包含 `.model3.json`、`.moc3`、贴图及引用文件的 Cubism ZIP。先检查预检结果，缺少引用或格式不受支持时修正资源包再导入。

附件可选择 FPL、Cubism 或并排视图，试调参数、动作与表情，检查头像和半身取景及状态映射。只存在一个明确的待机动作组时可自动预填，其余状态需要人工确认。Cubism 播放依赖当前部署具备对应的运行 SDK；加载失败不代表原生工程丢失。

## 转换为新的可编辑项目

转换会读取能够映射的绘制网格、UV、贴图和参数，先给出报告，再由你确认创建新的原生工程。源工程和运行附件保留。

物理、姿势、复杂遮罩、混合和多参数联动可能近似或无法转换。转换后需重新审阅默认姿态、参数极值及遮罩；得到可编辑副本不等于恢复了 Cubism Editor 的 `.cmo3` 源工程。

## 选择输出方式

| 交付目标                  | 操作与结果                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| 继续在研究所编辑          | 「交付 → 下载工程包」，得到 `.fpllive2d`，包含文档、素材与缩略图；带 Cubism 附件的包同时保留运行 ZIP |
| 交付透明画面              | 「透明 PNG 序列」，设置裁切、尺寸、帧率、帧范围及表情／动作组合，每个组合独立目录                    |
| 在 Cubism Editor 重新绑定 | 「下载素材交接包」，包含分层 PSD、逐层 PNG 与可映射的动作／表情 JSON                                 |

素材交接包不包含可运行的 `.moc3` 或可编辑的 `.cmo3`；这些文件仍需在 Cubism Editor 中制作。

## 检查导出与恢复

先「保存并更新预览」，确认预览显示当前已保存版本，再运行「兼容与范围检查」。结束帧不包含在导出范围内；自动范围取所选动作的共同有效时长，静态输出一帧。

点击「导出序列」后在导出记录查看状态，完成后下载 ZIP。失败时先查看记录中的原因和设置，修改后手动提交；不要把预览截图当作正式序列。冲突时下载本地文档备份再重新读取，完整可编辑备份优先使用工程包。
