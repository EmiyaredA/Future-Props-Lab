# 官方知识库写作与阅读组件约定

知识库版指南是思绪工坊内随版本发布的中文使用说明。内容位置和目录职责见[项目目录索引](../architecture/project-layout.md)；本文规定写作与验证方法。原文档中心不迁移、不重写。

## 从一个可以完成的任务开始

操作指南首段说明读者遇到的场景，以及完成后能得到什么。先列出必要权限、素材或已完成的设置，再按实际界面顺序写步骤。按钮名称必须在当前源码或隔离环境中核对，每组操作都有可观察的成功标志。例如「返回列表后，项目卡片显示刚才填写的名称」比「保存成功即可」更容易验证。

失败处理写清现象、原因和下一步，优先使用对照表；区分尚未实现、当前条件不满足和暂时失败。不得把原始工程、可编辑交换包和最终成片写成同一种交付。对保存冲突和模型提交中断给出保留编辑与检查状态的办法，不建议自动覆盖或重复提交。

SDK/API 示例说明运行入口、可替换参数、权限前提和预期输出。方法名与请求字段核对独立 SDK 和生成契约；真实凭证不得写入正文。网络调用示例不是离线可执行的功能保证。

## 用实例解释原理

技术文章围绕一个具体问题，用同一实例串起数据结构、执行步骤、设计取舍与异常恢复。标题表达本节解决的问题，避免全部文章复用「实现与设计取舍」等空泛模板。代码入口放在末尾，引用当前仓库存在的路径；链接不能代替解释。

每篇技术文章至少两幅解释性图。图前提出要回答的问题并标出图名，图后说明关键关系、图例与实现边界。Mermaid 用于时序、状态、类、ER 和流程关系；旁置 CanvasScene 用于带图标的信息结构。核对箭头方向、资源所有权、状态名称以及实际支持的能力。图只表示当前实现，不能把规划画成已支持的操作。

## Markdown 与目录数据

- 保持知识库 ID、文章 ID 和阅读路由稳定。正文保存在 `official/content/`，图形由现有受控清单懒加载。
- 每篇一个一级标题；二、三级标题用于可定位的章节。使用有意义的编号步骤，长代码和表格由局部滚动容器呈现。
- 提示框仅支持 `> [!NOTE]`（说明）、`> [!TIP]`（提示）和 `> [!WARNING]`（注意）；标记单独占一行，后接引用正文。不要把普通段落全改成提示框。
- 代码块标注语言，交代输入和预期结果；不使用原始 HTML、可执行 MDX、脚本或任意 SVG。
- 三份 `*Reading.ts` 元数据登记文章简介和相关阅读，由 `reading.ts` 汇合，目录条目附带这些数据。每条简介说明具体任务或问题，每篇至少两条有效、无重复且非自身的相关阅读；正文中的相关阅读可解释为什么继续读它。
- 修改用户行为时，同步更新对应指南、技术解释、图形及元数据；无需更改 ID，也不生成用户数据库记录。

## 阅读组件契约

桌面保留左侧知识库目录，中间正文控制阅读宽度，右侧大纲显示当前位置；中屏将大纲收为正文上方的折叠区域，窄屏继续使用现有目录抽屉和焦点恢复。大纲监听实际正文滚动容器，前后篇遵循可视分组目录顺序。新文章加载后将焦点交给标题或显式指定的章节；个人阅读位置通过账号偏好接口同步，不修改静态官方正文。旧阅读位置不得覆盖 URL 章节或搜索定位，账号、Workspace 和文章切换不得错写旧资源。标题 ID 由 Markdown 源位置生成；复制链接保留当前文章路径，不承诺改写正文后旧章节偏移仍有效。

普通代码由本地打包的高亮器处理并提供原始文本复制。提示框只解析受控标记，原始 HTML 始终关闭。复制失败保留可选择的代码并显示反馈；按钮、章节定位和抽屉应可通过键盘操作。

`OfficialArticle` 的图形代码块组件身份不得依赖菜单、弹窗或导航回调的变化。菜单打开和复制个人笔记弹窗只能改变外围状态，不得重新挂载图形或重置缩放。官方阅读与个人图表继续复用现有展示、导出和权限边界。

## 提交前验证

检查 12 个库、84 篇文章的唯一 ID、简介、相关阅读、正文链接、源码路径和图形引用。运行官方内容与阅读组件测试，覆盖提示框安全性、复制反馈、导航、大纲和图形状态。浏览器在隔离数据下检查读写角色、390/768/1600 宽度、明暗主题、刷新、返回和未保存保护；桌面静态构建阻断外网后检查懒加载正文、图形及高亮。

运行相关架构、lint、格式、构建、契约、Agent Note 和文档保护检查。范围外失败独立记录，不通过修改无关产品内容使检查通过。
