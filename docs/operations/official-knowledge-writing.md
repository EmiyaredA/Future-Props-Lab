# 官方知识库写作与阅读组件约定

官方指南是管理员维护并发布的普通笔记，主要来源位于 `web/src/features/thought-workshop/official/content/`。
内置 Markdown 与图形只构建可选导入包。管理员主动导入后得到私人笔记，通过普通编辑器维护并显式发布。
应用升级保留已导入的正文与图形。目录职责见[项目目录索引](../architecture/project-layout.md)，发布规则见[知识社区](../reference/knowledge-community.md)。

## 从一个可以完成的任务开始

操作指南首段说明读者遇到的场景，以及完成后能得到什么。先列出必要权限、素材或已完成的设置，再按实际界面顺序写步骤。按钮名称必须在当前源码或隔离环境中核对，每组操作都有可观察的成功标志。例如「返回列表后，项目卡片显示刚才填写的名称」比「保存成功即可」更容易验证。

失败处理写清现象、原因和下一步，优先使用对照表；区分尚未实现、当前条件不满足和暂时失败。不得把原始工程、可编辑交换包和最终成片写成同一种交付。对保存冲突和模型提交中断给出保留编辑与检查状态的办法，不建议自动覆盖或重复提交。

SDK/API 示例说明运行入口、可替换参数、权限前提和预期输出。方法名与请求字段核对独立 SDK 和生成契约；真实凭证不得写入正文。网络调用示例不是离线可执行的功能保证。

## 分层解释技术架构与实现

「Future Props Lab 技术文档」包含 31 篇文章，按系统全景与架构、组件化设计、数据模型与数据流、模型与执行机制、各应用实现、工程验证与设计取舍六组阅读。先用实例建立认识，再展开契约与实现；前三组帮助读者定位组件和数据所有者，应用文章链接公共机制，避免重复解释。

技术文章围绕一个具体问题，用同一实例串起数据结构、执行步骤、设计取舍与异常恢复。标题表达本节解决的问题，避免全部文章复用「实现与设计取舍」等空泛模板。代码入口放在末尾，引用当前仓库存在的路径；链接不能代替解释。

每篇技术文章至少一幅 CanvasScene 与一幅 Mermaid 解释性图。图前提出要回答的问题并标出图名，图后说明关键关系、图例与实现边界。Mermaid 用于时序、状态、类、ER 和流程关系；旁置 CanvasScene 用于带图标的信息结构。核对箭头方向、资源所有权、状态名称以及实际支持的能力。图只表示当前实现，不能把规划画成已支持的操作。

## Markdown 与目录数据

- 保持知识库 ID、文章 ID 和阅读路由稳定。导入来源保存在 `official/content/`，运行期正文和图形保存在普通笔记记录中；旧来源 ID 只用于可访问官方发布的兼容解析。
- 每篇来源一个一级标题，导入时复用笔记标题并移除重复正文 H1；二、三级标题用于可定位的章节。使用有意义的编号步骤，长代码和表格由局部滚动容器呈现。
- 提示框仅支持 `> [!NOTE]`（说明）、`> [!TIP]`（提示）和 `> [!WARNING]`（注意）；标记单独占一行，后接引用正文。不要把普通段落全改成提示框。
- 代码块标注语言，交代输入和预期结果；不使用原始 HTML、可执行 MDX、脚本或任意 SVG。
- 三份 `*Reading.ts` 元数据登记文章简介和相关阅读，由 `reading.ts` 汇合，目录条目附带这些数据。每条简介说明具体任务或问题，每篇至少两条有效、无重复且非自身的相关阅读；正文中的相关阅读可解释为什么继续读它。
- 修改用户行为时，同步更新对应指南、技术解释、图形及元数据；保持来源 ID；重新生成导入包并校验，已有导入记录不会自动回写。

## 阅读与权限契约

官方与普通社区文章使用相同富文本阅读器、大纲、编辑器和未保存保护。权限来自发布与逐篇授权。
官方徽标与当前读者的编辑能力分别显示。只读默认开启，源账号保留维护权，其他读者按显式逐篇授权和角色编辑授权获得相应能力。

代码、提示块、Mermaid 与 CanvasScene 保留普通笔记能力；原始 HTML 不执行。菜单、权限弹窗不得重新挂载图形或重置视口。章节位置按普通笔记阅读机制恢复，个人偏好不推进正文 revision。

画板持久化使用 `CanvasScene.sceneVersion` 契约。React Flow 状态只在运行期使用。前后端校验与静态 SVG 布局规则保持一致，
画板图片只引用经账号归属校验的托管素材。

## 提交前验证

检查 12 个库、93 篇文章的唯一来源 ID、简介、相关阅读、正文链接及图形，运行 `npm run knowledge:seed:generate` 后执行 `npm run knowledge:seed:check`。导入包包含 12 篇标准首页，转换跨库引用并通过正文校验。预览数量与导入回执核对，断线先查询成功结果；再次主动导入不得覆盖旧笔记。

在隔离数据中检查正文、画板、Mermaid、目录、代码和相关阅读。发布由管理员明确选择文章、勾选官方与只读并配置编辑角色，不自动发布。测试普通用户伪造标记、源普通成员社区编辑、授权撤销、表格与素材写入、可见范围、旧链接多匹配与无匹配。浏览器检查明暗主题、390/768/1600 宽度、刷新、返回及未保存保护。

运行相关架构、lint、格式、构建、契约、Agent Note 和文档保护检查；范围外失败独立记录，不修改无关产品内容使检查通过。导入包是内容，不是独立的运行期阅读产品。产品文档中心仍遵守原保护规则。

## 写作参考

技术文档编排参考 [Diátaxis](https://www.diataxis.fr/start-here/) 的读者需求划分、[arc42](https://arc42.org/overview/) 的静态结构与运行场景，以及 [C4](https://c4model.com/diagrams) 的逐层架构表达。应用内技术文档以解释为主，具体操作与字段参考通过链接关联；图形明确区分代码依赖、运行调用和数据传输。设计动机以当前实现及已有工程记录为依据，推断明确标注为分析。

本规范参考 [Claude Code 快速开始](https://code.claude.com/docs/en/quickstart) 的任务步骤与反馈、[Claude API 入门](https://platform.claude.com/docs/en/get-started) 的示例组织和 [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works) 的概念解释。仅参考组织和阅读方式；产品事实、按钮和示例由 Future Props Lab 源码与验证流程提供。

## 知识社区与授权说明

官方筛选查询已发布数据。发布管理弹窗允许发布者设置只读与逐篇账号授权，平台管理员额外看到官方标记和编辑角色。
旧 URL、引用和收藏只连接当前可访问的官方发布。
社区操作步骤从「更多 → 发布到知识社区」开始，权限逐篇或对选定文章批量设置。使用不同登录账号验证可访问计数、
隐藏父文档提升、过滤导出和素材隔离。预览图来自隔离实例的实际页面，覆盖发布、可读/可编辑/可管理、撤回、
390/768/1600 宽度和明暗主题。热度来自真实数据，授权验证以后端结果为准。

## 与用户笔记共享编排

导入包首页由来源清单生成标准正文块，导入后直接使用普通笔记布局。侧栏只使用父子文档树，六组阅读顺序和分组说明保留在正文中；不创建虚拟分组文章，来源 ID 保持稳定，数据库笔记 ID 由导入用例新建，所有内部引用统一重映射。

官方可见的卡片、引导样式、提示块、代码高亮与图形样式必须在笔记编辑器中有对应能力。用户通过斜杠菜单插入文档卡片、卡片组、动态文档目录和知识库首页模板；章节介绍使用标准标题与段落。共享样式归 `document-layout/`，Markdown 仅在构建和导入时转换，运行期统一富文本节点。

卡片仅持久化目标引用和展示配置。标题和简介按当前访问权限解析，失效目标不显示名称、简介或链接。
目录块只遍历适配器提供的当前可见目录。HTML 导出保留布局并过滤失效引用，Markdown 导出转为可见文字和链接并提示排版变化。
完整备份保留块结构。
