# 文件暂存与数据库事务

数据库事务不能原子覆盖文件系统，因此所有同时修改元数据和文件的用例必须使用“暂存、提交、补偿”
协议；不得把外部网络等待或大文件 I/O 放入已开始写入的长事务。

## 创建或复制

1. 在目标运行期目录内生成不可预测的暂存路径，并完成扩展名、MIME、文件头、大小和目标归属校验。
2. 使用短事务写入文件元数据、项目引用和任务状态；同一 `AsyncSession` 只能由一个异步任务使用。
3. 确认数据库回滚后删除本次暂存文件。文件落位失败时回滚事务或以正式失败状态结算，避免成功记录指向缺失文件。
   提交确认丢失或提交期间取消时，保留可能已被引用的文件，查询持久记录或回执再决定清理。
4. 外部上传、供应商调用和下载在事务外执行，完成后再用独立短事务 CAS 结算。

## 删除、移动与恢复

删除先把文件移动到同一文件系统的暂存删除位置，再提交元数据变更。确认回滚后恢复原路径，确认提交后清理暂存文件。
批量操作保持原子性，确认回滚后补偿本批已暂存的项目。恢复和覆盖必须校验目标路径、账号及项目归属与 revision，冲突返回 409。
取消后先等正在执行的文件 I/O 停止再清理，可复用 `studio/runtime/tasks/blocking_io.py`。

运行期修复、回填和导入只能通过所属能力的正式 `/v1` API；运维脚本、Web 和人工恢复不得绕过应用
直接写 SQLite 或向素材目录补文件。备份与恢复必须按同一时间点整体处理数据库和全部素材目录。
