# 账号与工作区治理

管理界面包含 `/management/accounts`、`/management/invites`、`/management/settings`、`/management/services`、`/management/permissions`、`/management/workspaces`、`/management/audit`，仅超级管理员可访问。个人资料、密码、会话和密钥仍位于账号中心。单进程、单 SQLite 和显式 Workspace 隔离保持不变。

## 固定角色

| 能力                                 | owner 拥有者 | admin 工作区管理员 | member 协作者 | viewer 只读成员 |
| ------------------------------------ | ------------ | ------------------ | ------------- | --------------- |
| 内部内容、素材、已有结果的浏览与下载 | 是           | 是                 | 是            | 是              |
| 内容写入、上传、删除、生成及模型调用 | 是           | 是                 | 是            | 否              |
| 模型服务、默认模型、集成配置         | 是           | 是                 | 否            | 否              |
| 调用概况、空间审计                   | 是           | 是                 | 否            | 否              |
| 空间设置、协作者与只读成员治理       | 是           | 是                 | 否            | 否              |
| 授予或撤销工作区管理员               | 是           | 否                 | 否            | 否              |

超级管理员和运营管理员有全部空间的管理权限，显式切换空间不建立成员关系。完整调用诊断还要求平台策略授予 `diagnostics.model`，实时诊断要求 `diagnostics.realtime`；空间拥有者身份不会绕过平台策略。任何人不能通过成员接口修改拥有者或自身角色；工作区管理员不能修改其他管理员。公开访客使用已有公开投影，不获得 `content.read` 内部权限。每个账号均保留个人资料、安全和本人邀请处理能力。

`WorkspaceOut.permission_keys` 返回有效权限。固定权限包括 `content.read`、`content.write`、`models.use`、`configuration.manage`、`logs.read`、`workspace.manage`、`members.manage`、`members.assign_admin`、`audit.read`。HTTP/SSE 使用显式路由策略；WebSocket 建立、新一轮调用前及连接期间每 5 秒重新校验。后台已提交任务继续按既有规则完成，不自动重提。

## 查询与写入契约

账号查询参数为 `q`（用户名/展示名/邮箱）、`status`（active/disabled）、`platform_role`、兼容字段 `is_platform_admin`、`page`（从 1 开始）、`page_size`（1–100，默认 25）。响应包含 `items/total/page/page_size`，账号包含邮箱。

账号创建接受 `username/display_name/email/platform_role`，兼容旧 `is_platform_admin`；返回账号及一次性临时密码，并自动创建个人空间。额外空间创建接受 `name/owner_user_id/visibility`（默认 private），拥有者必须启用；空间、拥有者关系、初始模型目录及审计在同一事务提交。空间查询支持 `q/visibility/page/page_size`，返回拥有者、有效访问身份和 `member_count`。

平台身份或状态 PATCH、密码重置、当前空间 PATCH、成员角色 PATCH/DELETE 与邀请接受/拒绝/撤销均要求 `expected_revision`。缺少版本返回 422，版本冲突返回 409 和允许公开的 `current` 快照；客户端刷新供用户核对，不自动重试原写入。治理事务使用 SQLite 短写锁后重验操作者和当前角色，再执行数据库 CAS。禁止禁用或降级自身，不能移除最后一个启用的平台管理员。

平台和当前空间审计支持 `event_type/actor_query/target_query/from_date/to_date/page/page_size`。账号筛选匹配用户名；时间支持 ISO 8601，带时区值转 UTC，无时区值按 UTC。响应元数据使用允许字段清单，禁止返回密码、Session、CSRF、密钥或原始供应商配置。

## 撤销和只读

平台身份变更、禁用、密码重置撤销目标账号已有 Session 和所有管理密钥；成员角色变化、移除撤销目标账号在该空间的密钥。密钥权限始终取签发 scope 与持有者当前角色的交集，只读成员只可签发 `studio:read`。平台与个人治理入口仍要求浏览器 Session。

只读浏览使用各功能的读取接口及预览组件，不挂载编辑、拖拽、自动保存和任务提交控制器。允许下载已有文件和结果，不提供需要新建后台任务的导出。界面失去权限后刷新身份、取消查询、清理缓存并重建功能界面，不自动重放写入。切换空间沿用未保存编辑保护与跨标签页通知。

## 升级

`r0050_workspace_governance` 在 `0049_thought_history` 后追加。成员表约束扩展为四角色，保留历史 ID、revision、时间、成员唯一性及唯一活动拥有者；邀请增加默认 `member` 的 role 字段。旧成员和待处理邀请保持 `member`，显示为“协作者”。**旧协作者不再具有模型配置、完整调用日志和空间审计权限**；需要这些能力时由拥有者或平台管理员显式授予工作区管理员。

迁移先在临时数据库验证历史数据和约束，再登记应用。不得修改历史迁移或直接写持久数据库。运行期管理统一通过上述正式 API。

## 三级平台身份与升级

`r0051_platform_governance` 将旧平台管理员保留为超级管理员；运营管理员可显式进入其他工作区，普通用户保留自己的工作区治理权限。`is_platform_admin` 兼容字段只表示超级管理员中台资格。平台角色调整、禁用与密码重置继续撤销会话和密钥。

普通用户即使是空间拥有者，也默认不能读取原始模型请求、响应、实时语音诊断、敏感工具返回或开发者文档。工作区四角色决定业务能力，平台策略约束敏感能力，密钥再与签发范围取交集。公开展台仍只有公开投影。

## 邀请码与角色模板

邀请码通过 `/v1/platform/registration-invite-codes` 创建、分页查询、更新、延期、重设有效期与软删除。兑换采用短写事务校验有效期、启停和名额；注册固定创建普通用户、个人空间，并使用注册者自己设置的密码登录。列表只返回掩码，重新读取明文要求近期密码验证并留审计。

`r0052_role_model_templates` 保存角色模板及持久同步任务，`r0055_model_suppliers` 保存供应商分组。模板保存与已有空间同步分开，预览记录各空间目录版本，执行时每个空间独立校验。保留自建配置、稳定模型 ID 和仍有效的默认选择；活动任务、重名及版本冲突跳过。撤销的模型保留以保护历史引用；空模板供应商组仅在没有连接引用时清理。模板密钥只在服务器保存，复制连接不复制密钥。

## 测试服务与并发额度

`r0054_platform_runtime` 增加敏感工具标记、官方项目标记和额度归属记录。Mock 文本服务和固定商品/订单示例在现有进程内运行，默认关闭；配置和启停使用 CAS。停用拒绝新调用，重新初始化等待已接收调用结束。接入当前空间通过正式目录用例完成。

账号初始总并发/语音为普通用户 2/1、运营管理员 4/2、超级管理员 8/4；工作区总并发 8、实例 16/8、管理员预留 2。HTTP 完整调用、流式调用、活动语音会话和图片/视频/转写任务均占额度；超额返回 429，不自动排队或重试。

持久任务通过 `runtime_admissions` 保存提交账号、空间及任务 ID，归属与任务创建在同一事务提交。重启释放临时调用占用，持久任务按记录恢复；历史无提交人任务只计空间和实例。额度下调不打断已接受任务。
