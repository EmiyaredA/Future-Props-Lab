# 账号与数据归属

应用使用单进程与单 SQLite。每个账号直接拥有私人项目、素材、模型目录、集成和任务；没有 Workspace、成员邀请、空间切换或公开空间展台。

## 身份和授权

仅有 `admin`（管理员）和 `user`（普通用户）。两者均能管理自己的内容、模型配置和集成；管理员另有账号治理、平台模型模板、CLI Agent 授权、演示服务、运行额度和官方标记管理能力。管理员不能浏览其他账号的私人资源或调用日志。权限由 `AuthMeOut.permission_keys` 返回，并与 API Key scope 取交集。

Cookie Session 使用 HttpOnly Cookie，写操作校验 CSRF。个人和平台治理只接受浏览器 Session。Management API Key 绑定签发账号。`studio:read` 不允许写入，管理员也无权访问其他账号的私人资源。密码重置、账号禁用和身份变更撤销已有凭据。

新建的有效密钥可以在「账号设置 → API 密钥」中查看并复制。超过 10 分钟未验证密码时，取回前需重新验证。服务端保存哈希和加密副本，列表只显示前缀。此前签发的密钥只有哈希，仍可用于认证，但无法找回明文。迁移 `0124_management_api_key_secrets` 和独立 Identity 迁移 `0010_management_api_key_secrets` 为加密副本增加可空字段。

普通账号可使用 `GET /v1/account/directory` 查询有效账号的最小公开身份（ID、用户名、展示名），用于显式文章授权及人员字段；不返回邮箱或私人资源。

## 管理中台

管理员入口包含 `/management/accounts`、`/management/invites`、`/management/settings`、`/management/services`、`/management/quotas` 和 `/management/audit`。模型模板按平台角色初始化新账号，已有账号可选择单独分配或按角色批量同步，保持项目引用的模型 ID，不删除自建连接或有效默认选择；预览只提供平台模板信息及保留数量，不展示私人模型名称。CLI Agent 按账号、Agent 与用途显式授权。

账号查询支持 `q/status/platform_role/page/page_size`。创建账号及初始化目录在同一事务完成，返回一次性临时密码；首次登录必须改密。治理写入要求 `expected_revision`：缺少版本为 422，冲突为 409，客户端保留草稿且不自动重放。不能禁用或降级自己，也不能移除最后一名启用管理员。

## 文章共享

知识库和未发布笔记属于账号私人数据。社区发布和逐篇读取、编辑授权保留；授予文章权限不开放作者的知识库、历史、其他素材或普通文件库。管理员也必须满足发布记录与文章授权。社区文件只开放可读正文实际引用的素材与封面。

## 存量升级

迁移 `0116_account_ownership` 将每个原空间的数据交给唯一活动 Owner，同一账号的多个空间合并，保持资源 ID。旧平台角色 `super_admin/admin` 统一为 `admin`，`member` 变为 `user`；旧 Session、API Key 撤销。没有唯一 Owner 时停止迁移，避免猜测归属。迁移只在独立测试数据库验证后定稿，正式升级先停机备份。

文件保存在 `accounts/<user-id>/`，个人头像仍在 `profiles/<user-id>/`。schema 升级登记文件清单，应用进入维护页，普通 API 和后台任务暂停。管理员重新验证密码后调用 `/v1/file-storage/layout/migrate`；文件先复制、校验大小及 SHA-256，再原子落盘。相同文件可重入，不同内容、路径穿越和符号链接拒绝处理。源文件保留为恢复副本，正常业务不再读取旧路径。全部核验成功后关闭并重启应用。

维护期间 `/ready` 保持 503，并返回 `account_storage_upgrade_required`。桌面壳仅识别这一明确状态来打开登录及文件升级界面；其他就绪错误仍阻止启动。登录、管理员身份与近期密码验证继续生效，桌面壳不会代为完成文件迁移。

## 验收

使用独立临时数据库和账号验证：普通账号与管理员均不能读取他人资源；只读密钥不能写入；社区显式授权保持有效；迁移保留引用并撤销旧凭据；文件迁移可重复执行且不覆盖冲突文件。禁止以真实数据库作为测试数据。
