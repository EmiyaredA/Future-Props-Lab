# 分层桌宠资源包

通过桌宠工坊「导入角色资源包」上传本地 ZIP；接口沿用 `POST /v1/desktop-pet/projects/import-whale`。此格式只保存数据，不接受 JavaScript、未登记文件、软链接或逃逸路径。

## 清单与兼容

`manifest.json` 固定为 `{"format":"fpl-coopanion-whale","version":1}`。`model.json` 缺省 `rigProfile` 为 `whale`；原 Coopanion 模型定义保持不变。人物模型使用 `human-chibi`，不要求裙子、尾巴或鱼鳍。

人物模型的 `character` 必须有非空 `name`，最多 120 字；可选 `persona` 使用角色配置已有的 `description`、`personality`、`speakingStyle` 和 `greeting` 字段。导入不会修改其他项目，首套配色作为默认。人物私人聊天默认关闭主动台词，之后由各账号自行保存偏好。

## 人物骨架

坐标采用桌宠行为引擎的空间，足底 `y=256`，身体中心 `x=128`。保留 `units.S`、`units.X0`、`units.FEET` 的数值字段；人物分件与五官直接采用骨架空间，不做鲸鱼娘原画像素转换。

- `view`：`[x0,y0,x1,y1]`，宽高为正且各不超过 512；推荐 `[0,-8,256,280]`。
- `pivots`：`body`、`neck`、`armNear`、`armFar`、`legBack`、`legFront` 各有二维坐标。
- `parts`：每件有唯一 `id`、`tex`、`z`、`parent`、`box=[x,y,width,height]` 和 `grid=[columns,rows]`。贴图为 `tex/{tex}.png`，宽高为正，网格每轴 1–16。
- 必需部件：`hair_back`、`hair_front`、`face`、`torso`、`coat`、`arm_near`、`arm_far`、`leg_back`、`leg_front`、`sit_lower`。
- 允许父变形器：`body`、`neck`、`head`、`hair`、`bangs`、`coat`、`armNear`、`armFar`、`legBack`、`legFront`。头部用 `head`，长发用 `hair`，前发用 `bangs`，外套用 `coat`，四肢用对应变形器。

`face` 是不带五官的皮肤底画。动态五官在 z=8、parent=head 的层绘制；脸底应在其下，前发在其上。关节、皮肤与衣物需要完整隐藏补画。`sit_lower` 替换站立双腿；行为引擎坐姿下降 29 单位，人物适配抵消其中 11 单位，因此完全坐下时该部件静态底边设为 `y=238`。

## 完整序列帧版本 1

新动作可使用独立的 `frameSequences` 描述完整原画帧，不通过移动头部、切块或旋转肢体生成姿势。此字段与 `motionRig` 可同包保存；完整序列路径优先使用自己的原画，关节描述保留兼容，不能补齐序列中缺失的动作。原 `parts`、默认站姿／坐姿、表情素材及已保存配置仍保留。当前新候选尚未通过全动作、三套服饰与鲸鱼的隔离视觉验收，不表示完整新版动画已经上线。

顶层必须有 `version`、`frameSize`、`modelBox`、`headLength`、`clips`、`transitions`，另可有 `cels`，不接受其他字段：

- `version` 固定为整数 `1`。`frameSize=[width,height]` 是全角色统一帧画布，每轴为 1–4096 的整数。
- `modelBox=[x,y,width,height]` 是所有帧共用的骨架空间放置范围；数值有限且绝对值不超过 512，宽高为正。`width/frameSize[0]` 与 `height/frameSize[1]` 必须等比，相对容差为 `1e-6`；渲染只使用这个单一比例，不按动作轮廓或每帧透明包围盒重新缩放、居中。
- `headLength` 为正且不超过 512 的骨架空间头部标尺。每帧两端头部标记的欧氏距离乘以统一比例，必须落在该标尺的 ±2% 内，否则拒绝导入，不自动修正大小。标记须对应真实原画；数字通过不能证明素材的身体比例、五官与姿势自然。
- `clips` 为 1–64 个安全 ID 对应的片段，必须有 `idle`。每片段仅有 `frames`、布尔 `loop` 和可选 `distancePerCycle`；后者为正且不超过 512 的模型距离，用于一个完整循环。每片段 1–128 帧。`frames` 的每项可以是下文的完整帧对象，或指向可选 `cels` 的字符串 ID；两种形式可混用。登记帧声明数与全部片段帧使用次数相加不得超过 2048，同一帧重复引用仍逐次计数。
- `cels` 为可选的安全 ID 字典，每个值必须是完整帧对象，用来复用已制作的原画及相同登记。ID 使用 1–48 字符的字母、数字、下划线或连字符；它与片段、贴图分别命名。不能登记别名、引用对象或逐次覆盖锚点／时长。读取端只查找字典自身登记的 ID，每次引用展开为独立帧，不共享可变锚点。原始资源保存引用形式，运行内部展开不改写上传内容。
- `transitions` 必须是数组，可为空，最多 128 条。每条必须有唯一安全 `id`、`from`、`to`、`clip`，可选 `branches`；三项引用必须都指向已有片段，端点对不能重复。`clip` 提供从来源最后实际画面到目标首帧的完整过渡原画；资源不能只写端点名称、靠硬切或翻转整人代替转身。空数组不表示引擎会生成缺失过渡。

当来源是循环行走等多帧动作时，可用 `branches=[{"fromFrame":0,"clip":"stop_0"},…]` 为每个实际已绘来源帧选择独立的完整收步或转身片段。`fromFrame` 必须是唯一的整数索引，完整覆盖来源片段每一帧；每个 `clip` 引用已有非循环、无 `distancePerCycle` 的计时片段。分支首帧必须与对应来源帧的图片、裁切、抓点、足底、头部及可选接触／支点严格相同，末帧与目标首帧严格相同；仅时长可以不同。运行按最后实际绘制的片段和帧选择分支，不能按刚选中的目标推测当前姿态。未声明分支的旧平铺过渡仍保持兼容。

同一计时片段可保存多个已制作的过渡区间，分支用可选 `range=[start,end]` 选择其中一段，例如 `{"fromFrame":0,"clip":"stop_pool","range":[3,7]}` 播放原片段索引 3、4、5、6。区间为左闭右开，端点必须是整数，满足 `0 <= start < end <= frames.length` 且至少两帧；首尾校验使用所选区间的首帧和末帧。未提供区间仍使用整个片段，兼容旧单帧桥。区间外的前后缀不参与播放、过渡计时或结束支撑释放；打断时的来源索引始终是原片段索引，不从零重新编号。实际图集解码只加载所选区间、目标及最后已绘画面需要的素材，但像素预算按引用 PNG 的完整尺寸计算。

任何被部分区间引用的片段都会被识别为过渡容器。它可以提供经过校验的分支，或作为正在播放时被打断的真实来源，不能作为 `idle`、任何过渡的 `to` 或普通动作直接播放，避免把多段收步姿势连成一次错误动作。显式全长区间和未声明区间的旧片段不改变其原有用途。不新增容器模式字段。

分支只支持直接映射。途中打断入口或另一条过渡时，当前来源是实际过渡片段，也需要它到新目标的直接资源；没有声明时保留当前画面并反馈缺失，不回跳旧来源、不跨图寻路或拼接未制作的姿势。左右行走的物理能力也检查左右转向直接桥。共享区间只减少重复片段，不增加 64 个片段、2048 帧、模型 JSON 或原图预算；八帧左右行走、逐帧收步及逐帧转向的最小数值包不等于完整四边自然动作已满足容量与验收。

每帧必有 `texture`、`rect`、`durationMs`、`grip`、`foot`、`head`，可选 `contacts`、`supports`，不接受独立 `scale`、`box` 等未登记字段。

`cels` 中未被片段使用的声明也必须通过全部帧校验，其贴图纳入授权素材闭包并在每套服饰中验证实际 PNG 范围。上传校验检查整个包；运行按选中片段和过渡区间加载图集，不为了未用声明预载素材。引用仅减少重复的 JSON 登记，不改变播放索引、时钟、首尾身份或支撑交接规则，也不提高 128 KiB 模型 JSON、片段、PNG 或 ZIP 预算。

- `texture` 是 1–48 字符的字母、数字、下划线或连字符 ID，不能是 URL 或任意路径。它可以独立于 `parts[].tex` 登记图集，不占一个新的角色部件名额。
- `rect=[x,y,width,height]` 使用原 PNG 像素；各项为 0–4096 的整数，宽高必须严格等于全局 `frameSize`。裁切不得越过任一服饰的实际 PNG；透明边距也属于帧，不得用各帧 alpha 边界改变比例。
- `durationMs` 为正且不超过 60000 的有限数值。`grip`、`foot` 和 `head=[上端点,下端点]` 是裁切帧内部的局部像素坐标，不加图集裁切原点，坐标均在 `0..frameSize` 内。`grip` 表示实际抓取点，`foot` 表示足底；它们随原画姿势变化，但不会触发缩放。
- `contacts` 可登记 `left`、`right`、`top`、`bottom` 的局部接触点；`supports` 可登记 `armNear`、`armFar`、`legBack`、`legFront` 的真实支点。提供的点必须有限且在局部画布内；仅有片段名称或数字支点不构成视觉验收，也不能宣称未提供的四边能力。

所有服饰共享帧坐标、画布、比例、时序和图集布局。首套图集使用 `tex/{texture}.png`，后续使用 `schemes/{id}/tex/{texture}.png`；每套必须提供全部引用，同名 PNG 尺寸必须一致。只在经典服饰提供完整帧，或在女仆／实验室服饰套用另一种图集尺寸，均不能作为兼容资源导入。序列帧仍受下文既有 ZIP、PNG 和 `model.json` 预算约束，2048 是帧数校验上限，不是容量承诺。

完整帧已经绘制的五官不应再叠加旧动作的脸部或肢体切片。实际使用仍须对照同一尺寸的待机、行走、拎起和过渡，录制正常速度画面并抽取原始源帧；检查头部、眼睛、肩腰和四肢比例稳定，支点可信且切换不跳变。未经视觉验收，不用于正式资源更新。

## 可选关节动作分件

旧资源包不必增加字段。`motionRig.version=1` 的人物包仍可读取，保留原站姿、坐姿、表情及换装；该版本把站姿切片用于大幅动作，已停用其运动拼接路径和自主运动。运行及试玩显示缺少完整动作姿势的原因，不自动修改已保存习惯。它只有数据，不允许上传变形函数、任意父子树或脚本。

- `waist`、`neck`：可选二维骨架坐标。腰部用于弓腰拎起的抓点；颈部用于按角色比例安排攀爬手部高度。坐标有限且绝对值不超过 512。
- `limbs`：必须且仅有 `armNear`、`armFar`、`legBack`、`legFront`。每项提供 `root`、`joint`、`end` 二维坐标和 `parts` 三个不同部件 ID。相邻骨段长度为 1–256。
- 三段的 `parent` 依次为对应四肢名、`<name>Lower`、`<name>End`；可选 `jointPart` 补画跟随 `<name>Lower`。各引用必须存在且不能复用。父子关系由渲染器固定，肩肘腕／髋膝踝保持连贯。
- `hiddenParts`：1–8 个原有部件 ID。启用关节动画时隐藏它们；坐姿仍使用原站姿／坐姿素材与衣物遮挡规则。
- `parts[].uvBox`：可选 `[u0,v0,u1,v1]`，均为有限的 0–1 数值，必须形成正面积矩形。可从原贴图提取上臂、前臂、手、大腿、小腿和脚；缺省使用整张贴图。弯曲接缝需要重叠和独立关节补画，不能靠拉伸骨段填洞。
- `profileHead`：可选侧向头部分件。`part` 指向 `parent=head` 的新部件；`hiddenParts` 登记被替换的脸底、头发和头饰。`eye`、`brow`、`mouth` 使用 `[x,y,width,height]` 定位侧向五官，宽高为正且数值有限。侧向头部保留空白脸底，复用原表情的单眼和嘴部，避免把正面头部压扁。

例如一条手臂可声明：

```json
{
  "root": [96, 153],
  "joint": [88, 170],
  "end": [79, 186],
  "parts": ["upper_arm", "forearm", "hand"],
  "jointPart": "elbow_patch"
}
```

关节动画由宿主确认的移动距离驱动步相。版本 1 的人物运动已停用，拖动窗口仍可使用，拖动期间保持完整原站姿。旧数值测试不构成视觉验收。资源包应为动作扩大的可见范围留出画布；仍受每轴 512 单位上限约束。

### 可选姿势绑定版本 2

`motionRig.version=2` 在既有关节描述上增加 `poses`。必须登记 `walk`、`held`、`side`、`top`、`bottom`、`glide` 六种姿势，保留原有站姿、坐姿和表情。当前候选素材仍在隔离验收中，不能作为已通过验收的正式资源。

每种姿势登记 `part`（躯干／完整姿势素材 ID）、`waist`、四个 `edges` 接触平面和 `face` 五官映射。可选 `head={part,neck}` 登记独立头部素材及颈部关节坐标；资源中该部件的 `parent` 必须为 `body`，渲染器内部固定绑定到 `head`，由颈部关节控制。`face` 包括正尺寸的 `eye`、`brow`、`mouth` 矩形、布尔 `twoEyes` 与有限的 `angle`（±90 度）。四肢 `armNear`、`armFar`、`legBack`、`legFront` 分别声明 `root`、`joint`、`end`、3–16 点的 `region`、四项相对关节 `limits` 和 `bend`（±1）。骨段长度为 1–256 单位，坐标有限且不超过 ±512，限制必须包含零且不超过 ±120 度。可选 `stride` 为 8–96 骨架单位，经过实际画布缩放后驱动宿主位移对应的步相。

四肢可选 `limb.part` 引用整条独立四肢的蒙皮素材，或使用 `limb.segments=[上段ID,下段ID,手或靴ID]` 登记三个刚性分件；两者不能同时声明。刚性分件分别跟随对应四肢名、`<name>Lower`、`<name>End` 关节，不通过拉伸绘画补齐接缝。资源中它们的 `parent` 仍固定为 `body`，关节绑定仅由渲染器建立。所有姿势的躯干、头部和四肢引用必须在整个 `poses` 内唯一且存在，不能上传任意父子树。未声明独立四肢的完整姿势素材及已有 `limb.part` 蒙皮包继续使用兼容路径。服饰通过分件绘制顺序遮挡；休息保留最后姿势。左右镜像同时交换左右接触平面。

兼容的刚性骨段可选 `parts[].restTransform={angle,pivot}`，为未旋转素材登记一次静态模型空间旋转；`angle` 有限且在 ±180 度，`pivot` 为两个有限且不超过 ±512 的模型坐标，不能带其他键。该字段只允许完整版本 2 的运行姿势或过渡中间姿势通过 `limb.segments` 引用的部件，不用于头部、躯干、完整姿势或蒙皮四肢，不与 `skin`／`mesh` 并存。GPU 装配时旋转静态顶点，保留原 UV、物理关节坐标、骨长和后续动画角度；它不替代新的完整动作原画。未声明时原包行为不变。上传的 JSON `mesh` 与旧未登记的 `restAngle` 字段会被拒绝；运行时内部编译的类型化网格不属于 ZIP 格式。

跨姿势比例以同一角色原站姿的头高、躯干长度和各骨段长度为标尺；服饰复用相同关节比例。不能按各姿势的总包围盒高度统一缩放：弯腰、伸臂和屈腿会改变轮廓高度，却不应改变角色头部、身体与四肢的实际大小。资源格式合法只表示安全且可解析，数字测试通过也不能证明接缝、动作和支撑自然。每轮修改必须录制隔离桌宠的正常速度录像，循环至少 10 fps 抽帧，起停和松手逐帧检查，并检查支撑阶段累计漂移不超过 1 DIP。未通过不得调用资源更新 API 应用到正式项目。

`limb.contact` 可选地登记画面中实际接触的掌心／鞋底坐标，必须有限且距 `end` 不超过 96 单位。`end` 是腕／踝关节，不能用鞋尖代替踝关节；接触时整个手掌或靴子保持共同朝向。配置应为支撑阶段留出可达空间，不能让伸直的关节持续滑离支点。

`face.sprites` 可选地把现有七种五官键映射到 `feat.sprites` 中已登记的干净素材；不增加表情种类。独立动作五官使用完整图像，不再把正面眼睛强制裁半；站姿／坐姿继续使用原五官。映射后的睁眼素材按 `eye` 的高度等比绘制、在该矩形内水平居中，不能把已经画成侧视的眼睛再次横向压窄；眨眼只改变张开程度，闭眼保留登记的睫毛宽度和 3 单位线高。制作时用原站姿的实际头冠至下巴及虹膜尺寸校准全部姿势，不能仅互比两张新动作。`face.clip` 可选地用 3–16 个有限骨架坐标定义露出的脸部范围，防止五官覆盖刘海。素材只应包含眼白、虹膜、睫毛／眉毛／嘴部，不能带入原正面脸的皮肤或头发块；打包时检查低 alpha 光晕、邻格碎片及实际绘制比例。

`face.sourceRects` 可选地为上述七种五官键登记 `[x,y,width,height]`，单位为对应 `feat` 原始 PNG 像素，引用沿用 `face.sprites` 映射。宽高必须为正，所有数值有限、非布尔且在 0–4096 内；矩形不得超出基础贴图及任一服饰同名贴图的实际尺寸。渲染器直接从未改写的原图取样，映射后的睁眼仍保持源矩形宽高比；未登记时沿用原有整图／单眼取样方式。源图可能包含完整人物，制作时仍须让源矩形与 `face.clip` 共同排除头发、皮肤边缘和重复眉线。完整姿势自带头部时，五官与该躯干共同变换，不再独立施加旧站姿的颈部或头部位移。

新动作先制作完整、比例一致的姿态，再登记关节和遮挡；旧动作的切片、蒙皮和姿势不作为新素材回退。完整图接入网格也可能在跨腿、跨袖口的三角形处拉裂，不能将“未切图”或关节数值合法视为视觉通过。当前候选仍未完成三服饰和鲸鱼验收。

完整拎腰原画应已经包含弯腰、放松肩膀和双手下垂的姿势。静止时保留原画中的关节角度；拖动只叠加有限惯性，不能把所有手臂强拉成竖直或强制增加相同膝角。完整 `held` 素材的小幅惯性采用连接的网格与肩胯渐变权重，避免没有独立补画遮挡时分割表面产生衣袖和裤腿裂缝；独立四肢及大幅接触动作保留各自绑定路径。这项处理不替代行走、攀爬或跨姿态素材的视觉修复。

拎起期间腰部跟随鼠标，允许身体暂时伸出工作区。桌面宿主可扩展透明窗口容纳悬挂轮廓，角色的渲染原点保持固定；松手后的最终请求使用放下姿态可见范围收回工作区，再判定贴附。悬挂可见范围不能用于持续把鼠标抓点往屏幕内推。

### 可选过渡描述与校验

人物和鲸鱼的版本 2 可登记 `transitions`，最多 32 条，每条有唯一 `id`、`from`、`to`、`durationMs` 和 `keyframes`。端点描述 `pose`（`stand` 或已登记姿势）、`facing`（±1）及可选四边 `edge`；相同方向端点对不能重复。时长为 80–1500 毫秒，每条 2–8 个关键帧，以严格递增的 `progress` 覆盖 0 到 1；关键帧可引用六种姿势名称，或登记复用同一校验规则的完整中间姿势。

关键帧可选 `viewFacing`（±1）说明原画到世界坐标的显示基准，与端点的移动方向分开。转向播放要求每帧明确该基准；旧描述省略时仍可读取，但缺少基准的转向会停止并反馈原因。完整左向原画可保持显示基准为 1，沿世界负 X 行进，不能在结束时换回右向原画并镜像。

可选 `supports` 将四肢名映射到 `{edge,point}`，`point` 必须对应姿势中实际登记的掌或鞋底。同一帧中声明接触同一边的支点，其法向坐标差不得超过 1 模型单位。附着端点的首／末帧须保留该边支撑；两端均附着时每帧保留支撑，顶部须有支撑手、底部至少两个支点，邻帧保留共同支点。相邻边转角至少三帧，不能跨越相对边。格式校验限制接触点变化，但它没有宿主位置、角色尺寸或运行期身体补偿，不能证明世界支点稳定；实际引擎须基于确认位移及显示基准验证稳定支撑不超过 1 DIP。

中间姿势使用的分件必须存在且绑定一致；重复引用仅允许完全相同的姿势，不允许同一分件换成不同五官、腰点或关节绑定。所有服饰的源矩形都按实际 PNG 验证；版本 1 不接受过渡字段，容量和 ZIP 预算保持不变。人物与鲸鱼渲染器一次绑定完整中间视图，播放时使用对应关节、五官和遮挡，结束后保留目标原画及显示基准。站姿必须来自明确的完整站姿视图，缺少站姿、转向基准或可达支点时明确失败。离散关键帧不自动生成缺失的过渡原画；格式与数值测试通过仍不表示跨视角视觉验收通过。

渲染器通过只读播放进度反馈过渡状态；真实窗口轨迹、试玩位移和休息计时等待过渡结束，渲染时钟继续播放原画。按住时手动移动仍跟随鼠标，并取消旧的过渡播放请求。重复试玩保留当前位置及当前实际姿势，不重建渲染器；缺少从该姿势出发的过渡时停止并显示原因。抓取位置取当前已绘制姿势的腰点，包含该帧身体补偿，不能重新套用旧站姿腰点。

### 鲸鱼专属姿势版本 2

默认或显式 `rigProfile=whale` 的旧包继续使用原素材与五官；不增加 `motionRig` 时不会自动获得新的四边姿势。新鲸鱼骨架只接受完整版本 2，字段为 `version`、`waist`、`neck`、`hiddenParts`、`poses`、`supportedEdges`。最后一项必须包含上下左右各一次，表示姿势数据齐备，不能作为视觉通过标记。`whale_motion.py` 独立校验鲸鱼绑定，人物五官协议不能用于鲸鱼。

六种姿势沿用上述有界关节、独立四肢、支撑点与步长规则，另登记 `neck`、`layers` 和鲸鱼 `face`。`layers` 必须包含 `headBack`、`headFront`、`skirt`、`tail`、`finNear`、`finFar`，每槽最多四个素材 ID；后发可以为空，其余至少一个。动作部件的资源父级固定为 `body`，运行时由渲染器绑定到固定鲸鱼链。所有姿势引用的 ID 唯一且不能列入旧部件隐藏清单；独立 ID 可复用同一 `tex`，不会因此重建渲染实例。

鲸鱼保留原 `feat.eyes.eyeL/eyeR` 的眼白、虹膜、睫毛、可选眼缘与眼睑曲线，分别合成眨眼、视线及原生表情。姿势 `face={kind:"whale",transform,clip}` 将原脸部画布局部像素投影到骨架空间；画布原点对应原画 `(520,578)`。`transform=[a,b,c,d,tx,ty]` 表示 `x'=a*x+c*y+tx`、`y'=b*x+d*y+ty`；前四项绝对值不超过 4，平移不超过 512，行列式必须大于 `1e-8`，镜像由角色朝向控制。`clip` 是 3–16 个有限点组成的非零面积露出面部范围。转头透视与眼睛遮挡仍需对应素材，不能通过拉伸整张脸伪造自然姿势。

## 五官与配色

`feat.sprites` 使用 `[x0,y0,x1,y1]` 标记每张五官的骨架位置；对应贴图为 `feat/{name}.png`。必需：`eyes`、`closed_eyes`、`angry_eyes`、`surprised_eyes`、`brows`、`neutral_mouth`、`happy_mouth`。眼睛贴图包含两眼，不包含独立眉毛；眉毛单独绘制。无需鲸鱼娘的 `feat.eyes`。

`schemes` 为 1–8 套，每套唯一 `id`，可提供 `brand`、`label` 和 `accent`。第一套素材直接放在 `tex/`、`feat/`；后续配色放在 `schemes/{id}/tex/` 与 `schemes/{id}/feat/`，同名 PNG 尺寸必须一致。每套必须有 `thumbs/{id}.png`。

人物服饰可提供 `outfit={standingParts:[...],seatedParts:[...]}`。两组分别登记站姿和坐姿衣物的部件 ID，每组 1–8 个、无重复且不能交叉引用，全部必须存在于 `parts`。坐姿过渡时站姿衣物淡出、坐姿衣物淡入；衣袖使用手臂父变形器，头饰使用 `head`，长裙或大褂下摆使用 `coat`。缺少 `outfit` 的旧包保持原部件行为；共用画布上的可选分件可使用同尺寸透明 PNG 占位。透明原画不要烘焙地面阴影，运行引擎统一绘制动态柔影。

已有本地分层项目通过 `POST /v1/desktop-pet/projects/{project_id}/replace-package` 更新完整 ZIP，multipart 提交 `file` 和 `expectedRevision`，返回项目文档。新包必须保持骨架类型及当前默认服饰的有效 ID；其他交互引用也需兼容。服务先校验并写入新 ID 素材，再 CAS 切换模型与映射。失败或版本冲突清理本次素材并保留旧包，成功不修改项目 ID、标题、人设、习惯和私人聊天。Live2D 来源仍使用更新来源或部件换肤入口。

资源包仅含清单、模型与模型登记的 PNG。人物及鲸鱼只有通过完整专属 `motionRig.version=2` 校验后，才允许最多 128 个 `parts`，其他模型仍最多 80 个；完整序列图集不会自动提高部件容量。ZIP 最多 32 MiB、解压最多 64 MiB、文件最多 450 个；`model.json` 最多 128 KiB，每张 PNG 最多 16 MiB、每轴最多 4096。导入经过 Workspace 权限和完整校验，素材随后通过鉴权 API 加载。
